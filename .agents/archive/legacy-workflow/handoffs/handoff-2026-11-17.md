## 6. 环境与工具坑（都是踩过的，照做可省时间）

1. **Node 24**：`.node-version`=24；探针 reporter 已在 `runner-selfcheck.test.mjs` 的 `runProbe` 用 `NODE_OPTIONS='--test-reporter=tap'` 固定，**不要**再靠全局 NODE_OPTIONS 跑测试。
2. **cargo 测试必须重定向 TMP/TEMP**：本机 DSH 会话的系统 `TEMP` 对派生进程不可写（会 500+ 处 "unable to open database file"，纯环境假红）。
   ~~~powershell

   $env:TMP = 'D:\soft\fluxreader\tmp\test-temp'; $env:TEMP = $env:TMP
   .\tmp\rust-env\run-with-rust-env.ps1 -WorkingDirectory src-tauri -CommandLine 'cargo test --no-fail-fast'
   ~~~
   另可用重定向 + `Tee-Object` 存日志（注意 Tee 的路径要用**绝对路径**，脚本内部会切目录）。
3. **cargo 全量门禁**：fmt / clippy(-D warnings) / test(--no-fail-fast) → 62 个目标、lib 680 passed（当前基线）；`#[ignore]` 14 个为既定容量/真实服务测试，不属门禁。
4. **不要并发跑 cargo 全量与 `test:components`**：CPU 吃满会让组件挂载超时触发**看门狗 exit 3**假死（非断言失败，表现为"组 failed 但 fail 0"）。串行跑即可定污。
5. **子代理冷启动易崩**：常见"failed before it finished / 无 closing message"且无产出。处置：先 `git status` 确认无半成品，再 `send_message` 唤醒同一代理（通常第二轮即可正常工作）。不要因此放弃该代理。
6. **`ask_user_question` 可能超时**（程序 120s/600s 都曾超时）：改为**文字提问**并让用户直接回复。`run_code` 默认 120s 限制：长任务（cargo 全量、ui-layout、components）用 `run_in_background` + `job_output` 收集。
7. **`docs:check` 不扫仓库根 README**：根 README 的链接/锚点断了门禁拦不住（已修一处，机制缺口仍在；扩展扫描=门禁变更，需依据+确认+独立审计）。
8. **clippy 依赖缓存**：若只改了注释/文档，clippy 秒回属正常（cargo 指纹按内容判定）。
