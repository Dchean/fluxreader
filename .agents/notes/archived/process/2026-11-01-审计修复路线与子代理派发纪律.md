# Agent Note: 2026-11-01 审计修复路线与子代理派发纪律

Status: implemented
Archived: 2026-11-06

## Problem

两轮独立证伪审计（2026-10-19 上游遗留核销 + 2026-11-01 全量双轮）累计确认：同步侧 6 条 P2 残留（4 条部分修复）、AI 管线 3 条新 P2（含 1 条未消毒流式输出进 HTML 渲染的 XSS 窗口）、OPML 重复目录 P2、供应链 13 条 cargo-update 级通告与 fetch_image SSRF。需要一条按风险排序、写集互不重叠、且能被「本机只跑 fmt + 前端门禁、CI 承担 Rust 编译级验证」的分工实际承载的修复路线；同时要为多代理协作确立派发纪律——用户明确要求：编程子代理视情况复用但必须避免长上下文污染与偏移，证伪审计子代理每次全新派发。

## Decision

路线按四波推进，波内写集互不重叠，波间按共享代码面排序：

1. **W1（三卡并行）**：A 工程化止血——`cargo update` 定向升级 ammonia/rustls/quinn-proto/tokio/rustls-webpki/webpki-roots、CI action 全部 pin 到 commit SHA、vite dev server 收敛 `host: 'localhost'`；B 同步失败关闭补口——GR `tag/list` 缺 `tags` 字段判协议错误、`item_contents` 非空请求空/缺条响应判错（各补严格夹具）、断开→连新账号路径清理 feed/分类墓碑；C AI 前端三 P2——`clearAiProduct` 与在途流式互斥（堵 XSS 窗口）、全局 `translating` 复位脱离 ownsView 门控、三处 catch 改 `extractError`/`extractErrorCode` 透传真实错误分型。
2. **W2**：订阅 outbox 收口（接入自动调度、会话构建失败落 attempts/last_error、subscribe 链起点与 ConfirmedSubscribe 重定两残留、push_feeds 挂载失败收敛通道）+ OPML 导入复用同名分类。排在 W1-B 落库之后：共享 `subscriptions.rs` / `db/folders.rs` 面。
3. **W3**：同步提速三件套——同步会话按账号代际缓存复用（TTL + 401 重认证重试）、GR `item_contents` 分块与 Fever `with_ids` 回补的有界并发（2–4）、窗口聚焦触发 light 同步（60s 节流）。排在 W1/W2 之后：改动同域（session/pull/scheduler），避免与失败关闭修复竞态。GR `ot`×状态流的协议级增量需真实服务端实机验证，本轮不做、单列观察。
4. **W4（2026-11-01 已落地）**：前端体验批次——画廊方向键行优先语义、模态焦点陷阱与 dialog 语义、产品树 ErrorBoundary、对比度点名项收敛、mockData 动态 import、App.tsx 事件监听竞态、AiTab 读改写串行化（各卡归因 Note 与验证证据见 .agents/notes/implemented/ 下 2026-11-01 各篇）。发布切点：v0.18.3 只包含 W1+W2+W3；W4 与通知竖条样式移除（无独立 Note）为发布后 dev 上的改动，随下个版本发布。

派发纪律：编程子代理在同一任务卡的返工循环内经消息复用原代理（保留其对本卡上下文），跨任务卡一律新开代理——上下文只属于一张卡，跨卡累积即污染；证伪审计子代理每次全新派发，不复用任何历史会话。编程代理不做任何 Git 写操作；主控负责按写集分卡提交（写集隔离使按路径 `git add` 干净）、推送 dev、跟进 CI（`cargo test/clippy/check` 由 windows-latest job 承担，本机只跑 `cargo fmt --check` 与前端门禁）。每张涉及行为或契约的卡随批维护 Note（按 write-notes-like-deepseek 红线判定，纯机械修复不立）。协作基线沿用 [主控与代码执行分离](2026-10-08-主控与代码执行分离.md)。

## Alternatives considered

- **全部任务一次性并行派发**：outbox/提速卡与同步失败关闭卡共享 `subscriptions.rs`、`session.rs` 面，并行必然产生跨代理写冲突与重复调查。按写集分波把两步串行化，换来零合并仲裁，总时长更短。
- **沿用上一轮 OPT 卡粒度（一卡一代理一流水）**：上轮粒度适配多月重构；本轮是收口批次，波粒度已足够隔离写集，再细则只增加派发与验收开销。取「任务卡内聚、波间串行」的中间粒度。
- **单一编程代理贯穿全部波次**：代理上下文会累积两轮审计的全部细节，正是要求避免的长上下文污染与偏移路径；跨卡新开把每卡上下文压到最小，返工复用只发生在卡内。
- **npm 依赖升级纳入 W1**：本机对 registry.npmjs.org 整体不可达（两轮实测），`npm install` 无法落地；vite/undici 升级改为遗留项，待网络恢复或 CI 侧方案。
- **审计子代理复用**：被用户约束直接排除——审计独立性要求每次全新上下文，不接受效率换独立性的折中。

## Consequences

- 收益：P0/P1 级安全与正确性缺口（XSS 窗口、SSRF、墓碑泄漏、缺字段对齐）在本轮收口；同步即时性的三个真实瓶颈（逐轮重认证、独立请求串行、固定节拍轮询）各有独立卡承载与独立审计；每张卡有 CI 证据，追溯链清晰。
- 代价：Rust 卡的行为验证完全依赖 CI 往返（每波约 8 分钟起），返工慢于本地可测；npm 升级悬置为已知供应链残留；W2/W3 串行等待 W1 落库；`ot` 状态流增量与实机端到端耗时基线（需真实账号并约定读写边界）继续挂账。
- 边界：Fever 星标 TOCTOU、GR read-wins 政策等已声明取舍不在本轮范围；roadmap §一~§七既有条目不因本路线自动扩展。前一轮收口的范围与证据见 [审计修复收敛路线](2026-10-31-审计修复收敛路线.md)。
