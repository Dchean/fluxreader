# Agent Note: 分区阅读与源内身份及持续同步契约

Status: proposed

## Problem

2026-11-09 用户已确认五个内容分区、源间独立、同源内容去重、读藏快速双向同步、本机提前抓取、未读与收藏保护，以及纯本地模式下 WebDAV 持续多端同步。允许必要重构或模块重写，运行目标只有 Windows，不要求兼容旧版本数据。这些是已授权的产品目标；本篇 `proposed` 表示跨域实现仍待落地，不表示需要再次确认同一需求。

`dev@16fb0bb` 的实现仍有相反契约：Google Reader light 为 read-wins；本地 read 按 URL 向别的源广播；直抓在真实 GUID 未命中后按同源 URL 覆盖；删除源级联删除全部文章；WebDAV 只 PUT/GET 一个 schema2 配置快照。单独修这些入口会让查询、状态队列、正文保留、备份和多端同步互相违背，因此先固定最小公共契约，再由同一责任人闭合一起变化的逻辑。

现有 Tauri/Rust/SQLite、事务化意图、账号代际、字段版本、失败关闭、写后确认、正文净化与 DPAPI 仍有实际价值。没有为了低耦合增加抽象层、为五布局分别建立数据架构或更换技术栈的要求。

## Proposal

### 源、条目与内容的最小身份

| 对象 | 单一职责与最小契约 |
| --- | --- |
| 订阅源 | 稳定身份独立于显示名称、分组、布局和本机整数主键；来源账号与协议绑定单独记录。改名、移动、换机不得变成另一个源；相同文章 URL 不得关联两个源的状态。 |
| 逻辑条目 | 稳定源身份 + 该源内条目身份。保存真实 GUID/服务端 entry ID 与本机提前抓取的对应证据；URL 只能提供候选，不能单独证明两个内容不同的条目相同。 |
| 正文版本 | 正文由内容身份与修订标识，标题、净化 HTML、正文及媒体集合须来自同一确认快照。指纹仅缩小等价候选，最终复核实际内容；缺正文不等于两篇内容相同。 |
| 远端绑定 | 精确远端 ID 属于源内条目，多个已证实等价的远端别名仍保留可写回目标。绑定过程不得丢本机提前发生的读藏意图；不靠跨源 URL 或旧 CSV 猜目标。 |
| 条目状态 | read/star 各有持久意图与版本，和正文是否保存分开。状态更新、意图入队及变更回执在同一提交边界；清正文不能顺带清尚需传播的状态或身份。 |
| 删除与停订 | 区分退订、普通已读正文回收、条目状态变化；有稳定身份和版本的删除记录阻止旧设备/旧快照复活订阅。删除记录不是“没下载到正文”的同义词。 |

不同源的条目、显示、读藏、AI 与生命周期独立。相同源中确认内容相同的重复输入应呈现为一条；内容不同必须独立，不按相同链接强合并。最小对照是：两个不同真实 GUID 共用 URL 且正文不同，保留两条；两个不同 GUID/链接但标题与正文内容相同，在同源内去重。同一稳定 GUID/远端 ID 已确认是同一条目的正常正文修订仍是修订，不能为每次抓取制造新条目。入库、远端绑定、列表/计数/搜索、单条和批量状态操作应使用同一身份规则；不能只关掉 `smartDedup` 显示开关而保留跨源状态传播。

本机提前抓取先建可读条目，用户可以离线标读/收藏；服务器稍后提供同源对应条目时，只有身份/内容证据匹配才绑定并发送积压意图。本机与远端可能有净化差异，不能只凭 URL 相同就强行匹配；相同 URL、不同真实内容是反例，必须保留两条。一次无法确证匹配保留待绑定状态，不能误推/误确认队列或覆盖正文，后续同步可继续尝试。

### 内容保留与退订

未读与全部收藏的正文长期保护；已读未收藏正文按设置期限回收，读藏状态仍能传播。回收可采用正文缺失的轻量条目/独立状态记录，具体表结构由实现者选择；必须能在重新标未读或收藏时恢复所需正文，不能把旧已读内容全部重拉作为每次轻同步的前提。

退订必须一次提交：记录停订意图与墓碑、保留收藏的正文/元数据/原源身份和所属内容分区、移除该源其余内容、停止后续抓取。可用停用源承载收藏或独立保存来源快照，但不得将收藏搬到会混淆来源的公共假源，也不能因删目录级联绕开保留规则。收藏查询、数量、阅读和换机恢复都要能消费这些退订收藏。未读保护仅适用于仍订阅内容；用户已明确退订只留收藏。

协议能力限制仍保留：Fever 的本机停订与远端退订不同；已排除源的远端条目应被明确过滤且安全消费分页，不得阻塞其他源及轮末状态对账。Google Reader 退订须保留持久意图/写后判断，不把 HTTP 接受等同于所有部署均已删除。

### 阅读会话与五分区

文章、社交、画廊、播客、通知是内容分区。“全部/今天/未读/收藏”先受当前分区限制，组和源继续收窄。查询返回的成员窗口与条目属性分开：J/K、标读/收藏和后台同步只更新属性与计数，不在阅读过程中移走当前成员、重排列表或移动锚。切分区、组、源、筛选时才按最新状态重建成员窗口；请求代次和稳定条目锚共同拒收旧范围结果。

今天的日历边界也属于查询输入。跨零点更新日期和计数，不让旧缓存永久代表今天；若当前正在阅读，遵循上述会话保位规则，下一次重筛使用新日期，不能借跨日修复偷偷打断当前阅读。

焦点、选中、打开正文、打开大图和开始播放分别表达用户动作；所有自动标读入口都服从同一组设置。文章保留长文阅读；社交短卡、长文折叠；画廊瀑布流首图和张数，打开后循环查看该条全部图片；播客底栏、进度和续播；通知承载 release 内容。保位要求适用于异步正文、图片自然尺寸、翻译和播放状态变化，验收看过程，不能仅比较最终位置。

画廊需要由正文/媒体提取给出有序的单条图片集合，再给列表轻量首图与张数，灯箱只保存条目身份、集合版本和当前索引。正文到来后补全列表、张数和灯箱须对应同一条目版本；有一图、多图、空图和失败图都可恢复。媒体二进制缓存、跨条目轮播和播客音频跨机下载不是此次多图要求。

### AI 触发与设置

文章在真正打开后按开关触发摘要/翻译；社交只允许翻译；通知允许摘要/翻译；社交与通知仅在成为视觉中心并停顿后自动触发。画廊、播客不运行 AI。布局、组、源的继承/覆盖配置必须由同一有效策略解析，隐藏 Reader、仅移动焦点和迟到正文不能绕过布局限制或重复发请求。

保留 HTML 结构与净化；续译恢复可以限定为短期，完成产物和短期片段仍绑定条目/正文修订/配置快照。设置初始回读不能覆盖已编辑草稿；“测试成功”只证明实际测试的那份配置，不得保存另一份配置后沿用成功提示。

### 纯本地 WebDAV 持续同步与换机

WebDAV 是纯本地阅读模式的持续多设备传输，服务端 FreshRSS/Miniflux 模式仍用 GR/Fever 管理读藏和订阅。一次只连接一个远端 RSS 服务；不把两个状态权威叠在一起。两种模式共用源内身份、读藏、保留和删除语义，传输适配可以不同。

| 数据 | WebDAV 与换机契约 |
| --- | --- |
| 订阅、组、布局、普通应用设置 | 持续同步稳定身份与引用；布局/组/源 AI 行为开关属于设置，随设置同步。设备窗口、启动等本机专属设置继续本机保存。 |
| 读/未读、收藏/取消收藏 | 全方向传播，与正文保留独立；普通已读正文可以不上传，但其状态变化必须上传。 |
| 未读和全部收藏正文 | 上传可恢复的正文及条目元数据、媒体引用；退订收藏也在内。远端暂缺正文须明确为待补齐，不能报告完整同步成功。 |
| AI 产物与秘密 | 摘要、译文、续译片段不上传；AI 服务配置、密钥与其他凭据仍保留本机，换机重新输入。普通 AI 行为开关不因此被排除。 |
| 删除和停订 | 版本化删除记录不能被另一端旧快照覆盖。未证明所有设备已越过删除记录前不得仅按时间清掉墓碑；需要有界压缩时配合可识别的同步代次/重新初始化规则。 |

传输不能继续用一个可盲覆盖的 `fluxreader-config.json` 充当多端同步。实施需要稳定对象键、设备/操作去重身份、版本化检查点与正文引用、持久待发送记录、下载游标/已确认前沿，以及失败重读重试。曾提出不可变正文对象配合 ETag 条件清单，并进一步尝试 LOCK 保护唯一下一代；真实 WsgiDAV 的过期后延迟 MOVE 反例否定了该唯一提交前提。当前方向是不可变操作批与逐字段确定性合并，检查点保全已知字段赢家、删除墓碑和连续已确认前沿，接收检查点不能仅凭前沿清掉本机已知语义；LOCK/ETag 可用于优化，不能承担合并正确性的基础。当前只在验证传输原语，应用持久 journal、生命周期接线、正文归档/GC、备份恢复和完整容量仍须落地。每次网络结果须复核发起时凭据/同步代次，断开或换配置后旧任务不能复活连接或覆盖新状态。

GR/Fever 状态冲突继续接受服务端实际接收顺序。2026-11-09 用户另行确认 WebDAV 的规则：同设备后操作优先；已同步看到另一端结果后再操作优先；两端离线对同项作相反操作时按固定规则自动收敛，不保证真实点击或上传先后。WebDAV 使用创建操作时固定的逻辑戳与设备/序号排序，允许多个不可变操作批并存并逐字段合并；读藏相互独立，重试不产生新操作。真实 WsgiDAV 的过期 MOVE 反例已否定“LOCK 保证唯一下一代”的原候选，不能用延长租期或多次读回恢复该承诺。网络失败、缺对象和不完整包保留待同步状态，不当作远端删除或空状态；同字段未确认本机意图与旧响应版本继续受保护。

换机需提供新版本可实际使用的备份导出与恢复流程，覆盖订阅、组、全部收藏正文与设置，并校验完整性和版本。恢复成功须实际能列出/打开退订收藏和恢复设置；只给 SQLite 手工复制说明或仅导出 OPML 不满足该目标。凭据不以明文迁移，恢复失败不能破坏当前可读数据。

### 新数据基线与历史边界

不兼容旧数据允许删除历史迁移链、旧凭据明文兼容、旧 URL 算法与旧快照 fallback，但须先核查所有当前装配/调用者。`sync_queue`/订阅 outbox、账号代际、字段版本、正文 revision、事务、备份、净化和写后确认都是当前安全边界，不能以“历史包袱”删掉。

新库有明确格式版本；遇旧库明确拒绝并保留原文件，给出可恢复的位置与启动新数据的可执行路径，不自动删库、清目录或套用旧迁移。新版本导出的备份/同步格式必须可以在新版本另一设备恢复。旧库与旧云快照若不支持，错误明确指明类型/版本，不把解析失败视为新建空库或远端空状态。

本篇只取代以下旧决定的相关产品方向，其他约束继续有效，实施落地时由各批负责人同步原归属文档及反向注释：

- [同步冲突政策](../../implemented/architecture/2026-10-07-同步冲突政策单点.md)：取代 GR read-wins、跨源 read 广播；保留 pending、字段版本、失败集合及实际提交信号。
- [条目与共享内容身份](../../implemented/architecture/2026-10-12-订阅条目与共享内容身份.md)：取代跨源显示聚合/状态传播、同源 URL 直接视为同一条的前提；保留内容修订、净化、事务及异步失效。
- [缓存清理](../../implemented/bug-fix/2026-11-05-缓存清理语义与未读保护.md)：保留未读/收藏保护，新增状态独立保留与退订仅保收藏；原“整条删除”的实现不自动满足新多端要求。
- [配置镜像](../../implemented/architecture/2026-10-15-配置快照镜像应用.md)：纯本地持续同步替代手动配置快照的产品角色；保留受校验的应用、凭据隔离、事务与失败可恢复要求，不把旧镜像删除代码直接当多端删除协议。

## Alternatives considered

- 只修已发现的小缺陷并沿用旧政策：工作量较小，但不能兑现已确认的分区、双向状态、退订收藏与 WebDAV 正文多端目标，故不作为完成路线。
- 连接 RSS 服务后停止本机抓取：可减少绑定复杂度，但用户已明确需要提前读到文章，故保留并解决同源对账。
- 延续 Gist 与手动配置快照：已有实现可复用少量传输/校验经验，但 Gist 副本发现与迟到凭据另有缺陷，且配置快照不传正文/状态。允许移除 Gist，优先只做 WebDAV 的真实多端能力。
- 继续兼容历史本地库和旧快照：能原地升级，代价是维护旧身份/字段/迁移。用户已放弃旧数据兼容，选择明确新基线与拒绝旧格式，同时保留旧文件和新格式恢复能力。

## Acceptance criteria

逐批操作序列与门禁承担者集中在[既有验收入口](../../implemented/process/2026-11-03-修复波次的分批、证伪审计与证据门槛.md#2026-11-09-已确认重构路线与退出条件)，未完成项集中在[roadmap](../../../../docs/roadmap.md)。必须覆盖：同源直抓先到再绑定、同 URL 异内容不误并、跨源读藏互不影响、退订收藏仍可读、读藏变化不抽走当前列表成员、五布局动作统一服从标读设置、AI 正确触发、两设备 WebDAV 离线/冲突/删除/重启及新设备恢复。结构校验或旧版本测试通过都不能代替这些行为证据。

## Risks

直接抓取与远端内容不完全相同，匹配失败时宁可保留独立条目与待绑定意图，不能静默误并。状态与正文分离会增加轻量身份/墓碑的保存期，必须用测量确定压缩策略；未读与收藏无数量裁剪承诺限制可回收空间。通用 WebDAV 的对象上传、读取、列举、移动和精确删除语义仍需目标服务器验证，不能把 LOCK/ETag 支持当作唯一提交或多端安全证明；旧配置往返证据也不覆盖这些契约。当前传输阶段的字段、字节和目录预算不代表完整 RSS 库容量，持久 journal、正文归档/GC 与换机恢复仍需按五万条规模验证。长期媒体 URL 可能失效，本轮保留正文与媒体引用不等于把所有图片/音频文件永久镜像。新库拒绝旧格式是明确破坏性边界，发布与恢复说明必须一致。

此记录依据基线源码与 2026-11-08 审计、2026-11-09 对标的静态核查；没有运行产品、真实账号或新增多端协议验证。状态、证据版本和发布结果只在验收入口维护。
