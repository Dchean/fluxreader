# Agent Note: 源内等价组与持久条目状态

Status: proposed

## Problem

用户确认不同源不去重、不传播状态；同源内容相同只呈现一条，内容不同独立；同稳定 GUID 的正文修订仍更新原条目。直接把多条远端身份合为一条，会使 Google Reader/Fever 的写回与确认丢失目标；继续用 URL 作为身份又会覆盖共用链接的通知。普通已读正文回收不能丢掉已读身份，退订则只保留收藏。

本决定承接[跨域产品契约](2026-11-09-分区阅读与源内身份及持续同步契约.md)，是后端的具体存储选择。它取代[旧条目身份记录](../../implemented/architecture/2026-10-12-订阅条目与共享内容身份.md)的跨源 URL 显示聚合、跨源 read 闭包，以及同源 URL 独立证明同一条目的前提；内容净化、哈希后字节复核、修订、SAVEPOINT 与异步提交保护继续有效。

## Proposal

每个真实 GUID/远端 ID 保留独立文章实体。内部远端条目的 GUID 键使用 XML 不允许的控制字符前缀划出命名空间，避免真实 RSS GUID 恰好为 `remote-数字` 时绕过内容确认；这是同一列中的一对一内部键，不是别名层。展示组只在同一 feed 内形成，成员必须有非空、已经字节等价复核的 RSS 内容，标题和附件 URL/MIME 也相同；空正文、不同标题或不同节目附件不组成组。列表、计数、搜索、分页、成员 ID 捕获使用相同组谓词。组显示未读取任一未读、收藏取任一收藏，列表、轻属性和详情水合保持同一口径；不把服务端不同实体的状态直接覆盖成同一个持久值。

用户对展示组的 read/unread/star/unstar 四向动作，在同一事务为每个成员写字段版本与独立队项；“全部已读”命中含未读成员的组时，组内已读成员也要承接本次版本与队项，返回数量仍只计真实未读→已读的翻转行；每条远端 ID 独立读回确认。一个成员尚有该字段 pending 时，组内其他成员也拒绝该字段的远端旧状态，避免部分确认造成组重新未读。HTTP 前版本快照与写时版本比较继续覆盖确认后迟到的响应。冲突只承诺服务端接收顺序，不声称跨设备离线真实点击的全局顺序。

RSS 内容引用 `rss_content_id` 与展示正文 `content_id` 分离。全文提取、翻译不会改变 RSS 重复组；同 GUID 的新 RSS 内容会更新 RSS 引用并令不同内容成员分组。contents 的最后引用判断同时识别两种引用。普通已读非收藏正文过期清掉两种引用及媒体、AI 大字段，保留稳定 GUID/远端 ID/read/star/版本；重抓同身份补正文，不复活未读。未读与收藏正文持续保护；同组只要还有未读、收藏、年轻正文或未确认成员，正文清理不拆开这个仍可见的等价组。已读非收藏可释放正文，但未确认队项和所引用的轻身份继续保留。

无真实 GUID 的直连 URL/title+date 仅是观察候选，不能单独证明同一条目。非空条目的持久弱键固定由规范 URL/无 URL 域、净化 HTML、正文、标题与附件的长度分隔 SHA-256 载荷构成，日期与候选键形式不进入持久身份；feed_id 在唯一键外层隔离来源。正文在时仍复核字节，哈希冲突拒绝；正文释放后只按同一精确载荷键恢复轻身份及已读/收藏/版本，不加 URL/date 猜测或别名。缺日期→补日期、未来日期→纠正、日期撤回都不会使同一内容换键。空正文没有等价证明。解析层为所有无真实GUID的输入统一构造完整观察token，包含规范URL或显式None、标题、源原始选定日期`published.or(updated)`的UTC值或显式None；源日期取钳制前值，不使用fetch/first_seen/clamp时刻。DB空载荷把观察token与附件URL/MIME用于候选身份：不同明确日期、标题或附件独立，相同完整观察重放幂等，不参与源内内容组。非空分支不消费观察token，仍沿上述日期无关内容键。无 URL 的同 title+date 异正文独立，同输入重放幂等。此规则取代[发布时间与条目身份](../../implemented/bug-fix/2026-11-03-发布时间与条目身份.md)原 title+date 正文覆盖边界，日期来源和首次时间规则继续有效。

首次修法把原候选键也放进载荷摘要，意在保留 URL/date 的候选边界；独审证明“补日期时正文确证复用→清正文→已补日期重放”会失去身份。现在以不含日期的规范域统一所有阶段，代价是无真实 ID、无 URL 且标题/正文/附件完全相同的不同日期条目无法区分，这与正文尚在时的等价复用一致；不保留一组候选别名来掩盖键不稳定。其后空载荷曾继续复用“URL优先、日期次之”的旧观察，独审证明同URL/title空条目的不同明确日期被吞并；这表明解析时丢失区分线索，不能由DB已钳制的published_at补猜。后继统一观察保留URL和原日期两者，空与非空只在是否消费该观察处有区别。

原本无真实ID的空观察以后补成非空，旧空候选没有内容证明，不把旧读藏/版本/pending转给正文；正文建立或复用规范内容身份，旧空候选保留，因此可能两行。两份输入分别重放稳定，数量取决于不同空观察和不同内容载荷，不按抓取次数增长；同一非空身份已清正文的stub不是“原本空输入”，重抓仍按原内容键恢复。真实GUID或精确remote ID的空→非空始终更新原实体，不套用这条弱候选边界。

URL 仅缩小同源绑定候选。远端新 ID 对本机早到文章的首次绑定，还须候选未绑定、标题附件一致，并经同一净化及可解释文本归一确认内容等价；多候选不猜选。无法确证时保留独立条目及待绑定本机意图，不伪确认。

封面 `image_url` 的 `image_source` 显式区分 rss 派生图与 page 独立网页封面；新条目/RSS 输入标 rss，页面补图/全文的独立封面入口标 page，不由 URL 恰好相同推断。非空完整 RSS 修订可增、换、清自己的 rss 封面；稀疏空回包保留已有图片，page 封面不因 RSS 图集变化被清除或替换。画廊 `images/gallery_first_image_url/image_count` 继续优先取当前展示正文的有序图片，无正文图片才回退当前封面；普通文章 `image_url` 独立保留。正文重指、图片、附件 URL/MIME/时长实际输出变化由一个 SQL 触发器递增媒体版本，重复同值不递增；全文提取、正文回收、直接抓取和远端修订共用，不再远端另手动加版本。该计数是单调失效版本，事务中多个实际字段变更可递增多次，不是用户编辑次数。

同远端 ID 的修订原子更新 RSS 引用、标题及媒体；显示中的 readability 继续保留，RSS 引用变化仍须报告组数据变化。AI 显示输入变化时清除旧产物/签名并递增 epoch，旧生成 token 不可落地；仅 RSS 变化而受保护的显示输入不变时不清有效 AI。稀疏空回包不抹除已有正文。

退订令源 `active=false`、递增生命周期，写稳定 `sync_id` 的墓碑。保留该源收藏与原来源元数据，冻结生效布局；分类删除先走每源退订，不由外键绕开收藏保留。导航、抓取、订阅枚举只含 active，文章来源索引包含 retained。重新订阅复用稳定源身份并开启新生命周期。HTTP 前捕获源 ID/生命周期，精确条目、GR 未读差分与 GR/Fever 权威集合在提交时必须仍命中同一 active 生命周期；退订再重订也拒绝旧响应，重建映射不能刷新原源快照。远端消失后再次出现可恢复原源，本机退订墓碑仍阻止复活；稳定远端 ID 仍在列表而仅 URL 变化不构成退订确认，不能提前清除旧 URL 墓碑。首连计数/推送候选及 OPML 只枚举 active，保留来源索引仍含 retained。取消最后收藏时立即隐藏并释放正文，轻身份保留到其精确状态意图被确认；列表、搜索、计数和批量范围使用相同可见谓词，不能因隐藏待确认行出现幽灵计数。URL 墓碑继续为 RSS 协议拉取提供排除，稳定 ID 墓碑为后续跨设备同步提供输入；两者不能互相冒充对方的完整协议。

新数据格式使用独立 `fluxreader-v2.db`；application_id、schema version 与当前必需的图片来源列共同识别。缺来源列的本轮早期试验格式也只读拒绝，不自动改写。启动不迁移或删除旧 `fluxreader.db` 及旁文件，首次启用新空间提供非阻断提示。误放到新空间的旧库先只读检查并明确拒绝，旧文件原样保留。

## Alternatives considered

- 物理只保留一个文章行并另建多 GUID/多远端别名表：可压缩行数，但需要多目标确认、别名修订分叉与生命周期迁移；本轮选择保留真实实体，避免为显示去重新增一套身份框架。
- 沿用 URL 组并仅关闭跨源开关：无法区分同链接不同通知，也不能满足默认源内内容去重，未采用。
- 只保留提取正文，以其内容 ID 分组：全文提取会改变分组与状态作用范围，未采用。
- 回收正文时删除整行：省下少量轻属性，但重抓忘记已读且可能丢待发送状态，未采用。
- 将候选 URL/date 包入持久内容键：首次尝试已被补日期与正文清理的组合反例推翻；采用稳定规范域，不增加候选别名。空载荷的观察则必须同时保留URL和钳制前源日期，不能继续沿URL/date二选一规则。
- 继续把 RSS 图和网页封面只存一个无来源 URL：完整修订去图后会将旧 RSS 图误当独立封面，增加一个来源列并闭合现有写点；不增加第二套画廊输入状态。

## Consequences

真实实体数量不会因展示去重减少，状态组操作需为每个远端身份入队。RSS 原文与提取正文可能同时占空间，但普通已读回收同时释放两者；未读与收藏保护优先于节省空间。组查询需 `feed_id/rss_content_id/title/id` 索引，并为 RSS 内容引用回收设置单列索引。不同源不聚合后，全局和分类计数可以直接加总源计数；同次计数快照复用一次源扫描，避免每个层级重复相关子查询。规模与读写耗时在 20k/50k 混合实体上测量，不凭小夹具判断性能。无法确证的早到绑定可能暂时显示两条，这优于把本机状态误推给不同内容。弱身份正文变化也可能增加行数；不能用 URL/title+date 强行覆盖来减少数量。空观察与后来的非空载荷可能并存，旧空观察的已读/收藏不会自动作用于缺乏证明的新正文；这是保守匹配的可观察代价。全部身份线索相同的多个实际空事件无法从输入区分，重放按同一观察处理。合成键命中且仍有 RSS 字节却不等价时明确报错，保留既有条目；已清正文的精确载荷键以 SHA-256 内容身份恢复，失去再次核对原字节的能力。图片来源多一个受约束列；保留的 page 封面不会被 RSS 首图替代，失效仍沿现有精确 URL CAS 清理与重试。

## Risks

早到条目的严格正文证明需要真实 FreshRSS/Miniflux 对同一 RSS 的返回形态验证，不能从相同 mock HTML 推导。当前过期正文释放后保留轻身份，但跨设备同步仍须有自己的持久变更日志与确认前沿；RSS 队列确认不能代替 WebDAV 的确认。宿主事件消费和真实界面连续性需要独立验收。

## Acceptance criteria

新反例覆盖同链接异内容、同源不同链接等价内容、跨源显示与四向隔离、同 GUID 修订分叉、附件/标题差异、媒体版本、清正文后状态重放、退订收藏及早到确证。事务故障、字段版本、ACK 读回、未知源失败关闭和当前格式拒旧保文件的检查继续承担各自不变量。新增单消费者重试/空闲通知/停止释放、Retry-After请求冷却、零新增正文/媒体/304恢复、20k与50k混合实体规模检查；这些入口不等于实际宿主事件或服务端canonicalization已验收。当前实现与审计状态以本轮交付入口为准，本篇 proposed 不代表尚未授权，也不代表全门禁已通过。
