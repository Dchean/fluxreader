# Agent Note: 清理前端回归脚本未使用绑定

Status: proposed

## Problem

`tools/frontend-regression.mjs` 当前产生 `assert`、`p` 和 `beforeCalls` 三项未使用绑定告警。它们增加 lint 噪声，使真正需要关注的告警更难辨认，但对应测试调用、异步等待、八项断言和执行顺序必须保持不变。本任务仅处理这三个已复现的局部告警，不把仓库中的其他既有告警或 Rust 格式差异混入范围。

## Proposal

在不改变测试行为的前提下删除未使用的 `assert` 导入，将 `toggleReaderTranslation()` 保留为直接调用，并删除未被断言读取的 `beforeCalls` 绑定。保留现有等待时序、调用表达式、八项断言及退出逻辑。产品源码、CI、依赖和测试门禁均不修改。

## Alternatives considered

- **不做，保留现有告警**：最强论据是这些告警不导致 lint 失败，当前测试也能通过，因此零改动风险最低。未采用是因为三个告警已有明确、局部且可验证的无行为变更修复，会持续污染后续 CI 和审查信号。
- **复用现有命名约定，将变量改为下划线前缀**：最强论据是改动机械且能让规则忽略变量。未采用是因为这些值从未被读取，保留伪占位变量会掩盖真实意图，直接保留调用并删除无效绑定更简单。
- **关闭或放宽 no-unused-vars 规则**：最强论据是一次配置即可消除同类噪声。未采用是因为会扩大到全仓并降低门禁强度，超出 TASK-004 的单文件低风险范围。

## Acceptance criteria

- `assert`、`p`、`beforeCalls` 三项指定未使用告警消失。
- `tools/frontend-regression.mjs` 的八项断言、调用顺序和等待时序保留。
- `npm run test:frontend` 显示 8/8 通过。
- `npm run build` 通过。
- `npm run lint` 如实保留范围外既有告警，不关闭规则。
- 产品源码、CI、依赖、任务治理文件和其他受保护路径没有由 Claude 修改。

## Risks

删除未使用绑定仍可能因误删调用表达式而改变行为，因此必须在差异审查中确认调用仍存在，并独立运行前端回归。若八项断言数量、顺序或等待时序发生变化，则拒绝该实现并在原任务预算内反馈修复。
