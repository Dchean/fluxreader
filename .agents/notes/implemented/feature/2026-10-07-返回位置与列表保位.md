# Agent Note: 返回位置分流、锚身份与窗口深度

Status: implemented

## Problem

刷新、切换返回和Reader关闭若共用滚动恢复信号，会重复滚动；用文章id作信号又不能触发连续开关同一篇。深页刷新只取首页时锚条目不在新列表，恢复逻辑也无从兑现。

## Decision

恢复以条目id、filterKey和卡片内偏移记账，不只记scrollTop。高频锚在模块内维护，store只发nonce，不让每次滚动触发订阅render。250ms节流有尾沿提交，恢复后立即重锚，避免下一次存档仍用恢复前位置。

三种触发分开：后台内容刷新使用positionRestoreNonce；切回缓存上下文使用switchRestoreNonce，并与entries同次set；Reader关闭使用readerCloseNonce归还原卡焦点。同上下文重复导航不算切回，导航动作自身不借刷新nonce，随后后台内容刷新可独立保位。

切回缓存且存档锚存在时恢复，首次/cache-miss/存档锚不在恢复列表时走顶部回落。后台刷新若当前锚已失效则不执行恢复，不凭空猜新目标；这与切换返回的归零不是同一个分支。Reader原卡仍在时align:auto归还焦点，可见时不滚，已切出列表则不聚焦。画廊仍不参与这套跨上下文顶条规则，异步图片测量锚属于另一机制。

后台重建已加载窗口按keyset续拉，防循环上限随目标已加载量计算ceil(target/pageSize)+1；它不是固定“深到某条就不能恢复”的页数限制。视图缓存另限单键1000条、LRU8键，并保存完整游标/加载深度与exhausted，不能拿截断后的数组长度冒充实际分页进度。

## Alternatives considered

只记像素会在新文插头部后指向另一条；只记id又遗漏长卡中部偏移。所有恢复合一个nonce会混淆持续刷新与一次性返回，同id信号则漏掉重复请求。

cache-miss硬猜索引没有可靠对象；选择重新首屏起步。排序改变清缓存并重建语境，不恢复旧排序中的位置。让store直接依赖组件锚模块会反向耦合，因此由Timeline消费信号并管理DOM焦点。

## Consequences

缓存淘汰、截断、文章删除/过滤和动态测量都可能限制精确恢复；这是明确回落，不是“所有随机跳位已从根上排除”的证明。深页重建多付查询，不能用历史50k堆样本宣称任何规模都平坦。

2026-11-06列表延迟焦点回调仍可抢菜单焦点，画廊也有异步测量漂移，见[界面与媒体路线](../../../../docs/roadmap.md#interface-and-media)。nonce分流并不自动保护焦点请求的有效期。

## Validation

锚纯函数、导航/深页前端回归核对上下文、游标和重复信号；真实组件/浏览器需按“停滚→切换→返回→后台更新”和“连续开关同篇”观察滚动与焦点。只验最终选中id不足以证明过程不跳。
