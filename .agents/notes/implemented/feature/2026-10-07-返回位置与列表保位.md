# Agent Note: 返回位置分流、锚身份与窗口深度

Status: implemented

## Problem

刷新、切换返回和Reader关闭若共用滚动恢复信号，会重复滚动；用文章id作信号又不能触发连续开关同一篇。深页刷新只取首页时锚条目不在新列表，恢复逻辑也无从兑现。

## Decision

恢复以条目id、filterKey和卡片内偏移记账，不只记scrollTop。高频锚在纯模块`lib/readingPosition`内唯一维护，记录不触发订阅render；store读取同一存档以准备返回窗口，再发nonce，由Timeline做DOM滚动。250ms节流有尾沿提交，恢复后立即重锚，避免下一次存档仍用恢复前位置。

三种触发分开：后台属性刷新使用positionRestoreNonce；切回缓存上下文使用switchRestoreNonce，并与准备好的entries同次set；Reader关闭使用readerCloseNonce归还原卡焦点。同上下文重复导航不算切回：按2026-11-09固定会话契约仍须重新捕获成员，落地沿当前活锚发positionRestoreNonce，不消费上次离开时的旧存档。新成员与锚窗口边界详见[查询与分页契约](../architecture/2026-10-05-查询与分页契约.md)。

切回缓存且存档锚仍在新成员中时，store须先让轻属性窗口覆盖它，再由Timeline按其id/偏移恢复。缓存首项删除不代表真实锚删除；不得因此回首500行而丢失深锚。首次/cache-miss或真实存档锚已不在新成员时走既有顶部回落。后台刷新若当前锚已失效则不执行恢复，不凭空猜新目标；这与切换返回的归零不是同一个分支。Reader原卡仍在时align:auto归还焦点，可见时不滚，已切出列表则不聚焦。画廊仍不参与这套跨上下文顶条规则，异步图片测量锚属于另一机制。

原后台窗口重建采用keyset续拉，防循环上限按目标加载量计算，是为了消除“只读首页导致深锚不可恢复”。2026-11-09固定成员需求部分取代这条算法：后台只回读当前会话已加载ID，显式返回重新捕获成员并准备锚附近窗口，不从0读取至深锚。视图缓存仍限单键1000条、LRU8键，并保存完整进度与exhausted，不能拿截断后的数组长度冒充实际分页进度。真实锚已在默认准备窗口时保持窗口起点，仅在锚不被覆盖时调整，避免普通首窗口因锚相对偏移被多余截头。

## Alternatives considered

只记像素会在新文插头部后指向另一条；只记id又遗漏长卡中部偏移。所有恢复合一个nonce会混淆持续刷新与一次性返回，同id信号则漏掉重复请求。

cache-miss硬猜索引没有可靠对象；选择重新首屏起步。排序改变清缓存并重建语境，不恢复旧排序中的位置。原先避免store反向依赖组件锚模块而让store只发信号；新固定会话需要先准备真实存档锚所在窗口，因此将现有纯状态归lib，让store和Timeline依赖同一实例。没有选择可选provider，因为它额外引入初始化/卸载生命周期；DOM滚动与焦点仍只归Timeline。

## Consequences

缓存淘汰、真实锚条目删除/过滤和动态测量仍可能限制精确恢复；缓存中非锚首项消失不再被视为丢失锚的理由。这不是“所有随机跳位已从根上排除”的证明。返回须查询新成员并回读有界轻属性邻域，不能用历史50k堆样本宣称任何规模都平坦。

2026-11-06列表延迟焦点回调仍可抢菜单焦点，画廊也有异步测量漂移，见[界面与媒体路线](../../../../docs/roadmap.md#interface-and-media)。nonce分流并不自动保护焦点请求的有效期。

## Validation

锚纯函数、导航/深页前端回归核对上下文、游标和重复信号；真实组件/浏览器需按“停滚→切换→返回→后台更新”和“连续开关同篇”观察滚动与焦点。只验最终选中id不足以证明过程不跳。

2026-11-09基于9e9319a的未提交会话候选，独立审计复现“深窗口50..1、真实存档40@17、仅删50再返回”的缺口；修复后正式组件保留该原序列，以及删真实锚40的null反控。jsdom核对同一Timeline消费者与邻域ID读取，不证明真实WebView2几何；原失败、门禁与复审状态由当轮验收入口保存。
