# Agent Note: 封面补全按缺图需求遍历并限定成本

Status: implemented

## Problem

仅补direct来源漏掉服务端正文无图的文章；“服务端已有正文第一图”只覆盖有图子集。旧说法担心下次同步清空本地补图，但刷新是新非空值优先、回填是旧值优先，远端NULL不会清掉本地图。固定前80候选加失败缓存还会饿死后续条目，DB错误压为空则把故障记成已处理。

## Decision

候选统一为无封面且有URL，不按来源排除。每轮请求最多20、并发2、单请求30秒、扫描最多4页/80候选，间隔60秒。scan_offset在进程内跨轮推进，按扫描行数而非成功数计，读空页回绕；不写数据库。

CoverAttemptCache默认1024，成功与失败共用容量，按插入序逐出。原先把成功也只记为“已尝试”会让扫描窗外、后来新增的同URL文章永久缺图；2026-11-07改为成功保存可复用图片URL，仅向正常扫描遇到的候选填图，不加全库扫描或HTTP。失败/无图完成后记10分钟TTL，避免临时故障直到重启才有机会；命中失败不会续期，TTL到期或逐出后可再尝试。DB写失败、退出中断不记。缓存命中/同URL重复/批次已满也推进扫描，避免固定失败前缀一直占窗。容量仍是条目数预算，非严格字节内存上限。

ShutdownToken由watch实现并保活接收端，避免所有receiver丢弃后信号发送失效；退出时等待和在途HTTP都能取消，round返回前等待子任务结束。候选读失败warn并停止该轮，写失败error且保留下轮机会；HTTP无图/失败是已知结果，与本地存储失败分开处理。

本轮部分取代旧“仅direct清空”政策：全来源本机封面都可按文章id与当前图片URL精确CAS失效，覆盖服务端条目的本地补图；不推远端、不改文章身份，后续远端pull仍可提供权威新图，旧404不能清后来不同URL。AppState唯一持有封面结果缓存，scheduler与上报命令复用；清空图片与撤销同URL成功缓存使用db→cache同序短锁，转成短期失败屏障，避免成功缓存立即填回坏图或远端反复提供坏图导致源站逐轮重抓。请求期间不持DB锁；在途结果落地再次复核文章URL/空图与失败屏障。

候选质量只按已知证据保守过滤：正文图片的avatar/emoji等角色、显式小尺寸/像素，OG图片关联宽高、feed媒体的锁定width/height；缺尺寸的正常新闻图保留，不发图片尺寸探测网络。文章页收体与全文同用16MiB CL预检/累计预算，重定向以最终响应URL解析图片。

## Alternatives considered

继续只补direct保留了无正文图服务端文章的缺口；另加“服务端且正文无图”分支与无封面判据重复。持久失败缓存会延长临时站点故障的影响，还需清理格式，因此只用进程缓存。

新增tokio-util取消依赖当时没有必要，watch语义已足够但必须处理接收端生命周期。DB失败也记缓存会隐藏恢复机会，不能因为失败结果同为“没图”就合并处理。

继续把成功记成负结果会漏掉后继同URL候选；对全库同URL立即广播又会扩大扫描成本，选择正常窗口内复用有界成功值。为分辨远端/本地图新增provenance列需要闭合全部同步写入，本轮没有这个必要：按精确当前URL本机失效即可，不迁移schema。只在重启/容量逐出才重试延长临时故障，失败TTL替代该部分取舍，仍沿原请求/扫描预算。

## Consequences

扩面会直接请求服务端收录文章的第三方页面，增加客户端IP暴露站点；当前没有专用关闭开关。这是个人客户端的已知取舍，不改写为“代理天然隐私保护”。首次历史存量总请求量/耗时没有因单轮预算而自动得到证明。

固定候选集可轮转，持续插入/删除下仍须观察实际机会；不从scan_offset存在推出所有动态集合严格公平。尺寸/角色是启发式，有未知尺寸/无角色信息的头像仍可能误选；成功缓存可逐出、失败TTL有等待期，不能声称所有坏图都会立即恢复。源站请求隐私边界与缺少开关保持原取舍，见[已接受取舍](../../../../docs/roadmap.md#accepted-tradeoffs)。
