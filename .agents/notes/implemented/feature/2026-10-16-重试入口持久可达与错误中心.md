# Agent Note: 本进程错误中心与按失败上下文重试

Status: implemented

## Problem

失败 toast 最多显示四条，带动作项也会自动退场；后台连续失败时，用户尚未看见的重试入口可能已经消失。把回调放到另一个无限数组只能转移内存问题。错误入口跨文章、列表和设置草稿存活后，另一个风险是重试时读取当前对象，把 A 的失败错误地施加给 B。

## Decision

带动作的 showToast 同时登记本进程错误中心，普通提示仍只有 toast。中心上限20条，按显式操作/实体/上下文 key 合并，更新文案、动作和次数；没有 key 才回落为文案去重。显式 key 与无 key 是两个去重域。24小时 TTL 在写入时惰性清理，条目不写磁盘，也不承诺过期瞬间自动消失。

入口位于侧栏底部，面板复用 ModalOverlay，提供重试、忽略和清空。toast 与中心通过同一 retryError 派发：先消费旧条目，失败动作自行以同 key 重新登记；同步抛错恢复快照。旧 toast 尚在时仍可从其动作回落派发。这个协议配合现有自行处理成败的回调，不要求所有业务动作改成返回统一结果。

调用点负责捕获目标，中心不猜实体：

- 批量标读保存范围和目标 id。每次 attempt 从当前列表或目标缓存重新取读态、feed id 与字段版本；成功及回滚逐 id 尊重后来的用户写入。后端返回 affected=0 也仍需收敛缓存和计数，因它可能是“上次已提交、响应丢失”。
- 加载更多保存查询、首页代际和游标。任一变化后重试终止并给普通提示；仍匹配但已有请求时重新登记同一入口，不发重复 IPC。请求 token 决定谁有权释放加载锁。
- 正文、全文和 AI 重试保存文章 id；离开当前列表不等于文章已删除。detached 重试允许按 id 查后端，真正缺行再由结果处理。当前 Reader 展示态只由仍拥有视图的请求修改。全局 translating 布尔已由[终态复位决定](../bug-fix/2026-11-01-translating终态复位与全局单布尔.md)改为无条件复位；per-id 状态才是在途真值，不能再承诺 A 的迟到完成保留 B 的全局布尔。
- 保存同步配置捕获完整草稿及 opaque revision；key 不含密码或密码哈希。save 和保存后同步分阶段，保存成功后重试只重跑同步。较新草稿提交后旧动作失效；全局忙锁覆盖请求结算且跨组件重挂，表单 revision 仅控制 UI 写权，不能提前释放锁。同一激活 token 成功消费后可清除，用户新编辑的凭据和不同 token 保留。

## Alternatives considered

提高 toast 容量或改成 sticky 仍会挤走入口，且让通知长期遮挡正文。无限保存闭包没有内存边界。按文案合并无法区分同样网络错误的多个源；让 store 从文案猜实体也不可靠，因此显式 key 由调用点提供。

等待异步动作结果再删除条目需要改造现有自行报错的回调契约；先消费、失败重报更贴合当前实现。右下角悬浮入口会与播放器和 toast 竞争空间，因此使用侧栏固定区。重试时读取当前 id/view/表单虽更省快照，却会改变失败操作的目标，不能作为默认回落。

## Consequences

入口在本进程内比 toast 更持久，内存和可追溯条目仍有上限；超出20条的旧项、重启前的动作不保留。TTL 是惰性清理，不能当定时任务。没有动作的提示不进中心，中心也不是完整日志。

按目标重试是调用点契约，中心不能自动保证。2026-11-06 播放器反例已证明旧 A 的“重试播放”可作用于当前 B；这条尚未修复，见[界面与媒体路线](../../../../docs/roadmap.md#interface-and-media)。同一实体的所有操作也未统一建立防双击锁。

## Validation

前端错误中心回归覆盖去重、上限、TTL、消费与重报；批量标读、续页和 Reader/AI 回归覆盖各自快照，组件回归覆盖设置草稿及跨重挂忙锁。这些断言证明具体场景，不能从“错误中心存在”推导每个新动作都捕获了正确对象。
