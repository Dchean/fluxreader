# Agent Note: 前端交互正确性与感知体验（审计卡2）

Status: implemented

## Problem

第五轮细粒度审计在交互正确性与感知体验上点名了三处**行为/契约**问题（其余为纯对齐项，不立此 Note）：

**IME 合成中的 Escape 误关浮层。** App 全局 keydown 的 Escape 分支只判 `e.key === 'Escape'`。输入法合成中的 Escape（语义是「取消选词」）在部分实现里同样以 `key='Escape'` 上送（isComposing=true，或 Chromium/WebView2 合成期 keyCode=229）——用户在中文输入法里打字时取消选词，搜索面板/设置页等浮层跟着被关掉。该分支位于 `inInput` 判断**之前**，焦点守卫帮不上忙。

**Reader 正文三态缺失。** Reader 把 `renderHtml` 直传 ReaderProse，`body.state`（loading/failed/missing）无分支：正文水合在途时整块空白、失败时没有任何重试入口、缺行时静默空白——而列表卡片（SocialCard，t114-x1b）已有同构三态，同一份数据两处呈现不一致。

**启动装载串行 + 静默早退永挂 splash。** `bootstrapSettings().then(bootstrapFromBackend)` 串行链的首屏等待是两者之和；且 `reloadFromBackend` 有两处静默 `return`（查询代际被更新查询抢占、后端空快照拒落）不关闭 `dataLoading`——启动首屏被 feeds-updated 等事件触发的更新查询抢占时，bootstrap 的 await 正常返回而无人关骨架，理论上 splash 永挂。

## Decision

**IME 守卫收在 Escape 分支内，口径与命令面板 Enter 一致。** `if (e.isComposing || e.keyCode === 229) return;` 置于浮层关闭链之前。App 的监听是原生事件（非 React 合成），所以是 `e.isComposing` 而非 `e.nativeEvent.isComposing`（Overlays.tsx 的命令面板 Enter 是合成事件，才有 nativeEvent 前缀）。两种 IME 形态都拦截，因为误关的真实形态就是「key 命中 Escape 但事件属合成」。不全局拦截合成期按键：合成期只有 Escape 在本分支有副作用，其它键（S/M/J/K）会被 inInput/浮层让路逻辑挡住，扩大拦截面只会增加回归面。

**Reader 三态在调用点分支，不进 ReaderProse。** `!isShowingTranslatedProse` 且 state ∈ {loading, failed, missing, unrequested} 时渲染与 SocialCard 同构的三态：failed → `.hydrate-retry` + `retryHydration(id)`（真实重入队）；missing → `body.message`；loading/未请求 → `.hydrate-placeholder`「加载正文…」。译文视图不走分支——切译文的前提是正文已水合，且译文为空时由 ReaderProse 的既有契约呈现（源码/渲染/流式三路径不受影响）。ReaderProse 保持纯渲染组件，不感知水合状态机，契约面不扩大。ready/cleared 且正文为空（AI 清理保留正文、空正文终态）不在本分支——那是「暂无正文」语义，与「加载中/失败/不存在」不同，保持原空白行为，避免把两套语义混进一个占位。**边界说明（审计返工 P3-3b）：阅读工具栏的「翻译」按钮是无条件渲染的；body 处于 missing/loading 时用户手动切入译文视图，ReaderProse 按空译文渲染——这是改动前既有的行为路径（三态分支只守基础正文视图），非本轮保证范围，如需收敛另立条目。**

**启动装载改为「首读并行、落库有序」。** 写集核实结论：`bootstrapSettings` 只写 `settings` 对象与 `activeViewFilter`/`timelineFilter`；`reloadFromBackend` 发起时读的范围快照（activeFeedFilter/activeContentLayout/timelineSort）都不在其写集内，**首读无依赖**。但**落库有顺序依赖**，颠倒的三个后果：① 数据快照落地时读 `settings.smartDedup` 决定 scopeCounts 快照——设置未接受则快照缺失，计数降级为按源求和且当次会话不自愈；② reload 完成时读 `activeViewFilter` 决定筛选视图补拉——设置未接受则恢复的 startupView 不触发首拉，筛选视图只显示 'all' 首批的客户端过滤子集；③ 设置接受晚于首帧则主题闪默认值（这正是原串行链注释声明的保护）。实现：`bootstrapFromBackend` 在发出数据查询的同一时刻并行启动 `bootstrapSettings`（设置读取与 list_folders/list_feeds/list_articles/counts_snapshot 并行在途），并把自己的完成 promise 记入模块级一次性落库门 `pendingStartupLandGate`；`reloadFromBackend` 发起时同步捕获（清空），落地计算前等待该门，等待后**复核查询代际**（等待期间可能有更新查询发起，拒落语义与代际早退一致）。splash 门控不变：仍由数据装载落地关 `dataLoading`，设置恢复不参与门控。并行收益 = 首屏等待从「设置+数据」串行和缩为两者较慢者。

**静默早退兜底：只关不开。** 两处静默 `return` 各补 `if (get().dataLoading) set({ dataLoading: false })`。语义刻意不对称：

- 代际早退（被抢占）：只关 `dataLoading`，**不写 bootstrapError**——更新的查询正持有落地权，其成败才是本轮最终态（失败已有 toast 可见性）；在此误标 bootstrapError，接手查询成功落地后错误浮层会盖住已落地的数据，除非再给「落地清 bootstrapError」加一条新契约。非启动路径 `dataLoading` 本就 false，兜底写不发生，零影响。
- 空快照拒落（后端契约异常，正常 tauri 流程不可达）：启动窗口（`dataLoading` 仍开）落 `bootstrapError: '后端返回空快照，装载中止'`，亮错误态 + 重试入口——数据没到且无更新查询接手，静默空屏不可诊断；非启动窗口保持旧静默语义（后台刷新拒落不劫持 UI，重试可恢复）。

门只约束「与设置恢复同时发起」的那一次 reload：捕获即清空，期间被事件触发的其它 reload 捕获到 null，不受牵连；若早退发生在门等待之前，门被消费但未被等待——设置接受本就独立完成，无泄漏。

**门放在 bootstrapFromBackend 内部而不是 App.tsx 持有，是测试加载器约束。** 组件测试链里 `src/store.ts` 被别名到 `dist-test/store.js`（tsc 产物），而 `src/App.tsx` 以源码形态被 rolldown 转译加载——若 App 直接 import `src/store/slices/bootstrap` 的导出符号去设门，会形成**第二个模块实例**（门设进源码实例、reload 读的是 dist 实例），门静默失效。这正是 store.ts 头部「组件一律经本模块消费协调协议」注释防止的坑；在 types.ts/store.ts 改动超出本卡改写集的前提下，由 `bootstrapFromBackend`（dist 内自洽）发起设置恢复并把门留在同一模块，是唯一在所有运行形态（生产 Vite / dist-test 前端回归 / ui-loader 组件回归）下都单实例的通道。

## Alternatives considered

**IME 守卫放全局（合成期按键一律 return）。** 覆盖面大但无对应缺陷：其它合成期按键本就被既有让路逻辑处理，全局拦截反而把「合成期 Ctrl+K 打开搜索」这类合理行为也拦掉。放弃。

**IME 只判 isComposing，不判 keyCode 229。** Safari 形态可拦，但 Chromium/WebView2（本项目实际运行时）合成期统一上报 229 的形态拦不住；两形态都已由 jsdom 用例钉住（isComposing / keyCode 229 各一）。放弃单判。

**三态下沉进 ReaderProse（内部按 body.state 分支）。** ReaderProse 的现有契约是「源码/渲染/流式三路径纯渲染」，接收的是已派生的字符串；把水合状态机拖进去会扩大组件契约，且 SocialCard 已有同构分支——对齐调用点是最小改动。放弃下沉。

**Reader 三态含 ready/cleared 空正文的「暂无正文」。** 与审计锚点（loading/failed/missing 三态）不符，且与 AI 清理语义（cleared 保留正文）耦合，混入会把范围翻倍。保持三态，空正文行为不变。

**App.tsx 直接 `Promise.all([bootstrapSettings(), bootstrapFromBackend()])`。** 首读确实并行，但落地无序——三个后果见 Decision；且 App 无法把 settingsTask 移交给 reloadFromBackend（types.ts 的 `bootstrapFromBackend: () => Promise<void>` 不可改，跨模块门经源码 import 会因测试加载器别名形成双实例）。放弃；改为 bootstrapFromBackend 内部并行 + 同模块一次性门。

**门放在查询发起前（快照读取前 await settings）。** 落库有序达成，但数据查询被推迟到设置读取完成之后，首屏等待退化为串行和——与不改等价。放弃；门必须在落地前等待（读不等待、写有序）。

**两处早退分支无条件落 bootstrapError。** 空快照分支合理；代际分支会把「接手查询成功落地」误标成错误浮层（landing 不清 bootstrapError），为救它又得加落地清错契约——一个兜底引出两个新契约。放弃，改为按 `dataLoading` 门控的只关不开。

**bootstrapFromBackend 的 await 之后再兜底关 dataLoading。** 与 494/495 处兜底重复：两处兜底已覆盖全部静默返回路径（早退即关、正常返回必经落地关、抛出走 bootstrapFromBackend 既有 catch），再加一层只是死代码。放弃。

## 后果与边界

**IME。** 合成中的 Escape 完全交还输入法语义（取消选词，浮层不动）——用户想关浮层需先让合成结束（上屏或取消）再按 Esc。这是语义修正，不是可用性损失；已由组件用例钉住 isComposing 与 keyCode 229 两形态及正常 Esc 负控制。

**Reader 三态。** 打开文章的 `unrequested` 短暂窗口（selectArticle 详情 IPC 在途）由「空白」变为「加载正文…」占位——与卡片水合呈现对齐；mock 模式（state 恒 ready）与译文视图不受影响。failed/missing 的重试入口走既有 `retryHydration`（幂等删档重入队），无新增 IPC 形态。

**启动装载。** 落库门使 bootstrap 路径的数据落地依赖设置接受完成：设置读取挂死会推迟落地——与原串行链的暴露面等价（串行链本来就不开始装载），不是新增风险。`bootstrapFromBackend` 自此会发起设置恢复，`retryBootstrap` 随之重读设置（失败重试场景无用户交互，startupView/主题重应用无感）；重试语义仍由 retryBootstrap 清错误态的既有契约承载。测试侧：dedup-display 的 boot 前置经 `resetAppSettingsWriteStateForTests` 复位，保留其「基线未知」探针起点（生产语义启动后基线已知，两不相扰）。

**静默早退兜底。** 只关不开意味着「首屏被事件查询抢占且接手查询尚在途」的窄窗口内 splash 提前收起、列表短暂为空——可恢复过渡态，严格优于永挂；bootstrapError 仅在空快照的启动窗口落地（错误态 + 重试入口），非启动路径语义逐字不变。
