# Agent Note: 封面代理、失败占位与会话记忆

Status: implemented

## Problem

多个封面位各自处理加载失败，导致破图、空白与虚拟卸载后的重复请求。历史带/不带Referer的图床对照解释了部分直连拒绝，不能据此假定所有图床永久具有同一策略。

## Decision

2026-11-10后继媒体预算改造：以下旧会话缓存策略保留为历史理由。当前候选把字节传输归imageProxy共享资源服务，按图片URL与有效pageUrl、资料库代际去重；Blob只有无人使用才可撤销，常驻播放器按可见生命周期持有，正文和灯箱各自持票，原URL一直是持久身份。后端四个在途槽、25MiB单图与整链30s保证取消及资源释放可收敛，raw IPC返回仍兼容宿主fallback数字数组；具体预算见docs/performance.md。候选运行及原生证据由当轮交付集中维护，不能从本篇implemented状态推导全部已验。

失败政策收窄：断网、取消、容量不足、过大响应、空/非图及原因未知的img解码失败都不清持久封面；仅完整Referer链均明确404/410且当前封面owner仍有效才调用原URL精确CAS。直连onError无法证明HTTP状态。短期失败TTL与1024条上限替代无限期失败Set；幂等上报也有界，数据库CAS保持最后防线。恢复开始暂停新图片和上报并等待已登记上报前沿，成功换图片代际；失败恢复允许旧库重试。普通属性同步不清阅读成员/图片缓存。


文章卡、播客卡、迷你播放条、全屏播放器与灯箱复用CoverImage；代理域名策略集中在imageProxy。需要代理且有IPC时由Rust取字节，否则直连；无URL不创建img、不代理也不上报。

代理传输失败按URL、有效Referer与代际保存在模块内，跨组件挂载显示占位；直链与各消费者的解码失败只留在该消费者，不进入共享失败缓存。非图片响应不能作为HTML注入。失败上报独立按文章id+URL幂等，无有效id/data URL不发；上报失败保留诊断，不向UI伪造成功。ready代理缓存有容量限，逐出后可能重新请求，故“同会话不重复”主要指仍保留的在途/失败记录。

2026-11-10审计反例补足持有边界：普通直链不能占代理lease，局部状态随已有消费者存在，不另建共享direct缓存。解码失败不代表同key的bytes对所有消费者都坏；先让该消费者的真实DOM去掉Blob src，再释放其代理票。React消费者在失败占位提交后的effect释放，正文节点在移除src之后释放；错误占位与显式重试保留原URL。同key重试建立新版本，仍显示旧版本的健康消费者继续保护旧Blob，最后一票释放后才可撤销。

画廊自管自然尺寸与失败视觉，保留共享代理/失败逻辑但不硬套CoverImage。后台补图覆盖所有来源；2026-11-07将旧仅direct失效清空扩为全来源的本机图片URL精确CAS，以接住服务端条目的本地坏补图。上报成功同时撤销相同成功补图缓存并设短期失败屏障，不向远端写，旧URL不能清新图片；详见[封面补全预算](2026-10-16-封面补全覆盖面与预算边界.md)。

## Alternatives considered

后继实际备选：继续data URL可以少改CSP，但保留base64/整篇HTML拷贝且难以统一精确byte/使用寿命；raw IPC+Blob需要明确CSP和释放责任，因此选择leased Blob而非裸URL字符串缓存。磁盘临时文件/asset协议会扩大路径权限和清理边界，没有离线镜像需求，未采用。原先按URL-only共享会让不同Referer页面互相毒化，故不保留这一去重边界。


全代理会增加每张图的IPC与字节复制；全直连又无法替防盗链域设置期望Referer。组件内state会随虚拟卸载丢失，旧方案因此把会话失败记忆放共享模块；后继只为代理传输保留有界共享记忆。未知解码错误不宜污染健康消费者，直链也不在代理预算内，因此这两类失败接受卸载后重新尝试。

画廊强行共用一个尺寸模型需要大量变体，当前保持展示层独立、判据共享。失败占位比持续破图清楚，但不等于能恢复所有坏图。

## Consequences

后继预算只覆盖代理编码bytes及服务持有的lease，普通直链既不占代理entry/lease也不受其饱和阻挡；非代理域、社交/通知HTML直连、favicon、音频、解码/GPU和Tauri临时复制另有成本。256服务lease饱和时只由单一装配回调唤醒现有React/DOM消费者，不另存无界等待者；现有组件/DOM本身不归该256界。失败占位不再保护已离开DOM的Blob，空闲缓存仍可能短时保留bytes，由原有LRU与预算压力回收。仍显示的图片优先保全，资源不足暂缓后续图并提供重试，不能为维持数字撤销在用URL或旁路直连。实际可见图长期无法加载仍是验收失败。正文懒加载要保自然几何，原生CSP/解码和连续滚动不能被fake IPC数据填补。


手工域策略需要维护，图床拒绝原因也可能变化。前端代理传输失败记忆避免冷却期间反复图片请求，代价是站点恢复后不一定立即重试；后端文章页失败TTL和成功补图复用是另一层缓存，不混称同一策略。first_image本轮按显式尺寸/角色保守剔除小图/avatar/emoji，无尺寸正常新闻图保留，但这不是完整视觉质量识别，未知尺寸/无标签的头像仍可能入选。

请求上限与图片解码、并发总内存各是不同边界；代理收体25MiB规则见[图片收体决定](../bug-fix/2026-11-02-封面图流式收体闭合旁路.md)。

## Validation

历史实现曾用coverRoute/coverView/getCoverState回归核对空URL、代理失败、非图片和上报幂等；这些旧helper已由后继资源服务取代，历史图床对照也只支持当时端点样本。

当前入口为`tools/frontend-tests/image-resources.mjs`的路由、原URL/pageUrl、raw/fallback字节及SSR契约，以及`tools/component-tests/image-resources.test.mjs`的生产组件挂载、取消/预算/失败退化与重试。后者包含普通直链不占代理额度、真实代理256票饱和后的第257个自动恢复、五张25MiB解码失败转占位后归还资源、健康共享消费者与同key新旧版本保护等反例；画廊行为另由现有`gallery-media.test.mjs`覆盖。这些事件与编码bytes断言不替代真实图床、WebView解码及占位几何，请求日志和真实可见结果仍需各自验证；当前批次的通过状态与未验证项由当轮交付记录。
