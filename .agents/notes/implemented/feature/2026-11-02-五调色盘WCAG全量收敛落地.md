# Agent Note: 五调色盘的文字层级与对比度取舍

Status: implemented

## Problem

2026-11-01的[历史记录](../../archived/feature/2026-11-01-五调色盘WCAG全量批量收敛.md)当时暂缓批量方案，只实施点名色值；2026-11-02用户另行批准后才执行本篇批量调整。要解决的是浅色语义色过浅、深色tertiary在hover/active底色上不足；只改文字会把tertiary推近甚至超过secondary，消失的层级又损害阅读。

当时探针计算9个文本/语义token、8个表面、10个盘位的720配对，按各配对阈值由271项不足收敛为0。它检查选定token配对，未覆盖所有实际按钮文字；不能用该结果命名为当前界面“WCAG全通过”。

## Decision

保持各盘色相，深色提高tertiary、缩小hover/active提亮幅度；浅色压深tertiary及语义色，同时收窄hover/active压暗幅度，保留secondary层级。选中态继续依赖既有accent ring，不把层级全部交给背景亮度差。

浅色star-color、sync-ok、feed-error和danger在共享light覆盖中设置；各盘accent/accent-light按背景调整。具体值以tokens.css为维护事实，不在本篇复制整张易过时色表。

图标/足够大字号可采用3:1，普通文字仍须4.5:1。深色accent兼作前景与白字按钮背景时，一个值无法同时满足两组方向相反的4.5约束，因此当时只按图形/大字口径验前景，按钮配对明确未覆盖。这是覆盖边界，绝不是允许普通小字降到3:1。2026-11-07 对已复现的选中布局/设置导航局部拆出 `--nav-selected-bg`：仅深色blue/purple/emerald/terracotta压深白字底色；accent前景与浅色盘/zinc继续原值，不全局改色相或重新设计层级。

## Alternatives considered

只调文字会压平tertiary/secondary层级；把浅色hover反向提亮会改变既有设计语言，因此收窄压暗幅度。深色accent一味提亮能改善暗底前景，却降低白字按钮对比，不能靠让探针列变绿替代消费面验收。

星标虽可按图形3:1，当时已批准关键配对4.5的收敛口径，故选择深金而非亮金。导航背景独立token避免为修白字而压低所有accent前景；把所有主题accent统一压暗会改变未受测消费面，故只调整已确认的导航配对。

## Consequences

hover背景变化更轻，浅色blue的次级文字层级差较小，这是现有视觉代价。2026-11-06实际导航12.5px白字在深色blue/purple/emerald/terracotta上的对比分别为4.041、4.248、3.286、3.709，均低于普通文字4.5，原反例保留。局部新底色已落代码，候选还需真实计算样式十盘检查与最小窗口观感复核，不能据静态色值宣布全部界面达标。

验收应区分文字尺寸、字重、前景/背景方向和半透明合成，不能由token名字决定阈值。美观仍需结合真实页面层级与交互观察，数学比值本身不能证明观感优雅。

## Validation

历史本机probe-contrast及tokens-baseline支持当时720配对结论；2026-11-06 UI审计以实际按钮样式取值补出漏项。后续需保留图形与普通文字独立断言，且分别检查五盘深浅主题，不降低阈值来关闭问题。
