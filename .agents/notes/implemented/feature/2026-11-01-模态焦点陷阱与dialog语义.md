# Agent Note: 模态焦点陷阱与 dialog 语义

Status: implemented

## Problem

早期浮层只在开关时移焦，Tab 可以走到遮罩后的控件，部分面板又缺少 dialog 名称。最初暂缓 focus trap 是为了控制与列表 roving、播放器和 Esc 链的交互面；出现实际键盘穿透后，这个取舍的重访条件成立。

## Decision

ModalOverlay、ConfirmDialog、PlayerFullOverlay、Lightbox 共用 useFocusTrap(open, panelRef)。打开时先捕获外部触发焦点，再移入容器或 `data-modal-autofocus` 指定控件。trapModalTab 对面板内 Tab/Shift+Tab 在首尾回绕，无可聚焦项时保留容器焦点；焦点位于 DOM 外的 portal 下拉时交还默认行为。dialog 的 role、aria-modal 和可访问名称位于正确元素，关闭态 ModalOverlay/Lightbox 用 inert 阻止隐藏控件获焦。

ModalOverlay 常驻 DOM 保留退出动画和关闭清理，不通过卸载关闭态面板修焦点。搜索/改名输入使用共享 hook 的初始焦点标记，不再使用 React commit 阶段的 autoFocus；只有面板打开时 hook 才执行聚焦。Edge 的 inert 行为与 jsdom 环境替身不同，不能把 jsdom 的隐藏输入聚焦现象直接当原生用户缺陷。

2026-11-06 的 F5 证明旧 autoFocus 先于 effect 执行，导致 hook 记住将卸载的输入，关闭搜索后落 BODY。2026-11-07 保留共享 hook、把初始聚焦移到触发点捕获之后；同一窗口的打开面板栈用于还焦：触发点仍连接、可见且未 inert 时优先归还；触发点卸载、失效或已在关闭层时，归还最上层仍存活面板。设置内 Ctrl+K 打开搜索再 Esc，因此保留设置内焦点。栈只管理这些 hook 的生命周期，不对整个 app-root 施加 inert。

## Alternatives considered

- 继续不做 trap：在只有开关移焦需求时成本较低；实际 Tab 穿透改变了前提。
- 首尾放隐藏焦点哨兵：可行，但需要各面板插入节点并分别处理无控件、Shift+Tab；集中 keydown 判据较小。
- 打开时给整个 app-root 加 inert：会跨到 App 和播放器的交互所有权，本次选择只限制面板内键盘循环。
- 关闭时卸载整个 ModalOverlay：能消除隐藏子节点，却破坏既定退场与恢复生命周期；改输入 autoFocus 条件更局部。
- 只把 useEffect 改为 useLayoutEffect：子输入在 commit 阶段的 autoFocus 仍先发生，不能恢复真实触发点；采用统一初始焦点标记，让先捕获再移焦成为同一执行路径。

## Consequences

共享 hook 减少了多处焦点算法，但它只拦面板内冒泡的事件，不能阻止所有异步任务抢焦。NF3 的卡片聚焦帧所有权由 Timeline 单独修复并在本轮首批复审通过，不由此栈代替。F5 现已按上述顺序修复；打开、关闭和键盘循环的不同保证仍分别验证。
