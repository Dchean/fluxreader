# Agent Note: 模态焦点陷阱与 dialog 语义

Status: implemented

## Problem

浮层的键盘无障碍有三层缺口同时存在：打开的模态里按 Tab 会**穿透**到被覆盖的三栏内容（焦点游走到看不见的控件）；9 个模态面只有 PlayerFullOverlay 带 `role="dialog"`，读屏不知道弹窗开了、也没有名字可播报；三处焦点管理实现各写各的（ModalOverlay/Lightbox 内联 effect、ConfirmDialog/PlayerFullOverlay 完全没有）。

2026-10-08 键盘导航批次的取舍是「焦点管理只做最小实现、刻意不做 trap」（见[键盘导航、焦点与卡片角色](2026-10-06-键盘导航、焦点与卡片角色.md)）。本篇部分取代该决定：trap 的重访信号（用户在弹窗里 Tab 到看不见的控件）已被审计正式确认为真实缺陷（roadmap §七「模态焦点陷阱缺失」），不再是理论权衡。

## Decision

**契约收口在一个 hook**：`src/components/useFocusTrap.ts` 导出 `useFocusTrap(open, panelRef)` 与纯函数 `trapModalTab`，四处共用同一实现——ModalOverlay（`.modal-card`）、ConfirmDialog（`.confirm-dialog`）、PlayerFullOverlay（`.player-full-card`）、Lightbox（遮罩根）。

- **打开**：焦点移入面板容器（`tabIndex=-1`）；面板内已有焦点（子组件 autoFocus，如搜索框、改名输入框）则不抢占。**关闭/卸载**：焦点还原到打开时的触发元素。
- **Tab 循环**：正向 Tab 在最后一个可聚焦元素 → 回到第一个；Shift+Tab 在第一个（或面板容器）→ 回到最后一个；面板内无可聚焦元素（灯箱）→ 焦点钉回容器，不逃逸；焦点在面板 DOM 之外（FluxDropdown 经 createPortal 的菜单，React 树内、DOM 树外）→ 不拦截，交还默认行为。回绕拦截必须 `preventDefault`。
- **dialog 语义（9 面）**：ModalOverlay 容器统一 `role="dialog"` + `aria-modal="true"` + `aria-label`（新增必传 prop），8 个面分别传名——搜索与命令面板 / 新建订阅分类 / 添加订阅源 / 编辑订阅源 / 重命名分类 / 关闭 FluxReader / 设置 / 错误中心；Lightbox（`图片预览`）、PlayerFullOverlay（`全屏播放器`）、ConfirmDialog（`aria-label={title}`）直接补齐。
- **保留的事实**：关闭态仍靠 `inert`（ModalOverlay/Lightbox 无条件渲染 children）；ConfirmDialog/ContextMenu 条件渲染、无需 inert；Esc 关闭顺序与浮层让路清单不变（同上篇 Note）。

反向注释：`src/components/useFocusTrap.ts` 头注。

## Alternatives considered

### Why not 继续维持「不做 trap」（2026-10-08 的取舍）？

当时的理由是 trap 与 roving/播放器/Esc 链的交互成本不成比例，而真实痛点只是「关闭后焦点丢失」。本轮审计把「Tab 穿透到背景」定为正式缺陷并排进本卡，痛点已从「理论」升级为「确认缺陷」——重访条件成立，取舍翻转。升级为共享 hook 后，新增的交互面只有 trap 自身的纯函数（`trapModalTab`），与 roving（列表卡片层）、Esc 链（App keydown 层）不在同一层，未发生当年担心的耦合。

### Why not focus-sentinel（首尾放隐形哨兵元素）而不是 keydown 拦截？

哨兵方案靠 DOM 顺序把 Tab 弹回来，不需要 keydown 监听；但哨兵要插进每张浮层的 JSX、且对「面板内无 focusable」（灯箱）与 Shift+Tab 边界要多写一套逻辑，四处面板的 JSX 都要动。keydown 拦截集中在 hook 里，面板只多挂一个 `onKeyDown`，纯函数可直接单测/组件测（`defaultPrevented` 断言）。

### Why not 用 inert 拦背景（打开时给 app-root 加 inert）？

改 app-root 的 inert 要经过 App 层的 state 或直接 DOM 操作，会与「浮层让路清单」「Escape 链」产生新的跨层耦合；且 PlayerFullOverlay 打开时背景是播放器本体，语义上不是「全部不可用」。keydown 拦截只作用于面板内冒泡的 Tab，影响面最小。

## Consequences

**收益**：打开的模态里 Tab 不再穿透；读屏能播报 9 个面的角色与名字；四处焦点管理一个实现，新浮层继承契约只需 `useFocusTrap` + `role` 三件套。

**代价与已知边界**：portal 下拉打开时 Tab 的焦点去向交还浏览器默认行为（菜单项本身不可 Tab，实际影响为零）；jsdom 无焦点遍历，「浏览器默认 Tab 会走到背景」这一半只能由源码形态断言（ui-contracts w4-3/w4-7）+ 真实浏览器行为佐证，组件回归锁的是 trap 自身的拦截与回绕（`tools/component-tests/modal-focus.test.mjs`）。旧篇 Note 的 Consequences 中「没有 focus trap」一条已按本篇改写。
