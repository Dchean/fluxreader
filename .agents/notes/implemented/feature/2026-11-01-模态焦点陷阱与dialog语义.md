# Agent Note: 模态焦点陷阱与 dialog 语义

Status: implemented

## Problem

早期浮层只在开关时移焦，Tab 可以走到遮罩后的控件，部分面板又缺少 dialog 名称。最初暂缓 focus trap 是为了控制与列表 roving、播放器和 Esc 链的交互面；出现实际键盘穿透后，这个取舍的重访条件成立。

## Decision

ModalOverlay、ConfirmDialog、PlayerFullOverlay、Lightbox 共用 useFocusTrap(open, panelRef)。打开时把焦点移入容器；子组件已经自动聚焦时不抢占。trapModalTab 对面板内 Tab/Shift+Tab 在首尾回绕，无可聚焦项时保留容器焦点；焦点位于 DOM 外的 portal 下拉时交还默认行为。dialog 的 role、aria-modal 和可访问名称位于正确元素，关闭态 ModalOverlay/Lightbox 用 inert 阻止隐藏控件获焦。

ModalOverlay 常驻 DOM 保留退出动画和关闭清理，不通过卸载关闭态面板修 autoFocus。搜索/改名输入只在打开状态启用 autoFocus；Edge 的 inert 行为与 jsdom 环境替身不同，不能把 jsdom 的隐藏输入聚焦现象直接当原生用户缺陷。

焦点恢复的目标仍是进入浮层前的触发元素，但现有 useEffect 捕获时机并未在所有路径实现该目标。自动聚焦发生在 effect 前时，它会记住面板内输入而非外部触发器；关闭搜索后焦点落 BODY 已被实际复现。不能继续把共享 hook 的存在当作完整恢复保证。

## Alternatives considered

- 继续不做 trap：在只有开关移焦需求时成本较低；实际 Tab 穿透改变了前提。
- 首尾放隐藏焦点哨兵：可行，但需要各面板插入节点并分别处理无控件、Shift+Tab；集中 keydown 判据较小。
- 打开时给整个 app-root 加 inert：会跨到 App 和播放器的交互所有权，本次选择只限制面板内键盘循环。
- 关闭时卸载整个 ModalOverlay：能消除隐藏子节点，却破坏既定退场与恢复生命周期；改输入 autoFocus 条件更局部。

## Consequences

共享 hook 减少了多处焦点算法，但它只拦面板内冒泡的事件，不能阻止所有异步任务抢焦。2026-11-06 的 F5 已证实搜索关闭恢复失败；NF3 还证实旧卡片聚焦帧可抢走菜单焦点。两者仍待修，见 [界面与媒体缺口](../../../../docs/roadmap.md#interface-and-media)。

组件回归覆盖 trap 的边界、默认行为阻止和角色名称；真实浏览器负责 Tab、autoFocus、inert 与遮罩可见性。尚未实际运行读屏软件，不能把 AX 名称证据写成已听到正确播报。
