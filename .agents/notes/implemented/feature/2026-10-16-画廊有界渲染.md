# Agent Note: 画廊有界渲染

Status: implemented

## Problem

画廊布局（image）是五种布局里唯一不做虚拟化的一个：`items.map` 把全部条目渲染进 `.gallery-masonry-grid`（CSS 多列 + `break-inside: avoid`），代码注释自述「图片数量通常较少，保持全量渲染」。规模证据缺失：`docs/performance.md` 的历史实机数字只覆盖文本布局，不能外推到图片布局（20k/50k 篇场景下画廊的条目数没有上限）。父卡 OPT-017 要求「有可验证窗口上限的瀑布流虚拟化（现有 tanstack-virtual 或分行模型），保持图片比例、焦点、键盘/灯箱/返回位置与加载更多」。

约束来自两侧：**不能用现有的行虚拟化直接套**——CSS 多列由浏览器在排版时对全部内容分列，只渲染窗口子集会被重新分列（窗口错位）；**也不能改成等高行**——画廊的观感建立在卡片自然高度（图片比例）之上，裁切或等高会破坏它。

另有一组行为要保持：roving tabindex 键盘焦点（`tabbableIndex`/`moveCardFocus`）、灯箱打开与关闭返回位置、顶条锚相关回位/归还的**回落口径**（TASK-111/115 对画廊本来就一律回落：画廊不参与）、触底加载更多、空态/已到底文案、其余四布局不回归。

不同自然比例的 HTTP 图片延迟解码还暴露了独立的测量锚缺口：默认虚拟化补偿把视口上方所有列的高度差累加到同一个 scrollTop，而某张可见卡片只受本列前驱影响；浏览器原生滚动锚又可能叠加补偿。真实 Edge 探针中，指定可见卡片 `image-013` 在第一波图片加载时 top 从 211px 变为 −674px，不能把固定高度 jsdom 或已完成的 data URI 布局证据外推为异步锚稳定。

## Decision

**列模型（lanes）+ 垂直虚拟化，复用 `@tanstack/react-virtual` 的 lanes 能力**（安装版本 3.14.10 原生支持：每列贪心最短分配 + item 级测量 + 列感知的可见范围）：

- 列数按与旧 CSS 媒体查询**同断点**解析（≤800 → 2、≤1200 → 3、否则 4；`matchMedia` 监听跨断点重建），列宽/列距公式 `(W − (n−1)×14px) / n` 与旧 `column-count/column-gap` 逐字等价，观感（列宽、间距、图片自然比例、错落）保持；
- 条目在网格内绝对定位（`.gallery-virtual-item`），位置 = `lanes` 的 `start`（纵向虚拟偏移）+ lane 的 calc 左缘；网格容器高度 = 虚拟化总高（估算/测量），不再是全量卡片高度之和；
- 窗口上界是**通用式 + 参考口径**（`GalleryLayout.ts` 单点）：渲染集 = 每列可见条数 × 列数 + 两端 overscan，**通用式** `lanes × (⌈视口高/卡片高度⌉ + 3) + 2×overscan`（`galleryMountBound()` 实现，任何视口高/卡高都成立、条目总数不出现）；**参考口径** = 参考视口（`GALLERY_REF_VIEWPORT_HEIGHT = 768`）× 卡片高度 ≥ `GALLERY_CARD_MIN_HEIGHT = 150` 前提下取 `galleryMountBound(768,150) = 44`、断言口径 `GALLERY_MOUNT_BOUND_REF = 48`。48 是**带前提的参考口径**：模型层不强制卡高下界（lazy 未加载/极扁图片可 <150px → 窗口按通用式变宽，方向性由域回归真值表钉住），实机矮卡分布未取数——估算只服务未挂载条目的定位，挂载后按 `offsetHeight` 测量修正，误差由 overscan 与余量承担；
- **roving 焦点窗口兜底**：焦点卡不在窗口内（鼠标滚到别处后按 Tab）时，`tabbableIndex` 兜底到窗口首卡（`galleryTabbableIndex` 纯函数单点）——保证任何滚动位置下都恰有一张卡可 Tab 进入列表；
- **测量补偿固定当前可见卡片**：图片测量首次发生时选择视口内顶边可见、位置最靠上的卡片，保存其身份/下标/列；只补偿该锚之前且属于同一列的测量差，其他列不会改变该锚的纵坐标。用户再次滚动后按新位置选择锚，筛选/列数/宽度变化清掉旧锚。它只处理当次异步测量，不接管跨布局返回锚；
- **主轴坐标与总高只有一个写入方**：画廊启用 react-virtual 的 `directDomUpdates`、保持 `useFlushSync: false`，网格挂 `containerRef`，React 只设置列宽与左缘。测量回调同时更新尚未卸载的已挂载节点，避免新窗口已算好但旧窗口 DOM 还保留一帧旧 transform。画廊滚动容器设置 `overflow-anchor: none`，由虚拟化独占测量补偿，避免浏览器原生锚再加一次；图片仍使用 `aspect-ratio: auto 4 / 3`，解码后按自然比例，未裁切；
- 三处回位/归还（TASK-111 刷新保位 / TASK-115 切换返回 / 阅读器关闭焦点归还）**维持对画廊的回落口径不变**（本卡行为保持；锚语义扩展留待后续任务）；
- J/K 门控在本篇落地时维持「排除 image」；**2026-11-04 已由[全布局键盘焦点与响应式阅读列](../architecture/2026-11-04-全布局键盘焦点与响应式阅读列.md)取代**：画廊接入 J/K，按线性条目下标选中并聚焦，取消收藏后的焦点迁移同其余布局。

证据（先红后绿、变异判别、真实挂载）：`tools/component-tests/gallery-virtual.test.mjs`（5000 项挂载上界与 200 vs 5000 对照、跨窗口焦点、灯箱开合返回、追加批次渲染与索引映射、列分配/列宽/同列不重叠）、`tools/frontend-tests/gallery-window.mjs`（列数/估算/放置/兜底真值表 + 灯箱与分页状态迁移 + 源级接线）、`docs/performance.md`「画廊布局有界渲染」节（常量推导、测量方法与未测边界）。

## Consequences

- **收益**：同时挂载的卡片数从 O(条目总数) 降为 O(视口/卡片高 × 列数)，5000 项下实测 ≤ 32（参考视口）；窗口有常量口径可审计，不再以「图片通常较少」免除上限。
- **已知差异**：列分配由 CSS 的「列优先平衡」变为「贪心最短列（行优先起步）」——同一组条目在两套模型下的列归属不同（列宽/列距/自然比例/错落观感一致）。有界渲染无法对未挂载内容做浏览器列平衡，这是裁决接受的取舍。
- **代价与上限**：48 是「参考视口 × 卡片高度 ≥150px」前提下的参考口径（模型层不强制卡高下界——lazy 未加载/极扁图片的实测高可更小 → 窗口按通用式变宽）；通用式本身才是无前提保证，由组件回归在每个滚动点用夹具实测视口高与 `min(估算, 实测最小卡高)` 现算断言。真实 Edge/CDP 已覆盖 1440×900 与 980×640 两档、HTTP 延迟分波释放、至少两种自然比例、两次滚动位置与同一可见 anchor 的逐帧数据；这不等同于真实 WebView2、全部图片高度分布或帧率基线。列数依赖 `matchMedia` 断点与 CSS 不再有第二份（旧 `column-count` 已删除），改断点必须改 `GalleryLayout.ts`。
- 画廊不参与顶条锚与焦点归还的现状保留为显式口径（有源级断言钉住三处 `image` 提前回落），不是遗漏。

同时只能保持一个可见锚：其他列的卡片仍按各自自然高度移动，不承诺所有列的所有可见卡片都固定。主轴由库直接写入，后续 JSX 不能重新声明 transform/网格高度；跨列误补偿、卸载前一帧坐标与原生锚叠加必须一起防止回归。

## Testing

`tools/ui-layout-regression.mjs` 的画廊用本机 HTTP 服务器保留真实未完成请求，分两波返回 600px 宽、320/450/540/800/1100/1400px 高的 SVG。每波前在实际滚动位置指定 anchor，保存逐帧 `top`、scrollTop、挂载卡片与图片自然尺寸，验证最大漂移 ≤3px、自然比例、横向无溢出、顶部与底部页脚。

当前版先红证据为 `tmp/convergence-c/gallery-before/metrics.json`（1440×900，同一锚最大漂移 885px，exit 1）。修正后两档分波最大漂移为 0；最终同命令两视口证据在 `tmp/convergence-c/gallery-final2/metrics.json`，进程 exit 0。jsdom 原画廊挂载回归仍覆盖窗口上界、焦点、灯箱、追加与列几何，定向 5/5 通过（`tmp/convergence-c-gallery-components.log`）；它不承担图片解码证据。

## Alternatives considered

### Why not 继续使用默认测量补偿或只修 flex-shrink？

默认补偿不增加应用代码，flex-shrink 修复也确实保护了虚拟容器总高；但默认算法把不同列的高度差相加，对指定可见锚产生了真实 885px 漂移。沿用现有 lanes 与自然图片，只限定补偿谓词、主轴写入和原生锚参与，范围小于重写列模型。

### Why not 保留 CSS 多列、只渲染窗口子集？

CSS 多列在排版时对**容器内的全部内容**做列平衡；只放窗口子集进去，浏览器会把窗口内容重新分列——窗口滑动时列归属/列高全部错位，与「保持列观感」直接冲突。要虚拟化就必须自己拥有列模型（本卡选 lanes）。

### Why not 行模型（等高行 / justified 行）？

两种都改变观感：等高行会在卡片间留空或需要裁切图片；justified 行必须裁切（object-fit/crop）才能对齐行高——「图片比例保持」的要求排除了它们。

### Why not 自研列虚拟化（自己维护列分配 + 偏移 + 测量）？

自研需要重造分配、测量缓存、可见范围、scrollToIndex 与滚动锚定五件事，而安装的 react-virtual 3.14.10 已原生支持 lanes（贪心最短列 + 测量 + 列感知范围 + scrollToIndex），本卡直接复用，降低回归面；本地只限定测量补偿和主轴坐标写入（见 Decision）。

### Why not 让画廊接入顶条锚/焦点归还（既然已虚拟化）？

本卡交付要求「行为保持」，三项机制对画廊的现状是回落。接入会改变既有语义（切回画廊的位置、关闭阅读器后的焦点），需要单独的取舍与回归；列为后续任务（timelineAnchor.ts 规则表已按本卡口径更新）。

### Why not 把窗口上界压成更小的固定常量（如 24）？

硬性上限必须小于视口可见量才能生效——大窗口（4K 全屏）下可见卡片数本身就超过小常量，截断会留下空白洞。上界只能随视口表达（公式 + 参考视口常量），组件回归在多个滚动偏移上扫描验证「不随条目总数增长」。
