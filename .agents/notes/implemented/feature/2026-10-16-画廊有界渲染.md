# Agent Note: 画廊逐列窗口与测量补偿顺序

Status: implemented

## Problem

原画廊对全部条目做 CSS 多列布局，缺少规模上限。只渲染其中一个窗口又会令浏览器重新平衡列，无法保留原位置；改等高卡会牺牲自然图片比例。后续异步图片测量还暴露了多列补偿叠加与单帧锚漂移。

条目已有独立的首图、图片数和媒体修订后，列表仍只能放大一张图。完整集合若随每张卡片预取，会让窗口外图片详情也占用请求与状态；放进正文缓存又会混淆媒体修订与正文修订。

## Decision

沿用安装版 @tanstack/react-virtual 3.14.10 的 lanes，按最短列分配条目；2/3/4列断点、14px间距由 GalleryLayout.ts 管理。网格项绝对定位，宽度与左缘由 React 设置，纵向位置和总高交给虚拟化。自然图片比例保留，加载前只用比例占位。

画廊继续使用 directDomUpdates、containerRef 和 useFlushSync:false；overflow-anchor:none 排除浏览器第二次补偿。测量时选择一个可见锚，只补偿它同列前驱的高度变化，滚动或上下文变化后重新选锚。

galleryMountBound 曾按“每列可见量 + overscan”估算窗口，参考视口/卡高得到48的口径。2026-11-06 反例推翻了默认连续下标提取器下的普遍保证：列间高度偏差会令该区间夹入大量屏外卡，代入最小卡高也不能补救。2026-11-07 的候选修正按虚拟器已计算的 lane/start/end 分列，二分求各列与视口相交项，再加分摊的 overscan 预算，最后合并为有序下标；不自建列分配或尺寸真值，也不硬截断可见卡。挂载检查式仅在对应测量最小高度口径成立，不能从均匀夹具外推自然图片所有分布。

逐列集合与默认 global range 是两种形态：同一组 global start/end 下，某一列可见集合仍会变化。业务比较实际下标集合和可见 Tab 候选，并在尺寸通知及滚动时请求 React 提交；只换 rangeExtractor 而沿用适配器的端点判据会漏渲染。Tab 回落先过滤几何可见项，完整可见卡优先，超高卡才退到相交项；屏外 overscan 不得充当“当前能看见”。

G2 的候选修正仅在本画廊 scrollToFn 截留非零 adjustments；core 推进逻辑 offset 后，onChange 先写容器总高和所有仍挂载节点的当前 start，再发布同次 DOM scrollTop 补偿。普通滚动/无补偿的 scrollToIndex 仍直通 elementScroll。新节点 ref 在注册/同步测量后立即取得当前 start，layout effect 再对齐；不让新节点等到后一次通知才获得主轴位置。此顺序意在关闭“先滚后坐标”窗口，不以最终回归锚位替代过程每帧≤3px。

画廊的 J/K 已由[全布局键盘决定](../architecture/2026-11-04-全布局键盘焦点与响应式阅读列.md)接入，按条目索引导航。跨上下文顶条恢复仍保留画廊回落边界；测量锚只服务当前异步测量，不替代返回位置协议。

多图预览只在点击首图或图片计数时取 `get_article` 的有序 `images`。UI slice 持有唯一当前集合、下标、媒体版本、请求代次与加载/空/失败状态；ReadingSession、正文缓存和卡片测量不持有这份集合。单次详情按请求代次、条目/来源身份、列表媒体快照和媒体修订共同校验；关闭、单图打开或再次打开均使旧请求失效。列表修订变化时隐藏旧图并重取，保留当前 URL（若仍存在），否则把原下标夹到新集合边界。详情版本可先于列表，但不因此不断重取，也不接受低于已展示详情的版本。

`lightboxUrl` 继续作为现有浮层/快捷键的打开信号。首图存在时立即打开；没有首图时先请求，空或失败留在同一卡片供重试，取到真实 URL 后才打开。真正打开沿用 `markEntryOpened` 与 `markReadOnOpen`；非文章分区选中和 J/K 不隐式打开。空详情保持空集合，不能回退封面制造图片。浏览器演示没有详情 IPC，只预览演示首图。

灯箱的前后按钮和左右键首尾循环，Escape/遮罩/关闭按钮关闭。图片计数与卡片触发容器保持稳定 DOM；代理结果以媒体快照归属，图片加载、失败或换源不更换触发点。焦点由共享 `useFocusTrap` 捕获与归还，使用 `preventScroll`。画廊正文图片的严格代理与解码失败可单独重试，不将正文图片误报为坏封面；原 Reader/社交单图 `openLightbox` 继续使用既有 `CoverImage` 路径。

## Alternatives considered

保留 CSS 多列再截取窗口会重新分列；等高/裁切模型改变既有图片比例体验。自研列分配、测量、可见集和 scrollToIndex 的维护面大于复用已装库，所以选 lanes，但库提供 lanes 不等于默认范围提取器已满足本项目的上界。

默认补偿会把其他列的高度差也加到同一个 scrollTop；只修 flex-shrink 不能解决这一问题。限制为同列锚、禁原生锚是已有选择。固定截断到24或48张则可能小于大视口的实际可见量，不能用删可见卡的方式满足数值。仅开启 flushSync 尚不能证明缺口在哪，而且会改变 React 调度；本次选择在已经核实的主轴/scrollToFn 边界调整发布顺序。

多图预览曾考虑复用 `CoverImage` 的失败缓存，但它按 URL 记会话永久失败且用于封面失效上报，不能表达正文图片显式重试。保留其旧单图路径，为画廊图片提供局部可重试呈现，代理域名和字节验证仍共用 imageProxy，不复制白名单。

## Consequences

列分配从 CSS 列优先平衡变成最短列贪心分配，列归属变化是已接受代价。逐列窗口仍消费已安装虚拟器的全量测量缓存，构造分列索引有随数据量变化的 CPU 成本；它收窄的是挂载 DOM，不宣称整个布局算法与条目总数无关。

多图集合只缓存当前灯箱会话，关闭即丢弃，因此反复打开同一条目会重新取详情；这避免长期保留过期集合，也避免新建媒体缓存失效协议。列表更新和晚响应的归属检查不取消已发出的后端读取，但保证它们不能重新打开已关闭会话或覆盖另一条目。全局数据恢复必须调用 `closeLightbox()` 使在途请求代次失效，再替换数据。若未来要跨关闭缓存或独立预加载，需要重访媒体版本与请求所有权。

## Validation

组件 gallery-virtual 与前端 gallery-window 覆盖装配、索引、灯箱、逐列候选集及已设定几何。jsdom 旧夹具允许600张约4万px总高的容器停在8万px，这个浏览器会夹取的不可达状态下没有可见Tab卡；夹具现按实际容器高度夹取后继续断言真实可见，原失败保留，真实DOM须独立复核。Edge ui-layout-regression 增加混合5000条三段深滚、统一/极扁对照与实际Tab，原真实两波图片的过程≤3px断言保持不变。2026-11-07 收口：候选最终真实浏览器门禁已执行——`test:ui-layout` r8 全量 exit0（`tmp/frontend/gallery-ui-r1/final-r1/ui-layout-r8/`），原只读诊断者定向复审通过（`final-r1/audit-row-root/REVIEW.md`）；本行此前的“尚未执行”仅描述当时时点。不得把当前实现状态写成发布验收通过。Edge不等同于真实Tauri WebView2的合成/字体表现。

多图的 `gallery-media.test.mjs` 覆盖真实组件事件、延迟详情与代理响应、修订重排/移除、空态/失败重试及单图兼容。jsdom 图片 load/error 事件用于验证处理链，不能证明网络解码与实际像素布局；新多图行为的运行、浏览器及独立审计状态由本轮交付入口记录，旧画廊几何证据不外推到新增交互。
