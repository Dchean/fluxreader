# Agent Note: 本地保存、远端确认与同步活动分开表达

Status: implemented

## Problem

本地写入成功、队列等待、远端确认和整轮刷新完成曾被合并为“已同步”。后端也允许 Ok(report) 携带单项 errors，只检查 Promise.reject 会把部分失败显示为成功。

## Decision

界面区分本地事务保存、bound_pending/retry_wait 等待、retry_wait/failed失败和远端确认。local_only、bindable_retry、expired_unconfirmed另列生命周期，不继承“连接后自动补推”的承诺；状态机见[队列生命周期](../architecture/2026-11-03-同步队列生命周期与本地意图.md)。成功即出队，没有累计确认记录，不能编造“累计已同步N条”，上次同步时间也不代表每项意图已确认。

syncPill负责稳定展示投影，活动进行时显示syncing，空闲后再按失败/待处理分类。旧“failed不得被syncing覆盖”已被[同步灯决定](2026-11-04-同步灯与账户状态.md)取代；失败计数和原因仍在详情保留。

整链完成由真实阶段结果决定，不能由队列瞬间清零决定。states包含推、拉及必要补推；手动/保存后同步还要承担抓取与重载。当前后端sync_run协调feeds/states，运行边界及事件见[同步运行生命周期](../architecture/2026-11-05-同步运行生命周期与诊断.md)。队列零统计最多补记阶段中的写回观察，任一非零分类会撤销，不能发布整轮成功。

前端活动以owner/generation归属阶段和终态，较早请求不得覆盖较新的活动；手动重复触发复用在途任务。保存后抓取失败仍完成必要reload，再发布对应失败和重试，空错误字符串也不是成功。

30秒只把展示改成“未返回/已等待”，不替后端取消、不释放忙锁。HTTP失败、IPC拒绝和report.errors都须消费并给出原因。队列事件更新分类，不修改连接态或直接发布整轮终态；AppHandle注册表让引擎不必携带宿主参数，未注册的测试不验证真实事件投递。

## Alternatives considered

把任何部分错误都改为throw会丢失已完成成果并中断其他项；保留report再显式消费更符合现有恢复模型。固定前端超时会把合法长抓取误作失败，并可能放行与仍在执行的后台任务重叠。

轮询统计需要长期IPC；已有事件适合通知变化，但事件丢失/装配仍需真实应用验证。把AppHandle加入每层引擎签名会扩大宿主耦合和测试改造，因此用注册边界。队列清零不覆盖后续pull/抓取/重载，不能作为整链完成信号。

## Consequences

展示状态属于进程内观察，既不是持久同步日志，也不是服务端逐项证明。底层任务永不结算时忙锁会持续；没有取消协议便不能安全假装它已停。

2026-11-06 已确认重认证可能丢失先前已提交的数据变化标记、订阅确认和Fever完成时间写入仍有静默失败，见[同步正确性路线](../../../../docs/roadmap.md#sync-correctness)。因此“错误已分类/报告已接线”不能提升为所有失败都可见的保证。

## Validation

sync-indicator、manual-sync-status、backend-sync-runtime及SyncTab组件回归覆盖阶段、generation、pending和report消费。Rust用例覆盖队列统计及错误分类；真实App事件投递与真实服务端确认需独立证据，mock返回结构不能自证这些边界。
