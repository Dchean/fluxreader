# Agent Note: 界面文案与控件口径

Status: implemented

## Problem

界面文案与控件在长期迭代里漂移出多套写法：同一个动作在不同地方有两个名字（「新建订阅源」「添加源」「添加订阅源」），标点混用半角与全角，快捷键有三种格式，收藏有四种视觉，下拉控件有的是原生 `<select>` 有的是自研组件。单独看每处都不是错，合起来让界面显得没有主张——用户会以为不同的说法意味着不同的行为。

设置页另有一类问题：说明文字越写越长，长到把控件挤出与其他卡片同一右缘。

## Decision

**同一动作全应用一套说法。** 统一为「添加订阅源」（右键菜单与设置页不得出现「新建订阅源」「添加源」）；同步/刷新分工明确：后端状态用「同步」，抓取动作才用「刷新」，单源是「刷新此源」、全量是「刷新全部订阅源」，两处各自唯一。

**标点硬口径**：省略号一律 `…`（U+2026），冒号一律 `：`；不得出现 `...` 或 ASCII `:`；全仓感叹号保持 0 个。快捷键提示统一为 `Ctrl+K`、`Ctrl+,`、`Esc` 这类紧凑加号形，禁止 `Ctrl K`、`Ctrl + K`、`ESC 关闭`。

**下拉控件必须是 `FluxDropdown`**，不得使用原生 `<select>`。它需要支持向上弹出、Esc 与点击外部关闭、空选项列表不崩。`FluxDropdown` 必须是 `SettingCard` 的**直接子元素**——中间加一层包裹 div 会让提示文本撑宽包裹层，把控件挤出与其他卡片同一右缘。

**布尔控件同类语义用同一控件**（设置页开关统一用 `Switch`；曾有一处用原生 checkbox）；图标按钮尺寸收敛到两档（`--icon-btn-hit-sm: 20px` / `-md: 22px`）；主按钮禁用态统一 `opacity: .45`。

**截断文本必须带 `title` 属性且等于未截断全文**（`line-clamp` 截断时）。

**焦点可见性覆盖所有可交互控件**；真实交互控件若用 `div` / `img` + `onClick` 实现，必须补 `role` + `tabIndex`，且 Enter/Space 触发与鼠标点击**相同**的动作（不得「能聚焦但按键无反应」）。

**设置页文案字数上限**：卡片说明与常驻提示单行 ≤ 48 字；动作行下的提示 ≤ 40 字且语义与按钮一一对应；API 密码提示 ≤ 32 字；不得有复述标题的说明。删除文案时**约束性语义零丢失**——数字阈值、确认类信息、不可回退的警示必须保留（例如「断开会移除同步拉取的内容」这条只能由断开确认框承载，不得出现在常驻文案里）。

**`index.html` 的 `theme-color` 必须等于深色 `--bg-base`**（`#14161a`），否则移动端或系统级配色与窗口内容不一致。

**这一整批改动只改字符串与静态视觉，不改变任何行为**——动作、跳转目标、计数口径、状态流转都不变。这条是审查判据：如果某个「文案修复」改了行为，它就不是文案修复。

## Consequences

**收益**：用户不会因为「说法不同」而怀疑行为不同；设置页控件对齐、说明不超行；截断文本有完整提示；读屏与键盘能覆盖全部可交互元素。

**代价与已知上限**：

- 字数上限是人工核对的口径，**没有脚本测量渲染宽度**。文案超限的表现是被 `line-clamp` 截断，不会报错——审查时需要留意。
- `theme-color` 与 `--bg-base` 的一致性靠人工维护，两者任一改动都要同步。
- 标点口径（全角冒号、U+2026）在新增文案时容易违反，而前端回归**不断言中文串**（那会让文案改动频繁打红），因此这类约束只能靠审查。
- `--text-tertiary` 在深色主题下的对比度约 4:1，处于 WCAG AA 边缘。它是全局视觉 token，改动需要单独的决策，当前未改。

## Alternatives considered

### Why not 用 lint 规则强制标点与用词？

`oxlint` 不提供中文文案规则，自研一个字符串扫描器可以覆盖「`...` 与 `…`」这类机械项，但会带来误报（代码里的 ASCII 冒号是合法的）与维护成本。当前选择把口径写进文档并靠审查，重访信号是「同类违反第三次出现」。

### Why not 让前端回归断言中文串？

断言中文串会在每次文案微调时打红，逼着改测试；久而久之开发者会倾向于不改文案（或改测试而不看内容），反而让文案质量下降。文案的口径属于审查对象，不属于门禁。

### Why not 保留各处不同的说法，只要含义清楚？

「含义清楚」是对写的人而言。用户看到两个说法时无法知道它们是否指同一件事，尤其是「刷新」与「同步」这两个在本应用里含义不同的动作——混用会让用户以为点哪个都一样。

### Why not 把长说明改成 tooltip？

tooltip 在触屏与键盘场景下都难以发现，而设置页的说明恰恰是用户判断「这个开关会不会删我数据」的依据。信息不能藏进 hover。字数上限是更直接的约束。
