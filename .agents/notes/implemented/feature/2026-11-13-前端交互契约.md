# Agent Note: 前端交互契约

Status: implemented

## Problem

前端问题很少是单点渲染错误，而是“同一个动作有多套表达”：卡片用鼠标可达但键盘不可达；本地保存、队列等待、远端确认被合并成“已同步”；后台刷新、切换返回与 Reader 关闭共用同一个滚动恢复信号；错误 toast 自动退场后重试入口消失；端点要求用户记住 API 后缀；模态只移焦不 trap。每类都需要一个可被后续实现复用的语义入口，而不是在组件里各写一套。

## Decision

- **卡片角色与键盘行为分开表达。** 社交/通知卡保留 `article` 角色，以 roving `tabIndex`、键盘处理器与事件目标守卫提供选择；文章、播客与画廊有各自 `button` 语义，不能把“卡片维持 article”泛化成五布局事实。卡内真实控件的动作不被卡片选择吞掉。五布局 J/K 的选择与 DOM 焦点由 Timeline 协调；源行主选择、刷新、编辑是同级真实按钮，动作在 hover/focus-within 可见。播放器激活时卡片 Space 让给播放控制，真实按钮/输入/菜单项保留自身 Space 行为。关闭后仍留 DOM 的 ModalOverlay/Lightbox 用 `inert`；条件卸载的 ConfirmDialog/ContextMenu 没有关闭态子树。（原 2026-10-06 feature/2026-10-06-键盘导航、焦点与卡片角色.md）
- **同步四态分开表达。** 界面区分本地事务保存、`bound_pending`/`retry_wait` 等待、`retry_wait`/`failed` 失败与远端确认；`local_only`、`bindable_retry`、`expired_unconfirmed` 另列生命周期，不继承“连接后自动补推”承诺。成功即出队，没有累计确认记录，不能编造“累计已同步 N 条”，上次同步时间也不代表每项意图已确认。syncPill 做稳定展示投影：活动进行时显示 syncing，空闲后再按失败/待处理分类；失败计数与原因仍在详情保留。整链完成由真实阶段结果决定，不能由队列瞬间清零决定；队列零统计最多补记阶段中的写回观察，任一非零分类会撤销整轮成功。前端活动以 owner/generation 归属，较早请求不得覆盖较新活动。（原 2026-10-06 feature/2026-10-06-同步四态与失败可见性.md）
- **返回位置按条目 ID、filterKey 与卡片内偏移记账。** 高频锚在 `lib/readingPosition` 唯一维护，记录不触发订阅 render；store 读取同一存档准备返回窗口，再发 nonce 由 Timeline 做 DOM 滚动。三种触发分开：后台属性刷新用 `positionRestoreNonce`，切回缓存上下文用 `switchRestoreNonce`，Reader 关闭用 `readerCloseNonce` 归还原卡焦点。同上下文重复导航不算切回：仍重新捕获成员，落地沿当前活锚发 positionRestoreNonce，不消费上次离开的旧存档。缓存首项删除不代表真实锚删除；真实存档锚不在新成员时才走顶部回落。后台刷新若当前锚已失效则不猜目标。（原 2026-10-07 feature/2026-10-07-返回位置与列表保位.md）
- **术语与控件口径统一。** “添加订阅源”“同步”“刷新”使用稳定术语；全量抓取按 direct/hybrid 真实范围写“全部/本地订阅源”。设置开关复用 Switch，下拉复用 FluxDropdown；共享下拉生成 listbox/option ID，combobox 关联 controls 与活动项，焦点留在触发器，方向键/Home/End 只移动活动项，Enter/Space 提交，Esc/Tab 或焦点离开收起，鼠标选项不抢触发焦点。常驻说明以识别对象、状态或后果为限；危险后果留在操作附近或确认框，不只藏 hover；已可见的成功态减少重复 toast。（原 2026-10-07 feature/2026-10-07-界面文案与控件口径.md）
- **Endpoint 用有限候选，404 才继续。** 用户可填服务站点根地址或完整 API 路径；回显保留原输入。`endpoint_resolve` 按协议生成有限候选并先试原输入：GReader 补 `api/greader.php`，Fever 补 `api/fever.php` 与 `p/api/fever.php`。只有 404 允许继续候选，其他状态立即交调用方按真实错误处理；非标准反代以 200 登录页替代 404 时仍需后续响应解析拒绝。解析缓存按协议与规范化输入匹配，账号变更/断开清理，不把结果写回输入框。Fever `api_key` 放 POST form，保留 MD5(username:API 密码) 小写十六进制规则。（原 2026-10-07 feature/2026-10-07-Endpoint-适配契约.md）
- **错误中心保存失败上下文，重试按目标。** 带动作的 `showToast` 同时登记本进程错误中心；普通提示仍只有 toast。中心上限 20 条，按显式操作/实体/上下文 key 合并，更新文案、动作与次数；无 key 才回落文案去重。24 小时 TTL 惰性清理，条目不写盘。入口在侧栏底部，面板复用 ModalOverlay，提供重试、忽略、清空；toast 与中心通过同一 `retryError` 派发：先消费旧条目，失败动作自行以同 key 重新登记。调用点负责捕获目标：批量标读保存范围与目标 ID，续页保存查询/首页代际/游标，正文与 AI 重试保存文章 ID，同步配置保存完整草稿与 opaque revision，播放器保存 URL 与实际 audio 元素。中心不猜实体，重试不读取“当前对象”替换失败目标。（原 2026-10-16 feature/2026-10-16-重试入口持久可达与错误中心.md）
- **模态共用焦点陷阱与 dialog 语义。** ModalOverlay、ConfirmDialog、PlayerFullOverlay、Lightbox 共用 `useFocusTrap(open, panelRef)`：打开时先捕获外部触发焦点，再移入容器或 `data-modal-autofocus` 指定控件；Tab/Shift+Tab 在首尾回绕，无可聚焦项时保留容器焦点；焦点位于 DOM 外的 portal 下拉时交还默认行为。dialog 的 role、`aria-modal` 与可访问名称在正确元素，关闭态 ModalOverlay/Lightbox 用 inert 阻止隐藏控件获焦。搜索/改名输入使用共享 hook 的初始焦点标记，不用 React commit 阶段的 `autoFocus`。打开面板栈用于还焦：触发点仍连接、可见且未 inert 时优先归还，否则归还最上层仍存活面板。灯箱导航在媒体修订/单图时保留原节点与原生焦点，以 `aria-disabled` 表达不可用，点击/Enter/Space/方向键由 `canStep` 守卫；Tab 仍按既有 trap 循环。公开 action 替换集合时移除导航控件，若焦点落在失效节点或 BODY 则交给 Close（无控件时交给容器）。（原 2026-11-01 feature/2026-11-01-模态焦点陷阱与dialog语义.md）

## Alternatives considered

- 给所有卡片统一 `button` 角色：会压平社交/通知卡内部链接与按钮语义，读屏更难用，否决。
- 继续不做 focus trap：只在“开关移焦”需求下成本较低；真实 Tab 穿透出现后前提已变，否决。
- 打开时给整个 `app-root` 加 inert：会跨到 App 与播放器的交互所有权，只限制面板内键盘循环，否决。
- 把任何部分错误都 throw：丢失已完成成果并中断其他项，保留 report 再显式消费，否决。
- 用固定前端超时把长同步判失败：会误伤合法长抓取，也可能与仍在执行的后台任务重叠，否决。
- 所有恢复合一个 nonce：混淆持续刷新与一次性返回；只用文章 ID 又无法触发连续开关同一篇，否决。
- 要求用户填固定 API 后缀：把部署知识转嫁给用户，且前端探测受 CSP/CORS 约束，否决。
- 把失败回调放到无限数组：没有内存边界，且重试读当前对象会改变失败目标，否决。
- 提高 toast 容量/改 sticky：仍会挤走入口并长期遮挡正文，改用侧栏固定错误中心。

## Consequences

- 角色正确、可 Tab 与快捷键让路是三项独立条件，不能互相代替；真实读屏实听仍未验。
- 展示状态属于进程内观察，不是持久同步日志或服务端逐项证明；底层任务永不结算时忙锁会持续，没有取消协议不能假装已停。
- 缓存淘汰、真实锚删除/过滤与动态测量仍可能限制精确恢复；nonce 分流不自动保护焦点请求有效期。
- 错误中心比 toast 持久，但仍有 20 条上限与 24 小时惰性 TTL；重启前的动作不保留，没有动作的提示不进中心。
- Endpoint 首连多付有限候选请求；非标准子目录/网关可能仍需显式完整地址。body 传 key 减少 URL 日志暴露，但不保证记录请求体的代理看不到。
- 统一组件/文案不能证明键盘、热区、溢出或 AX 已正确；真实 Edge/WebView2、字体与读屏需各自验证。当前缺口见[路线图](../../../../docs/roadmap.md#interface-and-media)。
