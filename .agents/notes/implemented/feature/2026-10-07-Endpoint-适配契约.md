# Agent Note: 同步 Endpoint 的有限候选与错误短路

Status: implemented

## Problem

Miniflux和FreshRSS的GReader/Fever端点布局不同，要求用户记住API后缀容易把凭据错误与路径错误混淆。旧文案曾要求填写完整后缀，这个方向已被有限后端探测取代。

## Decision

用户可填服务站点根地址，也可沿用完整API路径；回显保留原输入。endpoint_resolve按协议生成有限候选，先试原输入。GReader补api/greader.php，Fever补api/fever.php及p/api/fever.php形态。

只有404允许继续候选，其他状态立即交调用方按真实错误处理。这个规则是避免掩盖401/403/5xx的诊断政策，不是证明“任何非404一定是正确API”。非标准反向代理若以200登录页替代404，仍需后续响应解析拒绝。

解析缓存以协议和规范化输入匹配，账号变更/断开会清理；不把解析结果写回输入框。Fever api_key放POST form，保留MD5(username:API密码)的小写十六进制规则，其余动作参数按既有query传递。错误复用统一toast/extractError。

## Alternatives considered

让用户填固定后缀把服务部署知识转嫁给使用者。无短路尝试全部候选会掩盖真正凭据或服务端错误。前端探测受CSP/CORS约束且不应持有此网络协议适配，因此留在Rust。

把解析结果回填输入框会让用户误以为后缀必填，也让后续复制配置混淆用户输入与内部解析。有限缓存减少重复404，但不作为自动探测所有部署路径的承诺。

## Consequences

首连多付有限候选请求；非标准子目录/网关布局可能仍需显式完整地址，不能说只填域名对所有部署均成立。body传key减少URL和常规访问日志暴露，但不保证会记录请求体的代理不见凭据。

设置卡宽度随字体与窗口变化，旧234/219px只是一时测量，不应当作全局文案预算。兼容事实与来源由[同步兼容矩阵](../../../../docs/sync-compat-matrix.md)维护。

## Validation

endpoint_resolve单元测试核对候选顺序与404短路；endpoint_autodetect_e2e使用本地协议夹具验证请求和认证形态。这些不能替代具体FreshRSS/Miniflux部署、TLS和反向代理的真实连接证据。
