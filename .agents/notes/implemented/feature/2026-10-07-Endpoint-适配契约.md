# Agent Note: Endpoint 适配契约

Status: implemented

## Problem

设置页要求用户填同步后端地址，而不同服务端把同一套 API 放在不同路径下：

- **FreshRSS**：GReader API 在 `{域名}/api/greader.php`，根路径是 404；Fever 在 `/api/fever.php`；
- **Miniflux**：GReader API 在**站点根**；Fever 在 `/fever/`。

最初的方案是把这件事交给用户：输入框的提示文字教用户填完整路径（含 `/api/greader.php`）。这造成两个问题——用户不知道该填哪个后缀（取决于他用哪个服务端），填错时的报错是 404（用户理解为「地址填错了」，无法自行分辨是路径错还是服务端不支持）。更糟的是历史上曾把「教用户填后缀」写成明确要求，并配了「不得新增 endpoint 自动探测」的 запрет 条款，方向恰好是反的。

## Decision

**用户只填域名，后缀由后端候选探测**（`src-tauri/src/endpoint_resolve.rs`）：

- `greader_candidates(endpoint)` 与 `fever_candidates(endpoint)` 按协议给出候选路径序列；
- 探测判据是 `path_exists(status)`：**404 才继续试下一个候选，任何其他状态码立即停止并按真实状态码报错**。凭据错误（401/403）绝不能报成「地址不对」——那会让用户去改一个本来就正确的地址。
- 解析结果按 `(协议, 用户输入)` 缓存（`cached_base` / `remember_base`，`CACHE_KEY = "endpoint_resolved"`），避免每次操作都探测一轮。

**输入框回显始终是用户原始输入**，不回显解析出的完整路径——回显解析结果会让用户以为必须填后缀。界面任何位置不得再出现「需填 `/api/greader.php`」类指引，这条是防回归条款。

**旧用法仍须可用**：已经填了完整路径的用户不受影响（候选序列的第一个就是「按原样使用」）。

**实测宽度预算（不要超）**：设置卡的说明区 `.setting-card-text p` 宽 234px 且 `-webkit-line-clamp: 2`，超两行会被截断；输入框在 `box-sizing: border-box` 下**内容盒只有 219px**。判断一段文案或占位符放不放得下必须用**内容盒宽度**，不能用外框宽度。

**Fever 的 `api_key` 必须放在 POST form body 里。** FreshRSS 的 `fever.php` 只读 `$_POST['api_key']`，Miniflux 用 `r.FormValue`（两者都收）。统一走 form body 既修了兼容，又顺带消除了 `api_key` 出现在服务器访问日志里的泄露面。`md5(username:api密码)` 十六进制小写这个公式经官方文档验证正确，不要「顺手改」；其余参数保留在 query（FreshRSS 全走 `$_REQUEST`）。

**失败提示复用既有 `showToast` / `extractError` 通道**，不新造控件或弹窗、不加错误展示层级。

## Consequences

**收益**：用户只需要知道自己的服务端域名；凭据错误与路径错误可分辨；Fever 在 FreshRSS 上能连上；API 密码不再进访问日志。

**代价与已知上限**：

- 探测会在服务端留下若干 404 请求（有界：候选序列长度有限），且首次连接比直接给完整路径慢一点；
- 解析结果缓存在 `app_settings` 里，用户改服务端布局（例如把 FreshRSS 装到子目录）后需要重新保存一次配置才会重新探测；
- 宽度预算（234px / 219px）是实测常量，主题或字体设置变化会改变这个预算；文案超限的表现是截断而非报错，因此容易在审查中漏掉。

## Alternatives considered

### Why not 让用户填完整路径？

那是初版方案，被实测数据推翻：填入错误后缀时得到 404，用户无法区分「服务端不支持」「路径写错」「服务端没开 API」三种情况。而且不同服务端的正确后缀不同，这个知识不该由用户承担。

### Why not 在 404 时直接尝试所有候选（无短路）？

无短路会发出多余的请求，且真正的失败原因会被淹没在候选列表里。404 短路 + 其他状态码立即报错的规则，让「路径不对」与「凭据不对」这两种失败保持可分辨。

### Why not 把探测结果写回输入框？

用户会以为必须填后缀，下次手动填写时会照抄一个可能随服务端变化而失效的完整路径。回显原始输入让「填域名就够了」这件事在界面上自证。

### Why not 用前端做探测？

前端能发 HTTP 请求，但会受 CSP（`connect-src` 只允许 `self` 与 ipc）与 CORS 的双重限制——跨域探测在 webview 里不可行。后端探测是唯一可行的位置。
