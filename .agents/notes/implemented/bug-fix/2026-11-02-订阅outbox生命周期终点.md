# Agent Note: 订阅 outbox 的生命周期终点——同身份保留、身份切换清账

Status: implemented

## Problem

订阅 outbox 对已消失的账号没有生命周期终点：身份切换（换号）只是让旧账号的 pending 行**暂停**（key 屏障不发给新账号），`commit_account_settings` 与 `commit_disconnect` 都不清队——行连同 attempts/last_error 永久滞留。原语义设想「换号 → 回原账号后恢复可发」，但对一个**永远不回来**的账号（换服务、换用户名、弃用），pending 行只是永不执行的死意图：调度器按 key 过滤后永远不碰它，回执统计对任何在场账号都不可见，只剩表里的墓碑式残留。roadmap 2026-11-02 登记为「待产品决策」，本篇即产品拍板后的落地：**身份切换即清账**（已消失账号生命周期终结），显式放弃「换号 → 回原账号恢复 pending 意图」。

## Decision

`db/outbox.rs` 新增 `abandon_stale_outbox(conn, current_key) -> AppResult<usize>`：`DELETE FROM subscription_outbox WHERE account_key <> ?1`，返回删除行数。调用点收敛在 `commit_account_settings`（commands/sync.rs）的**两个分支、同一事务内、`bump_sync_generation` 之前**：

- `identity_changed`（协议/规范化根/用户名变化）：与 purge_remote_data/clear_feed_tombstones 同批清旧账号队项；
- `old_was_empty`（断开后重连）且断开身份见证键（`LAST_DISCONNECTED_ACCOUNT_KEY`）与新身份不同：与墓碑清理同批清账；见证键相同（同身份重连）则跳过，行保留。

边界：`commit_disconnect` 不调用（断开保留行，重连同身份仍可发——TASK-055 的防复活语义不受影响）；同账号仅密码变化（`password_changed`）不调用（同身份，行经代际重绑继续可发）。跨账号的**入队级** key 屏障（B 的本地动作不删 A 的行）与**执行级**守卫（adopt 的代际屏障）保持原样——生命周期终点是账号提交内核里的第三个独立层次，不影响那两层。

执行器（`push_subscription_outbox`）零改动：它本就只发当前 key 的行，清账后异账号行消失对其透明；`sync_local_feeds` 的 pending 查重、调度器的 `outbox_has_pending` 同样只看当前 key，无需调整。

## Alternatives considered

- **保留旧语义（换号暂停、回原账号恢复）+ 加过期清理**：给行加“最后活跃时间”，超期（如 90 天）由后台清理。最强理由：语义最平滑，真的临时换号再换回来的用户零损失。否决——过期窗口内的行为与现在一样难解释（行既不可见也不可发），且引入一个凭空的时间参数和一套后台扫描；“回原账号恢复”对可恢复场景本来就由**同身份重连**（见 `LAST_DISCONNECTED_ACCOUNT_KEY` 见证）覆盖，暂停-恢复只在“从 A 直接切到 B 再切回 A”的窗口有效，而该窗口的行保留价值（A 的在途写回意图）远低于永久滞留的表污染。
- **断开即清账**：`commit_disconnect` 一并删除全部行。否决——断开-重连（同账号排障、改端点）是明确要保留意图的场景（disconnect 的墓碑语义注释与 opt009_phaseb3 e2e 锁定）；断开清账会把「网络排障」升级成「写回意图全丢」，超出本决策范围。
- **只在 identity_changed 清、不管断开后换身份重连**：覆盖主要场景但留下后门——断开 → 换用户名重连，旧行照样永久滞留，与“已消失账号终结”的目标矛盾，且该分支已有身份见证键可精确判定，不利用是白浪费。
- **软删除（加 status='abandoned' 终态）而非物理 DELETE**：保留审计痕迹，但 `subscription_outbox` 的统计/调度查询要全部加 status 过滤，执行器重绑/adopt 的守卫面同样要排除新终态——为一个无人消费的痕迹扩大三处查询面。保留中的行有attempts/last_error，清账后只剩清理行数日志而无逐项历史；这是明确放弃逐项审计存档的取舍，物理删除满足当前单账号产品范围。

## Consequences

- `opt009_phaseb3_e2e.rs`（生产账号提交内核 + 独立文件库）：A 入队 → A→B 换号后 A 行清零（`COUNT(*) = 0`）→ 回 A 不复活；A 重新入队 → 断开后行保留 → 同身份重连行仍在且恢复可见 → 换用户名重连后旧行清零。
- 原「换号暂停、回原账号恢复」断言随语义更新：`outbox_stats_three_states_and_account_scoped`（commands/sync.rs 单测，seed_creds 绕过提交内核）注释改为只锁读取面的 key 过滤；`cross_account_same_url_preserves_other_account_intent`、`paused_other_account_intent_does_not_block_pull_removal`、`inflight_quickadd_response_after_account_switch_stays_scoped_to_old_account`、`unsubscribe_recovery_resolution_stays_scoped_across_account_switch` 改锁清账与在途响应不写行。
- 上述用例验证身份提交内核的事务清账与同身份保留，不把历史本机工具链限制当作当前事实；当前门禁状态由统一验收入口维护。
