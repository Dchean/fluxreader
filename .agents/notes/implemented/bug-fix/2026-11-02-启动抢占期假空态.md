# Agent Note: 启动抢占期假空态——Timeline 空态并入后端 reload 在途计数

Status: implemented

## Problem

Timeline 的空态判据是 `items.length === 0 && articlesLoading`（此前只看
`articlesLoading`）。启动装载路径是「先写游标镜像、再异步 reload」：在
`bootstrapFromBackend` 发起 `reloadFromBackend` 后、其首屏快照落地前，
`articlesLoading` 仍为 false 而 entries 可能是空数组/旧口径快照——列表会闪
「暂无匹配内容」假空态，随后才被真实数据替换。筛选视图的兄弟窗口
`reloadFilteredEntries`（切收藏/未读/今天时整体替换 entries）在同一时间窗
内有同机制假空态，修一处必须两处同盖。

## Decision

模块级 `backendReloadInFlight` 计数（TASK-100 P3-1）闭包外读不到，为其在
store 增加 `backendReloadsInFlight` 镜像（number）：`reloadFromBackend` 与
`reloadFilteredEntries` 的发起/finally 四个计数读写点各追加一次镜像
（`beginBackendReload` / `endBackendReload`，只读当前计数写 store）。计数
逻辑本身一行不动——`isBackendReloadInFlight` 作为 loadMoreArticles 入口守卫
的语义（含自身计数）保持逐字不变。Timeline 空态与哨兵让位判据同步改为
`articlesLoading || backendReloadsInFlight > 0`，空态处留反向注释。

镜像与计数共用同一次同步执行序（计数自增/自减后立即 set），不存在计数与
镜像的可见性窗口；`endBackendReload` 落在 finally，异常路径同样镜像。

## Alternatives considered

- **修法 (a)：Timeline 调 `isBackendReloadInFlight()` 判「有 reload 在途」**。
  它的最强形式是改动最小——不新增 store 字段，一行判据。但审计证伪：该函数
  语义是「当前实例**自己**的 reload 是否在途」（模块计数含自身调用），把
  `>0` 判据放进 UI 渲染后，「兜底只关不开」会变成「永不关」——reload 在途
  期间该守卫恒真，若把守卫当作空态关闭条件则空态永不恢复。故只镜像计数、
  不复用守卫判据。
- **autoFocus 改卸载关闭态面板**（同批另一项，ModalOverlay 层）：需要动共享
  ModalOverlay 的常驻 DOM 契约（退出动画与焦点还原依赖），爆炸半径大；本项
  的条件镜像方案是行级追加，行为逐字不变。

## Consequences

- 收益：启动装载与筛选切换两个时间窗的假空态消除；真实引擎与 jsdom 通道
  表现一致（jsdom 不尊崇 inert，焦点/可见性失真不再依赖引擎差异解释）。
- 代价：新增一个 store 字段及其 4 个镜像写点；镜像写点必须与计数读写点
  成对维护——后续若新增第三条 reload 入口，须同步调用两个助手（反向注释
  在 Timeline 空态与本篇互指）。
