# Agent Note: 启动抢占期的加载与空态判据

Status: implemented

## Problem

首屏 reload 和筛选 reload 在途时，articlesLoading 可能为 false，entries 仍为空或旧范围；只靠它区分加载与空态会短暂显示“暂无匹配内容”。分页加载与整页替换属于不同活动，需要让界面看到两者。

## Decision

backendReloadInFlight 的 begin/end 助手同步维护 store 镜像 backendReloadsInFlight；reloadFromBackend 和 reloadFilteredEntries 共用，finally 释放。Timeline 在 items 为空时，以 articlesLoading 或 backendReloadsInFlight>0 显示加载，并让哨兵退让。它是展示所需的响应式事实，不是另一套并发锁。

loadMoreArticles 原有“后端 reload 在途则早退”守卫保持。该计数包含当前 reload 自己，不能在 reload 内用 >0 判断“是否还有另一个接手者”或决定它何时可以关闭 splash；否则自身存在就能使判断恒真。UI 镜像和数据落地所有权必须分别处理。

## Alternatives considered

- UI 直接调用非响应式计数函数：不建立 store 订阅，计数变化未必触发重渲染；把含自身计数用作接手者判据还会制造自阻塞。
- 只扩大 articlesLoading：会把分页锁与整页 reload 生命周期混为一谈，异常/重入释放更难辨认。
- 卸载关闭态 ModalOverlay 修同批 autoFocus 问题：与列表加载无关且破坏退场生命周期；理由由 [模态焦点](../feature/2026-11-01-模态焦点陷阱与dialog语义.md)承接。

## Consequences

计数非零期间能避免把正在加载显示成空，但“没有在途”不等于“已按最终设置取得正确首屏”。2026-11-06 受控 IPC 回包交错中，设置迟到、后台 reload 接手后仍可落入未读错误空态；该 NF4 风险尚无原生 Tauri 回包顺序证据，不能解释成慢 SQL 绕过共享 DB Mutex，也不能称真实安装版已复现。见 [验证边界](../../../../docs/roadmap.md#verification-boundaries)。

新 reload 入口须通过同一 begin/end；镜像只是现有计数的可观察面，不能通过改变此文档放宽错误空态验收。
