# Agent Note: 权威集合回补、空链接键与范围计数

Status: implemented

## Problem

增量时间窗口可能漏掉晚收录旧文章；Fever又曾每轮回拉已有正文的权威成员。空link归一成空字符串使无链接条目共享去重/读广播键，feed计数中的冗余JOIN还放大了真实大库查询成本。这些属于不同边界，不能用一次“同步成功”共同证明。

## Decision

GR回补前置于对账，走既有merge_pulled_entry和字段版本/pending守卫，不另写匹配政策。当前读对账取完整unread差分，unread与starred按缺身份/正文回补；每次pull每集合预算2000，100条/请求，成功轮转位置由[11/05后继](2026-11-05-GR权威集合回补与过期意图恢复.md)管理。预算耗尽不同于请求失败：完整集合已知，已补子集可参与；请求/合并失败按侧保留对账与游标边界。

Fever need取unread∪saved减seen减has_body。查询“已有正文”的补集能保留尚无本地行的id；直接SQL查缺正文行会漏掉根本未绑定的成员。has_body读取失败取空集、允许多拉，是优化失败时不漏内容的保守方向；不能与权威集合失败时禁止清状态的方向混用。

入库normalized_url_key把trim后空链接变为None，拉取匹配也拒绝空键；v31清理articles.url_norm=''，回填避免重引入。contents历史附带url_norm不作本轮清洗，其身份主要由正文决定，避免扩大共享内容迁移。该修正防止空键误并，不代表协议pull已经接纳所有无链接条目。

feed级dedup EXISTS去掉冗余feeds JOIN：内层b.feed_id=a.feed_id时布局已由外层同源约束；all/folder仍保留跨源判断。查询参数由同一构建函数提供，不靠另写绑定数。历史50k同构SQLite探针支持这项查询形态优化，当前性能基线以性能文档和实测为准。

## Alternatives considered

回补后再做第二轮全量对账会复制快照/失败边界，故在既有合并前置。纯ANALYZE不消除冗余JOIN，也依赖统计更新，因此先简化等价查询。预算当失败会让大集合一直无法收敛，必须与不完整响应分开。

把normalize_url改成Option会扩大订阅/墓碑调用面；空link无身份属于文章调用方语义。内容has_body只看HTML/文本，不把封面或enclosure当正文：播客空文可能重复回访，这是所选口径的成本。

## Consequences

有限回补需要多轮，真实空正文仍可能持续回访；晚收录且已读未收藏的文章仍需full。2026-11-06协议真实拉取仍跳过空/空白link条目，见[同步正确性路线](../../../../docs/roadmap.md#sync-correctness)：DB空键修复不能被写成“无链接文章现已全部可用”。

计数变快不证明逻辑等价，四视图/布局/源范围需核对结果与计划；历史同构探针数字不外推到任意数据库或本机现在耗时。

## Validation

strict_greader、fever_compat及计数回归分别验证回补、已有正文过滤、逐ID完整性、空键迁移和结果等价。旧阶段执行记录见[历史收敛路线](../../archived/process/2026-10-31-审计修复收敛路线.md)，当前状态不在此复制。
