# Agent Note: 通用设置 IPC 敏感键与正文文本提取边界

Status: implemented

## Problem

DB读敏感键会透明DPAPI解密，通用get_setting曾把任意键直接暴露给WebView；写侧也未覆盖全部敏感键。另一个输入差异是html_to_text把script/style子树文本带入搜索和摘要，用户看不到的脚本/样式进入模型输入。

## Decision

通用read_setting/apply_setting拒绝credentials::SENSITIVE_KEYS，返回protectedSetting且不回显存量值。合法业务走专用命令/后端内核；DB层仍允许授权内部读取，不在持久层一刀切。AI设置专用get_ai_config仍可返回供编辑的明文key，因此这项修正缩小通用入口，并不建立WebView无法接触全部凭据的隔离。

html_to_text按解析树跳过script/style祖先下的文本，保持body和空白口径；摄取、GR合并及全文提取共用该函数，HTML渲染净化仍由原sanitize链承担。过滤隐藏子树不等于普通正文没有提示注入，模型输入仍应视为外部内容。

## Alternatives considered

只改正规前端调用不能约束其他invoke，保护须在命令边界。DB层拒绝会破坏合法同步/AI消费；通用命令返回打码值也不能替代专用编辑协议。复用protectedSetting避免两个同义拒绝码。

字符串切script/style易受HTML解析形态欺骗，已有解析树更适合表达祖先过滤。无需另造一套HTML扫描器。

## Consequences

DPAPI继续保护特定用户/机器下的落盘数据；它从来不等价于抵抗该用户下已经获得专用命令权限的WebView代码。专用AI配置可编辑是当前明确边界，不能写“加密形同虚设”或“WebView凭据完全隔离”。

正文哈希变化可在重摄取时建立新内容行、回收旧无引用行；未重摄取的历史body_text仍可能有旧文本。2026-11-06已证旧合成v1迁移备份含明文，但真实历史v1敏感值是否可达尚未确定，见[导入与备份路线](../../../../docs/roadmap.md#import-and-backup)。

## Validation

credential_safety_e2e用存量敏感行验证通用读写拒绝与专用内核；content_safety_e2e走真实摄取及捕获型模型请求，断言隐藏文本不出现在请求而可见正文保留。这两套测试不能证明全部提示注入或全部凭据流向安全。历史阶段出处见[收敛路线](../../archived/process/2026-10-31-审计修复收敛路线.md)。
