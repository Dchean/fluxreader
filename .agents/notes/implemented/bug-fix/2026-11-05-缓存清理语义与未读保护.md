# Agent Note: 缓存清理语义与未读保护

Status: implemented

## Problem

「清理旧文章」的后端谓词一直是「早于阈值、已读、未收藏、且不在
`sync_queue`」，因此未读文章永远不会被清理。界面却只写「删除该时间之前的
本地缓存（收藏文章与待同步状态始终保留）」，用户会自然理解为所有旧文章都会
被删，无法解释为什么未读文章一直留着。

同时，清理后的已读文章仍存在于远端。下一次 full sync 按服务器状态重新导入时，
它们可能再次出现。原确认框只写「不可撤销」，没有说明该远端回灌边界；这不是
本地删除可撤销，而是同一内容可能以新拉取结果回来。

## Decision

**保留现有删除谓词，不改用户数据规则；把真实条件与远端回灌边界写进设置页、
确认框、回执与 API 注释。**

- 只删除「早于阈值 + 已读 + 未收藏 + 无待同步状态」的文章。
- 未读文章永不清理；收藏文章与 `sync_queue` 中待同步文章保留。
- 确认框明确「此操作不可撤销」与「远端仍有的内容可能在同步后重新导入」。
- 清理回执说明「已读文章 N 篇（未读/收藏/待同步保留）」。
- 不实现 tombstone 防回灌。本地删除没有远端删除意图时，远端仍是事实；用
  本地墓碑压制远端同 URL 会改变同步冲突政策，超出「清理本地缓存」语义。

## Alternatives considered

### Why not 删除未读文章？

未读是用户尚未消费的内容。删除后 full sync 会按远端 unread 状态重新拉回，
既无法真正省空间，又制造「阅读列表突然少了一截、过一会又回来」的体验。保留
未读也是当前实现的既有承诺。

### Why not 给清理过的文章写 tombstone 防回灌？

这会把一次本地缓存维护变成远端内容删除意图。FluxReader 的 feed 墓碑用于
「删除订阅」这一显式操作，且与远端退订分离；文章级内容墓碑会压过正常的同步
拉取，用户无法从 UI 区分「我删了缓存」与「我永久不想再看到这篇」。要支持永久
抑制，需要新的产品语义与远端协议/墓碑生命周期，不在本卡范围。

### Why not 只改文案、不补测试？

清理谓词是用户数据的破坏性路径；文案与行为都可能在下一次重构中漂移。新增
数据库级保留边界测试和真实组件确认框测试，确保「未读/收藏/待同步不删」与
「远端回灌说明」同时存在。

### Why not 让清理只删正文而保留列表行？

那会改变本地存储形态与列表来源，且用户点开旧文章仍需正文；当前「删文章行」
同时回收独占内容（共享正文由最后引用规则保活）。本卡只澄清边界，不扩展成新的
分层缓存协议。

## Consequences

- 用户能看到真实清理条件，不再误以为未读文章会被清掉。
- 未读文章与待同步意图继续保留，代价是本地库不会因「清理旧文章」收缩到只含
  已读内容的小规模。
- 远端仍存在的已读文章可能在同步后重新出现；文案已说明，不把它伪装成永久删除。
- 未实现文章级 tombstone，若未来要做「清理后永不回灌」，必须另立决策并明确
  远端协议与 UI 契约。

## Testing

- `cleanup_cache_keeps_unread_starred_and_pending_articles`：四个同龄旧文章中，
  只有已读/未收藏/无队列项被删；未读、收藏、待同步三类逐 id 保留。
- `tools/component-tests/data-safety.test.mjs`：真实挂载 `CacheCleanupSection`，
  点开清理确认框并断言「已读、未收藏且无待同步状态」「未读文章不会清理」
  「远端仍有的内容可能在同步后重新导入」「此操作不可撤销」；确认后真实调用
  `cache_cleanup` 并显示新回执。
- `tools/frontend-tests/ui-contracts.mjs` 的清理文案契约同步改为新边界，避免
  旧断言继续锁住误导文案。
