# Agent Note: 社交虚拟行坐标单一写入者与动作采样对齐 paint

Status: implemented

## Problem

CI（run 42364796224, commit 0ae302b）在社交卡展开/收起往返的逐帧采样中记录到真实重叠，本地同代码全量通过。证据包帧数据显示两类独立缺口：

1. 行虚拟项 transform 有两条写入路径：React render 快照（JSX 内联 style）与 syncRowGeometryNow 直写。慢调度下，一次携带陈旧虚拟项坐标的 React 提交可以晚于直写落地，把已收敛的坐标打回上一帧；CI 帧里出现「展开卡已变高 1266px、邻居 transform 仍是折叠位 644px」和「收起后 dataset 已折叠、transform 仍是展开位且同帧混杂新旧值、wrap 总高陈旧」的连续两帧——对 CI 证据包捕获的这两帧判定：均为被 paint 的陈旧 transform（按证据包帧数据判定），属真实可见重叠；该判定针对证据包帧，不作为「连续两帧即已 paint 真重叠」的一般规则。
2. 展开提交后仍有异步二次高度变化（三张卡均精确 +4px，文本高度不变，属卡片 chrome 重排），它落在 rAF 采样相位与该帧 ResizeObserver 回调之间。RO 回调在 paint 前完成测量回写与坐标收敛，该中间态从未上屏；rAF 相位采样却把它记成 4.33px 重叠。

本地快时序下所有路径在一帧内收敛，所以历史全量通过；缺陷面是慢调度/慢媒体环境暴露的确定性时序缺口，不是随机 flake。

## Decision

行虚拟项 transform 退出 React 快照：JSX 不再携带 transform，唯一写入者是 syncRowGeometryNow，并在 row 虚拟化的 onChange（每次 notify，含 measureElement 的 ResizeObserver 测量路径）同步直写容器高与窗口内坐标。任何测量变更都在同一任务内收敛、先于 paint；滚动补偿消费仍排在坐标发布之后（与画廊实例同契约）。挂载当帧由无条件 layout effect 落位，paint 前完成。

动作逐帧采样从 rAF 相位延到本帧渲染步进结束（rAF→setTimeout(0)）：新采样回调晚于本次 rendering update 内 RO 收敛，可过滤相位中间态。采样语义不再是「rAF 相位的 DOM 状态」，但 setTimeout(0) 非逐帧 paint 快照，执行前可能有后续任务修复 DOM，不能仅凭它证明捕获每个上屏瞬时重叠；CI 环境对该提交的全量复跑是最终绑定验证。重叠阈值保持 0，场景与断言不变。

## Alternatives considered

只修采样不修产品：CI 证据包捕获的两帧 stale-transform（连续两帧、wrap 总高同帧陈旧，按证据包帧数据判定）均为被 paint，属产品缺陷，采样修复掩盖不了它。

用 flushSync/useFlushSync 强制同步 render：resizeItem 的 notify(sync=false) 不走 flushSync 路径，且全局改 flushSync 是无差别性能取舍；同帧直写已达到收敛目标。

给行虚拟化开 directDomUpdates（照抄画廊适配器写路径）：同样能收敛，但需要引入 containerRef 契约；onChange 直写复用现有 syncRowGeometryNow，改动面更小。

放宽重叠阈值或容忍少量帧：会把真实可见的一帧重叠合法化，验收明确禁止。

## Consequences

data-virtual-start/dataset 仍由 React render 提交，可滞后一帧；产品几何与回归断言都以 rects 为准，dataset 只作诊断。geom 在每次 notify 直写同值 transform，成本为窗口内 N 个元素的样式赋值，无布局失效。采样节奏仍约每帧一次，frameCount 量级不变（28–31 帧）。

若未来把行虚拟化切到 directDomUpdates，适配器 applyDirectStyles 与 syncRowGeometryNow 会成为两个坐标写入者，届时必须删掉其一，不能并存。验证证据：tmp/frontend/ci-ui-fix-r1/evidence（修复后全量）；诊断链：tmp/ci-ui-evidence-0ae302b（CI 证据包）、tmp/ci-ui-fix-r1/probe-evidence-r4（本机插桩事件流，显示 report→resizeItem→geom 同 commit、dataset 渲染滞后约 12ms 的健康时序）。

负对照边界：旧产品+新采样的负对照未运行——本地无法复现 CI 慢时序，负对照在本地无判别力。masking 风险的控制是结构性单写入者（行 transform 只剩 syncRowGeometryNow 一个写入者，陈旧 transform 不再存在可写路径），绑定验证为该提交在 CI 的全量复跑。
