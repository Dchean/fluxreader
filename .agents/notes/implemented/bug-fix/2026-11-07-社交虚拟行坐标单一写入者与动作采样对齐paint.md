# Agent Note: 社交虚拟行插入定位、提交内坐标绑定与动作采样对齐

Status: implemented

## Problem

社交时间线虚拟行的坐标时序缺陷跨三轮 CI 逐步收敛，每轮证据修正上一轮的机制假设：

第一轮（run 42364796224，commit 0ae302b，动作逐帧采样失败 max=4）：展开/收起提交的 React render 发生在同一 commit 的测量回写（report→resizeItem）之前，JSX 内联 transform 按渲染时仍是旧值的测量写入陈旧坐标并被 paint；另有展开后卡片 chrome 的异步 +4px 二段重排落在 rAF 采样相位与该帧 ResizeObserver 回调之间，把从未上屏的中间态记进采样。

第二轮（run 42438367837，commit 5c9f8b5，静态水合采样失败 max=10）：删除 JSX transform 后，虚拟器随布局切换重新启用时的首个 commit 渲染时还没有 scrollRect，JSX 先渲染出空窗口（wrap 无卡片），卡片要等 notify 触发的下一次 rerender 才插入；插入帧唯一的位置写入者是 layout effect 直写，本机探针证明该直写在 wrap commit 的 layout 阶段找不到卡片元素（geom wrote=0/miss=11），CI 慢调度下插入帧 paint 出 11 张卡全部堆叠在 wrap 顶部的画面（3 帧，dataset virtualStart 正确）。同一轮的 metrics 还记录了三个动作的既有邻居陈旧坐标（bodyimage/long/video overlapFrames=6/6/4），当时被误写为「动作帧 CI 全绿」——静态断言先抛导致动作断言未执行，不等于动作通过。

第三轮根因分析（tmp/frontend/ci-ui-fix-r2/residual-analysis.md）把动作残余分解为三个机制：①展开首帧目标已变高、已挂载邻居仍在折叠起点且 wrap 高度仍旧——携带新 dataset 的父级 commit 与坐标直写分属不同通道（notify 直写与父级 layout effect 兜底），而父级 layout effect 在 SocialCard 自身状态提交时不会重跑，慢调度下两条通道可被任务边界隔开；②展开 +4px chrome 二段重排由 ResizeObserver 驱动二次上报，其直写又晚于对应 dataset 一帧；③收起帧的重叠全部来自新挂载条目无坐标（邻居陈旧在收起方向只产生间隙）。机制①②是更新路径缺口，挂载 ref 覆盖不了；机制③由 ref 覆盖。

两轮探针同时否定了两个候选机制：直写读到滞后测量（resizeItem 先更新 itemSizeCache/version，notify 后的 memo 读取必然新鲜）；commit 内部 mutation/layout 被拆进不同任务（React 19.2 commitRoot 三阶段同步，suspensey commit 只整体推迟）。本机 6×/12× CPU 节流均单任务收敛，CI 的确切任务交错未能本地复现，修复依据是不变量分析与多通道冗余。

## Decision

按「插入定位」「提交内坐标绑定」「commit 间隙收敛」「全窗口兜底」分层，各自用对其时序免疫的写入者；四条通道都从同一虚拟器测量真值取值：

1. 插入定位：行虚拟项 ref 回调 measureRowElement（与画廊 measureGalleryElement 同模式）在 commit layout 阶段附着（paint 前）执行 measureElement 同步测量，并按当次渲染的测量写 transform；data-card-id 与 measurement.key 的守卫拒绝不匹配条目的坐标写入（测量与缓存注册仍照常进行）。该写在被插入元素自身上进行，不依赖 querySelector/根查找/effect 时序；正常 enabled、key 匹配的挂载定位由此保证，不承诺「任何环境都无坐标首帧」。
2. 提交内坐标绑定：行虚拟项包装为 TimelineRowItem 组件，行项自身 layout effect 按当次渲染的 vi.start 直写 translateY（依赖 [vi.start]）。任何携带新 dataset 的 commit 在同一提交的 layout 阶段、paint 前把每个条目的 transform 一并写齐——dataset 与 transform 由同一次渲染的数据驱动，机制①的跨通道窗口被关闭；同一 commit 内 child report 的 resizeItem（更新值）先于行项 effect（React 子先父后），父级兜底又后于行项 effect，最终值取最新，无回退。挂载当帧同样由此 effect 落位。
3. commit 间隙收敛：syncRowGeometryNow 保持更新直写者——row 虚拟化 onChange（每次 notify，含 measureElement 的 RO 测量路径）与 SocialCard 高度上报链，覆盖无 commit 在途时的 resizeItem（如 RO 驱动的 +4 二段上报）。
4. 全窗口兜底：父级无条件 layout effect 每次 render 后全窗口直写，保持 React 快照与 DOM 同值并修正任何回退。
5. 采样对齐：动作逐帧采样从 rAF 相位延到渲染步进结束（rAF→setTimeout(0)），即在本帧 ResizeObserver 收敛之后取样；这是相位过滤手段，不是逐帧 paint 快照，rAF 之间被 paint 的帧不进入采样。重叠阈值保持 0，场景与断言不变。

第一轮记录的「React 快照 transform 被陈旧直写覆盖」假设经后续证据修正：删除 JSX transform 后，插入帧缺写入者（第二轮）与更新路径跨通道窗口（第三轮）才是真实机制；「单一写入者」修正为「单一测量真值、分层写入通道」——每层通道读同一 memo 体系，任何 painted 帧的 DOM 至少与最新提交的 dataset 一致。

## Alternatives considered

恢复 JSX 内联 transform：能消除插入堆叠，但重新引入第一轮已实证的「提交渲染用滞后测量写陈旧坐标」，collapse/expand 帧会再次 paint 旧位置。

行虚拟化切 directDomUpdates（照抄画廊适配器写路径）：也能收敛更新，但需要引入 containerRef 契约并新增一批写入者；行项 layout effect 复用既有测量真值，改动面小且与画廊实例同构。

卡片定位前隐藏（visibility）：rect 不变，回归断言仍会记重叠，只是把可见问题藏起来，不解决时序缺口。

放宽重叠阈值或容忍少量帧：把真实缺陷合法化，验收明确禁止。

## Consequences

ref 回调读取 measurementsCache 依赖创建该元素的 render 已算出测量 memo（渲染出元素即保证 memo 含该条目），key 守卫防止复用/错位；data-virtual-start 等 dataset 仍由 React 提交，允许滞后一帧，产品几何与回归断言都以 rects 为准。wrap 首帧空窗口仍可能被 paint（视口出现空列表一瞬），无重叠、与加载态语义一致。每次 notify 直写同值 transform、每次含 start 变化的 commit 逐条目直写，成本为窗口内 N 个元素样式赋值。若未来把行虚拟化切到 directDomUpdates，适配器 applyDirectStyles 会与现有通道并存，届时必须收敛为单一通道，不能并存。

验证证据：tmp/frontend/ci-ui-fix-r3/（r3 全量 UI 回归与各门禁日志、慢时序探针 trace.json/run.log）；tmp/frontend/ci-ui-fix-r2/residual-analysis.md（机制分解与不变量论证）；tmp/ci-ui-evidence-5c9f8b5/（第二轮 CI 证据包，动作残余逐帧明细）；tmp/ci-ui-fix-r1/（第一轮探针与插桩）。CI 2 核调度下 dataset 领先直写的确切交错未本地复现，最终判定以目标提交的 CI 全量为准。
