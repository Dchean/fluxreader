# Agent Note: 减弱动态效果不能激活几何与可见性过渡

Status: implemented

## Problem

虚拟行/网格的坐标时序缺陷经两轮 CI 与一轮本地候选逐步收敛，每轮证据修正上一轮的机制假设：

第一轮 CI（run 42364796224，commit 0ae302b，动作逐帧采样失败 max=4）：展开/收起提交的 React render 发生在同一 commit 的测量回写（report→resizeItem）之前，JSX 内联 transform 按渲染时仍是旧值的测量写入陈旧坐标并被 paint；另有展开后卡片 chrome 的异步 +4px 二段重排落在 rAF 采样相位与该帧 ResizeObserver 回调之间，把从未上屏的中间态记进采样。

第二轮 CI（run 42438367837，commit 5c9f8b5，静态水合采样失败 max=10）：删除 JSX transform 后，虚拟器随布局切换重新启用时的首个 commit 渲染时还没有 scrollRect，JSX 先渲染出空窗口（wrap 无卡片），卡片要等 notify 触发的下一次 rerender 才插入；插入帧唯一的位置写入者是 layout effect 直写，本机探针证明该直写在 wrap commit 的 layout 阶段找不到卡片元素（geom wrote=0/miss=11），CI 慢调度下插入帧 paint 出 11 张卡全部堆叠在 wrap 顶部的画面（3 帧，dataset virtualStart 正确）。同一轮的 metrics 还记录了三个动作的既有邻居陈旧坐标（bodyimage/long/video overlapFrames=6/6/4），当时被误写为「动作帧 CI 全绿」——静态断言先抛导致动作断言未执行，不等于动作通过。

第三轮本地候选（r3，commit e323903）：把上述动作残余分解为三类帧表现并给出候选机制——①展开首帧目标已变高、已挂载邻居仍在折叠起点且 wrap 高度仍旧；②展开 +4px chrome 二段重排的直写晚于对应 dataset 一帧；③收起帧的重叠全部来自新挂载条目无坐标（邻居陈旧在收起方向只产生间隙）。候选修复为「提交内坐标绑定 + 挂载 ref 定位」。该轮 CI 之后画廊 G2 首次失败（run 42462857980，锚漂移 295px），独立诊断（tmp/frontend/ci-ui-fix-r3/audit-regression/REPORT.md）与 CI 轨迹回传分析确认：本波 159/295 补偿经业务 geometry 事件后才发布原生 scroll、pending 守卫未拒绝本波补偿，观察到的坏帧是「原生 scrollTop 先行、可观察几何更新滞后」；但滞后窗口内 parent geometry/布局 effect 已多次重写、timer 采样仍坏，哪次冗余写触发布局未证。诊断同时修正证据口径：CI 为 Edge/Chrome 156、本地 verify 为 157，「同浏览器唯一差异是负载」不成立；style 写入插桩未捕获任何 `style.set` 事件且无安装命中自检，不能据此宣称全部 style 写入者闭合、排除中间覆盖；上一 run 的原点节点现象在本 run 未复现，不能跨 run 等同根因。因此 r3 的社交修复与画廊补偿布局读取（候选 A）都是可测试候选，有效性由目标 CI 证明。

探针证据同时否定了两个候选机制：直写读到滞后测量（resizeItem 先更新 itemSizeCache/version，notify 后的 memo 读取必然新鲜）；commit 内部 mutation/layout 被拆进不同任务（React 19.2 commitRoot 三阶段同步，suspensey commit 只整体推迟）。本机 6×/12× CPU 节流均单任务收敛，CI 的确切任务交错未能在本地复现；修复依据是绑定结构 + 不变量论证，不是对 CI 交错的直接复验。

2026-11-09 的精确诊断提交 `87119b2`（CI run 42602153277）首次采到有效 style setter、inline、computed 和节点身份：Edge 156.0.4314.58 中，社交水合坏帧的 `9002` 已写入 `translateY(322px)`、测量 start=322，但 computed matrix 的 Y=0、rect top=90；连续3个样本11张卡堆在同一原点。展开后邻居同样是 inline=1588、computed=644，随后还有4px差。该轮画廊四波均为0，不把它当作旧159px的同次复现。

根因是系统 `prefers-reduced-motion: reduce` 分支给所有元素设置 `transition-duration:0.01ms!important`。没有声明 transition 的虚拟节点默认 `transition-property:all`，因而从“无过渡”变成了短时间 CSS transition；不是简单地把既有动画压短。本机同一 Edge 157、同一 CSS 的 no-preference/reduce 对照直接捕获 `CSSTransition`（transform，duration=0.01ms，currentTime=0，startTime=null，fill=backwards）：inline 已新，computed 仍取旧几何，而原生 scrollTop 已生效。总高的 height 同样插值；社交正文折叠/展开的 margin-bottom 从4到8px则造成先+主高度、再+4px的二段测量。

只切换本机应用的媒体偏好、不改产品代码后，原门禁真实复现画廊第二波 `image-013` 最大295px、最终0；社交专项复现3帧/maxOverlap10和展开往返重叠。此前本机默认偏好全绿与CI失败的差异因此有了可控复现。旧CI 159/295px的序列与此机制吻合，但其未记录的 computed 值不被补写为历史事实。

第一版CSS候选只给五个虚拟几何/社交边距节点设置 `transition-property:none!important`，全四组几何通过后，完整门禁两次在1536-reduce源行Tab失败。第二次完整快照证实焦点确实在NASA主按钮、窗口有焦点、没有弹窗；Tab跳到下一源行，跳过刷新和编辑。父actions虽computed visible且transition:none，子button仍因默认all与继承visibility生成短CSSTransition。真实Edge最小对照直接复现子按钮computed hidden，且原生Tab跳过；五节点候选不能覆盖这个同根问题。

原reduce注释用“保留transitionend / animationend以免状态悬挂”解释非零duration。2026-11-09核对产品源码、动态媒体事件列表及实际运行依赖后，只有 `useEnteringClass` 消费animationend，没有产品transitionend/run/start/cancel消费者；React DOM只是提供事件注册/派发。旧解释对transition的假定没有当前实现依据。最小正控又确认只把transition改0s后，animation仍为0.01ms且实际animationend触发。

## Decision

当前决定：只在 `prefers-reduced-motion:reduce` 全局规则中把 `transition-duration` 从0.01ms改成0s，保留 `transition-delay:0ms`、`animation-duration:0.01ms`、已有animation:none例外与加载指示器旋转。撤去五节点候选，不继续为几何或继承visibility增加逐节点例外。该模式下颜色、显隐、位移和尺寸的CSS transition立即完成；no-preference下既有hover、入场、展开/收起体验不变。

门禁显式使用 no-preference 与 reduce 两个媒体模式，重复原两视口 gallery/social/五布局和键盘场景；原采样相位、过程≤3px和重叠0断言不变。模式标签进入证据，reduce 社交 fixture 使用独立ID空间，避免第一模式的正文缓存代替第二模式水合。新增最小真实浏览器契约覆盖同次样式更新的坐标/总高/社交边距、源行父子可见性与原生Tab顺序、reduce animationend正控；它不替代后续原应用场景，不给原Tab检查增加重聚焦或等待。

以下既有几何写入通道本次保留，没有顺手重写已审 Timeline。它们仍从同一虚拟器测量真值取值，但不能再被当作上述 CSS 根因的修复证据：

1. 插入定位：行虚拟项 ref 回调 measureRowElement（与画廊 measureGalleryElement 同模式）在 commit layout 阶段附着（paint 前）执行 measureElement 同步测量，并按当次渲染的测量写 transform；data-card-id 与 measurement.key 的守卫拒绝不匹配条目的坐标写入（测量与缓存注册仍照常进行）。该写在被插入元素自身上进行，不依赖 querySelector/根查找/effect 时序；正常 enabled、key 匹配的挂载定位由此保证，不承诺「任何环境都无坐标首帧」。
2. 提交内坐标绑定：行虚拟项包装为 TimelineRowItem 组件，行项自身 layout effect 按当次渲染的 vi.start 直写 translateY（依赖 [vi.start]）。行 effect 读的是 render snapshot（vi.start 为当次渲染值），不是实时最新值：同一 commit 内 child report 先经 notify 直写更新值、行 effect 随后可能暂写本次 render 的旧值，存在 commit 内暂态。实际保证是：任何携带 start 变更的 commit 把该条目的 element 直写绑进同一 commit（paint 前必执行）；父级无依赖兜底 effect 在全部后代 effect 之后运行，以最新测量写末值；经过该序列后 paint 前收敛，不承诺中间态不存在。
3. commit 间隙收敛：syncRowGeometryNow 保持更新直写者——row 虚拟化 onChange（每次 notify，含 measureElement 的 RO 测量路径）与 SocialCard 高度上报链，覆盖无 commit 在途时的 resizeItem（如 RO 驱动的 +4 二段上报）。
4. 全窗口兜底：父级无条件 layout effect 每次 render 后全窗口直写，保持 React 快照与 DOM 同值并修正暂态。
5. 采样对齐：动作逐帧采样从 rAF 相位延到渲染步进结束（rAF→setTimeout(0)），即在本帧 ResizeObserver 收敛之后取样；这是相位过滤手段，不是逐帧 paint 快照，rAF 之间被 paint 的帧不进入采样。重叠阈值保持 0，场景与断言不变。
6. 画廊补偿发布前布局读取（旧候选 A）：consumeDeferredScroll 在几何写入后、补偿 scroll 前读 grid.offsetHeight，原意是强制收敛布局。后继 `9e9319a` CI 42519067493 仍失败159px，2026-11-09本机reduce也失败295px，已证该读取不能关闭 CSS transition 窗口；它本次暂留，仅为避免和CSS修复混入另一组JS时序改动，不再承担“已修复”的结论。后继清理须单独比较补偿发布与重启用边界。

第一轮记录的「React 快照 transform 被陈旧直写覆盖」假设经后续证据修正：删除 JSX transform 后，插入帧缺写入者（第二轮）与更新路径跨通道窗口（第三轮候选）是继续工作的机制假设；「单一写入者」修正为「单一测量真值、分层写入通道」——每层通道读同一 memo 体系，但 g2 轨迹的 style 插桩未命中不能证明写入者闭合或排除中间覆盖。

## Alternatives considered

恢复 JSX 内联 transform：能消除插入堆叠，但重新引入第一轮已实证的「提交渲染用滞后测量写陈旧坐标」，collapse/expand 帧会再次 paint 旧位置。

行虚拟化切 directDomUpdates（照抄画廊适配器写路径）：也能收敛更新，但需要引入 containerRef 契约并新增一批写入者；行项 layout effect 复用既有测量真值，改动面小且与画廊实例同构。

卡片定位前隐藏（visibility）：rect 不变，回归断言仍会记重叠，只是把可见问题藏起来，不解决时序缺口。

放宽重叠阈值或容忍少量帧：把真实缺陷合法化，验收明确禁止。

画廊候选 B（让先长高再滚或先滚后补出现另一时间窗口的时序重排）与候选 C（改变过程无感验收口径）：独立裁定均不采纳——没有当前授权内的收益证据，C 改变既有过程无感验收。

最初试过全局默认 `transition-property:none`，它能阻止未声明过渡的节点被非零duration激活，但原候选希望只改已证阅读几何，所以曾选择五节点例外。随后源行子button继承visibility的反例证明该局部选择漏掉同根路径。也考虑过再给源行button增加例外，但没有实施；在确认没有transitionend状态消费者后，选择只在reduce模式统一transition-duration:0s，避免逐节点追补。这不是全局关闭animation；animationend与加载反馈仍保留。

## Consequences

ref 回调读取 measurementsCache 依赖创建该元素的 render 已算出测量 memo（渲染出元素即保证 memo 含该条目），key 守卫防止复用/错位；data-virtual-start 等 dataset 仍由 React 提交，允许滞后一帧，产品几何与回归断言都以 rects 为准。wrap 首帧空窗口仍可能被 paint（视口出现空列表一瞬），无重叠、与加载态语义一致。每次 notify 直写同值 transform、每次含 start 变化的 commit 逐条目直写，成本为窗口内 N 个元素样式赋值。若未来把行虚拟化切到 directDomUpdates，适配器 applyDirectStyles 会与现有通道并存，届时必须收敛为单一通道，不能并存。

候选 A 没有已证性能上界：一次布局读取仍可能强制布局整个相关文档。本次按其失败后的约定停止叠加getter/等待，并以computed style和实际CSSTransition闭合根因。CSS修复没有新增DOM读取、订阅或调度，但也不宣称现有JS补偿链已最简。旧临时诊断提交22f62d0已随原修复退出；新诊断87119b2有独立宿主透传审计，仍只提供证据，不能凭插桩运行一次绿关闭无插桩场景。

统一0s让reduce分支不再触发CSS transition事件；当前无状态消费者，未来新增依赖此类事件的状态推进须同时提供无动效完成路径。CSS animation事件、显式加载旋转与默认媒体模式各自保留，不把transition和animation混为同一生命周期。2026-11-09六组最小对照为两媒体×原0.01ms/五节点/统一0s：原和五节点的reduce子按钮均hidden且有visibility CSSTransition，统一0s同步可见并按原生Tab到refresh/edit；统一0s与五节点都同步更新几何，原规则滞后；三种reduce方案的animationend均实际触发。此证据证明机制与最小宿主行为，不能替代当前最终候选的全门禁与目标CI。
