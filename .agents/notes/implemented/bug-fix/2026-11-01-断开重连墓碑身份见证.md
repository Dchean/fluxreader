# Agent Note: 断开重连的墓碑身份见证

Status: implemented

## Problem

`commit_disconnect` 刻意保留订阅删除墓碑（feed 墓碑按 URL 存、无账号归属），
为的是「断开后重连同一账号」时仍防复活（TASK-055）。但断开后的下一次账号
保存里 `read_credentials` 返回 `None`，`resolve_save_plan` 把它归入
`old_was_empty`，该提交分支只重置游标、不动墓碑。于是「A 断开 → 连接 B」：
A 的 feed 墓碑继续压制 B 的同 URL 订阅导入（导入把墓碑 URL 视为本机已删，
不导入不绑定）——F05「旧账号删除意图不得污染新账号」在断开路径被绕过；
直连换号（凭据在场）走 `identity_changed` 分支会清墓碑，唯独这条路径漏掉。
分类墓碑（v24 起按 `account_key` 隔离）对异账号本就不生效、也不会被异账号
回收，没有这个泄漏。

## Decision

- `commit_disconnect` 在凭据仍在场时，把断开账号的身份指纹明文写入
  `settings['sync_last_disconnected_account_key']`。指纹用
  `sync::account_key`（协议|规范化服务器根|用户名）单点实现；不经
  `read_credentials`——断开是损坏密文的恢复路径，任何 DPAPI 解密失败都不得
  阻断断开，这里只读 `sync_protocol`/`greader_endpoint`/`greader_username`
  三个非加密键。
- `commit_account_settings` 的 `old_was_empty` 分支：见证存在且不等于本次
  连接的 `account_key`（同一单点函数、与 `folder_tombstones_for` 同样的
  字符串比较语义）→ 执行 `db::clear_feed_tombstones`，与 `identity_changed`
  路径同一动作、同一覆盖语义；见证相等 → 保留（重连同一身份，TASK-055）；
  见证缺失 → 保留（真首连，纯本地墓碑维持既有语义）。见证不消费，每次
  断开覆盖；只有凭据为 `None` 的保存（必然刚经历一次断开）才读它。
- 分类墓碑不在该路径清理：非空 key 条目对异账号不生效
  （`folder_tombstones_for` 按 key 过滤），空 key 全局墓碑按
  [分类墓碑的账号隔离与失败关闭](../architecture/2026-10-14-分类墓碑账号隔离.md)
  对所有账号生效且无自动解除路径——清空前者违反「隔离比清空更强、不许顺手
  统一」，清空后者违反全局契约。feed/分类墓碑的清空策略不对称维持不变。

## Alternatives considered

### `old_was_empty` 一律清墓碑，不判身份

实现最省，但「断开后重连同账号」的防复活直接失效——正是 `commit_disconnect`
刻意保留墓碑要服务的场景，等于用本卡的泄漏换回 TASK-055 的复活窗口。

### 用 folder_tombstones_v2 的非空 key 当「换过身份」的见证

不落新键、复用现成归属字段，但不完整：用户只删过订阅、从未删过分类时
不存在任何非空 key 条目，泄漏原样保留；而且让 A 的墓碑数据充当身份账本，
把墓碑语义和身份判定耦死。

### 断开时把端点/用户名留在 settings 里当见证

免新增键，但 `sync_status` 用 `endpoint.is_some()` 判 `connected`、
config_sync 用三键快照做待确认建议的匹配——残留值会把断开状态误报成
已连接、污染建议 CAS，两处读取方都得跟着改语义。

### 断开时立刻清墓碑

被否的主案同款：丢掉重连同账号的防复活，且断开命令无法知道用户下一次
连接的是谁。

### 把 feed 墓碑改成按账号归属的存储形状

隔离比见证更彻底，但 feed 墓碑的清空策略与 v1 legacy 命名空间的字节保留
绑定（见 2026-10-14 Note 的不对称说明），改形状要连动只读消费方
（`subscriptions.rs` 的 `feed_url_tombstoned`），超出本卡写集与风险预算。

## Consequences

- 收益：断开 → 连接不同账号不再继承旧账号的删除压制；重连同一账号的
  行为（数据、游标、墓碑）逐字节不变。
- 代价：新增一个 settings 键；它尚未列入 `commands::settings` 的
  `PROTECTED_SETTING_KEYS`——通用设置 IPC 理论上可写它（第一方前端无此
  路径，最坏影响是单次清理决策被篡改），补入保护表是一行遗留。见证值含
  用户名，与 `folder_tombstones_v2` 的 `account_key` 同级明文，非新增暴露面。
- 验证：`commands/sync.rs` 的
  `disconnect_reconnect_clears_feed_tombstones_only_for_new_identity`
  覆盖见证写入、端点等价形态归并后的重连同身份保留、新身份清理、A 的
  分类墓碑按 key 隔离保留；本机仅 `cargo fmt --check` 与静态自查，行为
  验证由 CI rust job 承担。
