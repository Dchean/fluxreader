# Agent Note: 画廊方向键行优先语义

Status: implemented

## Problem

画廊（image 布局）行优先 lanes 下，方向键把 ArrowDown 与 ArrowRight 等价（都 = 下一卡 +1）、ArrowUp 与 ArrowLeft 等价（都 = -1）。用户按 ↓ 期望「同列下一行」，实际却横向跳到下一列——视觉与按键语义错位（审计 C-P2-2，roadmap §七点名）。

## Decision

**按键语义按几何修正**：`ArrowRight = +1`（同排下一卡）、`ArrowLeft = -1`（同排上一卡）、`ArrowDown = +lanes`（同列下一行）、`ArrowUp = -lanes`（同列上一行）。`lanes` 即 `GalleryLayout.resolveGalleryLaneCount` 的列数（≤800 → 2，≤1200 → 3，否则 4），由 Timeline 经新 prop 传入 GalleryCard。

**越界用 clamp（不跳列、不回绕）**：目标下标越出条目范围（首尾行按 ↓/↑、末卡按 →、首卡按 ←）时**不动**——复用 `moveCardFocus` 既有的越界 no-op，即 clamp 语义。选 clamp 而非跳列/回绕是按最小惊讶：回绕（末卡 → 首卡）会让焦点瞬移整个列表；跳列（末列 → 下一行行首之外的补位）依赖贪心分配不存在稳定网格。

**±lanes 是工程近似，如实声明**：react-virtual 的 lanes 是「贪心最短列」分配，卡片高度不均时同一列的相邻行下标差不必恰为 lanes；等高时退化为轮转（index % lanes）恒成立。±lanes 是同列语义在贪心模型下的最佳静态近似（真实同列查询需要反查列成员数组，虚拟化窗口下成本不值）。布局与列分配的既有事实见[画廊有界渲染](../feature/2026-10-16-画廊有界渲染.md)。

反向注释：`Timeline.tsx` GalleryCard 两个 keydown 分支。

## Alternatives considered

### Why not ArrowDown = 跳到「视觉正下方」的卡片（反查列成员）？

视觉精确需要维护 index→lane 的反查（贪心分配随测量高度动态变化），虚拟化下目标卡常未挂载、其 lane 未知；为方向键维护一份全量列映射与「有界渲染」的前提冲突。±lanes 在等高（绝大多数瀑布流观感）下就是精确值。

### Why not 回绕（末卡 → 按方向绕到对面）？

5000 项列表里一次回绕 = 焦点从列表尾部瞬移到头部，视觉上等于失焦；单列布局的 J/K 回绕是行模型语义（相邻关系成立），网格的行列回绕没有对应几何。

## Consequences

**收益**：画廊四方向键与瀑布流几何一致；边界行为可预期（越界不动）。

**代价与已知边界**：高度悬殊的瀑布流里 ±lanes 可能落到「斜向」位置（近似误差），重访信号是用户报告方向键「跳格」；回归网 `tools/component-tests/gallery-virtual.test.mjs` 锁四方向落点（等高夹具下精确断言）与边界不丢焦点，旧「ArrowDown=+1」断言已随语义改写（先红后绿取证）。
