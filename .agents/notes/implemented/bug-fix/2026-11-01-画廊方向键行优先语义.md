# Agent Note: 画廊方向键的索引近似

Status: implemented

## Problem

旧画廊上下与左右都只移动一个索引，上下方向缺少区别。但自然高度瀑布流按最短列分配，索引相邻并不等于视觉同列相邻。

## Decision

左右移动±1，上下移动±lanes，lanes沿GalleryLayout断点传入；越界不动，不回绕。这里的±lanes是索引近似，等高轮转时可对应同列，混合高度时可能斜向。

本决定没有建立“最佳静态近似”的比较证据，也没有证明精确列查询成本不可接受；不能把选择理由写成这两条客观结论。当前行为及列模型见[画廊虚拟化](../feature/2026-10-16-画廊有界渲染.md)。

## Alternatives considered

按视觉正下方查找可更精确，但需确定未挂载目标、测量后列归属变化及焦点滚入规则，当时未扩大到这套模型。回绕会让长列表的首尾焦点大幅移动，选择越界no-op保留明确边界。

## Consequences

上下动作与左右有区别，但不能宣称四方向都与任意瀑布流几何一致。混合高度下的跳格是已接受的近似成本；2026-11-06屏外挂载和Tab焦点问题另见[界面与媒体路线](../../../../docs/roadmap.md#interface-and-media)，不由±lanes覆盖。

## Validation

gallery-virtual组件回归的等高夹具验证索引与边界，未证明所有自然比例分布的视觉邻接。需要重访时以混合高度真实几何和焦点可见性决定方向语义，不用等高测试冒充视觉精确。
