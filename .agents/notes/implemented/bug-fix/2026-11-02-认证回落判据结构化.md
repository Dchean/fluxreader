# Agent Note: 会话缓存认证回落的结构化判据

Status: implemented

## Problem

会话缓存曾从错误文案的 [auth]、“→ 401/403”判断是否剔除缓存并重认证。普通 URL 或协议回显可以含同样文字，且改文案会改变行为。认证性质必须在仍有状态码/认证语义的构造点保存。

## Decision

AppError 用内部 is_auth 标记及 auth/auth_if 构造器表示认证失败，SyncReport 用 serde(skip) 的 auth_failure 汇总；HTTP 捕获点先 note_client_error，再保留原错误文案。report_has_auth_failure 只读结构化信号，不再回退字符串匹配。401/403 和 Fever auth!=1 属认证失败；DB/合并及普通协议错误不因文字相似而触发回落。

未读差分的批量/逐 id 存在性探测也登记 client 认证信号，即使其面向用户的错误只以聚合计数呈现；这些路径因此参与当前认证回落判定。

错误 Display、IPC 字符串数组形状保持；此决定只引入回落所需的 bool，没有把整个错误报告改为新公共枚举。

## Alternatives considered

- 标记缺失时仍串匹配：保留原伪造和文案耦合，不能作为安全的过渡。
- 将 SyncReport.errors 全量改成结构化枚举：长期类型表达更丰富，但会改前端 wire 和大量错误写入面；当时只需一个内部认证信号，收益不足以覆盖扩面成本。
- 任务外全局计数器：并发阶段会相互污染，而且没有对应 report 的起点快照。

## Consequences

回落不再依赖文案；新增客户端错误捕获点仍需保留认证属性。认证后重试成功不应抹掉首轮已经提交的变化，但当前存在 SYNC-03：真实入库后重认证成功，最终 has_data_change=false。这是报告合并的另一个缺口，未由认证标记解决，见 [同步正确性](../../../../docs/roadmap.md#sync-correctness)。

error.rs 的认证标记测试、session.rs 的非串匹配测试和 session_cache_e2e 的单次重认证链是回归入口；这些夹具不替代真实服务端验收。
