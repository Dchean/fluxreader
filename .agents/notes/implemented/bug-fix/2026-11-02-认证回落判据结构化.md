# Agent Note: 会话缓存认证回落的判据结构化——标记取代错误文案串匹配

Status: implemented

## Problem

会话缓存（W3-1）的 401 回落判定 `report_has_auth_failure` 串匹配 `report.errors` 文案：`[auth] ` 前缀或「→ 401 / → 403」子串。错误串由 AppError Display（`[code] message`）与 greader/fever 状态码文案在**各捕获点**组合而成，判定发生在错误早已变成 `String` 的报告层——「URL 类错误理论上可伪造标记」是当时已登记的边界（原注释自认）：任何路径里恰好含「→ 401」子串的普通错误（恶意 feed 的 URL 进错误消息、协议回显等）都会触发一次多余的剔除重认证；反过来，判据绑定文案格式也意味着 greader/fever 改错误措辞会静默弄坏回落。

## Decision

判据从「文案形状」改为「错误构造点的结构化标记」，错误文案与 IPC 面逐字不变：

- **标记**：`AppError` 增加私有 `is_auth`（`serde(skip)`）+ `auth()` / `auth_if(bool)` 构造器与 `is_auth_failure()` / `is_auth_status(u16)` 判据。打标点收敛在 greader.rs（ClientLogin / GET / action-token / 两条 POST 的 401/403 状态码错误）与 fever.rs（`Fever {action} → {status}` / `Fever mark → {status}` 的 401/403、`auth != 1` 的 AUTH_FAILED_MSG、probe 的「认证被拒」401/403）。
- **汇入**：`SyncReport` 增加内部信号字段 `auth_failure`（`serde(skip)`，同 `binding_incomplete` 的选型）与 `note_client_error(&AppError)`——各 HTTP 捕获点在把错误文案 push 进 `errors` **之前**调用（文案拼接原样保留）。捕获点分布在 greader_pull（5 处）、fever_pull（5 处）、push（2 处）、subscriptions（11 处，其中 outbox 执行器的 `exec_edit_item`/`exec_unsubscribe_item`/`exec_unsubscribe_recovery` 为此增加 `report` 参数）。DB/合并类错误无认证标记，不登记。
- **判定**：`report_has_auth_failure` 改读 `report.auth_failure`，`is_auth_failure_message` 删除；消费点（phases ×4、push、subscriptions）签名不变零改动。`probe_unread_diff_candidates` 的存在性探测本就把 client 错误吞成聚合计数（无错误文案），改动前后都不触发回落，行为一致。
- **单测**：`report_has_auth_failure_reads_structured_marker_not_text` 锁「非串匹配」——文案含「→ 401」但未标记不得触发；401/403/Fever api_key 三类标记都必须生效；error.rs 单测锁 Display 与 IPC 序列化形状不受标记影响。

session_cache_e2e 的 401 用例不经改动保持绿：端到端路径（item_ids 401 → greader_pull 捕获点登记 → states_phase 回落重认证恰好一次）全部走生产接线。

## Alternatives considered

- **混合判定（标记存在看标记、否则回退串匹配）**：过渡期最平滑，但串匹配的伪造口子原样保留，等于没修；标记覆盖全部 client 构造点后，回退分支是死代码。
- **把 `SyncReport.errors` 改成结构化条目（元素带标记）**：类型上更"正统"，但 `errors` 是 IPC 面（前端收字符串数组），需要自定义 Serialize 保形状并改遍全仓 100+ 处 `errors.push(format!(...))`——为携带一个 bool 重写整个报告写入面，收益与 `note_client_error` 一行登记相同。
- **全局/任务本地计数器（构造点自增、判定点比对）**：不用动捕获点，但进程级状态在并发阶段间串味（漏报/误报都可能出现），且 `report_has_auth_failure(&report)` 的签名决定它拿不到"本轮起点快照"，语义靠不住。

## Consequences

- `error.rs::auth_marker_tests`：标记的构造器语义、Display/序列化形状逐字不变。
- `session.rs::report_has_auth_failure_reads_structured_marker_not_text`：非串匹配 + 三类构造点生效 + 纯网络失败不误报。
- `tests/session_cache_e2e.rs::auth_failure_on_cached_session_reauths_and_retries_once`：端到端回落恰好一次（只读核对，未改动）。
- 行为验证由 CI 的 rust job（windows-latest）承担；本机不可链接，仅 `cargo fmt --all -- --check`。
