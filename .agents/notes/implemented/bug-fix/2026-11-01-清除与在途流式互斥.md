# Agent Note: 单项 AI 清除与在途生成互斥

Status: implemented

## Problem

清除译文先等待后端再删前端 raw 标记时，后续未消毒 delta 可能进入 HTML 渲染分支；生成落库和 Done 后回读还可能复活刚清除的产物。旧清除路径也不区分 kind，清摘要会误删失败译文保留的 raw 标记。

## Decision

单项 clearAiProduct 在调用后端前检查以文章 id/kind 为键的 aiInFlight，验签或生成在途即拒绝清除；提示等完成，长时间无响应可重启，不承诺不存在的“停止生成”按钮。摘要同样受闸，避免生成落库与清除交叉。

流式译文每次追加 delta 前确保 rawTranslatedIds[id] 为 true，使未消毒片段走文本渲染。摘要清除只触碰摘要状态，不能拆散译文“失败半截 + raw 标记”这一对；译文清除才删除自己的标记。

单项清除成功后，只有请求代次仍等于发起清除时的代次才递增。旧 Done 回读据此失去写权；若 await 期间已有新请求接管，不能误杀它。回读不并入 aiInFlight：现有契约允许 invoke settle 后发起下一笔，逆序回读由代次处理。

2026-11-07后继边界：显示验签另绑定正文输入、已保存配置与显式产物变更代次，并按最新读取序号拒收旧check/hint/refresh。清除后旧状态不能恢复partial；生成终态强制新读取，不复用生成中的早期状态。批量年龄清理在后端也覆盖仅片段条目并推进epoch，旧token不能再写回；这些修复分别由前端第二批和数据AB独立审计验收，不由本篇单项互斥自证。

## Alternatives considered

只补 raw 标记不能消除后端缓存复活；只设硬闸又依赖所有删标记入口永远正确。两者分别守住清除交叉和 delta 渲染。排队到生成结束再清除会新增等待/取消状态机，当前选择明确拒绝。

把回读也算作在途会改变 invoke 结算后即可重试的契约。清除成功后无条件推进代次更短，却会丢弃清除期间新发起请求的有效回包，因此需比较捕获代次。

## Consequences

单项清除的作用域是文章与产物kind，不能外推为所有清理、验签和批量入口都已安全。2026-11-06旧AI状态迟到覆盖和仅片段批清不推进代次的反例保留；2026-11-07已由上述分别负责的后继修复关闭。原始失败与新的定向证据按各批保留，不能仅看到单项硬闸就推导这些边界已验证。

每个 delta 多一次标记查找，标记已在时无需额外写状态。被拒清除没有后端副作用；单项清除后旧回读不能获得该代次的写权，但清除本身不取消模型服务端的请求。

## Validation

tools/frontend-tests/ai-cache-signature.mjs的b3-6覆盖单项在途拒绝、先补标记再追加、跨kind隔离与清除后迟到回读。后继ai-status-lifetime覆盖显示校验资格/逆序/清除/生成终态，后端批清测试覆盖仅片段epoch和拒旧token；前端第二批与数据AB各自独审通过，不把组件或mock结果冒充真实provider调用。
