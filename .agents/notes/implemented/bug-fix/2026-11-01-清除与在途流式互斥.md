# Agent Note: 清除与在途流式互斥

Status: implemented

## Problem

`clearAiProduct`（src/store/slices/ai.ts）先 `await` 后端 `ai_clear_cache`，返回后才清前端状态并删除 `rawTranslatedIds[id]`。若该条目的翻译正在流式生成，删除标记后后续未消毒 delta 仍会追加进 `translatedContent`，而 Timeline 的卡片渲染（`rawTranslatedIds` 未命中时）走 `dangerouslySetInnerHTML`——未消毒模型输出直接进 HTML 路径（XSS 窗口）。同一组合还有一层后端竞态：清除删掉缓存后，生成完成回写（Done + 回读落账）会把刚清空的缓存复活。

## Decision

**清除与在途生成互斥，双侧设防：**

- **硬闸（a）**：`clearAiProduct` 在发起后端调用前检查在途表 `aiInFlight`（验签 + 条件生成整链，键 = `aiKeyOf(id, kind)`）；命中即拒绝——不调后端、前端状态一字不动，toast「生成中，先等完成或停止后再清除」。摘要与译文同闸（摘要无 XSS 面，但后端清除与生成落库同样互斥）。
- **自愈（b）**：`streamAiDelta` 对 `translatedContent` 的每个 delta 先检查 `rawTranslatedIds[id]`，缺失即补回 `true` 再追加。任何路径在流式在途期间丢掉标记（含清除 await 竞态残留），下一个 delta 都会把渲染拉回纯文本分支。

**不变量：凡 `translatedContent` 可能含未消毒 delta，`rawTranslatedIds[id]` 必为 `true`。** a 挡住已知的制造窗口的组合，b 让不变量对流式期间的一切标记丢失自愈，不依赖「今后不再新增会删标记的路径」这一全局论证。

回归钉在 `tools/frontend-tests/ai-cache-signature.mjs`（b3-6）：在途清除被拒（不调后端、标记保留）、拒绝后流式继续按纯文本口径、标记丢失后 delta 自愈补回、摘要在途同闸。

## Alternatives considered

- **只做自愈（b）**：改动最小、不新增用户可见拒绝，但窗口只是收窄而非消除——清除的 set（删标记 + 清产物）与下一个 delta 到达之间，渲染路径短暂回到 HTML 分支；且后端清除与生成落库互相复活/清空的竞态完全没堵。作为独立方案不充分，保留为纵深防御。
- **只做硬闸（a）**：挡住本缺陷的组合，但不变量的成立依赖审计「所有删标记路径」，未来新增清理入口时不设防；与 b 组合后才能宣称不变量。
- **清除排队等待在途流结束再执行**：避免拒绝用户，但「已清除」反馈时刻与真实清除时刻分离，还要处理流失败/重试与清除动作的交叉状态机；拒绝 + 提示的语义最小且可预期，用户等生成收尾后重按即可。

## Consequences

生成/验签在途期间清除入口返回 `false`（不执行），提示文案统一为「生成中，先等完成或停止后再清除」——验签窗口（毫秒级）也按此文案拒绝，覆盖面略宽于字面「生成中」，可接受。delta 路径每发多一次 map 查找，标记健在时零写入、无额外渲染。Timeline/ReaderProse 的渲染口径不变，本契约由标记单点保证。
