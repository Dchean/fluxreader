# Agent Note: 入口校验、真实滚动与语义单点的事故教训

Status: implemented

## Problem

2026-09 的发布前自检发现多组表面无关、根因相同的问题：前后端都假定对方会校验分类，程序性滚动触发了用户标读，同一设置在刷新、查询、配置导入的判据不一致。本篇保留这些事故为何要求边界清晰；逐项进度和当时遗留不再作为当前状态。

## Decision

- 前端把无分类规范为 null，后端仍校验实际 folder_id 是否存在。UI 校验帮助用户纠正输入，后端校验保护所有调用入口，两者职责不能互相代替。
- 列表滚动标读必须同时有真实输入依据和非程序性滚动依据。J/K、搜索定位、返回锚都会产生 scroll 事件，事件发生本身不证明用户读过途中条目。wheel、touchmove、pointerdown、翻页键置输入闩；程序性定位进入抑制窗口。
- 同一业务含义沿入口到消费者使用同一判据；共享的是语义，不是机械消除所有重复代码。范围派生、分类存在性、设置值域若各写一套，单侧检查会遗漏交界错误。

原文的两项安全取舍已分流：流式译文保持 React 纯文本呈现、完成后才读净化 HTML，理由是逐 delta 净化会破坏跨块标签，详见 [可渲染正文安全边界](../architecture/2026-10-08-可渲染正文安全边界.md)。早期接受通用 get_setting 返回敏感值的决定已被 [通用 IPC 与隐藏文本收口](2026-10-31-安全横向面收口.md)取代，当前通用读写拒绝敏感键；不能继续把旧开放行为当作不修边界。专用 AI 设置命令仍可能把用户需要编辑的配置交给前端，这不等于整个 webview 已成为凭据隔离边界。

## Alternatives considered

- 只在前端挡非法分类：合法 UI 之外的调用仍可绕过，且旧入口可以带来不一致输入。
- 只看 scroll 事件标读：最省代码，却无法区分手势与程序定位，误标会写回远端，代价高于多一个输入闩。
- 逐块剥标签再展示译文：跨块 HTML 可能被切断；纯文本直到完整产物净化更容易解释和验证。
- 保留旧敏感 IPC 开放以节省专用命令：当时以威胁模型/改动成本为理由保留，随后实际安全审计确认通用能力过宽，已收口；该旧理由仅作为被取代的历史。

## Consequences

这些边界减少入口分歧，但不证明所有行为已正确。真实输入闩仍需随新增手势或定位路径维护；CSP 是内容策略的纵深防御，不能替代流式纯文本和完成态净化。缓存、设置和同步的当前未修项集中在 [roadmap](../../../../docs/roadmap.md)，不再从本篇历史缺陷清单复制当前待办。

2026-11-06 审计实际验证了通用敏感 IPC 拒绝和有限净化输入；它没有穷尽全部攻击变体。历史检查数字与旧发布状态保留在 Git 历史。
