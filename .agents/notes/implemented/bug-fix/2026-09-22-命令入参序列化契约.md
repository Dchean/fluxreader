# Agent Note: 命令入参序列化契约

Status: implemented

## Problem

列表 IPC 曾发送 snake_case 的对象字段，而 Rust 的 ArticleListArgs 使用 serde camelCase 映射。feed_id、folder_id、only_unread、only_starred、only_today、newest_first 等字段未按预期反序列化，默认值让请求看似成功，却丢失筛选语义。limit 这类两种命名下相同的字段不属于该问题。

容易混淆的是两个独立边界：Tauri 命令参数的命名规则由 #[tauri::command(rename_all = ...)] 控制；参数内部结构体的字段名由该结构体自己的 serde 属性控制。前者不会替结构体决定内部字段名。

## Decision

ArticleListArgs 保持 snake_case 字段，与前端 args 对象逐字一致，不给结构体增加 camelCase 重命名。命令参数名与内部对象字段分别核对，不能为了表面统一一次替换两层。

此决定保存的是 IPC 契约与最小修复的理由，不要求所有其他命令采用同一种命名。新增或调整 DTO 时，应把真实序列化输入送入生产反序列化类型，而不只测试 TypeScript 对象形状。

## Alternatives considered

- 改前端全部发 camelCase：可以成立，但需要同时迁移调用方和夹具，是一次外部契约变更；删除结构体上不匹配的重命名属性影响更小。
- 在每个命令增加字段数量检查：默认值和可选字段使数量不能可靠表示正确性，还增加样板逻辑；真实 DTO 反序列化与命令行为断言更直接。

## Consequences

字段契约可以直接测试，但 Rust 编译成功仍不能发现调用方拼错键名。生产 ArticleListArgs 的 serde 反序列化回归位于 src-tauri/src/commands/articles.rs；前端回归检查实际发出的 args。两侧证据要共同解释，不能把手写假后端等同于真实 serde。

真实命令调用仍须核对外层参数和内部结构体两个边界，不能仅由 serde 结构体单测推断 Tauri 装配已运行；当前验证范围见 [roadmap](../../../../docs/roadmap.md#verification-boundaries)。
