# Agent Note: 订阅绑定、响应上限与媒体数值边界

Status: implemented

## Problem

三条小边界曾被调用方绕过：legacy订阅创建后精确URL查找漏绑定且吞DB错误；favicon首页与全文提取直接完整text读取；SMTC的Duration::from_secs_f64只防负值，超大有限值或无穷可使专用线程panic。

## Decision

legacy创建后的绑定改用feed_id_by_url_normalized，查找错误记报告并保留队项，不当作“本地已删除”。这是调用口径收敛，不是规范URL能取代精确远端身份的保证。

favicon首页和全文经read_body_capped使用16MiB累计上限，字节再按Content-Type charset/BOM解码，保留GBK等站点；favicon超限走既有失败缓存，全文返回responseTooLarge。favicon基础URL保留显式端口，避免探测另一个origin。封面代理后继以25MiB复用同一helper，见[图片收体决定](2026-11-02-封面图流式收体闭合旁路.md)。后继修复将全文 HTML、相对资源和封面的基址统一取最终响应 URL，全文提交 token 同时复核请求 URL 与内容身份/修订；URL 在请求中变化时拒绝旧页面。正文已提交后补封面失败只记警告，不把正文成功返回为失败，见[内容身份](../architecture/2026-10-12-订阅条目与共享内容身份.md)。

media_secs先把NaN/负值归0，把超大值和正无穷钳到7天，再交Duration构造；三处SMTC数值入口共用。7天是产品选定上限，不以“任何真实音频都不会超过”论证。

旧文曾把异账号outbox清账列为待裁决，随后已由[订阅outbox生命周期](2026-11-02-订阅outbox生命周期终点.md)决定；本篇不再把它列作当前未做项。

## Alternatives considered

单条绑定错误中断整轮会扩大失败面，保留队项并继续其他订阅符合既有阶段语义。favicon再设更小独立阈值可降低单请求成本，但当时选择与文本主管线共享上限，减少策略分叉；这不是进程绝不会耗尽内存的证明。

Duration取极大类型上限会产生没有阅读意义的系统进度显示，因此用有限媒体上限。浮点转换保护不能代替真实系统媒体控制生命周期验证。

## Consequences

上限只约束已接入的收体路径。2026-11-06 审计发现的 WebDAV、模型列表和 AI 错误响应旁路由后继 AB 修复补齐：WebDAV/Gist 读取、Gist 创建成功响应及模型列表成功响应使用 16MiB CL预检+累计上限；AI 和需正文的错误详情使用 8KiB 前缀并标明截断，不为错误通知收完整页。scheduler 文章页也使用 16MiB；这些变化沿用本篇的共享 helper，不表示进程整体内存有统一界或全部网络接口已穷尽。当前验证边界见[AI与内容路线](../../../../docs/roadmap.md#ai-and-content)。规范URL碰撞、播放器旧Promise和重新挂载问题也不由本篇修复，后继各自结果仍归相关记录。

## Validation

read_body_capped测试分别验CL预检、无CL的EOF/分块累计和正常通过；hyper按Content-Length定界，谎报小CL会截断而不是穿透累计，因此不能用它冒充无界收体复现。favicon、提取及legacy绑定分别用真实loopback/SQLite；2026-11-07 首批/AB/C/D 限定检查与独立审计覆盖最终响应基址、在途URL变化、封面写入故障，以及新增预算调用点正常/超限对照。分批证据和当前整合门禁分别报告，不互相代替；media_secs纯函数证明数值安全，不证明SMTC实机可用。
