# Agent Note: 不足一屏时的补拉和可操作哨兵

Status: implemented

## Problem

布局过滤后补一页仍为空，items.length不变使effect不再触发；内容不足一屏又无法产生scroll事件，“滚动加载更多”变成不可执行提示。非文章卡未调用selectArticle还曾使依赖选中的自动AI链不触发，CSS隐藏阅读器并不是其原因。

## Decision

用视口剩余空间决定自动补拉，撑满、到底或达到AUTO_REFILL_MAX_CALLS=8后停止。sentinelMode按可滚动性选择滚动提示或可聚焦的加载按钮，到底才显示终态。空态不同时承诺用户无法执行的滚动动作。

卡片选择接入selectArticle，使文章身份、自动AI和Reader链共享入口。可达性验收是“后端可列出的条目能经分页与操作到达”，不是最终同时挂载全部卡片；五布局虚拟化本来就只挂窗口。

## Alternatives considered

把items长度继续加入依赖不能解决长度未变的补页。IntersectionObserver能感知可见，却不能单独表达“仍不足一屏，需要接着拉”；需要明确补拉状态及预算。给缺陷写“此布局不支持”文案不能恢复可达性。

CSS display:none不停止React effect；自动AI问题需追查选择动作是否发出，不能靠显示阅读器列掩盖缺失接线。

## Consequences

自动预算用于防止异常连续请求，不表示最多只能查看八页；后续用户仍应有可执行入口。几何测量、数据过滤与请求完成交叉时仍需验证哨兵状态，不从纯函数通过推出真实布局均可达。

正文/启动的其他竞态仍见[阅读与状态路线](../../../../docs/roadmap.md#reader-and-state)，特别是受控IPC假空视图尚需原生可达性验证。已加载、可到达、当前挂载是三个不同数量。

## Validation

timelineRefill/timelineSentinel纯函数覆盖预算和模式；列表/组件用例需驱动“过滤后一页仍空、无滚动空间、手动加载、最终到底”序列。真实视口还要核验按钮可见与可聚焦，不能只数DOM卡片等于总数据。
