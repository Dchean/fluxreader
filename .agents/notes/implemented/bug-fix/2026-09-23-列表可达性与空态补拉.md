# Agent Note: 列表可达性与空态补拉

Status: implemented

## Problem

用户报告「画廊、播客、通知三个布局看不到多少内容」，实际情况比「少」更严重：内容**永远到不了**。

两个独立机制叠加：

1. **空列表补拉不级联**。列表为空时，effect 依赖是 `[filterKey, items.length, articlesExhausted, loadMoreArticles]`。补拉一页后，如果结果仍为空（或条目数与之前相同），这些依赖全都没变，effect 不会重新触发——真实症状是永久空列表，而界面上没有任何错误。
2. **「滚动加载更多」不可执行**。容器内容不足一屏时 `scrollHeight == clientHeight`，`onScroll` 永不触发；而提示文字「滚动加载更多」就在这时显示，指向一个不可能发生的操作。

审计在真机上确认了这两点，并给出了设计约束：**空态哨兵必须可点击或自动续拉**。

此外，非文章布局下自动 AI 摘要不生效。一度被归因于「阅读器列被 CSS 隐藏」，实测推翻：`display: none` 不阻止 React effect 执行。真因是**卡片点击不调 `selectArticle`**（画廊还要点两次），所以文章从未被选中，依赖选中态的逻辑自然不跑。修法落在交互层，不在 CSS。

## Decision

**不足一屏时自动续拉到撑满视口或到底**，不要求用户滚动。`AUTO_REFILL_MAX_CALLS = 8` 是防呆上限（`src/components/timelineRefill.ts`），决策由纯函数 `refillDecision` 给出，可单测。

**哨兵形态由容器是否可滚动决定**（`src/components/timelineSentinel.ts` 的 `sentinelMode` 纯函数）：

- 容器可滚动 → 显示「滚动加载更多」；
- 容器不可滚动且未到底 → 换成**可点击、可聚焦、Enter/空格可触发**的按钮，沿用同体系按钮样式；
- 到底 → 显示「没有更多了」。

**空态与承诺性加载提示不得同时出现**：无内容时只显示既有空态文案，不再同时显示「滚动加载更多」这类指向不可执行操作的提示。

**强判据（可机械核对）**：任一布局只要有后端条目，用户必须能用滚动或可见的加载按钮触达全部；渲染的卡片数最终等于该布局的条目数。

**切布局从该布局的首批开始**；切回不重复卡片、不跳条目；文章与社交布局既有的滚动体验不得回退。

**卡片点击统一调用 `selectArticle`**，让依赖选中态的链路（自动 AI、焦点归还、返回位置）在五个布局上一致生效。

## Consequences

**收益**：三个布局的内容可达；空列表不再是终态；不可滚动的容器有可执行的操作入口；自动 AI 在五个布局一致触发。

**代价与已知上限**：

- 自动续拉会在 `loadMoreArticles` 真正返回空页时停止，因此连续 8 次空响应后不再尝试（上限到了就停，等用户操作）。这个上限是防呆而非分页语义。
- 哨兵形态依赖「容器是否可滚动」这个运行时测量，窗口尺寸变化时会重新判定；测量时机若与布局变动交错，可能短暂显示错误的哨兵形态。
- 判据「卡片数最终等于条目数」在极端大规模下需要自动续拉足够多轮，而这个上限（8 次 × 每页大小）可能不足以覆盖；此时用户仍需滚动。重访信号是「某布局自动续拉后仍不足一屏」。

## Alternatives considered

### Why not 把 `loadMoreArticles` 放进 effect 依赖并把 items 长度也纳入变更检测？

已经这么做了——问题恰恰在于「补拉后 items 长度不变」时依赖不变。真正的解法是让补拉由「是否撑满视口」这个几何条件驱动，而不是由数据变化驱动。

### Why not 用 IntersectionObserver 替代 onScroll？

Observer 能检测「哨兵是否进入视口」，但容器不可滚动时哨兵一直可见，Observer 会立即触发一次然后就没了——它同样不能表达「还需要再拉一页」。`refillDecision` 用「剩余空间」这个量判断，语义比「是否可见」更准确。

### Why not 在提示文案上写「此布局暂不支持滚动加载」？

那等于把实现缺陷写成产品文案。用户要的是看到全部内容，不是被解释为什么看不到。换成一个可点的按钮是正确修法。

### Why not 把「自动 AI 不生效」也归到 CSS 层修？

因为它不在 CSS 层。审计用真机实测确认 `display: none` 不阻止 React effect 执行，因此「隐藏阅读器列」不会阻止逻辑；真因是卡片点击没有调用 `selectArticle`。按错误归因去修 CSS 会得到一个看起来合理但无效的改动。
