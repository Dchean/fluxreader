# Agent Note: 目录重名的导入复用、创建拒绝与按名落点确定性

Status: implemented

## Problem

R2-P2-1（第二轮全面审计，基线 83fafbd）：`folders.name` 无 UNIQUE 约束，而
`db::create_folder` 恒 INSERT，三条创建路径行为不一致：

1. **OPML 导入**（`commands/opml.rs` import_feeds）：目录名 → id 缓存只在单次
   导入内去重（TASK-062 N1 只修了根级订阅产生 N 个「导入」的形态），库内已有
   同名分类时照样新建第二个——订阅分裂，重复目录经配置快照上传放大 B-P2-4 的
   按名歧义。
2. **手工创建**（`commands/folders.rs` create_folder 命令）：不查重，同名输入
   静默插成第二个目录，用户无感知。
3. **配置同步 sink**（`config_sync.rs` list_folder_id_by_name）：`SELECT id
   FROM folders WHERE name = ?1` 无 ORDER BY，同名多条时落点不确定（SQL 不保证
   扫描顺序，SQLite 恰好按 rowid 返回只是实现细节）。

`find_folder_by_name`（pull 段按名映射，roadmap §八 P3 描述为「取 rowid 首个」）
同样只有隐式假设，无 SQL 层背书。

## Decision

**创建分层：用户手工创建拒绝重名，内部导入路径查重复用；所有按名查找固定取
id/rowid 升序最旧一条。**

- **OPML 导入复用**：import_feeds 的缓存 miss 分支先 `find_folder_by_name`
  查既有同名目录，命中即复用其 id（**不触碰其 layout/collapsed 等用户设置**），
  未命中才 create_folder；单次导入内的缓存保留。跨次导入同样复用：第二次导入
  的同名条目落进第一次建的目录。
- **手工创建同名拒绝**：create_folder 命令抽出 `create_folder_checked`（命令与
  测试共用，对齐本文件 record_* 形态），同名时返回类型化错误
  `duplicateFolderName`，前端按 code 识别、不解析中文文案。
- **按名落点确定性**：`find_folder_by_name` 与 `list_folder_id_by_name` 统一
  `ORDER BY id LIMIT 1`——同名多条（存量重复，本卡不清）时取最旧。`folders.id`
  是 `INTEGER PRIMARY KEY`（rowid 别名），这与 `ensure_uncategorized_folder`
  既有写法及 roadmap §八 P3 的「rowid 首个」描述一致，把隐式假设变成 SQL 契约。
- **配置同步 sink 本就有查重复用**（plan.rs resolve_folder 先
  list_folder_id_by_name、命中即复用、未命中才建），本卡只补确定性；schema2
  分类按 sync_id 匹配、FolderPlan::New 由计划期匹配守卫，不在本卡范围。

## Alternatives considered

### Why not 给 folders.name 加 UNIQUE（迁移去重存量）？

schema 层约束是最强背书，但要先迁移去重存量：同名目录各自挂着订阅（正是本
bug 的产物），合并意味着把其中一个目录的订阅挪进另一个并删除目录行——挪哪个、
保留谁的 sync_id/position 都是**数据损失方向**的猜测（两个同名目录可能各自有
远端身份，合错方向会让远端标签挂错对象）。存量重复能否安全合并必须显式选择
保留方，本卡是行为修复，不携带迁移风险。**已登记为可独立立项的后续项**：先出
「重复目录检测 + 合并工具（用户显式选择保留方）」，再上 UNIQUE 迁移；立项前
本卡的复用/拒绝/确定性三层是防增量的完整防线。

### Why not 在 db::create_folder 内统一查重（命中返回既有 id 或报错）？

db 层统一看似收口最彻底，但 `db::create_folder` 的既有语义是「恒 INSERT」：
ensure_uncategorized_folder（自带 find-first）、配置同步 plan、测试夹具等十余处
调用点依赖这个语义；pull 侧（sync/subscriptions.rs）另有 find-first 守卫且不在
本卡范围。改成「命中即返回既有 id」会让 config_sync 的 FolderPlan::New（需要
真实新建以承接远端身份）与测试「两目录同名」前置条件的语义漂移。查重语义归属
各调用方（命令拒绝 / 导入复用），db 层保持纯 INSERT。

### Why not OPML 复用时顺带把既有目录 layout 归一为 article？

导入的 feed 固定 inherit 布局，目录布局/折叠是用户自己的选择——覆盖它等于
导入行为改写用户设置，与「复用保留布局/折叠状态」的目标相反。

## Consequences

**收益**：

- 带已有分类的 OPML 与重导不再分裂订阅；重复目录不再经快照放大按名歧义。
- 手工撞名得到可识别的明确报错（不再静默）。
- 同名多条时 pull 按名映射与配置同步 sink 的落点跨次确定（最旧优先）。

**代价与已知上限**：

- 存量重复目录不做清理：已分裂的订阅保持原状（合并属上述后续项）。
- 拒绝只在命令层：「先建 A → 把 B 改名为 A」仍可产生同名（rename 路径不在本卡），
  UNIQUE 立项前这是接受的下界。
- `find_folder_by_name` 的 ORDER BY 对 pull 侧是行为锁定而非变化（SQLite 现状
  本就按 rowid 返回）；换来的是契约由 SQL 显式保证，不依赖扫描顺序巧合。

## Testing

- `commands/opml.rs` 单测：`import_reuses_existing_folder_preserving_its_settings`
  （复用 + 布局/折叠原样 + feed 挂既有 id）、`second_import_reuses_folder_
  created_by_first`（跨次导入同目录）；既有 N1 两测（单次导入内单目录）继续锁定。
- `commands/folders.rs` 单测：`create_folder_rejects_duplicate_name`（类型化
  duplicateFolderName + 不残留第二行 + 首建目录 layout 原样）。
- `tests/config_sync_e2e.rs`：`sink_resolution_picks_oldest_folder_when_
  duplicates_exist`（两条存量「导入」时 feed 落最旧、不建第三个）。
- 本机不可链接（AGENTS.md 门禁表 2026-10-31 结论）：cargo test / clippy / check
  由 CI rust job（windows-latest）承担；本地仅跑 `cargo fmt --all -- --check`
  与静态自查。
