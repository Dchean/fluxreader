# Agent Note: GR 权威集合回补与过期意图恢复

Status: implemented

## Problem

GR 增量窗口按发布时间筛选。服务端晚收录、发布时间早于游标的未收藏未读文章不会进入窗口；已有未读差分只对本地绑定行标读，没有发现这些身份的通道。原 starred 回补只补无身份行，无法补齐已绑定却无正文的行，真实空正文或未绑定源也可能反复占据每轮预算。普通 contents 只校验条数，重复或无关条目可以掩盖缺失目标。

无身份状态意图在 30 天后转为 `expired_unconfirmed` 并保留，但设置没有显式恢复入口；恢复又必须尊重当前账号、库代际及用户最新的 read/star 目标。换号或断开会清除旧状态队列，确认界面却没有说明直连状态保留不等于之后自动补推。

## Decision

- light 轮对完整 unread、starred 集合补缺身份或正文，复用现有同 feed 身份匹配和字段版本/pending 保护；权威集合回补不把 GR 已读翻回未读。
- 每次 pull 的每集合回补至多请求 2000 个唯一 ID，按数值 ID 排序轮转。settings 的 `greader_backfill_unread/starred` 保存 `{generation,last_id}`；只有整批请求及合并成功才保存进度，短响应、错 ID、请求和数据库失败均保留相关进度及主游标。空正文和缺 feed 仍占有限预算，轮转防止其一直挡住后续成员。states 原有订阅发现后最多重拉一次的边界保留，发生该重拉时同一 states 轮每集合最多消耗两份预算。
- contents 必须覆盖全部唯一请求 ID；重复或无关 ID 不能凑数，额外 ID 不参与合并。
- 队列摘要在同一 DB 锁内返回 `account_generation` 和分类计数。`sync_retry_expired(expected_account_generation)` 在锁内读取当前账号，代际不符返回 `staleAccount`，未配置返回 `notConnected`，配置读取错误原样失败。事务以内文章当前 read/star 重建过期行，绑定项转 pending，无身份项按 feed 分类；缺文章的意图保留过期。每个新意图使用新操作 ID，避免旧推送确认误删，重复点击为 no-op。结果分别返回重排总数、三类状态和仍过期数量。
- 断开和换号确认明确说明旧队列丢弃、本地直连 read/star 保留及不会自动迁移补推；不增加多账号档案。
- 过期项恢复后的局部摘要补刷，无论成功或失败都先比较发起时捕获的账号身份。旧账号的迟到失败不能清空新账号已成功读取的快照，否则恢复按钮会因缺失 generation 而失能；旧失败也不自动重放恢复请求。
- 保存后的同步通过无参数 `sync_run` 串联 feeds/states；前端保留两份报告的 partial 错误、阶段错误和原草稿重试，不把重试当重新保存，也不覆盖用户在途编辑的新草稿。整链协调由运行边界模块持有，本 Note 不重复定义其锁和事件契约。

## Alternatives considered

- 只依赖 `ot` 或每轮全量 reading-list：前者无法发现晚收录旧文，后者扩大正常 light 成本。已有完整 unread/starred 集合可直接提供有界发现通道。
- 每轮从候选首项开始：实现最少，但真实空正文和缺 feed 的成员不会退出候选，能够长期占满预算；成功轮转保存的只是遍历位置，不改变条目身份或冲突政策。
- 用过期行原 action 重排：能最直接保留历史操作，却可能重放比当前本地状态更旧的目标。恢复只以当前本地目标为准，缺行则不猜目标。
- 跨账号存档并恢复旧状态队列：可以切回账号续推，但本轮已经采用换号清旧意图的安全边界，不扩展多账号状态模型。

## Consequences

晚收录旧未读可在自动 light 同步里被导入或绑定到同 feed 的直连行；真实空正文和缺 feed 成员不能永久挤掉尾部身份。代价是无正文候选需要持续回访，并新增两个小型 settings 遍历位置；每次 HTTP 请求仍最多 100 ID，批内并发 3。

完整集合仅保证分页耗尽，不能识别服务端语义性漏报。已读且未收藏的旧文章仍需全量同步；远端已删除的历史正文无法补造。当前账号身份检查失败保持队列不变。显式重试仅重排本地意图，不等于远端已确认，也不保证无身份项一定能绑定。真实部署、真实应用和全局门禁不属于上述定向证据。
