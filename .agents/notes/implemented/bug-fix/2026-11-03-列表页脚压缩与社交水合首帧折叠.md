# Agent Note: 虚拟总高与社交折叠外框保持稳定

Status: implemented

## Problem

纵向flex压缩虚拟容器，把“没有更多了”提前推到首屏；社交正文水合后先完整布局、再折叠，出现卡片高度中间帧与重叠。只用line-clamp不能裁图片，按摘要/行封面猜高度也会漏掉“短摘要、无封面字段、正文含图”。

固定外框后还有两个独立问题：观察外框不会发现内层媒体自然增长；每次render重新创建dangerouslySetInnerHTML对象会重设HTML，视频节点及加载状态可能重建。

## Decision

虚拟总高容器不参与纵向flex收缩，页脚是完整内容末尾标记，不做sticky。社交折叠态统一卡片310px、正文150px、按钮槽26px，含12px行距的估算为322px。占位、短文、空文、图文均用同一外高，内容溢出只决定展开按钮和fade。

展开或显示译文退出固定外高，并在layout effect向虚拟器回写实际尺寸；收起恢复同一常量。TS常量承担测量/估算决策，CSS只保留必要裁切兜底，避免另写一份不一致高度。

观察自然高度的social-text-inner，首次layout effect同步采样；图片load/error、视频metadata/data/duration事件经rAF合并再采样。正文替换重建监听，短→长→短重新决定按钮和裁切。固定的social-text外框不能替代这一测量目标。

正文/译文的HTML注入对象按内容memo，正文未变时不重新设置innerHTML，使视频跨展开、收起和测量render保留节点。160ms入场动画只处理透明度/位移，旧重叠可在动画外复现，因此没有用删动画处理几何错误。

## Alternatives considered

页脚sticky改变“到底”的空间语义，不能修容器被压缩。普通effect首判晚于paint，line-clamp又不能裁所有块级媒体；按摘要估算已被无封面字段的正文图反例推翻。

只依赖子卡变高后的同帧resizeItem曾留下可见中间帧，所以占位→折叠水合直接固定外高；用户主动展开仍使用测量回写。预取/隐藏预测量后挂载能保留自然短卡，但需等待正文并处理预测量/骨架成本，当前选择固定外高。

给视频fixture写死宽高或放过首帧会掩盖metadata/poster增长与节点重建。CLS不能直接删除：保留原始数据，同时区分裁切正文内部媒体增长和会推走卡片的外部位移。

## Consequences

短文/空卡保留明显空白，标题单行截断，列表可能比自然短卡更长，这是固定节奏换水合稳定的已接受代价。若要紧凑短卡，应重新选择预测量等完整模型，不能悄悄恢复摘要猜高。

这些约束服务社交折叠水合与页脚，不证明画廊异步测量、所有窗口焦点或全部动效已正确；画廊现存过程漂移见[界面与媒体路线](../../../../docs/roadmap.md#interface-and-media)。展开/译文是明确允许增长的操作，不能拿折叠外高不变推导它们无需测量。

## Validation

social-collapse真实挂载验证占位/首次commit固定外高、观察目标、按钮aria关系和展开动作；jsdom不证明像素。ui-layout-regression以1440×900与980×640运行七类正文，含无尺寸视频readyState=0→metadata→poster、成功/失败HTTP图片，逐帧记录外高、虚拟起点、重叠、裁切、横溢和节点身份。

历史证据在tmp/ui-layout-final-3及故障注入目录；无媒体重测变异应由视频专项断言判红，不能仅等超时。验收过程帧而非只看恢复终点。该浏览器证据是Edge/Chromium，未直接证明Tauri WebView2真实IPC或系统合成差异；当前整套门禁状态统一在验收入口维护。
