# Agent Note: 订阅退补事务与附带写入失败的表达

Status: implemented

## Problem

远端快速创建成功、本地源却已删除的结转分支，需要删除旧意图并写入退订意图。原调用未包事务，三写间失败会留下远端订阅而丢失本地补偿任务。另有 GR 游标推进和关闭 smartDedup 后清旧墓碑的写错误被忽略。

## Decision

在结转调用点包外层事务，enqueue_unsubscribe 的多写同生共死；开事务、入队或提交失败按既有软失败路径记录日志并返回 Skipped。事务责任仍属于调用点，不在可被其他事务调用的数据函数内部再开事务。

GR 游标写失败记录 warn 和 report.errors，保留已经合并的数据；下一轮仍从未推进的游标继续。关闭 smartDedup 后旧去重墓碑清理失败只记 warn，设置保存仍可成功。两条路径可见性不同：后者有诊断日志，不能宣称用户收到同步错误。

## Alternatives considered

把事务下沉到 enqueue_unsubscribe 会与其他调用方已有外层事务冲突，因而只补漏掉的调用点。附带写失败全部上抛会把已完成合并或设置保存表达成整体失败；采用日志、报告与保留成果的边界更符合已有恢复模型。

## Consequences

退补多写具有原子性，不等于所有 outbox 确认失败都已可见。2026-11-06 仍有订阅确认失败静默和 Fever 完成时间戳写失败静默，见[同步正确性路线](../../../../docs/roadmap.md#sync-correctness)。不为事务成本写未经测量的“纳秒级”结论。

旧 deduped_urls 已不是新文章入库闸门，不能继续把清理失败描述为“仍在拦截重复文章”；该清理属于有限兼容维护。

## Validation

opt009_phaseb_e2e.rs 中结转分支的真实 DB 测试覆盖三写提交及 INSERT 的 RAISE(ABORT) 整体回滚。相邻 adopt 分支的测试不能代替此分支，日志存在也不能代替用户可见错误验证。
