# Agent Note: 关闭取消语义与授权关闭守卫

Status: implemented

## Problem

两条关闭路径都把「取消」实现成了超出用户意图的动作。

`CloseAskDialog` 的遮罩点击与显式「最小化到托盘」共用同一个 `onClose`，
而 `remember` 默认是 `true`。用户点遮罩本意通常是取消本次关闭确认，实际却
触发 `resolve_close { action: 'tray', remember: true }`：窗口被隐藏，且以后
不再询问。Esc 虽有 `remember: false` 的例外，但仍会提交最小化，同样不是取消。

设置弹窗则只在遮罩路径做了 GitHub 授权检查。右上 X、全局 Esc、Ctrl+, 都直接
调用 `closeSettings()`，授权进行中仍会关闭并卸载设置面板。设备流轮询本身在
store 中继续，但用户看不到 `user_code`、验证入口和进度，授权流程实际失去
可操作的界面。发起请求尚未返回时 `githubFlow` 还是 `null`，只检查 flow 的
关闭守卫会让这一窗口穿透。另有一条发起失败路径：`openExternal` 在 code 已
写入 flow 后拒绝，旧实现只报 toast，既不清 flow 也不清状态，后续关闭与再次
登录都被永久挡住。

## Decision

**取消询问与提交关闭动作分离。** 新增 `dismissCloseAsk`，只把
`closeAskVisible` 置为 `false`，不发 `resolve_close`、不改
`closeToTray` / `closePromptShown`。`CloseAskDialog` 的遮罩和 App 的全局 Esc
都调用它；只有「退出 FluxReader」「最小化到托盘」两个显式按钮调用
`answerCloseAsk`，并把当前 `remember` 值一并提交。

**`closeSettings` 自身是唯一关闭守卫。** 它在状态转换前检查
`githubFlow || githubLoggingIn`：任一存在时只显示「GitHub 授权进行中，等待
网页授权完成后再关闭」并保持 `settingsOpen`；否则正常关闭。右上 X、遮罩、
Esc、Ctrl+, 全部调用这个公开动作，不再保留可绕过的第二套 `closeSettings`。
授权结束或取消后 flow 与可取消的登录中状态归零，同一条路径自然恢复关闭能力。

**关闭沿用共享焦点契约。** 关闭确认框和设置弹窗继续使用共享 `useFocusTrap`；
本决定没有另造焦点管理器。具体归还时序仍受[模态焦点决定](../feature/2026-11-01-模态焦点陷阱与dialog语义.md)
所列autoFocus边界约束；授权状态与轮询取消按下文代次协议处理，不再称其“完全不改”。

**发起、轮询、取消共享登录代次。** 每次发起递增代次，取消与测试夹具再递增；
取消、错误清理和测试夹具都清除轮询定时器。`github_login_start`、`github_login_poll` 与
`openExternal` 的迟到回包在写状态前复核代次，因此取消后不会重新写回 flow
或重排轮询。`openExternal` 拒绝时统一清掉 flow、发起中状态与轮询定时器，
用户可立即关闭设置或重新发起。

**取消先要求后端作废设备流。** 等待卡提供「取消授权」，发起中提供「取消发起」。
两者调用 `github_login_cancel`，等待后端清 flow、递增代次后才清前端 flow、
轮询与 `githubLoggingIn`，并提示「网页上的 GitHub 授权不会被撤销」。后端
取消失败时显示可见错误，不显示成功文案；本机停止展示以允许关闭设置和重试。
后端代次与迟到 poll 的落库守卫见
[GitHub 设备流后端取消与代次](2026-11-04-GitHub设备流后端取消与代次.md)。

**`githubLoginStartPending` 防止并发第二次发起。** 取消只清可视化等待状态，
不清底层 `github_login_start` IPC 的在途标记。旧请求 settle 前，登录按钮
保持禁用并显示「等待上次发起结束…」；settle 后清标记并重新允许发起。迟到
回包仍由登录代次丢弃，不会复活 flow。这样不依赖后端单槽行为：前端在旧请求
结束前不会发出第二次 start。

**`githubPollPending` 封住取消后的第二批设备流。** `github_login_poll` 进入
在途时置 `true`，取消保留该标记并允许关闭设置；旧 poll settle 前登录按钮
禁用并显示「等待上次轮询结束…」，`githubLoginStart` 也拒绝重入。poll 的
`finally` 清标记；代次复核保证迟到的账户/空结果不写 `githubAccount`、不复活
flow、不重排轮询。

**WebDAV 冲突确认前复核代次。** 首次 start 的拒绝回包先检查登录代次；取消后
迟到的 `webdavConflict` 直接退出，不弹 `window.confirm`，确认之后再次复核，
不发出 `github_login_start(force=true)` 的第二次请求。

## Alternatives considered

### Why not 给 `ModalOverlay` 加“遮罩不关闭”开关？

这只能修遮罩一条入口，仍要把 Esc 的语义另放在 App 的全局分支；而且
`ModalOverlay` 不知道当前关闭是取消还是提交业务动作，容易把一个通用原语
变成业务策略容器。显式拆出 `dismissCloseAsk` 后，取消与提交的边界在 store
动作名上就可见。

### Why not 新增 `requestCloseSettings`，保留原 `closeSettings`？

两套关闭入口会让未来调用者继续选错，回归网也只能逐个锁调用点。现有所有
生产调用本来就经过 `closeSettings`，直接把这个公开动作升级为守卫，既不增加
API，也消除了可绕过的原始写入口。

### Why not 在 App 的 Esc/Ctrl+, 分支里先检查授权流？

那只能覆盖全局快捷键，X 和遮罩仍要各自检查；判断会复制三份，任何一处漏改
都会重新打开缺口。守卫放在 `closeSettings` 内，入口再多也只有一个判断点。

### Why not 授权中禁用或隐藏右上 X？

禁用控件会让用户不知道为何不能关，隐藏控件又改变既有布局与可达性预期。
保留按钮并给出统一提示，既维持可发现性，也说明当前阻塞原因。

### Why not 保留 Esc = `tray, remember=false` 的旧语义？

它虽然不会写「不再询问」，但仍会隐藏窗口。Esc 在对话框里的通行语义是取消，
把取消映射为最小化会制造不可预期的后台行为；只有用户点明确动作按钮时才应
执行关闭。

### Why not 在取消时只清前端状态？

这只阻止前端继续展示和重排轮询，无法阻止 Rust 中已经拿到 token 的旧 poll
写 `config_sync_credentials` / `github_login_name`。P2 返工已把取消下沉为
后端命令与 generation 校验；前端 `githubLoginStartPending` /
`githubPollPending` 仍保留，用于在 IPC 未结算时阻止新 start。

### Why not 同时拦截窗口控制区的应用关闭 X？

那是关闭整个应用的独立产品入口，不是设置弹窗关闭。把它纳入设置守卫会让
「授权中不能关设置」升级为「授权中不能关应用」，改变用户退出能力；本卡只
记录边界，不扩大行为范围。

## Consequences

- 遮罩或 Esc 不再产生隐藏窗口、退出程序或写入「记住选择」的副作用；误触的
  代价仅是重新触发一次关闭确认。
- 四个设置关闭入口共享同一判断，未来调用 `closeSettings` 的入口也自动受
  授权锁约束，不再依赖每个组件自行记得检查。
- `ui` slice 读取 `githubFlow` / `githubLoggingIn` 两个同步域字段，形成只读
  的跨 slice 依赖；它们本来就在同一个 store 组合中，且守卫需要与状态转换
  同点，收益高于拆出第二层事件协调。
- 授权中每次关闭尝试都会显示同一条 toast；没有新增去重，因为这是用户刚刚
  触发操作的即时反馈，保持与既有遮罩提示一致。
- 本卡只锁设置弹窗关闭。应用窗口控制区最右侧 X 仍直接关闭应用，是「关闭
  设置」与「关闭应用」之间的独立产品边界；本卡不改变它的语义。
- 真实挂载回归覆盖：Sync 页真实显示 `user_code`；授权等待与
  `github_login_start` pending 时四个设置关闭入口均被拦截；焦点元素派发的
  Esc/Ctrl+, 同样被拦截；取消授权后四个入口恢复关闭；`openExternal` 拒绝后
  flow/发起中状态归零、无轮询调用、可关闭且可重试；取消发起后立即重试按钮
  禁用且不发第二次 IPC，旧 start settle 后按钮恢复、迟到回包不复活 flow。
  poll 在途时取消仍可关闭，但立即重试禁用且不发 start；旧 poll 迟到账户
  不写 `githubAccount`、不复活 flow，settle 后才允许新发起。取消真实调用
  `github_login_cancel`；后端失败显示错误，不显示取消成功，仍可关闭并重试。
  取消后迟到的 WebDAV 拒绝不弹确认、不发 `force=true`。
  CloseAsk 回归覆盖遮罩/Esc 零 `resolve_close`、零 `set_setting`、焦点归还，
  以及显式按钮的 `tray/exit × remember=true/false` 四组合。
