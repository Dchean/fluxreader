# Agent Note: 测试替身对齐真实服务端语义（阶段 A）

Status: implemented

## Problem

2026-10-31 两轮证伪审计（固定上游源码钉死真实语义，证据留档 tmp/audit-gr2 与
tmp/audit-net）确认四类测试替身失真，门禁锁的是替身行为而非真实服务端行为：
mock_greader 的 ot 过滤列按 `changed_at >= ot` 实现，而真实 Miniflux 把 ot 映射
为 `AfterPublishedDate` → `e.published_at > $N` 严格大于（reading-list/starred/
read/feed 四类流全部适用）；Fever 星标 mock 是绝对赋值，而真实 Miniflux 对
`as=saved/unsaved` 都走 `storage.ToggleStarred` 取反；quick_add mock 默认对重复
URL 返回既有 id，而真实 FreshRSS 捕获 addFeed 异常后回 200 + `numResults: 0`
（无 streamId）、Miniflux 走 `JSONServerError` 回 500；compat 套件的
StrictServer `/stream/items/ids` 不实现 ot 过滤与 continuation，窗口类行为在
该套件里不可判别。这些失真掩盖了 5 项高危缺陷（含 quick_add 跨重启卡死、
Miniflux 星标翻转）。按 [审计修复收敛路线](../../proposed/process/2026-10-31-审计修复收敛路线.md)
的阶段 A 先修门禁、后修源码。

## Decision

四类替身契约现在按下述 must/never 执行：

- **GReader ot 窗口**：mock_greader 与 StrictServer 的 ot 过滤必须按
  `published_at > ot` 严格大于，四类流全部适用；never 用 changed_at 或含入
  边界（>=）做窗口判定。changed_at 保留为服务端记账（状态/内容变更仍前移），
  never 再参与窗口可见性。published 早于游标的条目只经手动全量（ot=0）进入
  本地。StrictServer 必须实现 Miniflux 形态 continuation（`c=` 已消费条数的
  offset 推进），并像 mock_greader 一样支持强制单页大小驱动分页。
- **Fever 星标**：星标语义必须按服务端变体参数化——Miniflux 变体
  `as=saved/unsaved` 都是取反切换，FreshRSS 变体是绝对赋值；never 用单一语义
  冒充两家。read/unread 两家固定实现都是绝对赋值，不参数化。
- **quick_add 重复 URL**：mock 默认必须按真实形态拒绝（FreshRSS 200 +
  numResults=0、Miniflux 500 feed_already_exists），产品路径的契约是「被拒后
  保留意图、不重复创建远端订阅」；「返回既有 id」只能经 `ReturnExistingId`
  显式开启，且仅限本篇登记的阶段 B 候选用例。
- **门禁分工**：本机不可链接（2026-10-31 三轮独立确认：零依赖探针、
  hello-world cargo build、VS 目录空），`cargo test`/`clippy`/`check` 由 CI
  windows-latest 承担，本地承担 fmt 与前端门禁；每项检查必须有承担者。

阶段 B 红门禁候选（当前产品源码在真实语义下必然卡死或翻星，本阶段按旧契约
显式保绿，B1 修复时与源码原子替换）：opt009_phaseb_e2e 的
`opml_import_mount_failure_keeps_folder_target_then_converges`、
`opml_import_title_lands_on_remote_wire_and_mock`、
`move_success_then_delete_readd_removes_accepted_label`、
`mount_window_production_edit_survives_old_mount_success`、
`unsubscribe_recovery_resolution_stays_scoped_across_account_switch`、
`readd_after_confirmed_move_and_delete_carries_remote_old_label`、
`unsubscribe_recovery_missing_resolved_target_converges_instead_of_stuck_retry`、
`unsent_move_then_delete_and_readd_removes_remote_old_label`，以及
account_lifecycle_e2e 的 `create_feed_conflict_returns_existing_id`。另：
Fever「已收藏条目再推 as=saved 翻转为未收藏」（星标判向）已在夹具层锁定真实
语义，产品路径的配对红门禁留待 B1。

## Alternatives considered

### Why not 保持 changed_at 语义？

真值表证伪（tmp/audit-gr2/ot-truth-table.mjs）：Miniflux 的过滤列是发布时间，
changed_at 语义下「published 早于游标但 changed 晚于游标」的历史条目会经增量
窗口进入拉取，与真实服务端相反——门禁继续锁定错误行为，B1/B2 的源码修复将
无法被证伪；旧语义还使 sync_content_e2e 的历史文章用例与机器时钟赛跑
（changed_at 与游标同秒时结果随调度翻转）。保留双语义按后端切换会引入第三种
从未存在过的服务端形态，门禁判别力归零，否决。

### Why not 红门禁先推送 dev、源码后补？

dev CI 长期红违背稳定收敛，红窗口内其它合并的门禁信号同时失效。改为：必然红
的用例本阶段按旧契约显式保绿并逐个登记，B1 与源码修复原子替换——dev 上每一
刻都是绿的，每个登记项都有明确的替换责任点，否决。

## Consequences

**收益**：门禁在四类语义上判别真实服务端行为；「published 早于游标」的分歧、
Miniflux 取反星标、重复 URL 拒绝都在 CI 有自动化锁定；阶段 B 的红门禁有固定
清单与替换契约，不再依赖 mock 默认值的隐式放纵。

**代价与已知上限**：quick_add「被拒后如何收敛」的真实语义覆盖仍为空（F2 =
B1 修复项，当前无自动化锁定，只有拒绝保留意图的行为锁）；9 个候选测试在旧
契约上运行，它们对真实语义的判别力到 B1 才恢复；docs/sync-compat-matrix.md
的时间过滤列行已随 mock 同步，其「未实机验收」声明不变。
