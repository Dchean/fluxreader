# Agent Note: 测试替身对齐真实服务端语义

Status: implemented

## Problem

2026-10-31 的证伪发现，mock 曾按 changed_at 过滤 ot、默认重复 quick_add 返回既有 id、StrictServer 没有分页，Fever 星标还把不同历史实现混为单一行为。测试会绿，却无法区分发布时间窗口、响应丢失或重复创建等实际兼容问题。

## Decision

夹具命名和断言绑定具体协议形态，不把更方便的模拟当真服务器。固定来源与版本集中在[兼容矩阵](../../../../docs/sync-compat-matrix.md)。2026-11-05 核对的 Miniflux faecfa2 在 api_version 3 下 saved/unsaved 已是条件绝对赋值，FreshRSS 4e8a258 同样绝对赋值；旧 Toggle 仍可作为兼容反例，版本号本身不协商行为。

- GReader mock 与 StrictServer 的 Miniflux 时间模型使用 published_at > ot，适用于其 reading-list/read/starred/feed 流；changed_at 只记录变化，不参与窗口。StrictServer 支持 continuation 与强制单页大小。FreshRSS 鉴权形态夹具借用这个时间模型时，不能证明实际 FreshRSS 的 id/lastModified 过滤。
- 2026-11-05 完整 unread/starred 也可补游标前文章，纯窗口用例必须用已读未收藏条目隔离回补通道，否则通过可能来自另一条链。
- Fever 星标显式参数化 Absolute/Toggle，read/unread 固定形态仍绝对赋值。不能把 Toggle 叫“所有 Miniflux”，也不能通过 api_version=3 断言一定取反。
- 重复 URL 的 quick_add 默认模拟拒绝：FreshRSS 200+numResults=0 无 streamId、Miniflux 对应错误。产品恢复先查列表，确认缺席才创建；读失败不盲发。旧 ReturnExistingId 与恢复时先建再删的假定已由[订阅恢复](../bug-fix/2026-10-31-fever推送幂等与订阅恢复收敛.md)取代。

当时采取两阶段迁移测试：先显式登记旧契约下的候选用例，再让产品修复与这些用例切到真实语义同批提交，避免共享 dev 长期处于无法归因的红窗口。这是 2026-10-31 的实施取舍，不是现在允许保留失真绿灯的长期规则；相关阶段已经结束。

## Alternatives considered

- **保留 changed_at 或任意双语义开关**：若不存在对应服务端，仅给测试造成功路径；发布时间早于游标但状态刚改变的反例必须表现出真实差异。
- **红门禁先推共享 dev、以后再修产品**：当时会让其他提交失去可用门禁信号，选择同批替换并登记每个候选责任；本地红证据仍必须保留，不能删除失败冒充已修复。
- **继续依赖幂等 quick_add 默认**：固定实现拒绝重复，无法证明崩溃/响应丢失后的恢复；改用列表存在证据，并单独记录列表语义性遗漏的限制。

## Consequences

测试现在能区分声明的发布时间、绝对/取反星标与重复 URL 拒绝，但只证明这些模拟。固定源码不等于部署实测，服务端升级需复核；并发探测到发送之间仍存在窗口，不能由兼容 fixture 绿灯宣称所有实现幂等。

## Verification
