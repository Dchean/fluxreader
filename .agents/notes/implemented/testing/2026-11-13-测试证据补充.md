# Agent Note: 测试证据补充

Status: implemented

## Problem

测试工具本身也会制造错误结论：用“与生产不同建窗路径”的驱动去验证首帧跳位，八场景全绿却与用户实测矛盾；把 React 的 act 调度噪声与真实运行时错误放进同一条判红通道，会导致同一提交在不同 Node 版本/运行之间随机失败，失败组件还会漂移；mock 按更方便的协议形态实现（把 ot 当 changed_at、默认 quick_add 幂等、Fever 星标混成单一 toggle），测试会绿却无法区分真实兼容问题。三类都需要把“证据类型”与“结论类型”对齐。

## Decision

- **窗口启动隔离驱动用差集设计。** 同一 driver、最小页面、隔离 state 文件、同一 `restore_and_show`，只切换建窗开关：`manual` 臂复刻手工建窗（`windows.clear() + from_config`）作为必须绿的对照；`auto` 臂不清空 config windows，由 Tauri 自动创建 main，再对既有窗口调用同一恢复函数——即生产创建路径。判据是物理事实：首次可见（`IsWindowVisible` 0→1）瞬间的窗口矩形、隐藏期 `Moved/Resized/WINDOWPOSCHANGING` 轨迹、首次可见前 `WM_SHOWWINDOW` 次数，以及退出后 state 文件是否被居中/默认几何覆盖。取消状态文件、离屏、损坏、最大化、全屏等初值都纳入场景。（原 2026-10-15 testing/2026-10-15-窗口启动隔离驱动的证据边界.md）
- **接受有边界的隔离，不伪造隔离。** tauri 2.11.5 在 `from_config → build` 路径忽略 `WindowConfig.data_directory`，auto 臂的 WebView2 UDF 实际落到 `%LOCALAPPDATA%\com.fluxreader.opt015q-diff.*`，而 manual 臂按 `--webview-dir` 落到任务 tmp。该物理落点差异必须如实记录并计入未排除因素，不因为想让两臂一致而改 runner 或写死参数。状态文件用插件同款 filename 写到任务 tmp，identifier 用隔离前缀，正式数据零接触，run 后按前缀清理。
- **act 警告单独计数，不进入普通错误判红。** `tools/component-tests/harness.mjs` 用精确正则 `ACT_WARNING_RE` 匹配“An update to … inside a test was not wrapped in act(...)”；命中的 console.error 只 push 进导出的 `actWarnings` 计数，不进入 `consoleErrors`、不触发终态运行时守卫。`runFinalTeardown` 打印 `act warnings recorded: N`，信息级输出，不改变退出码；其它 console.error、jsdom 未捕获、React 三通道错误仍严格判红，one-shot 例外与“未消费例外同样判红”不变。计数整轮累计、不按用例清零。（原 2026-10-19 testing/2026-10-19-组件回归act警告分级.md）
- **同时减少噪声来源。** `store/slices/ui.ts` 为 toast 两段退场定时器登记句柄并导出 `clearToastTimers()`，`harness.resetStore()` 在用例切换时调用；`tauri-compat-loader.mjs` 的 `getVersion` 桩默认 reject，避免页脚 `.then(setVersion)` 在 act 外落地；`componentTest` 在 body 之后、卸载之前执行 `flush(2)`，覆盖挂载后的短异步 effect。连带删除逐用例 act 例外——警告不再进入 `consoleErrors` 后，保留例外会因“未消费例外”反向判红。
- **测试替身绑定具体协议形态，不把方便模拟当真服务器。** GReader mock 与 StrictServer 的 Miniflux 时间模型用 `published_at > ot`，`changed_at` 只记录变化、不参与窗口；StrictServer 支持 continuation 与强制单页大小。完整 unread/starred 回补可补游标前文章，纯窗口用例必须用已读未收藏条目隔离回补通道。Fever 星标显式参数化 Absolute/Toggle，但不能把 Toggle 叫“所有 Miniflux”，也不能由 `api_version=3` 断言一定取反。重复 URL 的 `quick_add` 默认模拟拒绝（FreshRSS 200 + numResults=0 无 streamId；Miniflux 对应错误），产品恢复先查列表、确认缺席才创建，读失败不盲发。（原 2026-10-31 testing/2026-10-31-测试替身对齐真实服务端语义.md）
- **固定来源与版本集中在兼容矩阵。** 夹具命名和断言绑定具体协议形态；固定源码不等于部署实测，服务端升级需复核。两阶段迁移（先登记旧契约候选用例、再与产品修复同批切换）是历史实施取舍，不是允许保留失真绿灯的长期规则。

## Alternatives considered

- 让两臂共用同一 WebView2 数据目录：最初意图，但 R1 误以为 auto UDF 进了 tmp；实际每 run 新 pid 落新 AppData 目录。未排除项必须如实记录，不改 runner/构建路径制造一致，否决。
- 继续让 act 警告判红：act 外更新确实可能是真实缺陷，但实测无法稳定复现、失败组件漂移，最终只能不断追加 act 包装；让门禁失去“红=代码有问题”的含义，否决。
- 全局放宽 console.error：会掩盖真实运行时错误，只对精确 act 正则做窄口径分级，否决。
- 保留 changed_at 或双语义开关：若不存在对应服务端，只为测试造成功路径；发布时间早于游标但状态刚改变的反例必须表现真实差异，否决。
- 红门禁先推共享 dev、以后再修产品：会让其他提交失去可用门禁信号，选择同批替换并保留本地红证据，否决。
- 继续依赖幂等 `quick_add` 默认：固定实现拒绝重复，无法证明崩溃/响应丢失后的恢复，改用列表存在证据。

## Consequences

- 窗口驱动结论建立在消息级首帧事实而非源码意图；auto 臂 UDF 落点与 manual 不同，冷/热目录、真实前端页面、真实 profile 热态、DPI 动态变化与多显示器物理拔插仍在范围外；用户复现的确切构建归属仍待核实。
- 真实 act 外更新不再自动判红，只增加 `actWarnings` 计数；若无人看最后一行，回归可能静默通过。兜底是定期审查计数与代码评审；按用例断言上限是后续可选手段，当前未设阈值。
- 组件套件在 Node 22 下曾从“约 2/10 随机失败”变为 10/10 通过（历史 44 用例），这证明当时构建的修复，不表示当前套件通过。
- mock 现在能区分声明发布时间、绝对/取反星标与重复 URL 拒绝，但只证明这些模拟；固定源码不等于部署实测，兼容 fixture 绿灯不能宣称所有实现幂等。
- 历史验证时点与原始记录保留在对应 Git 提交与证据目录；当前门禁状态见[开发与门禁](../../../../docs/development.md)与[路线图](../../../../docs/roadmap.md#verification-boundaries)。
