# Agent Note: 验证方法与复核纪律

Status: implemented

## Problem

历史审计出现过工具偏差被当产品结论：缩进假设不符触发 SKIP 却写成“未捕获”；mtime 使变异测试用了旧 rlib；mock 的默认值比生产宽松；合成 click 被当媒体用户手势；关闭弹窗仍挂 DOM，程序调用绕过 inert 点错对象；Channel shim 漏了真实 Tauri 序列化形态而造出假卡死。

## Decision

先区分未执行、执行失败、执行后未复现。探针内部保护条件未满足必须显式失败/未验证，不可把 SKIP 变成负面结论。负面结论也要说明触发序列与观察窗口，不能仅以没有报错认定不存在问题。

变异结果须绑定实际执行的产物。历史 `Compiling app` 是发现缓存问题的一个信号，不能作为永久唯一标准；若已有产物与待测版本一致可以复用，若修改了源码却无法证明重建/加载了变体，则结果不采信。恢复后也要确认恢复对象与执行产物，避免 mtime 假一致。

数据库恢复失败也要区分信号来源。缺失savepoint、外部提前释放等真实SQLite语句错误可以稳定覆盖`ROLLBACK TO`/`RELEASE`返回错误的控制流；它们不证明物理磁盘已损坏、WAL/文件系统I/O失败或进程在系统调用边界崩溃时还能执行同样的恢复命令。没有隔离且可恢复的存储故障注入手段时，只能报告“普通事务与SQL恢复失败已验，真实介质I/O损坏未验”，不能把合成分支、mock返回值或静态代码当作后者通过。若恢复失败后代码进入failed-closed，测试还须观察外层提交被拒绝、连接回到可判定状态以及后续writer行为，不能只断言首个错误字符串。

集成测试链接普通lib target，不能依赖只对lib单元测试成立的`cfg(test)`条目。确需观察生产claim先后关系时，可用仅在`debug_assertions`构建存在的单向hook，并以database identity与规范化key过滤；release不编译该hook，hook不改变claim成功后的生产状态。等待必须用异步timeout/oneshot，不能用阻塞recv占住current-thread Tokio runtime；并行测试还须证明其他测试的同类事件不会抢占该信号。

按语义追查入口、装配、最终消费者与错误路径，不按 diff 行数判完成。共享 helper 仍可能被漏调；源码发现调用关系只能支持静态结论，行为与竞态须有实际运行证据。

编排边界不能用一个“边界名称列表”重复调用统一错误 helper 来代替。states、GR、Fever 的stale/ACK/下一批契约必须分别从真实阶段入口制造代际失效，观察该协议的请求记录、游标/回执和后续页，证明失效后的请求或数据库推进没有发生；只测 helper 的测试应明确命名为helper contract，不能声称覆盖生产边界。若未来只能通过依赖注入进入某分支，测试须同时给出生产调用点、注入接口依据和请求/回执观察点，不能把“注入了错误”当作真实边界。

数据库切换和清单约束同样要观察最终语义。计划文本包含逻辑表，不能证明读藏筛选、定位、去重代表、计数和返回值已经一致；应在同一输入上从生产查询面比较pending逻辑快照与materialized快照。正文receipt测试也不能只证明tuple在ACK时存在：必须保留旧receipt，经过cleanup后确认同tuple的新hold代次仍存活，并由它自己的publication/ACK释放。

mock 应忠于被验证契约的解析、默认值和副作用，并声明模拟的服务端版本/形态；不需要复制无关实现。更宽松会漏缺陷，更严格会造假反例。受控 Promise 证明前端在该顺序下的反应，不自动证明原生线程、SQLite 锁或远端能产生同一顺序。

| 结论类型 | 合适证据 |
| --- | --- |
| 符号、声明、装配路径 | 固定版本源码/类型，按符号追踪 |
| 状态机与迟到响应 | 生产逻辑加受控顺序，断言持久态与 UI |
| React 订阅/effect/事件 | jsdom 真实挂载或浏览器，纯逻辑/SSR 不够 |
| 尺寸、滚动、动画中途 | 真实浏览器/WebView2 的逐帧量测；静帧只证明该帧 |
| 用户手势播放、原生 Tab/inert | 实际输入事件与焦点遍历；程序 click 不等价 |
| 原生 IPC、窗口与服务端兼容 | 对应目标环境，mock/固定源码只作分层佐证 |

属性存在只证明声明，是否作用于实际焦点/AX 关系须运行验证。临时 DOM 内有多个关闭但挂载的弹窗时，定位必须包含可见/活动上下文；不要通过程序调用绕过用户不可操作边界。

机械统计结构按真实属性/语法，而非注释字样。例如 ignore 按属性行计数；退出码、断言执行数和失败语义须共同核对，零匹配 exit 0 不是通过。

长期定位使用符号与版本，行号只辅助固定版本跳转。环境错误保留原始失败，不能转述为产品无能力；环境会变化，每次判断按可用工具和当前对象核实。

## Alternatives considered

- **只跑单元、不做探针**：不足以覆盖实际输入、几何或原生集成；按结论选手段，不要求每个任务机械全套。
- **所有探针都不进 CI**：早期完整原生窗口/正式数据探针隔离成本高，因此一次性留档；后续 Edge/CDP 与 jsdom 已有 CI 通道，不能再说真实渲染一律无法 CI。值得长期防止且可隔离的反例由修复任务纳入现有通道。
- **mock 更宽松减少维护**：会隐藏字段丢弃和默认值分歧；维护成本应通过明确契约缩小，不通过虚构成功降低。
- **源码字符串代替运行**：便宜但锁文本，可能锁住缺陷手法；仅保留必要单点接线约束。

## Consequences

需要维护测试对象、产物和环境的对应关系，验证成本高于只看绿灯，但能区分工具故障与产品缺陷。归档探针的假设会老化，复用前要读当时报告、核对版本与数据隔离。共享 UI/真实端到端资源仍按 [AGENTS.md](../../../../AGENTS.md)统一预留，证据方法不替代运行授权。

## Verification

本篇来自 2026-09-22 起的实际事故，2026-11-06 整理时修正 Node/CI 与编译信号的过宽断言。历史复现细节见[整理前记录](https://github.com/Dchean/fluxreader/blob/91ece562d79fd909642cd6d570d636e884b7387e/.agents/notes/implemented/testing/2026-09-22-验证方法与复核纪律.md)。当前典型边界是 NF4：前端受控 IPC 时序已证，原生可达性未证，不能将假后端执行顺序当真实数据库调度结论。

2026-11-12组合候选已真实执行fmt、all-targets check、clippy `-D warnings`、50k exact、单线程完整测试和默认并行完整测试并全部自然exit 0。claim-acquired hook、settings SAVEPOINT失败关闭、缺正文/stale ACK、pending逻辑查询全表面和receipt代次场景均由实际入口覆盖；真实物理存储I/O损坏/WAL故障仍没有安全注入，继续明确标为未验证。Windows长路径backup夹具改回候选内短私有TEMP后通过，只说明测试环境路径前提，不是存储介质故障或生产backup语义通过。
