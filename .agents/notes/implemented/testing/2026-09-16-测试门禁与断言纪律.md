# Agent Note: 测试门禁与断言纪律

Status: implemented

## Problem

2026-09-16 的连续 CI 失败只显示 fmt，因为前置红项阻止 clippy/test 执行，类型复杂度与持锁跨 await 的真实问题因此没有被检查。ignored 理由不实、零匹配仍绿、恒真断言与不可靠 runner 又说明“有测试/有绿灯”不足以证明保护有效。

## Decision

### 门禁责任与执行前提

检查责任必须明确为谁、在哪个环境运行，而不是互相假定有兜底。当前命令与必需分工集中在 [AGENTS.md](../../../../AGENTS.md)；本篇不复制当前用例总数、CI 状态或环境清单。2026-10-31 本机曾无法链接，2026-11-03 当前工作区补齐 tmp/rust-env 隔离环境；旧机器限制不能替代本次实际判断，Windows CI 仍承担对应生产平台检查。

CI 的 Rust 各检查和前端 lint/build/frontend/components 采用独立执行条件：安装/checkout/toolchain 前提正常时，前一步失败不阻止其余检查给出各自结果；不以 continue-on-error 隐去失败。保留单前端 job 复用 npm ci，代价是前置检查失败后仍花时间完成后续。Release 通过 `workflow_call` 运行同一提交的完整 CI，所有 checkout 固定 workflow SHA；不能把别的提交或历史运行绿灯当当前通过。发布逻辑回归用隔离文件和 API 替身验证 tag、草稿、上传内容与拒绝路径，仍不能证明真实 GitHub 发布或安装器可用。

ignored 按属性行机械计数并核实依赖。自托管 loopback mock 不应仅因“要启动服务”默认跳过；真实账号 live 测试需要具体任务约定读写边界，不作为统一门禁。`--ignored` 只跑被忽略项，零匹配可 exit 0，不能用成功退出冒充覆盖。2026-11-09 核对 Cargo 自动发现及六个 mock 套件均无 `#[ignore]` 后，将其责任收口到 `cargo test --no-fail-fast`，移除后续重复的 `--include-ignored` 六套执行；测试目标失败后仍执行其余目标，最终退出仍非零。全部未忽略用例仍须实际运行，live 边界不随去重扩大。

### 行为断言与静态佐证

修复应把有判别力的最小反例转成相应行为回归，特别是连续操作、迟到响应、跨字段与清理失效。旧断言若锁住缺陷手法，可随新行为更新并保留理由；不得为变绿削弱有效要求。源码字符串断言仅保留必要单点/接线约束，不用它代替运行行为。

源码形状退出须逐项找到实际消费者的替代，不能因准备重构就整段删除。2026-11-09 的第一批对应如下；这些用例检查生产组件的真实事件、effect、DOM 与外部 IPC 边界，不要求内部函数名、队列字段或 JSX 分支顺序：

| 原 ui-contracts 静态项 | 行为承担者与判据 |
| --- | --- |
| w4-4：AI 三入口/写链/执行时读取表单 | [ai-config-race.test.mjs](../../../../tools/component-tests/ai-config-race.test.mjs)：测试与提示词并发不丢写、切模型保留其余字段、写失败可重试；另核对保存身份和在途草稿 |
| w4-7：焦点陷阱函数与分支文本 | [modal-focus.test.mjs](../../../../tools/component-tests/modal-focus.test.mjs)：边界双向 Tab、空面板、DOM 外 portal 冒泡、关闭还焦 |
| k2-1：IME Escape 守卫位置 | [ime-escape.test.mjs](../../../../tools/component-tests/ime-escape.test.mjs)：isComposing/keyCode 229 不关浮层，普通 Escape 仍关闭 |
| k2-2：Reader 正文状态分支顺序 | [reader-body-states.test.mjs](../../../../tools/component-tests/reader-body-states.test.mjs)：在途/失败/缺行 DOM、点击重试、正文真实恢复 |
| k2-4：加载态条件字符串 | [timeline-empty-loading.test.mjs](../../../../tools/component-tests/timeline-empty-loading.test.mjs)：分别驱动分页加载与后端重载在途，核对空态、可访问名、哨兵互斥和结束恢复 |

第一批仍保留的相邻静态项有明确缺口：App 错误边界装配（w4-1）缺实际子树崩溃注入；七事件晚注册清理（w4-2）缺延迟注册边界；全部模态面的语义（w4-3）尚未逐面挂载；演示数据分包和失败重试（w4-5）缺构建产物/加载失败证据；对比度（w4-6）缺对全部目标底色的运行取值；虚拟器同步策略（k2-3）仍需真实逐帧几何；启动装配（k2-5）、搜索单段防抖与本地即时结果（k2-6）、启动读屏状态（k2-8）尚无完整等价行为覆盖。其它源码断言沿各自现有覆盖保留，后续按同一标准迁移，不能把这批替换说成全部消除。

AI 配置回归必须区分“用户草稿”“已测试快照”和“已保存身份”。旧首例为避免新 Key 丢失，要求测试 A 后直接保存当时草稿 B，反而把未测试配置写入当成成功。新的判据保留草稿不丢，并只允许持久化实际测试成功的身份；可保存 A 并保留 B 草稿，也可拒绝陈旧结果。慢初始回读同时设未编辑的恢复对照，不能靠禁用全部恢复制造绿灯。修饰键浮层反例由 [modifier-shortcuts.test.mjs](../../../../tools/component-tests/modifier-shortcuts.test.mjs) 派发真实按钮冒泡事件，比较背后选中/读藏和写 IPC。既有缺陷触发的新回归应保持真实失败，进入后续产品修复；不使用 xfail、跳过或吞异常。

README 配置同步检查按语义分句验证“订阅源 + 客户端设置”及 AI 服务/敏感凭据本机保留，不锁一条固定文案。静态提取 build_payload 的 get_setting 直接字面量，只能守住已知键，不覆盖别名、间接拼接或最终序列化；真实 payload 排除由 Rust `config_sync_e2e` 承担。两者各有责任，不能互相替代。

计数不是判别力。保留条件变异/退化抽样：临时副本破坏回滚、分页收敛、源码态纯文本、文档语义条件，应使同一断言失败。变异需要确认被执行的构建确实来自变体；不要求所有普通低风险改动写镜像测试或机械全套变异。

### 三条前端证据通道

| 通道 | 能证明 | 不能替代 |
| --- | --- | --- |
| test:frontend | 生产状态机、受控异步序列、SSR/静态接线 | effect 挂载、浏览器几何、原生 IPC |
| test:components | jsdom + createRoot/act 的真实组件、effect、DOM 事件/订阅 | 布局/字体/媒体解码、真实 Tauri IPC |
| test:ui-layout | Windows Edge + CDP 的布局、滚动、键盘、AX 与媒体时序 | Tauri WebView2 原生窗口/插件、真实读屏/真实服务端 |

组件与逻辑通道共享 loader 和同一份 dist-test store/bodyCache，不能各断言另一实例。IPC、事件、窗口和 autostart 由明确 fake 提供，浏览器缺失 API 只作最小环境替身，不替身业务规则。jsdom 有真实 React 渲染，旧“Node 永远无 DOM/不能捕获 #185”不再成立。

布局门禁覆盖五布局、社交正文与异步媒体、多个视口、画廊锚定及键盘/AX 等现有场景，具体矩阵归现行命令与规范。视频用无宽高 fixture 记录 readyState=0、metadata 自然尺寸、poster 后撑高，要求同节点并让 no-social-media-remeasure 变异由视频专项判红。终态位置正确不能代替逐帧过程约束；名称存在也不能替代完整 combobox 关系。

### 组件 runner 自身也须可证伪

- console.error、jsdom 未捕获与 React 错误通道默认判红；预期错误使用 one-shot 精确例外，未消费也失败。React act 警告是唯一窄计数例外，后继[act 分级](2026-11-13-测试证据补充.md)取代早期“act 外更新一律红”，没有启用计数阈值。
- 等待状态时匹配真实调度：setTimeout(0) 不等于 rAF，所需帧在 act 内等待；不扩大白名单、不靠任意长 sleep。
- 看门狗必须 ref 保活；unref 曾使悬挂 after 在事件循环空转后 exit 0。正常收尾显式解除。
- body、卸载清理和错误账本失败聚合；毒 cleanup 仍继续清其余树，finally 移除登记后聚合抛出。programmatic node:test 的 after reject 不自动保证非零退出，因此 final teardown 显式设置 exitCode。
- 终检后武装晚错守卫：新 console/jsdom/React 错误同步写诊断并置 exitCode=1，旧例外不再屏蔽。不能用一次 finalcheck 假定后续不会来错误。
- 黑盒自检以子进程断言真实诊断与退出码，覆盖 body/after 悬挂、毒清理、listener throw、例外消费及晚异步错误。
- React 19 的 act 对错误分派有影响：边界 onCaughtError 与无边界 onUncaughtError 分别用合适窗口验证，避免“零错误”断言无消费者而恒真。

2026-11-11 的组合运行暴露了另一条边界：持续增长的业务组件与末尾黑盒自检共享全局120秒计时，合法顺序工作也会耗尽生命周期预算。原完整运行在最后一项黑盒自检前已累计超过107秒；隔离诊断中该自检本身约19.5秒，所有预期失败/成功探针与最终清理均闭合。这支持拆分执行责任，不证明原整套已通过，也不以耗时推断每个旧子进程当时的状态。

默认 `test:components` 仍由 [component-regression.mjs](../../../../tools/component-regression.mjs) 承担完整清单，串行启动业务组件和runner自检两个独立进程。业务文件的显式导入顺序保持，自检仍运行原有全部探针；每组各有原120秒ref看门狗、每用例错误检查、after收尾及晚错守卫。父入口对启动异常、signal、缺少正常状态或非零退出都判整体非零，并继续另一组收集证据。`--group business|selfcheck` 仅用于明确的定向诊断，未知、多余或缺少参数不能成为零用例绿灯；统一门禁无参数运行两组。子探针的短看门狗与外层调用超时不随拆分改变。

### 逻辑回归的数据归属

入口仅编排功能域，harness 的 S 拥有共享夹具和假后端；域模块通过 ctx 访问，不复制 store/harness。每个域复位自己的夹具，可独立进程运行。临时全局覆盖通过 overrideGlobal 注册，在 finally 按原 descriptor 恢复；原来不存在就 delete。保留 smoke 初始假后端的显式前提，其余域自行切换，不依赖前一个域残留状态。

## Alternatives considered

- **把 fmt 移到最后**：只换了被遮住的检查，未解决失败独立性；保留逐项执行与独立结果。
- **增强源码文本断言防全部回退**：会锁住实现甚至旧缺陷；只为必要结构使用，行为由动态断言负责。
- **删除全部 ignored**：真实账号测试仍有外部副作用，需具体边界；只移除不成立的自托管 mock 跳过。
- **通过数只增不减**：恒真断言可以虚增数量；使用针对反例的判别力证据。
- **拆多个前端 job**：可并发却重复安装；当时选择单 job 的独立步骤，不因文档整理重新改变执行标准。
- **提高组件全局看门狗时限**：2026-11-11 实际考虑后未采用。黑盒自检有独立的正确性责任与故意悬挂子进程，拆为串行独立进程可保留每组原超时与错误保护；增加一个总时限不能区分两类工作。

## Consequences

门禁能给出更可解释的失败，代价是 runner、夹具和证据范围也需维护。模拟器、时间、Node 版本、浏览器与上游版本变化都可影响结论；本机 Node 24 通过不自动证明仓库 Node 22 CI 通过。真实环境不可用必须写未验证，不能以采集日志成功、计数、格式通过或历史全绿替代。

组件分组增加一次进程与夹具启动成本，两组之间不共享运行状态；业务用例内部仍保持原顺序与共享实例，因此不会靠拆散业务链掩盖跨用例污染。父入口聚合语义、默认覆盖和各组完整收尾必须独立复核，局部自检通过不能替代拆分后的默认整套运行。若业务组自身以后超时，应按原失败定位，不能继续机械切片或延时。

2026-11-06 对 `91ece562` 的证伪审计包含现有组件/布局门禁失败与门禁外反例，说明旧“当前全绿”计数已经失效；该次记录整理没有改命令、阈值、跳过规则或产品测试。后续 2026-11-09 门禁调整仅按上表迁移有替代的断言并加入已确认反例，不更改真实 UI 的采样、重叠阈值或等待策略。失败仍阻止产品验收与发布，门禁本身更有判别力不等于产品已经正确。
