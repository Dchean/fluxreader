# Agent Note: 用户文案精简与能力矩阵折叠

Status: implemented

## Problem

客户端界面把实现说明、审核口径和成功反馈都摊在常驻位置：同步按钮下重复解释动作语义，订阅页教用户点分类名，GReader 逐动作矩阵与六条协议限制一直占着首屏，低价值成功 toast 复述用户已经看到的布局、折叠和译文状态。搜索明明走本地数据库，却提示“请检查网络”；密码旁把“填写新值”写成“更换账号”；正文失败把重试藏在整句文本里。这些文案让客户端看起来像演示或审核页面，而不是日常阅读工具。

限制与危险信息不能一起删掉：断开连接会移除哪些数据、删除源/分类的本地后果、GReader 的分类逐源表达、Fever 的仅本地边界、首连推送确认、镜像删除、缓存清理与凭据不同步，都必须在用户做决定前可见。

## Decision

**主界面先回答“现在能做什么”，技术边界按需展开。** GReader 已连接时只保留一句“GReader 会写回新增、编辑、移动、退订与分类变更；分类按成员逐源处理。”；Fever 只保留“Fever 仅同步阅读状态；订阅与分类改动只保存在本机。”。逐动作矩阵与限制清单收进“查看写回细节”，但数据仍由 `subscription_capabilities` 单一事实源提供，不在前端另写一套协议说明。

**操作附近的短句优先于页面顶部的长说明。** Fever 的新增、编辑、删除和分类操作用“仅本地”标题或弹窗句说明本地边界。AddFeed 按状态分支：未连接只说连接后“可在「同步本地订阅」中确认是否推送”；GReader 只承诺本次新增；Fever 与协议未知时只说本机保存，不继承通用推送承诺。SyncTab 的“测试连接 / 保存并同步”语义由 `aria-describedby` 关联说明面板，按钮获得键盘焦点或所在区域被悬停时才显示；native `title` 仅保留为补充，常驻解释行仍删除。

**成功态由可见界面承担，toast 只留给需要用户知道的结果或失败。** 布局已更新、全部展开/收起、正文翻译显隐不再弹成功 toast；落库失败仍保留失败提示。搜索失败改为“本地搜索失败 + 重试”按钮，即使命令/订阅源结果仍在也独立显示，不再把本地 DB 错误指向网络。正文失败统一为独立“重试”按钮；音频的 play reject 与 error 事件按音频 URL 在时间窗内去重，只保留一次带“重试播放”的提示。所有外链入口（右键菜单、正文 `<a>`、卡片/阅读器、About、配置同步、GitHub 授权）统一经同一封装；失败说明检查默认浏览器或稍后重试，仍允许 GitHub 登录流程保留原始错误语义。

**用户文案说后果，不说内部机制。** 能力细节把“墓碑、label、no-op、400/404、quick_add”等改写为“只在本机生效、后续同步会再核对、可能留下额外重复订阅”等后果句。设置页统一使用“同步服务 / 同步账户 / 本机抓取”的口径；协议名与 API 密码等必要术语保留。

**危险信息只压缩位置，不压缩事实。** 断开确认仍列明移除订阅、文章与已读/收藏绑定；删除确认仍说明本地条目级联移除与 GReader/Fever 的账户差异；已连接但能力矩阵未加载时，确认框额外声明“无法确认此操作对同步账户的影响”，不把未知当成仅本地。首连推送、镜像删除、缓存清理和凭据不同步的提示继续留在对应确认处。

## Alternatives considered

### Why not 把能力矩阵和限制全部删除？

最省界面，但会删掉真实的用户后果：空分类只在本机生效、分类改动要等下一轮同步、删除后立即重加可能多一条订阅、Fever 订阅不会出现在服务端。把这些事实藏到用户看不见的地方，会把“界面干净”换成“误判远端已完成”，因此保留为可展开详情。

### Why not 继续把完整技术矩阵常驻？

它在 980px 高度下占掉大量设置页首屏，而且大多数 GReader 用户不需要先读七行“已支持”才能连接。逐动作信息对排障仍有价值，所以改为默认收起、按钮明确标为“查看写回细节”，而不是删除。

### Why not 让前端按协议写死两套说明？

前端知道当前协议，确实可以不依赖能力 IPC。但失败重试、空分类、逐成员表达与协议限制会立刻出现多处副本；这次删除的重复概述正是这种漂移。继续由后端给结构化能力与用户后果，前端只投影，才能让确认弹窗、摘要卡和帮助共用同一份事实。

### Why not 继续用成功 toast 给每个动作确认？

布局、树和译文在操作后已经可见，成功 toast 没有新增信息，反而在连续操作时遮挡内容。保留失败提示与少量不可见结果（如导入/导出、同步完成），比“每个成功都弹一下”更符合客户端使用节奏。

### Why not 只改测试里的精确句，不改测试意图？

旧测试锁的是整句文本，任何合理的文案精简都会打红，最后会逼着实现绕开文案质量。现在改为语义断言与负向缺词：按钮 title 必须保留哪些事实、危险确认必须包含哪些后果、AddFeed 不得出现“自动同步”、失败/待处理不得显示“后端已同步”。这样仍能防事实回退，但不把某一句措辞变成永久契约。

## Consequences

- 设置页首屏只保留协议结论；需要排障时仍能展开逐动作矩阵和限制，能力事实没有丢失。
- AddFeed 与 FeedsTab 不再让“本地成功”看起来像“账户已同步”；Fever 的本地边界在新增、编辑、删除附近可见。
- 搜索、正文和音频错误都能给出下一步动作，减少“只报错、不告诉用户做什么”的死路。
- 低价值 toast 清零后，连续布局/折叠/翻译操作不再被提示条打断；失败提示与错误中心仍保留。
- 代价是详情多一次点击，且主界面无法一眼看到所有协议限制；这是为日常阅读场景主动选择的层级。
- 回归网从“锁中文整句”改为“锁语义、缺词与行为”。截至 2026-11-04，原先 copy-1..12 中可行为化的条目已迁到 `copyPolicy` 纯函数断言与真实组件挂载；copy-11 另附一条外链入口单点接线守卫，AiTab 的静态标签是唯一保留的文案源级 `includes` 例外。文案可以继续精修，不会再把整句措辞当永久契约。

## Validation

copyPolicy行为断言与真实SyncTab/FeedsTab/AddFeed/SearchModal/App挂载覆盖能力细节折叠、焦点显示帮助、Fever本地边界、危险确认、搜索失败与已有结果并存，以及减少重复成功toast。外链保留单点接线守卫，AiTab静态标签仍有少量源级例外；它们不能代替真实交互验证。

音频错误去重只限制提示次数，不能证明恢复动作目标正确：2026-11-06旧A的重试仍会影响当前B，见[界面与媒体路线](../../../../docs/roadmap.md#interface-and-media)。文案提供“下一步”不等于该恢复链已通过证伪。
