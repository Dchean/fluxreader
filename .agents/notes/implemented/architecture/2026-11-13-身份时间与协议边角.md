# Agent Note: 身份、时间与协议边角

Status: implemented

## Problem

有些缺陷不在主流程里，却能悄悄改变数据含义：IPC 对象字段命名不一致时默认值吞掉筛选；时间格式混用让排序错一天；源码视图走 HTML 渲染路径；计数在写结算窗口落地陈旧；正文收体/媒体数值缺少边界；认证回落靠错误文案猜测；发布时间被当成身份；清理旧文章的实际条件与界面文案不一致。这些边角需要各自的单点契约，不能靠“命令成功”或“测试通过”共同证明。

## Decision

- **IPC 对象字段与命令参数分开核对。** `ArticleListArgs` 保持 snake_case 字段，与前端 args 对象逐字一致；命令参数的 `rename_all` 不替内部结构体决定字段名。新增/调整 DTO 时把真实序列化输入送入生产反序列化类型，不能只测 TypeScript 对象形状。（原 2026-09-22 bug-fix/2026-09-22-命令入参序列化契约.md）
- **时间存储、排序与本地日期各守口径。** 列表用非空 `published_at` 与 id 建立全序，分页谓词同源，避免在热查询排序键外包函数。同步写入转 UTC，直连解析用 feed 解析器的 UTC 日期；不同时区 offset 的 RFC3339 字符串不具备字典序等于时间序的性质。“今天”按用户本地日期，`published_at` 与 now 两侧一致做 localtime；缓存清理需要比较历史混合格式时才用 `datetime` 归一，不把冷路径规则套进热索引。前端 `parseTs` 兼容历史空格时间按 UTC，游标仍传后端原始时间串。（原 2026-09-23 bug-fix/2026-09-23-时间比较与时区口径.md）
- **发布时间来源显式，抓取时间不参与身份。** `published_at` 是排序/显示的非空时间，另有永久 `first_seen_at` 与 `published_at_source`：源日期为 `feed`；未来日期按策略钳制但标 `feed_clamped`；源无日期时新行 `published_at = first_seen_at` 且 source `inferred_fetch`，二者只写一次；后续出现真实日期可升级为 `feed`，已有 `feed` 不被推断/钳制/抓取时间覆盖。存量行从 `fetched_at` 回填 `first_seen_at`、source 为 `legacy_unknown`，不猜成 `feed`。无精确 ID 时的身份只由稳定来源构成（真实 feed id/guid；同 feed 规范 URL；有源日期时 title+源日期；否则 title+HTML+正文指纹），合成键带控制字符前缀，匹配限定同 feed，弱身份只在出现真实 feed id 时升级，弱身份之间不来回改写。（原 2026-11-03 bug-fix/2026-11-03-发布时间与条目身份.md；后继弱身份契约见[订阅条目与共享内容身份](2026-10-12-订阅条目与共享内容身份.md)）
- **Reader 源码走纯文本路径。** ReaderProse 区分三条结构路径：源码用 `pre` 文本插值，未完成译文用纯文本，完成渲染使用既有 HTML 与外链/灯箱事件。源码绕过图片代理，`sourceText` 是应用当前内容的源文本，不承诺源站 HTTP 原始字节，也不承诺数据库替换全文后仍另有 RSS 副本。转义与代理绕过正确不能证明两份原文都被保存。（原 2026-10-08 bug-fix/2026-10-08-阅读器源码显示契约.md）
- **计数落地增加“写结算序号”判据。** `endLocalFlagWrite` 推进 `localFlagWriteSettleSerial`；reload 与 `reconcileCountsOrdered` 在取数发起时快照该序号，落地时不一致即拒落，并仅在“仅因本判据拒落”时安排 force 对账自愈。其他拒落原因已有各自收敛路径。窄列标题换行、画廊加载 `aspect-ratio: auto 4/3` 占位是同一批视觉边界：占位只是近似，自然比例不同时仍测量改高，不承诺无跳变。（原 2026-10-31 bug-fix/2026-10-31-计数落地写结算判据与窄列视觉修复.md）
- **订阅绑定、响应上限与媒体数值统一。** legacy 订阅创建后的绑定用 `feed_id_by_url_normalized`，查找错误记报告并保留队项，不当作“本地已删除”；规范 URL 不取代精确远端身份。favicon 首页与全文经 `read_body_capped` 使用 16 MiB 累计上限，字节再按 Content-Type charset/BOM 解码；favicon 基础 URL 保留显式端口。封面代理后继以 25 MiB 复用同一 helper，不混淆图片与网页预算。SMTC 数值先把 NaN/负值归 0、超大值与正无穷钳到 7 天，再交 `Duration`；三处入口共用。（原 2026-11-02 bug-fix/2026-11-02-订阅绑定规范化与旁路16MiB界与SMTC浮点饱和.md）
- **认证回落用结构化信号。** `AppError` 用内部 `is_auth` 标记及 `auth/auth_if` 构造器，`SyncReport` 用 `serde(skip)` 的 `auth_failure` 汇总；HTTP 捕获点先 `note_client_error` 再保留原错误文案。回落只读结构化信号，不匹配字符串。401/403 与 Fever `auth!=1` 属认证失败；DB/合并/普通协议错误不因文字相似触发回落；未读差分的批量/逐 ID 存在性探测也登记 client 认证信号。（原 2026-11-02 bug-fix/2026-11-02-认证回落判据结构化.md）
- **缓存清理的本地保留期独立于发表时间。** `readBodyRetentionDays=0..3650`，默认 0 永久；自动保留使用本机字段 `articles.body_retention_since`（nullable UTC 秒），手动清理仍按发表时间。首次接受已读、离开未读/收藏保护、缺失正文实际恢复时开始本机保留期；远端同值快照、普通刷新、同值物化不续期，显式本机标读（含同值）可启动新期，失败的版本守卫不触发计时。L 决定保护资格：accepted/folding、bootstrap、本地投影与计时 work、未接纳 intents 未闭合时暂停清理；维护先按部分索引取候选，再在 writer 事务内重查 L、队项、等价组与真实 body hold（含已无 article 定位的 hold），每批最多 64 候选、8 次真实释放、15 ms 软预算，前台 mutex 忙则跳过。释放展示/RSS HTML、`body_text`、摘要、AI 产物与片段并推进 AI 清除代次；保留身份、读藏版本、原文链接、有效 HTTP(S) 封面、`images_json` 外链顺序与图片计数、enclosure 与播放时长；不删除用户下载文件、不制造同步删除意图。未读/收藏/待同步与未确认 hold 继续保护。（原 2026-11-05 bug-fix/2026-11-05-缓存清理语义与未读保护.md）
- **入口校验分层与真实滚动标读。** 前端把无分类规范为 `null`，后端仍校验实际 `folder_id` 存在；UI 校验帮助纠正输入，后端校验保护所有入口，二者不能互相代替。列表滚动标读必须同时有真实输入依据与非程序性滚动依据：wheel、touchmove、pointerdown、翻页键置输入闩，程序性定位进入抑制窗口；J/K、搜索定位、返回锚产生的 scroll 事件本身不证明用户读过途中条目。同一业务含义沿入口到消费者使用同一判据（范围派生、分类存在性、设置值域）。（原 2026-09-29 bug-fix/2026-09-29-发布前自检的缺陷集群与遗留.md）

## Alternatives considered

- 改前端全部发 camelCase：是外部契约变更，影响面大于删除结构体上不匹配的重命名属性，否决。
- 把时间统一迁移为 epoch 整数：要改全链读写、分页与 fixture，当前保留 TEXT 模型；热查询全面 `julianday` 又需要一致的表达式索引，不能免费沿用裸列索引，否决。
- 用发布时间/抓取时间做冲突或身份键：缺日期时它就是抓取时间，每次刷新变化，等于把刷新变成换文章，否决。
- 源码采用“手工转义 + dangerouslySetInnerHTML”：保留易误用的 HTML 创建路径；隐藏 DOM 再取 textContent 有先执行节点副作用的窗口，否决。
- 计数窗口直接每次都补对账：稳态每次 toggle 多一条 IPC，换极小概率窗口，否决；只在结算落入取数窗口时补。
- 清理时删除未读文章或写文章级墓碑：前者会被 full sync 拉回，后者把本地缓存维护变成远端删除意图，需要新产品语义，否决。
- 给清理只删正文保留行：改变本地存储形态与列表来源，且点开旧文章仍需正文，否决。

## Consequences

- 真实命令调用仍须同时核对外层参数与内部结构体两个边界；Rust 编译成功不能发现调用方拼错键名。
- 弱身份规则意味着同标题同日期或同内容的不同条目可能声明式碰撞；正文变化会产生新行，这是没有完美身份的明确代价。旧格式身份迁移边界不构成新格式兼容承诺。
- 计数的“拒落瞬间仍显示旧值”是一次异步收敛，与既有失败保留现值语义一致；后端锁序未改变。
- 16/25 MiB 是单请求收体上限，不是进程整体内存界；解压、解码、并发与已交付网络块各有成本。
- 认证标记只解决回落判据，不解决“真实入库后重认证成功但 has_data_change=false”的报告合并缺口。
- 本机保留期在 L 未闭合、pending 保护、巨大等价组或离线 hold 存在时会延后回收；恢复失败、没有原文或服务端已无内容时不保证全文可重新取得。
- 上述边界由受控 HTTP、SQLite 夹具与组件挂载覆盖，不替代真实部署、原生宿主与用户库验证；当前缺口见[路线图](../../../../docs/roadmap.md#reader-and-state)与[同步正确性](../../../../docs/roadmap.md#sync-correctness)。
