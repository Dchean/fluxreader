# Agent Note: 本地同步与便携恢复界面边界

Status: implemented

## Problem

旧配置快照页面只上传/下载订阅与部分设置，无法表达持续读藏同步或正文补齐。恢复新资料库会重分配行 ID，直接调用普通 reload 会保留旧 ReadingSession 成员；旧设置、AI 服务和播放进度的迟到写入也可能污染新库。后台同步普通设置后，前端基于旧确认快照整包写回会覆盖远端刚改变的其他键。

## Decision

WebDAV 连接、状态请求序号、单飞操作与便携恢复任务/结果由 `store/slices/localLibrary.ts` 唯一持有。表单拥有本地编辑草稿，读取与事件不覆盖 dirty 字段；状态回复按请求序号和后端连接代际落地。已配置连接与同步成功分开，状态/正文确认时间、待处理状态、封批数量与本机缺正文分别显示，无可证进度时不生成百分比。

便携文件只有校验预览后才显示替换确认，恢复携带用户看到的完整文件摘要。选择取消、预览取消不写数据。成功提交即消费预览并保存结果；后续任何错误归类为界面刷新失败，重试只回读，不能重复 restore。旧 Gist/OAuth 整体退出；GitHub Releases 更新检查继续使用原受控入口。

确认恢复后 App 统一 busy/inert 与最前键盘守卫阻止新用户编辑，不把冻结散布到每个按钮。先停当前播放，等待已有 AI 行为写、普通设置写、AI 服务读改写队列、读藏写和已登记播放进度写。播放 key 在恢复边界内拒绝迟到事件；AI 服务队列保持原单链，在成功恢复后推进 epoch，拒绝旧页面排队任务。普通设置/AI 行为保留原写屏障、读回凭据和失败恢复，不因删除 Gist 误删。

整合基础批画廊后，恢复开始及成功换库都调用画廊唯一的 `closeLightbox`，同步递增其请求序号并清图片集合、URL 与条目归属。开始阶段在等待读藏前沿之前执行，尤其拒绝无首图详情晚到后才 `markEntryOpened` 发起新标读。画廊请求还绑定 `libraryGeneration` 并检查恢复 busy；单图/多图打开和共享 `markEntryOpened` 在 busy 期间不产生新打开副作用。已经登记的标读照常结清，不能清队列逃过前沿。恢复失败不推进资料库代际，但被关闭的旧图片请求仍无效；用户可在结束后明确重开旧库图片，不能由旧回包自动恢复灯箱。提交后仅刷新重试也先关闭当时灯箱，避免刷新期间留有可作用的图片请求。

仅成功恢复调用 `resetLibraryViewAfterRestore`：推进 reload/page/session 与 libraryGeneration，清旧源/组/文章选择、视图缓存、阅读锚、错误重试入口与正文/AI状态，设置/搜索表单按代际重挂。正文 revision 序列、AI request generation 不归零；旧响应无资格复活。普通同步只回读当前成员属性；设置事件回读不应用启动筛选，不改变正在阅读的成员关系。

独审SUI-A1证实只清正文缓存与现有errors不够：旧详情/全文请求在恢复后拒绝仍可重新登记旧库重试。Reader现在在请求发起时捕获libraryGeneration，详情、批量水合、手动/自动全文提取的成功/缺失/降级/失败回调及其保存的重试闭包共用同代际资格；待flush的水合批次也不能把旧ID带过恢复。只有成功恢复换代才使这些工作失效；当前代内异常继续按原流程可见，普通切篇不取消离屏重试，恢复失败保原代际。此资格不替代body revision stamp：后者仍约束同库正文修订与重复ID缓存，不可因新guard删除。

普通设置每笔仅发送已验证的显式 `intent.patch` 给 `patch_app_settings`。后端在事务内合并当前设置并返回已提交完整 JSON，该结果成为确认基线后再投影后续本地意图。保留既有串行链、写 serial、读 epoch、apply gate、未知基线校准与失败回投；禁止用缓存全量 JSON 或“先读再写”冒充原子合并。

`readBodyRetentionDays` 注册为 0..3650 整数，默认 0（永久），与瞬时手工清理的 `days` 独立。界面只说明已读且未收藏正文、未读/收藏保护，不先承诺未经统一的计时起点。后端期限执行与正文 pending 恢复由同批后继负责；只有这些真实链路与验收闭合后该控件才能作为已生效功能发布。

## Alternatives considered

- 在旧 ConfigSyncSection 改标题：不能承接持续状态/正文义务、RSS互斥或便携恢复事务，退役旧页面并新增明确入口。
- 依赖普通 reload 清旧数据：固定成员会话按设计不重新筛选，故采用仅恢复可调用的新数据代际 reset，不改变普通同步阅读体验。
- 只在恢复成功时清灯箱 URL：无首图请求在等待前沿期间仍能补标读；只改展示字段也不会推进画廊自己的请求序号。改用开始及成功两处真实关闭动作，代价是失败后需明确重开图片。
- 只在设置 UI 中设 busy：播放时间事件和 AI 阅读停顿计时仍可越过，因此追踪实际消费者：播放写有独立边界；自动 AI 的 unobstructed/lease 立即尊重 libraryRestoreBusy；原有 AI/正文响应继续用既有代次戳拒迟到。
- 删除原 SQLite 快照入口：其当前 Windows 用户本机故障恢复仍有用途，保留折叠高级区；换机主入口明确使用无凭据的 `.flxb`。
- 先读取远端设置再拼整包写：读取与写入之间仍可发生 WebDAV 更新，必须后端事务原子 patch。

## Consequences

恢复等待既有写链期间不可编辑，但状态明确可见，结束后可恢复操作。导出只等发起时已有写前沿，导出本身不挡后续设置写入。新鲜 ID、正文单调戳和 AI 代次共同防止旧响应污染新库；不声称取消已经发出的网络/AI工作。

普通 WebDAV 属性刷新保留既有 ReadingSession 成员、阅读位置与画廊操作；只有恢复/恢复后刷新边界关闭灯箱。失败仍保留旧库数据和当前代际，但不会自动复活关闭前请求或焦点。

记录只描述边界与理由，不把 TypeScript/mock 通过视为 Windows 原生选择器、真实 WebDAV、跨机器恢复或容量验证。前后端共同门禁、当前版本独审与真实环境证据由本轮验收入口承担。原数据库快照决定中 `VACUUM INTO`、DPAPI本机边界与应用外恢复继续有效；旧配置镜像和“不提供任何应用内恢复”的结论由本决定与便携v4后端部分取代，历史理由与验证保留。

## Verification

正式组件用例覆盖取消零写、完整预览后果、摘要传递、四类前沿等待、提交后新ID/缓存重建、失败保原、成功后回读失败只刷新重试、导出前沿、逆序状态与dirty草稿、RSS互斥、忙态键盘和原子patch保远端别键。原settings R3–R6串行/回读/失败/基线竞态断言继续保留，假后端改成真正合并patch并分别检查传输patch与后端状态。

旧 OAuth 的发起/取消/轮询专属用例随功能退役；其真实可达关闭/防穿透风险由恢复忙态用例承接，普通RSS activity generation的多活动逆序用例保留。旧ConfigSync的merge/mirror专属计数、远端快照token和删除前快照断言退役；预览零写/确认后写/前沿/失败释门/回读失败/导出不阻塞由便携用例承接。AI配置队列和AI行为模块的独立回归继续执行，不用调用计数代替终态。

新域会实际修改startupView、普通设置与settingsTab，因此测试结束恢复进入前值并清自己的IPC计划。不能让后继IME或焦点用例继承starred筛选/about页；相邻顺序复验属于测试隔离证据，不改被保护行为。原长等待中，AI 700ms停顿、防抖和runner错误终态均有实际时间语义；本轮不为了运行预算缩减它们或上调120s门限。

F5焦点用例另显式打开general页再取得将卸载的input：About前导用例可合法留下about页，不能依赖已退役OAuth用例顺手切到sync。原输入触发搜索、切页卸载、Escape回最上层存活设置面板的断言全部保留。

SUI-A1的正式回归位于local-library域：详情三终态、手动/自动全文三终态、批量三终态、已有重试闭包、失败恢复和同库切篇正控。原独审8反例的失败记录保留，修复重跑仅改变脚本导入前缀，结果绑定当前TypeScript转译字节；作者自测不替代原审计者复审结论。

画廊/恢复整合的正式回归由 `restore-gallery.test.mjs` 覆盖：开始即关闭、等待旧标读前沿且不新增标读、迟到成功/空结果/失败不能复活旧集合、失败后明确重开、成功后新库继续开图与普通同步保成员/位置。它与基础批画廊用例共用真实组件和生产 store；既有 F5 通用页显式选择及画廊局部设置清理保留。当前整合的运行版本、结果和未验证项集中在当次交付，不沿用旧 R2 的自测或针对 SUI-A1 的独审结论冒充整合通过。
