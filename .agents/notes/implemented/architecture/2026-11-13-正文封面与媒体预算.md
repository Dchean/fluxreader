# Agent Note: 正文、封面与媒体预算

Status: implemented

## Problem

正文与封面都曾把“已经请求”当成“已经有值”：列表快照清掉 hydrated 标记后界面只显示加载却没有请求；封面候选固定取最新前缀，失败项长期占据窗口；只看 Content-Length 就完整读取图片，无长度响应在拒绝前已占满内存；来源不明的旧封面会在 RSS 去图后继续显示。这些问题共享一个边界：重字段与媒体必须有独立于列表快照的生命周期、有界预算和可解释的失败终态。

## Decision

- **正文与 AI 重字段归实体缓存，列表只带轻字段。** 缓存状态为 loading、ready、cleared、missing、failed，无记录表示未请求；卡片是否需要正文由统一入口决定。列表查询不批量携带正文，详情与 AI 产物不随每次列表快照重建；已请求但响应缺行落 missing，真实错误落 failed 并提供提示/重试。失效由内容身份、修订与轻字段事实协调，不能靠强制重挂载列表解决——那会丢滚动位置与展开状态。（原 2026-10-05 bug-fix/2026-10-05-正文水合生命周期统一.md；所有权见[正文与 AI 实体缓存](2026-10-06-正文与-AI-产物的实体缓存.md)）
- **封面候选按扫描行数推进，不按成功数。** 每轮最多 20 个 URL、并发 2、单请求 30s、扫描 4 页 × 20 条、间隔 60s；进程内 scan_offset 跨轮推进，读空页回绕，不写数据库。一次尝试结束才写失败/无图缓存；HTTP 失败是已知结果可缓存，DB 写失败与退出取消不算完成。成功结果保存可复用图片 URL，使扫描窗外或后来新增的同 URL 候选在正常扫描到时复用，不扩大扫描或额外发 HTTP。（原 2026-09-23 bug-fix/2026-09-23-封面补全的候选窗口饥饿.md、2026-10-16 feature/2026-10-16-封面补全覆盖面与预算边界.md）
- **封面来源显式 rss/page，不比较 URL 猜来源。** `image_source` 由 RSS 摄取/修订与网页补图入口分别写入；page 独立封面在 RSS 图片增删改后保留，完整非空 RSS 可删除旧 rss 派生图，稀疏空回包保留。普通文章封面仍是 `image_url`，画廊优先展示正文有序图；实际媒体输出变化由单一 SQL 触发器推进媒体版本，全文、清正文、direct 与同步共用。缺该列的试验库只读拒绝，不做旧库迁移。
- **封面请求预算与质量过滤有界。** 候选统一为“无封面且有 URL”，不按来源排除；正文首图、OG、RSS 媒体按显式尺寸与角色跳过小图/头像/emoji，缺尺寸的正常新闻图保留，不另发尺寸探测。文章页收体复用 16 MiB 的 Content-Length 预检与累计流式上限；重定向以最终响应 URL 解析图片。DB 读失败只结束本轮，写失败保留下轮机会；退出信号同时取消等待与在途 HTTP，round 返回前等待子任务结束。
- **封面失效按精确 URL CAS。** 全来源本机封面都可按 article ID 与当前图片 URL 精确 CAS 清除；不推远端、不改文章身份，后续远端 pull 仍可提供权威新图。撤销相同成功缓存并设短期失败屏障，旧图迟到不能清新图。后端失败/无图 TTL 为 10 分钟，失败命中不续期；scheduler 与上报命令共用 AppState 中一份结果状态，网络与图片处理不持 DB 锁。
- **图片代理在读取期间限字节。** `fetch_image_inner` 经 `ingestion::read_body_capped(resp, MAX_IMAGE_BYTES)` 收体，长度预检与累计上限同时生效；图片按二进制返回，不做 charset 解码。超限统一 `responseTooLarge`，前端三条代理路径都降级为隐藏或占位。25 MiB 只约束封面/图片收体，文本与 WebDAV/模型列表等分别使用 16 MiB 上限，不能把单请求上限当成进程整体内存上限。
- **失败占位与会话记忆只覆盖代理传输。** 代理传输失败按 URL、有效 Referer 与资料库代际保存在模块内，跨组件挂载显示占位；直链解码失败只留在该消费者，不污染共享失败缓存。断网、取消、容量不足、过大响应、非图与未知解码错误都不清持久封面；只有完整 Referer 链明确 404/410 且当前封面 owner 仍有效才按原 URL 精确 CAS。非图片响应不能作为 HTML 注入；无 URL 不创建 img、不代理也不上报。
- **Fever 星标与订阅恢复的幂等边界。** api_version ≥4 直接发目标态；3 或未知先 `with_ids` 读取 `is_saved`，不同才发 mark；缺条、缺状态或请求失败保留队项，不盲发，后继 ACK 读回确认后才出队。订阅恢复先读远端列表，规范 URL 已存在则复用；未确认缺席前不发 `quick_add`，创建失败/无 id 后再读列表处理“已创建但响应丢失”。（原 2026-10-31 bug-fix/2026-10-31-fever推送幂等与订阅恢复收敛.md）

## Alternatives considered

- 列表快照重拉所有正文：每次刷新制造额外 IPC，并把“缺正文”等同于“换过快照”，否决。
- 一次请求所有历史封面候选：放大网络与内存；只取固定头部又穿过不了持续失败项，否决。
- 预先标记“已尝试”而不等请求完成：不能证明请求已执行或结果已落库，否决。
- 只用 Content-Length 预检：无长度/流式响应会在拒绝前占满内存，必须累计收体，否决。
- 按 URL-only 共享代理失败：不同 Referer 页面会互相毒化；按 URL + 有效 Referer + 代际，否决。
- 盲发 Fever saved/unsaved：旧 toggle 变体会翻反星标，必须先读后写，否决。
- 订阅创建失败后继续 quick_add：非幂等查找会卡住或造重复订阅，改为先列表后创建，否决。

## Consequences

- 实体缓存让按需水合与刷新解耦，代价是每个失效入口和消费者都必须遵守同一协议；响应缺行会被判 missing，不能要求后端返回不存在的行。
- 封面扩面会直接请求服务端收录文章的第三方页面，增加客户端 IP 暴露；当前没有专用关闭开关，这是个人客户端的已知取舍。
- 有界预算让固定候选与持续失败前缀可轮转，但不是动态集合下严格公平性的数学保证；尺寸/角色过滤是启发式，未知尺寸头像仍可能误选。
- 成功缓存可逐出、失败 TTL 有等待期，不能声称所有坏图都会立即恢复；代理 25 MiB 上限不等于解码、并发与 WebView 内存上限。
- 图片代理与封面补全有受控 IPC/真实 HTTP 夹具，但不替代真实图床、WebView 解码与原生窗口验证；当前缺口见[路线图](../../../../docs/roadmap.md#interface-and-media)。
