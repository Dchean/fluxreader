# Agent Note: 凭据失败关闭与受控更新检查

Status: implemented

## Problem

两处「失败时往坏方向降级」的路径（审计 F22、F16）：

1. **DPAPI 失败退回明文（F22）**。`encrypt_secret` 在 `CryptProtectData` 失败时只记 warn 并把原文明文返回，保存调用方照常落库——用户以为凭据受静态加密保护，实际可能已明文落盘。同构的降级还在读取侧与账号生命周期：解密失败（base64 损坏 / DPAPI 失败）把 `dpapi:` 原串当「已解密值」返回；`read_credentials` 用 `.ok().flatten()` 把读取错误吞成「未配置」，`sync_save` 于是把损坏凭据当**首次连接**、跳过换号清理直接写新账号（R1 P2）；且账号保存的「换号清理 + 四项配置落库」不在一个事务里——purge 与新 protocol/endpoint/username 已生效后，密码加密失败会留下「新地址 + 旧密码 + 已清空的数据」（R1 P1）。
2. **关于页更新检查被自身 CSP 拦死（F16）**。AboutTab 直接在 webview 里 `fetch('https://api.github.com/repos/Dchean/fluxreader/releases/latest')`，而生产 CSP 的 `connect-src` 只允许 `self`、`ipc:` 与 `http://ipc.localhost`——正式版里这个请求必然失败。另有两条正确性缺口（R1 P3/P4）：固定首跳若复用共享抓取 client 会**跟随 30x** 到任意主机或降级 http；`html_url` 已提供但非法时被悄悄换成官方页并返回 Ok，前端拿同一版本号会误报「已是最新」。

## Decision

**一、凭据失败关闭（Windows 生产）：加密与解密失败一律返回 `AppResult` 错误；账号保存/断开的清理与配置必须同一事务全有全无。**

- `encrypt_secret` → `AppResult<String>`：DPAPI 失败返回 `Err`（`credentialEncrypt`，信息不含明文）；`decrypt_secret` → `AppResult<String>`：base64 损坏 `credentialCorrupt`、DPAPI 失败 `credentialDecrypt`，无前缀旧明文照常透传（迁移兼容）。加密核心 `encrypt_secret_with` / 迁移核心 `migrate_legacy_plaintext_with` 是**模块私有**注入点（库外无 pub 入口，webview/其他模块不可操控加密后端），失败语义由模块单测锁定。
- 启动迁移 `migrate_legacy_plaintext`：任一键失败整体 `Err`——不写假密文、不计数；`db::open` 既有 `?` 传播。
- `db::set_setting` 在 SQL 执行前加密，失败时旧值原样、缺行不插入。
- **账号提交事务（R1 P1）**：`commands/sync.rs` 的 `commit_account_settings` 把「换号 purge（`db::purge_remote_data_in` 事务内核，不再嵌套 BEGIN）+ protocol/endpoint/username/password + 游标重置 + 端点缓存」放进**同一短事务**；任一步失败（含密码 DPAPI 加密）整体回滚——旧配置/订阅/队列/墓碑原样。`sync_disconnect` 同样收口到 `commit_disconnect` 事务内核。
- **读取错误 ≠ 未配置（R1 P2）**：`sync::read_credentials` 改为三态 `AppResult<Option<...>>`。`sync_save` 读取错误原样上抛（`resolve_save_plan` 纯函数收口），绝不写新账号；`sync_configured`（folders 三处 + sync_local_feeds）传播 Err 而非静默当离线；`build_client` 把读取错误归入 `Failed`（记录 attempts/last_error）而非 `NotConfigured`；scheduler 记警告并跳过本轮（不发请求）；队列事件按「已配置」显示口径上报（错误原因经 last_error 呈现）。**损坏密文的恢复路径**：`sync_disconnect` 不读旧密码 → 清空 → 重新配置（模块单测锁定）。
- **可失败检查先于本地副作用（R2）**：`record_feed_deletion` / `record_feed_edit` 的 `sync_configured` 读取前移到**任何本地写入之前**并复用结果——坏密文时整单失败：订阅/文章/墓碑原样、编辑字段原样（修前：墓碑已落+订阅已删/字段已改，才发现凭据读取失败）。`add_feed` 的入队检查本就在其单事务内，失败随事务回滚，维持不变。
- 非 Windows 保持**显式开发降级口径**（无 DPAPI → 明文 + warn；迁移跳过返回 0），不假装加密成功；不影响 Windows 生产失败关闭。

**二、更新检查收口到固定目的地的后端命令：CSP 不放宽，webview 不获得任意 URL 代理能力。**

- 新 IPC 命令 `check_for_updates`（无入参）恒请求 `api.github.com/repos/Dchean/fluxreader/releases/latest`，**专用 client**：`RedirectPolicy::none()`（禁止跟随 30x，3xx 一律失败）+ 显式超时（生产 10s）+ 应用身份 UA；**不复用抓取 client**（后者按设计允许跨域跳转）。
- 404/429/5xx/3xx、JSON 畸形、`tag_name` 缺失或为空 → 明确 `Err`（只回状态码与原因，不回显响应体），**不误报「已是最新」**。
- `tag_name` 去可选 `v`/`V` 前缀后交给前端既有 `compareVersions`；前端对不可比较的远端版本按「检查失败」处理。
- `html_url` 契约（R1 P4）：**缺失** → 回落官方 releases 页（可容忍）；**已提供但非 string / 非法 / 非受信** → 整体 `Err`（不接受「换成官方页还返回 Ok」的静默替代）。受信判定：https + github.com 主机 + 本仓库 releases 路径（段边界校验、大小写不敏感）。
- 注入面只在 `commands/settings.rs` 模块单测内（本地回环 HTTP mock、双 listener 重定向目标零请求、慢响应有界超时）；`check_for_updates_at_base` 是模块私有函数——原 `tests/update_check_e2e.rs` 与所有 pub 测试入口已删除。

## Consequences

- Windows 上 DPAPI 故障不再产生「静默明文落盘」：代价是保存/启动会可见失败（迁移失败甚至启动失败）——显式取舍：宁可失败可见，不悄悄降级保护级别。
- 损坏或跨用户拷贝的密文，读取错误现在沿调用链可见：账号保存被拒（提示可用「断开 → 重连」恢复）、自动同步跳过并记警告、推送失败标记 attempts/last_error；不再出现「把密文当密码发出」或「当首次连接写坏账号状态」。
- 账号切换/断开的半套状态被事务消除：失败后旧账号配置、订阅、绑定、队列与墓碑全部原样（模块单测 + 既有 account_lifecycle e2e 双保险）。
- 更新检查在浏览器开发环境（无 IPC）返回 null → 前端按失败处理；只有 Tauri 实机路径有真实结果。`tauri.conf.json` 的 CSP 一字未改。
- 用例迁移说明：原 `tests/update_check_e2e.rs`（依赖 pub 测试 helper）整体收进 `commands/settings.rs` 模块单测并新增重定向/超时/非法 html_url 反例；`credential_safety_e2e.rs` 保留 5 条不依赖注入的真实 DPAPI/损坏密文黑盒用例，注入类用例收进 `credentials.rs` / `db/settings.rs` / `commands/sync.rs` 模块单测。
- 本决定取代《发布前自检的缺陷集群与遗留》遗留清单中的「关于页『检查更新』被 CSP 拦死」一项（roadmap 对应行的收口由主控集成时处理）。

## Alternatives considered

### Why not 放宽 CSP 的 connect-src 加 api.github.com？

为一个检查更新请求，给整个 webview 放行对外网域的连接面，等于让「将来任何前端代码都能发任意请求」成为常驻能力；审计也明确建议不要宽泛放开。收口到后端固定目的地后，webview 的出网能力零变更。

### Why not 更新检查复用共享抓取 client？

抓取 client 按设计允许 30x 跨域跳转；固定 URL 的语义是「首跳即目的地」，一旦跟随重定向，被跳方可以是任意主机（甚至 http 降级），白名单形同虚设。专用 client 把「不跟随」变成结构属性，测试用双 listener 证明目标零请求。

### Why not 提供非法 html_url 时回落到官方页还返回 Ok？

「缺失」是响应形态不全，官方页回落仍指向正确仓库；「已提供但非法」说明响应不可信或地址被替换，静默回落会让「有更新但版本同号」的场景变成「已是最新」的假结论。失败关闭让用户看到检查失败而不是错误结论。

### Why not 账号保存先做可失败步骤、再写库（不开事务）？

「先加密后写」只能覆盖加密失败这一个失败点；purge 已执行、后续任一步 SQL 失败同样会留下半套状态。统一短事务覆盖全部失败点，且 `purge_remote_data_in` 内核解决「事务套事务」的嵌套问题——不需要在每个步骤上逐一预检。

### Why not DPAPI 失败时显式降级并告知用户？

「显式告知 + 用户选择」需要一套凭据保护状态 UI 与重试流程，而用户无法修复 DPAPI 本身；静默明文落盘又直接违背用户对「静态加密」的预期。失败关闭（保存 Err、启动迁移 Err）以最小改动消除错误方向。

### Why not 非 Windows 也返回 Err？

非 Windows 无 DPAPI 是开发态事实而非故障；明文降级口径是显式的（warn + 文档），迁移本就跳过。若未来出现非 Windows 生产目标，应引入该平台的加密实现，而不是让现有降级蔓延。

### Why not 直接 mock DPAPI 来测解密失败？

`encrypt_secret_with` 注入只覆盖「加密失败」分支；解密失败用两种真实损坏形态驱动（非法 base64、合法 base64 但非 DPAPI 密文），跨平台可复现且更接近事故形态，不引入 mock 与真实实现漂移的风险。
