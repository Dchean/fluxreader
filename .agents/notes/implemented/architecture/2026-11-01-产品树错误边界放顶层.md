# Agent Note: 产品树错误边界放顶层

Status: implemented

## Problem

生产树零错误边界：全库只有测试假件有 `componentDidCatch`，任何组件渲染崩溃都直接白屏，且崩溃发生时没有留下任何归因信息——只能靠复现猜。审计把它列为 P3 与美观批次的点名项（roadmap §七）。

历史教训（NotifCard #185 一类问题）表明：崩溃治理的核心需求不只是「别白屏」，还有**归因**——要知道崩的是组件树哪一段。`componentStack` 只有在边界捕获时才能拿到，错过这一次就没有了。

## Decision

**边界放产品树顶层，全树一个**：`src/components/ErrorBoundary.tsx`（class 组件，`getDerivedStateFromError` + `componentDidCatch`），在 `App.tsx` 包住 app-root、全部浮层与 toast 层。`componentDidCatch` 记 `console.error`（error + componentStack），兜底态用 `.error-boundary-splash`（自带全屏居中——复用 `.app-loading-splash` 会因居中依赖 `.app-root` grid 拉伸而顶对齐；文案/重试样式复用 `.bootstrap-error`）+ `role="alert"`，提供「重试」按钮清除边界自身错误态让 React 重渲染子树。

- **窗口控制在边界外**。无边框窗口在崩溃态下仍必须能最小化/关闭——兜底态替代的是内容树，不是窗口本身。
- **不做逐卡片/逐面板分包**。每包一层就多一个「错误静默局部化」的点：卡片级兜底态会让用户面对一堆残破的占位卡，而系统性错误（store 损坏、虚拟化错位）本来就该整树兜底；顶层单点同时保证 componentStack 只有一处记录通道。
- **重试只清边界状态，不重置 store**。瞬态错误（竞态、时序）由此恢复；确定性崩溃会再次落入兜底态——不静默吞掉，也不假装能自愈。

反向注释：`src/components/ErrorBoundary.tsx` 头注。

## Alternatives considered

### Why not 每个卡片/浮层各包一个小边界？

局部兜底的收益是「一棵卡崩了别的卡还能用」，但代价是：兜底 UI 要为每个位置单独设计（卡片里塞不下全屏兜底语言）；边界层层嵌套后 componentStack 的记录点分散，日志侧要重新拼接归因；且真实崩溃多为系统性（数据形状变化、store 契约破坏），局部兜底只是把白屏换成满屏残卡。审计对 NotifCard #185 的归因需求要的是「一次崩溃、一处完整 componentStack」，顶层单点正好满足。

### Why not 只记 log 不出兜底态？

记 log 不改白屏事实——用户已经失去整个界面；一个带重试的兜底态成本极低（复用既有启动失败视觉）。

### Why not 把窗口控制也包进去？

无边框窗口的原生控制按钮是崩溃态下唯一可用的 UI。包进去意味着一次渲染崩溃后用户只能用系统强制关窗。控制按钮不依赖任何会崩溃的数据面。

## Consequences

**收益**：渲染崩溃不再白屏；每次崩溃必有带 componentStack 的 log（归因可走回）；崩溃态下窗口仍可最小化/关闭。

**代价与已知边界**：App 组件自身 hook/render 抛错不会被自己的边界接住（边界在它 return 的树里）——要兜住那一层需要在 `main.tsx` 再包一层，当前未做；崩溃瞬间的 store 状态不重置，重试恢复的是渲染而非数据。行为腿由 `tools/component-tests/error-boundary.test.mjs` 取证（真实边界 + 崩溃探针），接线腿（树内/树外划分）由 ui-contracts (w4-1) 源码形态断言钉住。
