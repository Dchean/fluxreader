# Agent Note: 同步会话复用、请求有界并发与聚焦触发

Status: implemented

## Problem

2026-11-01 的优化针对三个已知成本：每次短间隔同步重新认证；已确定 ID 集合的独立正文块串行等待；用户切回窗口后仍需等周期。需要减少重复工作，同时保留账号代际、页游标顺序和个人服务端的负载边界。

## Decision

### 会话复用

`session.rs` 的进程级单槽缓存以 account_key+generation 为键，TTL 10 分钟。锁内快照身份与代际，命中不认证；未命中走原 build_session，构建期与写回期代际守卫保留。启动 setup 注册缓存，未注册的独立集成测试不读写缓存。单槽是当前单 AppState 的工程选择，不是跨数据库长期共享会话的通用服务。

缓存租约遇认证失败时，只剔除自己持有的 Arc 指向的条目，再重认证并重放阶段一次；新租约不再触发这一回落，避免循环。2026-11-02 的[结构化认证判据](../bug-fix/2026-11-02-认证回落判据结构化.md)已取代早期 `[code]`/401 文案扫描，不能再将字符串误报记为当前已接受方案。

绑定不完整 marker 仅在成功 pull_feeds 后清理。认证恢复后的 light 若受 5 分钟发现节流，可能仍等待下一个发现窗口或手动 full，不能把重新认证成功等同于已恢复所有绑定。

阶段重放必须保留首轮已提交事实。2026-11-06 基线 `91ece562` 以重试报告替换首轮报告，实测丢失 has_data_change=true；旧文把它描述为可接受统计偏移错误，因为它会影响消费者刷新。后继修复由 `SyncReport::preserve_changes_from` 累计首轮已提交变化标志和处理计数；feeds、states、即时状态推送、订阅写回、只读发现及定向 feeds 的有界重放均使用同一合并规则。处理计数可能包含幂等重放，不能当唯一条目数量；实际数据变化继续由值条件/前后数据判定。

2026-11-07 首次独立审计又证实“只保留变化、完全沿用重试错误”仍会抹掉首轮已发生的 SQL 确认失败：同一轮后续401触发重放，第二次确认成功并不能使第一次数据库错误从历史中消失。后继修复在客户端错误入报告时以 `AppError::is_auth_failure` 原子登记消息与认证索引；普通 DB/协议消息直接追加默认为非认证。报告的 errors 只追加，absorb 按原消息数量平移索引；push/outbox 延迟汇聚也携带相同分类，不按文案或“下一条消息”推测。

重试交接去掉首轮的认证错误消息，保留所有非认证故障并明确引用“重认证前曾发生”的当时状态。仅重试报告无错误时提示后续阶段重试已完成；仍有错误则注明后续已重试且仍有错误，不把旧“队项保留待重试”说成当前持久结果。重认证构建失败不替换原报告，保留原来的 SQL/认证事实；绑定完整性及当前认证结论仍沿用实际重试结果。该内部分类不进入 IPC，不引入第二套日志或永久故障状态。

### 独立请求并发与屏障

GR 主正文/权威集合的 100 条块、Fever with_ids 的 50 条块，最多三个请求一批并行拉取，然后按原块顺序串行短锁合并。maps 更新、失败重建与游标依赖顺序，不能并行写库。分页 continuation、since_id/max_id 链仍串行；PULL_LOCK 保护 pull 编排，HTTP 不占数据库锁。2026-11-05 又由[运行生命周期](2026-11-05-同步运行生命周期与诊断.md)收口整轮所有权，不能把旧 PULL_LOCK 当全入口协调器。

测试屏障必须区分请求到达与数据库提交。批内 N 个请求可能在任何合并前全部到达；只有后继批首请求 `k·W+1` 能证明前 k·W 块已合并。主 ids 起点、权威集合阶段及订阅 edit/quickadd 屏障各按实际阶段定位，不假设较小请求序号已经落库。

### 聚焦触发

Rust 主窗口 Focused(true) 直接进入 scheduler；AtomicI64 CAS 认领 ≥60 秒的触发窗口。即使后续 autoSync/凭据前置判定不通过也不返还认领，因此刚启用 autoSync 可能顺延最多一个节流窗口。通过前置判定后先处理 pending outbox，再发 light，事件与诊断由当前协调器承担。

周期设置和发现节流仍分别生效；聚焦成功推进同步时间后，周期自然顺延。60 秒是事件节流，不是网络完成、错误恢复或新内容可见的时限。

## Alternatives considered

- **并发整个 pull 或移除 PULL_LOCK**：订阅绑定、条目合并、权威对账、Fever 历史共享状态，阶段有真实依赖；重建 DAG/游标细锁超出收益，保留串行编排。
- **全量预取**：在途正文随条目数增长；固定批并发把响应占用限制在批规模，不能因此宣称整个进程内存有严格常数上限。
- **滑窗完成即补下一块**：可减少慢块头阻塞，但当时没有 futures 直接依赖，手写要维护任务句柄与取消（drop JoinHandle 只 detach）。选择简单 join 批次；是否有可观收益须用当前端点 RTT 测量，不以“必可忽略”排除未来重访。
- **item_contents 从 100 调到 1000**：2026-11-01 第五轮调研保留 100。常态窗口/差分候选往往小于 100，大块主要影响追赶期，同时扩大失败重拉单位；没有足够收益证据去改变边界。这是当时的负载取舍，不是协议上限。
- **缓存穿 AppState 参数**：会改大量双参 sync 入口和测试调用；进程单槽与既有启动注册模式一致，代价是注册点在 setup、引擎中不能只靠构造器判断启用。
- **只以代际作键**：不同数据库可同号，身份额外隔离不同账号；现行仍以单 AppState 为前提。
- **过期后后台刷新**：增加任务生命周期和“是否继续用旧租约”语义，当前直接 miss 重建。TTL 10 分钟小于典型 30 分钟周期，纯周期每轮都会 miss；复用收益来自聚焦、即时推送与短间隔 outbox，旧“每三轮认证”计算已撤回。
- **请求点各自重认证**：重建会话需穿过每个循环，半程提交边界更分散；保留入口有界重放，并在报告交接时保留首轮提交事实。
- **重试成功后删除所有首轮错误，或按错误文案过滤认证**：前者掩盖真实 SQL 故障，后者会误删同文非认证错误；选择构造点的认证标记并保留带当时状态的历史消息。不能仅凭阶段重放推断每项首轮故障都已恢复，因此不自动去重或转成永久失败。
- **前端监听焦点再发命令**：Rust 已有窗口事件入口，新增 IPC 和装载时序没有必要。

## Consequences

短间隔入口减少重复认证，三个独立请求可重叠等待，但吞吐受慢块、响应体与合并耗时制约，不能承诺所有场景 1/2–1/3 时延。缓存吊销首轮可能先失败再认证；重放可能重复已成功部分，幂等和诊断事实都须验证。并发度为内部常量，直连抓取 UI 的 fetchConcurrency 不改变同步并发。

## Verification

历史 `session_cache_e2e` 覆盖命中、一次认证回落、TTL/代际、失败计数与恢复；字段版本屏障用例按批边界重锚，scheduler 单测覆盖聚焦节流。`sync_correctness_e2e` 后继回归把“首轮真实插入一条→权威集合401→重认证成功→报告仍有数据变化”锁定为必要条件；另用一次性 RAISE(FAIL) SQL 确认故障验证 SQL→401→重试成功、无401对照、纯认证恢复、重认证登录失败与阶段重试仍401。报告单元回归锁定 raw 消息、相同文案不同分类、absorb 索引平移和重复非认证事实保留。固定上游能力证据另由[GR 差分记录](2026-11-01-GR未读差分对账.md)保存，未验证的推送/缓存协议能力不得被当作永不存在。2026-11-06 `91ece562` 的原反例、首编失败和2026-11-07独立组合反例均保留，不改写成通过；精确修复版检查状态在当轮验收入口。早期方案和历史测试背景见[整理前记录](https://github.com/Dchean/fluxreader/blob/91ece562d79fd909642cd6d570d636e884b7387e/.agents/notes/implemented/architecture/2026-11-01-同步会话复用与有界并发与聚焦同步.md)。
