# Agent Note: 纯本地资料库同步与便携恢复

Status: implemented

## Problem

已确认的新产品需要纯本地模式下持续同步订阅、分类、普通设置、独立读藏状态及未读/全部收藏正文，并能换机恢复退订收藏。原 Gist/WebDAV 手动配置快照没有文章正文、逐字段意图或多设备冲突语义，基础批后续schema3补齐分组三态仍不能承担持续资料库同步。其历史理由与真实修复保留在[镜像记录](2026-10-15-配置快照镜像应用.md)。RSS 服务账号已有自己的状态权威，不能再叠加 WebDAV 改写同一库。

真实 WsgiDAV 已否定“LOCK 能保证唯一下一代提交”的前提：先取得租约的一方延迟请求可在过期后到达，后取得租约的一方并不能消除它。对象写后读回只证明该对象字节，不证明用户操作的新旧。上传/重试时间也不能替代点击时的操作顺序。

本篇记录隔离候选已经实现的决定；`implemented` 不表示整体门禁、当前真实服务端、原生文件选择、规模可用性或独立审计已通过。动态版本、失败、待办和放行状态只在[既有验收入口](../process/2026-11-03-修复波次的分批、证伪审计与证据门槛.md#2026-11-09-已确认重构路线与退出条件)维护，未合入根的实现边界见当轮交付。

## Decision

### 意图、身份与生命周期

本机业务提交中固定 Lamport、actor、seq、观察前沿及显式变化字段。普通SQL字段由capture触发器捕获；已有逻辑候选尚未物化时，读藏等显式操作从同一逻辑赢家取前态并登记固定意图，不能靠物理行同值UPDATE推断用户没有动作。重传复用封批字节和操作戳；publication只给同一设备的不可变清单编号，不充当全局用户顺序。字段合并复用transport的同一寄存器join：同设备后操作与已观察远端后操作胜出；真正离线冲突按固定戳收敛，读与收藏独立。相同操作戳不同值明确拒绝。

初版整份接收、验证与投影曾使大库写锁阻塞前台；后继以`local_sync_winners`作为已落地字段F与已接受候选C的唯一SQL join。分批stage/preflight在接受前完成，接受用逻辑修订CAS；物化和折叠只是把相同逻辑结果落到应用表，不能成为第二套状态权威。工作集记录源、组、条目及旧/新关系边，普通文章patch只验证直接目标与其alias/来源依赖，源身份变化仍核广域闭包。候选尚未物化时显式用户写仍可见，已接受新赢家不能被旧物理行或迟到旧候选反向覆盖。

Preflight的目标集是候选字段与durable旧/新工作项的确定闭包，而不是对全proposed view按key排序后逐实体重投影。直接文章/设置目标去重后单次验证；source按文章meta的`source`归属展开到全部文章；旧、新原始URL展开到同URL的全部source及这些source的文章；group展开到成员source及文章；文章meta变化同时保留旧、新实体。文章键是源与GUID的摘要，不能把source ID误当作`a/<source>`键前缀。闭包用有序集去重，但仍须在每个目标上按proposed关系重做显式创建、alias选择、来源/分类依赖和同戳合法性检查，之后才进入revision、pending、clock与CAS。普通单条读藏因此只验证一个文章实体；源URL变化可触碰整组alias，但其范围由旧/新URL决定，不随无关全库实体增长。反例至少覆盖旧/新URL跨页alias，以及closure内非候选页依赖损坏必须拒绝。

初始化既有资料库时，bootstrap 只建立逻辑winner、journal、clock与必要body hold；已存在的物理行不再生成逐文章`job=''`物化尾部。抑制范围只限bootstrap自己产生的投影工作：初始化期间真实本地编辑仍按普通capture登记，并在drain时物化。此边界避免五万文章首连把清backlog推迟到点击或merge，同时不靠清空全部空job工作掩盖真实用户修改。

源身份复用 `feeds.sync_id`；条目键为源稳定身份、NUL、真实/已确认持久 GUID 的 SHA256。不能将文章 URL 规范化器用于源身份。两个设备独立添加完全相同原始订阅 URL 时，由于现有表的原始 URL 唯一约束，投影形成别名组；保留全部原始 wire key，现有本机 sync_id 不改写。不同原始 URL 保持独立。

源有显式 created/deleted/reactivate 字段。删除戳形成epoch；重订必须引用已观察的删除epoch，普通标题/文章补丁不能激活源。物理删除一个已捕获本地源同样生成删除记录；旧设备快照不能因本机行已消失而恢复活跃。退订只保留收藏，分类删除也不能绕开这一规则。别名投影和正文目标解析沿同一源内语义。

### 纯本地范围和账号互斥

WebDAV 只允许无活动 RSS 服务账号时连接；网络验证前与最终提交事务内均核 RSS 账号代际。`origin != remote OR origin_was_local = 1` 是本地源范围的唯一谓词；远端绑定不改变原本地源归属。

分类有创建归属 `origin`，与 remote_id 分开。GReader label 和远端“未分类”从第一条 INSERT 就是 remote；已有同名本地分类不降级。本地源被放入远端分类时，同一源写事务将分类永久转为 local，并捕获完整分类创建字段。本地源曾被 RSS 标为 remote 时保留原本地历史。初始化、实时捕获与正文归档采用同一闭包范围；普通应用设置继续捕获。

RSS 断开仅删除创建归属仍 remote 且已空的分类，不能再由 remote_id 非空或曾有remote成员猜测本地分类是否该删除。此决定取代旧的分类清理推断，保留本地空分类和已绑定分类的正控。便携备份故意不使用 WebDAV 本地源过滤：当前可读的 RSS 来源收藏也必须导出。

### 状态与正文的独立通道

状态、快意图和正文有各自运行职责、持久重试与预算；正文HTTP不持状态通道或前台数据库锁。状态按固定键桶分片，小字段变化附增量页，必要时压缩。封批的精确字段基线与逻辑frontier/completed取同一读快照，精确ACK只激活对应已封版本；后来的本机动作继续留在下一批。后台恢复不依赖仍有WebDAV凭据，portable导出必须先达到可读的稳定边界。

网络单请求遵守transport超时，调度片到期不取消尚在合法时限内的marker/list/GET再从头请求；保存有界游标继续，停机/连接代次改变后拒迟到提交。快发送与发现/接收分别推进，慢peer不能占住本机新意图的发送机会。行数/时间片预算限制普通批次工作，不将一次slice wall time直接当作精确SQLite写锁时长；真正前台响应和大库SLO仍需测量。

正文采用分页轻量目录和独立内容流。条目引用现有 `db::portable_content_identity`；primary/RSS或多条相同内容只存一份，SHA256另用于编码流/对象完整性。内容逐批编码、写本机临时spool，再以短事务写对象缓存和封批清单；接收只取本机缺失的保护正文，逐流与有界目标批次安装。目录元数据随条目数增长，正文载荷工作集不随全库正文体积增长。Windows spool使用删除即关句柄语义以处理进程退出。

own/peer清单、pending、download和构建pins共同保护缓存，目录到内容对象的引用保持子对象；旧会话不能ACK或清理新会话对象。正文hold另有持久ID，body publication在同一读快照中记录精确hold ID集合；ACK只释放该publication捕获的代次，cleanup仅清理receipt元数据，不得再按`(entry, BodyRef)` tuple猜测后产生的hold。相同tuple在首轮ACK后重新未读或收藏时获得新ID，必须由下一次receipt-only publication及其ACK释放；无新输入的下一轮seal仍保持idle。当前远端物理DELETE关闭：替换对象精确ACK及已知actor覆盖不足以证明未知/离线读取者已无保护义务。早期曾允许新加入设备晚保护时只能缺正文的设想已被取代，它不构成丢失保护字节的授权。持久GC请求和精确ACK保留，受root约束的本机清理可继续；远端对象增长、配额和列举成本仍未解决。保护和期限不同，不能按年龄删除尚无释放证明的同步正文义务。

### 便携v4与恢复

v4是有格式标识、逐块长度/摘要和最终容器摘要的记录流：头、分类、源、文章、唯一内容。预览完整扫描引用和摘要，只留轻量索引；被引用的正文块缺失是损坏，声明本来缺正文是可显示的缺口。普通已读条目保身份/状态，不携未受保护正文。

恢复重新验证预览digest，同一Windows文件句柄拒绝其它写入/删除共享；真正导入再对实际解析字节复核全容器摘要。一个写事务替换本地数据；任何格式、SQL、引用、内容规范化或digest失败都回滚。源/分类/文章主键为AUTOINCREMENT，恢复从sqlite_sequence与当前MAX的较大值之后分配，包含已删除最高ID；失败时序列也回滚，溢出明确拒绝。新actor、新运行状态、清空RSS/WebDAV/AI凭据、游标与交付队列，防止旧后台结果作用于新对象。

同步与备份只传普通设置和AI行为开关，不传AI服务配置/密钥、结果、片段、actor或运行队列。`syncMode`只便携，启动/首次关闭提示只本机。`readBodyRetentionDays`为0–3650整数，0永久；该后继已由[本机正文保留](../bug-fix/2026-11-05-缓存清理语义与未读保护.md)实现本机起点和有界分钟维护，手动清理days仍按发表时间；本机年龄不进入同步或portable。当前控件候选已沿原子patch与恢复守卫接入永久/限定天数，草稿与模式职责见本机正文保留决定；组合/真实键盘布局/native验收独立承担。

### 后端整合候选的导出截止点、工作扇出与已知规模边界（2026-11-12）

便携导出的截止点从“work 队列清空的 settled 状态”改为读取快照：`export()` 只等待已接受候选
（300 秒上限、50 ms 轮询），随后开启 deferred 读事务，首条语句读取 `local_sync_revision` 固定
WAL 快照，流式写出并在末尾 commit 释放；预收敛的 `drain_local` 与 `pending_publication` 门闸删除。
因此后台同步继续、队列非空时也能完成导出，正确性由快照而非队列状态保证。

工作扇出由 capture SQL 触发器与 `touch_field` 共用一张 A–F 规则表（唯一事实来源）：
A 普通文章字段（meta/read/star/body）只入自身 `a/<entry>` 与同 GUID 且同源 URL 的有界显示别名；
B 身份变化落旧/新两个条目；C 源身份/生命周期（feed_url/created/deleted/reactivate）入
`source/<sid>` 与旧/新 `url/`；D 文件夹成员入 `source/<sid>`+`group/<folder>`；E 分组生命周期
入 `group/<gid>`；F 设置入 `p`。`a/%/meta` 不再展开 `source/`；`affected_before_from()`
不再从 meta 键贡献 URL 别名。普通元数据编辑的成本因此由 O(文章数) 降为 O(同 GUID 同 URL 别名数)。

work picker 使用固定桶序 `p → g/ → s/ → a/ → group/ → source/ → url/ → cleanup-feed/ →
retention/`，每桶一次主键范围 seek，不再按全部待办排序；批删保留 `(job,key,revision)` CAS，
每个 slice 最多 16 个目标与 15 ms 预算。

实现中自引入并已修复的两个缺陷：picker 初版缺独立的 `g/` 桶，捕获产生的文件夹实体键永远不被
取到；批量 CAS 删除初版在 `EXISTS(json_each)` 内使用未限定的 `key`，被 `json_each` 的 `key`
列遮蔽而永不匹配。两者均有回归钉住。另一个既有缺陷在 50k distinct-body 首次跑到 restore 半场
才暴露：preflight 的 `article_alias_targets` 对同一 relation 做两次引用 JOIN；relation 是
`temp.local_sync_proposed` 视图时 SQLite 每次引用物化全视图，实测单次 516 ms、50k 目标外推
25,825 s。现改为按 GUID 等值单引用查询（命中 partial expression index），再按 source 对
feed_url 点查；结果集与顺序由新旧取法等值回归与两分支计划回归钉住。

整库 state 应用的窗口要按三条路径分开，不能把测试入口当成生产恢复：生产便携恢复走
`backup::restore`（自有独占锁、UI 处于不可操作状态、`clear_for_restore` 后 `capture=0`）；
生产同步状态应用走 runtime 的 `begin_receive → stage_page → preflight → accept`；容量测试的
整库应用到新库走 `merge_apply` 测试入口。后两条同样要求候选折叠期间逻辑修订稳定，持续
20 写/秒的前台负载只会得到可重试的 `localSyncPending`，停写后同一条 receive 收敛——这是生产
busy 语义，不是缺陷；生产入口与测试入口各有回归（见 Verification）。容量测试因此只在源半程
保留持续前台写者，整库应用阶段不并存写者；2 秒断言仍覆盖全部源阶段。

范围裁定（2026-11-13）：本版 v0.19.0 的规模验证标准正式定为 10k distinct 4KiB 全流程；50k distinct-body 记为本版开放边界，不写成通过或已验证（`r9-i1-50k-03/04` 证据保留）。依据是用户口径“以实际使用为参考，不需要考虑太多极端情况”、50k debug 构建整库应用约 2 小时量级且 state-only 50k 主测通过、连续两轮范围确认未获回复后按推荐继续；测试强度未变。

已知规模瓶颈（既有缺陷，本轮未修）：整库恢复到新库时，每条被应用的 read/star 字段会生成一个
`retention/` 工作键。10k 库约 20,001 个，debug 构建的 cargo test 下实测排空 306,998 ms；
50k 约 100,002 个，r9-i1-50k-04 的整库 apply drain 在 60 分钟硬上限内未完成，因此
**50k distinct-body 容量未验证**。只影响“一次性整库应用”（换机恢复/首次合并整库）的耗时，
不影响便携导出、不影响前台延迟（10k 前台单次最大 358,782 µs，全部 <2s）、不影响正确性
（10k 自然 exit 0、全部断言通过）。数字来自 debug 测试构建（opt-level=0、无内联、无优化）
与合成数据，release 构建通常快一个数量级，不能据此推算用户换机恢复体验；retention 也只在
整库 state 应用时成批产生，日常增量 state 只覆盖变化条目，数量级不同。修复它需要新增 schema
索引与迁移并补旧库兼容验证，超出本轮范围，本轮不做；容量测试按裁决降为 10k（4KiB 正文、
全部相位、全部断言与 2 秒门槛不变，仍为 ignored 容量测试）。后续方向（不承诺）是
`articles(guid)` 索引，或把 retention 的按 key 查询批量化、去掉 LIKE 前缀扫描。

## Alternatives considered

- 延续单个Gist/WebDAV配置快照：可以少改传输，但无法承载逐字段冲突、状态/正文和退订收藏，已按新需求退役。旧镜像的理由与历史验证留在[原记录](2026-10-15-配置快照镜像应用.md)。
- ETag/LOCK唯一下一代：真实过期延迟写反例使正确性前提不成立；可作为优化，但不能作为收敛基础。
- 全库JSON同时载入并重复每条primary/RSS正文：旧v3五万共享正文实测放大文件和内存，预览未完成；改为唯一内容与流式块，保留原失败而不改口称优化前已通过。
- 用remote_id判断分类归属：GReader分类根本不维护该值，本地分类也可能绑定它；采用真实创建归属与本地源成员闭包。
- 只使用当前MAX分配恢复ID：已经删除的最高ID仍可能被异步任务持有，故采用持久高水位；不恢复旧actor或传输队列。
- 接收整份checkpoint后一次物化：实现简单但实测大库前台锁失败；改为F+C共同逻辑赢家、修订接受与分批物化，保留原失败和更高持久状态复杂度。
- 仅凭已知actor覆盖删除远端对象：不能证明未知离线读取者已交还保护，故暂停远端物理删除，接受空间治理尚未完成的代价，不能宣称容量已受控。

## Consequences

相同可移植数据有清晰身份、失败边界和最终消费者；代价是持久字段、候选、工作集、轻量墓碑、清单和缓存索引占用空间。当前实现仍有单块、单流、字段数与根目录解析预算，这些是防护实现边界，不是用户已接受的资料库容量。五万文章的首轮状态路径已在2026-11-12组合候选真实测量，但自然正文、真实WebDAV时延、IPC/渲染和前台无感仍不由该合成测试背书；远端DELETE关闭也意味着不能宣称远端空间受控。

永久媒体二进制镜像不在本决定：保留正文与媒体URL不保证远端URL永不失效。v4不兼容旧schema2配置或旧数据库文件，旧文件须只读拒绝并保留。普通数据库快照仍包含本机凭据密文与队列，不能当作安全便携包。
