# Agent Note: 正文与 AI 产物的实体缓存

Status: implemented

## Problem

列表反复刷新、筛选、翻页时，如果正文和 AI 产物随视图行一起替换，会同时出现两类错误：保守 `newValue || oldValue` 合并使已清除产物复活；无条件清空水合标记又会让 id 未变的组件停在加载态而不再发请求。需要独立于列表生命周期的正文归属。

## Decision

`src/store/bodyCache.ts` 保存按条目的正文实体。无记录表示未请求；记录状态为 `loading / ready / cleared / missing / failed`，其中 loading 是进行态，空正文、不存在和失败有独立语义。LRU 当前上限为 2000 项；这是数量预算，不是严格字节内存上限。

列表快照保留轻字段和 URL，正文按需水合，不在 reload 时同时请求所有文章。`reconcileBodyEntities` 处理行真值对齐，显式内容操作也会经 `invalidateContentRevision` 等入口失效；它们必须遵守同一版本协议，不能把某一个函数误称为唯一失效入口。请求携带 `contentRevision` stamp，响应落地前核对。2026-11-06 修复使 snippet 变化保留记录并转 cleared、清空正文、保留/推进失效戳，避免删记录丢失刚推进的代次。Reader 对未请求与正文空的 cleared 记录幂等补取；LRU 淘汰或重试新建记录不会复用旧请求戳，已淘汰记录的迟到响应不得重建实体。详情正文与 snippet/URL 共用同一次 `applyBodyRow` 接受资格，旧响应不能只污染轻字段。

全文仍采用单一持久正文，不额外保存 RSS/提取两份。本轮选择轻量界面承诺：只有本次缓存确实持有与全文不同的独立 RSS 字节，才显示回切入口；提取后的详情只返回全文时 rawContent 为空，Reader 直接读 content，未水合已提取条目的菜单也隐藏两态切换。此决定保留提取当次可用的回切体验，接受重开后没有独立 RSS 原文时不提供该操作，不能把按钮切换误写为数据库恢复原正文。

`applyExtractedFulltext` 成功接收提交身份后推进 contentRevision，拒绝提取发起前的 get_article/get_articles 覆盖新全文。Reader/ContextMenu 仅在 ready 或持有正文的 cleared 状态判断提取/回切资格，loading 不能当作“未提取”；菜单使用 store 公开正文 selector 与 Reader 同一缓存真值。默认 loader 的真实 RSS 提取点击正控制与迟到详情反例分别提供验证，不能仅靠隐藏按钮掩盖状态误判。

2026-11-10 的正文释放后继：Reader 查询到条目但正文为空时显示“本机未保存正文”，`missing` 继续只表示缺行。自然空源正文与释放后正文共用这一准确提示，不推测“已清理”。有 HTTP/HTTPS 原文地址才提供“从原网页重新获取”；它复用当前 `extract_fulltext`，明确请求原网页，不承诺恢复原 RSS 字节。普通列表 reload 与空正文水合只读本机，不自动重抓；既有自动全文仍仅在用户打开且满足截断判据时执行，AI 资格不变。

全文操作的在途请求和错误归属于已有正文实体，操作对象与 `libraryGeneration` 约束命令归属，正文戳保留原有 AI 写入/清理的失效规则，轻目标凭据另外约束实际 CID/revision、条目锚和 URL；不是新的正文状态。重复操作复用在途资格，切篇完成只写原 ID，失效后不落旧正文、提示或重试。资料库恢复 busy 阻止新全文操作，成功换库清实体并推进库代次，失败 restore 不把同库操作误作换代。非空正文、未降级与实际提交的 contentId/revision 缺一不可；失败仍呈缺正文并允许明确重试。提交后按原 ID 回读轻媒体信息，不回写读藏，不从 HTML 猜测封面。ReaderProse 的图片 DOM、原 URL、页归属和源码/流式零取图边界沿用现有媒体租约实现。

提交身份只立即更新正文实体，列表 contentId/revision 保留上次属性查询基线，直到真实新快照接管。提前把列表基线抬到提交结果会令早发晚到的旧 reload 被误判为新内容，独审已复现刚恢复正文退回 loading/空白；保留基线让旧快照不失效新实体，而后发的新快照与实体提交身份相等也无需清空。轻媒体回读另外比较条目的 mediaRevision，不能以正文戳相同推定媒体未更新；回读仅更新媒体字段，URL/snippet仍由原属性链路管理，避免借媒体版本覆盖非媒体事实。这些修复不改变公用 reload 的查询/成员或读藏前沿语义。

失败重试仍允许目标离开当前列表。已存在缓存的旧正文戳不同则拒绝旧动作；LRU 正常淘汰导致无记录时，不能把“未知”当作已确认内容换代而吞掉错误中心入口。此时按原 ID 只读详情，对照失败动作保存的轻量内容身份/修订、条目锚与原文地址后再明确提取；新内容先水合可读，但不执行旧提取。缺行或读取失败保留新的可重试错误；回读与嵌套提取都受原库代次和当前正文戳保护。该分支没有另存正文、无界墓碑或第二套缓存真值，持续沿用 2000 项 LRU 和有界错误中心。

正文戳只证明尚未显式失效，不证明某次详情仍拥有落地资格。独审随后用真实 LRU→旧恢复回读在途→重新打开的正常详情先接受，复现同戳旧成功清空新正文并嵌套提取、旧失败把 ready 改成 failed。恢复回读现额外持有发起时 loading 记录的对象归属，成功和失败均先核对仍由该对象承载；回读失败后的重试只能删自己产生的失败记录，不能删掉正常详情在同戳接受的新记录。已有缓存写入都会替换对象，因此无需新增代次、无界请求表或改变普通 `applyBodyRow` 语义；再次正常淘汰后的无记录仍可按原 ID 重新验证。

该对象守卫只闭合 private 回读，独审进一步复现外层 success/failure/retry 三路仍可在同戳新正文接管后继续执行。完整后继统一区分“命令结束/被后继替换”和“目标已知接管”：request 与 failure 共用轻目标，LRU 核验继承该目标但有自己的短期读取命令，成功媒体回读新建提交后目标；目标不存 HTML 或重 BodyEntry。已接受的缓存写只规范化这些操作凭据，实际 CID/revision、锚或 stamp 已变化就永久撤销目标，正常淘汰本身只表示未知。凭据没有全局表，随已有 2000 项实体、有界错误中心和在途闭包回收；已知接管之后再被 LRU 淘汰不能令旧动作重新有效。

外层成功与失败共用“仍是自己的 request + 目标当前”的判据，captured retry 要求仍是自己的 failure + 同一目标；无记录且目标未被撤销才按原 ID 核验。private 成功、失败及其重试共享目标判据，同时保留上述 loadingOwner/failureOwner，不能借目标相同越过另一详情的接管。普通同身份详情允许换 BodyEntry 对象，不撤销外层合法命令；mediaRevision、计数及读藏变化不代替正文资格。提交后媒体读取拥有独立短期槽，必须仍是自己的 readback、符合提交后目标和媒体版本，完成即清理；后继提取与读取仅结束自己的槽。

Reader 单篇、批量与 private，以及 AI 离屏详情的所有实际 `applyBodyRow` 消费者，只在行被接受后校验其 raw URL/内容身份；被拒绝行没有撤销权限。轻属性快照另外只确认 URL/锚/明确 unavailable，不用列表旧 CID/revision 判新正文。`urlKnown` 仅表达本次 wire 是否提供 URL，来自接受的原 src：缺省未知不撤销，明确 null 可撤销；普通 URL 展示继承与列表查询/成员/读藏/正文戳规则不变。这补足 URL-only 接管后再 LRU 的寿命边界，不扩大成新的 URL 合并策略。

后端全文发起快照同锁读取原文 URL、内容身份/修订及正文，提交前重新比较；仅订正 URL 而摘要/内容身份未变也拒绝旧网页结果。重定向的相对资源和封面以最终响应 URL 解析。正文成功提交后封面补写是 best-effort 元数据维护，失败记录日志而不把正文成功回执改为失败。AI 独立使用 AiCommitToken 与输入签名，不把 URL-only 变化当正文修订。

实体携带产物与签名，同一次更新应对齐两者。命中判定由后端 `ai_cache_check` 负责，显示状态由 AI 切片选择器负责；旧签名/无签名产物的现行标记为“已过期”，具体规则见[AI 完成信号与缓存提交](2026-10-08-AI完成信号与缓存提交.md)。无实体时仍存在视图行兼容回退，不能据此声称所有旧值复活路径都已移除。

前端本批status.input还绑定正文与轻字段/anchor、已保存配置revision和产物mutation，详情水合/正文提取与配置成功回调共同失效旧校验；check/hint/refresh落地再核输入及latest read serial。terminal需要新读，不能复用生成前的状态请求；Reader与窗口内已水合卡片ensure仅只读，片段-only也可显示partial/continue/clear。动作决策与显示读的接管权限区分，未保存草稿/保存失败不发行新配置revision。2026-11-07 收口：该实现的前端链路已由独立审计关闭（`tmp/repair-2026-11-06/audit-frontend/player-ai/report.md`）；本行原“仍待验”仅描述记录时点，记录不预写为通过的纪律不变。

`selectArticleBody` 返回新对象，Zustand 5 订阅必须维持稳定的快照比较。现有订阅使用 `useShallow`；历史上漏掉它曾触发 `getSnapshot should be cached` 与 React #185。需要验证所有消费者的订阅行为，不能只给单个组件加临时 memo。

## Alternatives considered

- **引入另一套缓存库**：原问题是列表、实体与同步意图间的所有权；未计划整体迁移时加入另一所有者会增加边界。选择小范围实体缓存，不将此理由推广为库本身不适合本地产物。
- **列表继续带正文并保守合并**：掩盖正文丢失，却无法区分“后端未返回”与“已明确清除”，容易复活已删除内容。
- **每次 reload 全页重拉正文**：会形成大量 IPC、解析与内存分配；按需水合保留较小的工作集。具体滚动性能必须按数据和布局测量，历史 50k 夹具不能证明所有正文/画廊场景无卡顿。
- **组件自行缓存选择器对象**：把缓存键正确性分散给每个组件；浅比较订阅直接解决引用不稳定的来源。
- **永久保留 RSS 与提取全文两份**：本轮未选择新增持久化和生命周期协议；仅在确有独立 RSS 字节的会话中提供回切。
- **snippet 改变时删除实体**：删除会同时丢掉失效代次，迟到请求和 Reader effect 都无法识别更新；改为保留 cleared 记录和独立发行的请求戳。
- **用再次本机水合冒充恢复**：空正文已是查询终态，重复本机查询不能取回远端内容；明确网页提取另需用户动作。自动保留期限与后端提交续期由正文保留实施承担，不以本界面可点击证明已生效。
- **提取后立即更新列表内容基线、只凭正文戳接受媒体回读**：初稿采用后，独审实际复现旧 reload 清空新正文，以及纯媒体更新后旧详情把媒体修订 9 回退到 8；分别保留快照基线和核媒体版本，保留独审失败证据。
- **把缺缓存一律当成旧重试失效**：独审经真实 2000 项 LRU 淘汰复现错误中心消费入口却未请求。改为按 ID 回读后核轻身份；已确认新版本和成功换库的旧动作仍拒绝。
- **LRU 回读只守正文戳**：后继独审实际复现普通详情在同戳先接管后旧回读继续写入。短期不可变记录归属同时保护成功、失败和其重试，保留正常详情水合的现行版本规则。
- **外层只守 stamp/request、或把所有对象变化都当接管**：前者被三条独审反例证实仍能覆盖新正文/登记旧错/重放旧重试；后者会误拒同身份正常详情。采用命令归属与轻目标资格的统一判据，保留 private 对单次详情的更严格对象归属。

## Consequences

实体与视图分离减少了列表替换对正文的影响，但新增的 stamp、内容身份、AI 校验缓存和组件 effect 必须闭合。2026-11-06 在 `91ece562` 实测的 snippet 同步变化/删除记录反例保留，本次按上述保留代次和整条详情接受资格修复。AI 校验状态的内容变化过期及清除后迟到恢复另有专项范围，不能由正文修复推出“清理后旧值不可能复活”。仅有片段的批量 AI 清理本轮已纳入后端 epoch 协议，片段和整篇产物采用同一清除代次；年轻条目保持原代次，清理计数按受影响文章计。

2026-11-10 轻目标方案增加有界实体内的操作凭据及已接受详情/位置通知，需要覆盖公共 set 与 AI/Reader 消费者；它保留同身份详情的原体验，同时不会承诺任意后端乱序都由前端修正。实际正文提交仍以后台受检事务为准，前端凭据只决定可观察结果是否有资格落到当前会话。
