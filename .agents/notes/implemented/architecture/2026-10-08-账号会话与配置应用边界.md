# Agent Note: 账号会话与配置应用边界

Status: implemented

## Problem

配置导入曾直接覆盖协议、地址、用户名，却保留本机密码，形成“新地址 + 旧凭据”；同步在锁外等待 HTTP 时，断开或换号也没有让旧响应失效的身份边界。通用 settings 写入还能绕过账号清理与验证。同账号换密码则需要保留阅读数据，不能等同于换号。

## Decision

2026-11-09后继补充：RSS账号的身份/代际/专用凭据提交约束继续有效。纯本地WebDAV与RSS活动账号互斥，便携恢复不导入账号建议或旧密码，而是断开服务、清运行状态并新建actor，见[后继资料库决定](2026-11-09-纯本地资料库同步与便携恢复.md)。后台独立WAL连接使原“同mutex临界区”不再足以覆盖所有写者；账户等读后写事务现经[写预留单点](2026-11-09-多连接SQLite写预留与原子设置.md)先取得IMMEDIATE，再读/复核代际。下文旧配置建议流程保留作历史实现来源，不表示新便携包携账号连接信息。

账号身份由协议、规范化服务器根与用户名组成。服务器根保留 scheme、host、有效端口及 basepath，只合并默认端口、大小写和尾斜杠等价形态；同主机不同端口或路径仍是不同身份。

每库在 settings 持久化 `sync_generation`。只有键缺失表示尚未初始化的 0；空白、非法、负数和溢出均是可见数据错误，`bump` 用 checked_add，不覆盖坏值、不饱和复用代际。`build_session` 在同一短锁中读取凭据和代际，锁外验证，返回前再核对；端点缓存写回也必须受保护。会话不携带或记录明文密码。

账号提交采用短事务：验证开始捕获代际，提交复核，迟到保存报 `staleAccountSave`。身份变化清旧远端绑定/数据、游标、Fever 历史和源删除墓碑，重置发现状态并清端点缓存；同身份只换密码保留这些数据，但任何成功账号提交都推进代际。同身份重连与断开保留订阅意图，换身份按[生命周期终点](2026-11-13-同步写回与状态一致性.md)清除旧账号 outbox。分类墓碑另有[账号作用域](2026-10-14-分类墓碑账号隔离.md)，不能将源墓碑清理概括成全部墓碑清空。

普通保存只有身份不变时才允许空密码复用；新身份空密码必须在 HTTP 前拒绝。显式激活导入建议即使身份相同，也必须重新提供密码。通用 `set_setting` IPC 拒绝活动连接、代际、游标、历史、端点缓存及建议键，内部受控事务仍可写它们。

历史配置快照导入只落非敏感连接建议，不激活账号；该快照入口于2026-11-09退役。连接建议的已有CAS消费纪律继续适用于专门建议入口，不能用恢复文件自动激活账户。建议由独立持久 `pending_connection_serial` 发号：清内容不重置 serial，同值重复导入忽略，换值或清除后重导发新号，溢出报错。激活携带可选 `activate_pending_version`，在 HTTP 前及提交事务内同时核对 token 与目标身份；不匹配整体拒绝，活动配置和新建议均保持。普通保存不消费建议。可选参数保持旧调用方“普通保存”的语义，不能因参数缺失放宽校验。

同步回写必须在同一数据库临界区执行 `ensure_current` 后写入；失配报告 `staleSession`，不得给新账号记旧推送失败。2026-11-06 在基线 `91ece562` 证实 Fever 的高层推送内部还有多个 HTTP 请求，外围批次检查没有覆盖断开后第二次 mark。后继修复在同步构建的 Fever 客户端上注入可选的异步请求前检查：持数据库弱引用和会话代际，在每次真实探测/读取/mark 发送前短锁复核；`at_resolved` 保留检查。独立协议客户端没有同步会话，默认不注入，也不改变其调用方式。

2026-11-10来源凭据独审证实GR也有独立的惰性action token窗口：token等待中断开/换号，旧客户仍可能随后发POST。GR当前会话注入同型逐请求账号检查，GET、token与POST实际发送前复核，POST取token后再核；文章edit-tag另在最终发送前检查该次计划的来源凭据，详见[运行生命周期](2026-11-05-同步运行生命周期与诊断.md)。OnceCell保留原缓存实例，协议独立客户仍默认无DB依赖；登录候选发现及已发认证请求的现实边界不扩大为可撤回。

订阅outbox断开保留的契约继续有效：迟到旧响应既不确认也不记失败，原id、账号key、旧generation、目标和状态保留；断开后的新feeds调用为notConnected且不发网络。同身份重连后，执行器先按当前key识别并重绑generation再发送；不能把“旧会话不能继续发”误写为“旧代际意图永远不能恢复”。身份切换仍按既有生命周期决定清账。

检查与网络发送不跨数据库锁：断开已经完成后才开始的新请求会失败关闭，但检查通过后已经交给网络层的请求仍不能撤回，也不能撤销服务端已接受的操作。数据库回写继续使用同锁代际条件，不能因协议入口已有检查而移除。

断开与身份变化在事务内将 Fever 历史置 Unknown、GR 时间戳与 Fever since 游标归零。页事务同时核对会话代际并提交页数据与 checkpoint；同身份换密码只失效旧请求，不重置历史。HTTP 始终在数据库锁外；整轮串行与退出排空由[同步运行生命周期](2026-11-05-同步运行生命周期与诊断.md)继续约束，不能把代际当任务取消器。

## Alternatives considered

- **全局原子代际**：会让独立测试库或客户端互相失效；代际归数据库身份，随库持久化更直接。
- **入口只检查一次**：挡不住检查后、HTTP 返回前的换号；写回须在锁内复核，内部多请求也需单独核对发送边界。
- **只用取消令牌**：能通知任务停止，却不能撤销已发送请求，也不能替代提交时的身份条件；可作为生命周期补充，不能承担数据授权。
- **只拆分外层 Fever 标读批次**：能覆盖逐 ID mark，却仍遗漏收藏探测后写入、feeds→groups 和端点候选之间的后继请求；检查落在两处实际发请求入口，避免复制协议内部编排。
- **导入直接换号或新身份空密码复用**：载荷不含密码，自动激活会泄露旧密码给新目标；后端拒绝是必要边界，UI 提示不能代替它。
- **同身份换密码也清数据**：身份与远端 ID 命名空间未变，清理会无故丢失阅读与历史进度。
- **普通保存清建议、或激活后无条件清建议**：会吞掉未确认建议或在验证期间新导入的建议；token+身份 CAS 让消费只作用于被激活的一条。
- **内容 hash 代替持久 serial**：放弃后重导相同内容会使旧在途请求误中新的建议，即 ABA；serial 清除不复位可区分两次意图。
- **坏代际当未连接**：会静默跳过数据故障、误导重输凭据；保留原始错误且不记队列阻塞。
- **保留旧 push 的确认、依赖队列 id 不复用**：编号约束不能替代账号代际；旧失败记账与确认都必须丢弃。
- **保存链 fire-and-forget**：saving 不能覆盖实际同步，故设置页等待真实链路并在 finally 归位；报错与账号事务是否已提交仍需区分。

## Consequences

身份、凭据、建议与同步会话有明确的所有权，但额外短锁查询和代际失效会让同账号换密码中止在途工作。换身份清源墓碑后，换回旧账号可能重新导入以前删除的源；断开未换号则保留防复活语义。身份切换丢弃旧 outbox 的远端孤儿代价由后继 Note 明确记录。

历史配置预览/镜像采用[快照应用边界](../../../../docs/backup.md)，当时只生成连接建议。当前便携v4恢复成功会断开RSS和WebDAV，并生成新行ID与本机同步身份，必须重新输入凭据；本机同步和RSS服务互斥。建议serial、账号代际、备份摘要和前端libraryGeneration仍各管自己的竞争，不能相互替代，见[当前恢复边界](2026-11-09-本地同步与便携恢复界面边界.md)。

## Verification

历史回归使用 HTTP 屏障验证提交前换号、密码/端口/basepath、建议替换/重导和坏代际，不能外推到每个协议内部请求。`sync_correctness_e2e` 后继回归用生产 disconnect 与 HTTP 屏障锁定 Fever 首次 mark 已发之后禁止后续 mark、v3 收藏探测返回后禁止开始 mark；`sync_session_e2e` 继续覆盖旧响应不得污染绑定与游标。2026-11-06 的基线失败保留在原审计交付，修复版检查与未验证项集中在当轮验收入口。原 R1/R2 收紧过程见[整理前记录](https://github.com/Dchean/fluxreader/blob/91ece562d79fd909642cd6d570d636e884b7387e/.agents/notes/implemented/architecture/2026-10-08-账号会话与配置应用边界.md)：缺失/空串兼容与“同值导入换号”均已被后续决定取代，未作为现行规则保留。
