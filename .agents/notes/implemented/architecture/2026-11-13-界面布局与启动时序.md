# Agent Note: 界面布局与启动时序

Status: implemented

## Problem

列表、画廊与社交折叠的几何都在异步数据到达后才确定：虚拟化需要测量高度，图片/视频加载会改变尺寸，启动/筛选 reload 又与分页共用同一列表。历史缺陷集中在三类：把“未加载”显示成“空态”、把索引相邻当成视觉相邻、以及让组件内部的重启/恢复逻辑在错误的上下文里继续执行。窗口恢复与关闭确认也有同一类问题——动作发生在用户可见之后，或“取消”被实现成了提交。

## Decision

- **不足一屏自动补拉，并给出可执行哨兵。** 以视口剩余空间决定补拉，撑满、到底或达到 `AUTO_REFILL_MAX_CALLS=8` 后停止；哨兵按可滚动性选择滚动提示或可聚焦的加载按钮，到底才显示终态。空态不承诺用户无法执行的滚动动作；卡片选择统一走 `selectArticle`，使文章身份、自动 AI 与 Reader 链共享入口。验收是“后端可列出的条目能经分页与操作到达”，不是同时挂载全部卡片。（原 2026-09-23 bug-fix/2026-09-23-列表可达性与空态补拉.md）
- **启动/筛选 reload 的在途状态可见。** `backendReloadInFlight` 的 begin/end 同步维护 store 镜像，`reloadFromBackend` 与 `reloadFilteredEntries` 共用，finally 释放；Timeline 在 items 为空时以 `articlesLoading` 或 `backendReloadsInFlight>0` 显示加载，并让哨兵退让。该计数是展示事实，不是第二套并发锁；它包含当前 reload 自身，不能在 reload 内用 `>0` 判断“是否还有接手者”。（原 2026-11-02 bug-fix/2026-11-02-启动抢占期假空态.md）
- **虚拟总高不参与 flex 收缩，社交折叠外框固定。** 虚拟总高容器不参与纵向 flex 收缩，页脚是完整内容末尾标记，不做 sticky。社交折叠态统一卡片 310px、正文 150px、按钮槽 26px（含行距估算 322px）；占位、短文、空文、图文同一外高，溢出只决定展开按钮与 fade。展开或显示译文退出固定外高，并在 layout effect 回写实际尺寸，收起恢复常量；TS 常量承担测量/估算决策，CSS 只保留必要裁切兜底。（原 2026-11-03 bug-fix/2026-11-03-列表页脚压缩与社交水合首帧折叠.md）
- **社交自然高度观察内层，HTML 注入对象按内容 memo。** 观察 `social-text-inner`，首次 layout effect 同步采样；图片 load/error、视频 metadata/data/duration 经 rAF 合并再采样；正文替换重建监听。正文/译文 HTML 对象按内容 memo，正文未变时不重设 innerHTML，使视频跨展开/收起/测量 render 保留节点；入场动画只处理透明度/位移，不用删动画处理几何错误。
- **画廊用 lanes 虚拟化，逐列取可见窗口。** 按最短列分配条目，2/3/4 列断点与 14px 间距由 `GalleryLayout.ts` 管理；网格项绝对定位，纵向位置与总高交给虚拟化，自然图片比例保留，加载前只用比例占位。挂载界不能用“每列可见量 + overscan”的默认连续下标提取器：列间高度偏差会夹入大量屏外卡。当前按虚拟器 lane/start/end 分列、二分求各列与视口相交项，再加分摊 overscan 预算，合并为有序下标；不自建列分配或尺寸真值，也不硬截断可见卡。Tab 回退先过滤几何可见项，完整可见卡优先，超高卡才退到相交项。（原 2026-10-16 feature/2026-10-16-画廊有界渲染.md、2026-11-01 bug-fix/2026-11-01-画廊方向键行优先语义.md）
- **画廊方向键是索引近似。** 左右 ±1，上下 ±lanes，越界 no-op、不回绕；等高轮转时可对应同列，混合高度时可能斜向。没有证明精确列查询成本不可接受，也不把 ±lanes 写成视觉几何一致。
- **测量补偿只针对同列锚。** 画廊用 directDomUpdates、containerRef、`useFlushSync:false` 与 `overflow-anchor:none`；测量时选一个可见锚，只补偿它同列前驱的高度变化，滚动/上下文变化后重新选锚。候选修正仅在 scrollToFn 截留非零 adjustments：core 推进逻辑 offset 后，onChange 先写容器总高与所有仍挂载节点当前 start，再发布同次 DOM scrollTop 补偿；普通滚动/无补偿的 `scrollToIndex` 仍直通 `elementScroll`。新节点 ref 注册/同步测量后立即取得当前 start。（原 2026-10-16 画廊有界渲染篇、2026-11-07 bug-fix/2026-11-07-画廊重启用时虚拟化offset对齐.md）
- **跨阅读上下文的焦点恢复必须过期。** 焦点恢复只在同一 filterKey（布局|视图|订阅|筛选|排序）内生效；`focusedCardRef` 记录产生时刻的 filterKey，恢复 effect 与 `focusCardAt` 任务的 `isCurrent` 都按实时 store 校验，上下文切换即终止原生 focus 链；同 filterKey 内的条目移除仍恢复。重启用时对停用方实例清内部 offset，并派发一次无输入闩的 scroll 让虚拟化回读真实位置；这些通道与焦点门控共同封堵跨上下文跳转，不能只留其中一环。（原 2026-11-07 同篇；历史 159/295px 失败保留在证据目录）
- **reduced-motion 只统一 transition，不动动画生命周期。** 仅在 `prefers-reduced-motion:reduce` 全局规则把 `transition-duration` 改为 0s，保留 `transition-delay:0ms`、`animation-duration:0.01ms` 与加载指示器旋转；no-preference 下 hover、入场、展开/收起不变。门禁显式运行两种媒体模式、原两视口与五布局/键盘场景，阈值（过程 ≤3px、重叠 0）不变。transition 与 animation 是不同生命周期，未来新增 transition 状态消费者须同时提供无动效完成路径。（原 2026-11-07 bug-fix/2026-11-07-社交虚拟行坐标单一写入者与动作采样对齐paint.md）
- **窗口首帧恢复只有一个入口。** 主窗口以 `visible:false` 创建，window-state 插件对 main `skip_initial_state`；Rust 在 setup 内一次性 `restore_state(ALL − VISIBLE − MAXIMIZED)`，保存最大化时用原生 `SW_SHOWMAXIMIZED` 首显，再 `show()/maximize()` 对齐缓存；恢复失败回退 `center()` 再显示。全生命周期只有这一处恢复，不存在“显示后再恢复”的第二次跳动。fullscreen 保留在插件恢复内走普通 show；打包实例、物理显示器拔插与多显示器仍未验。（原 2026-10-08 bug-fix/2026-10-08-窗口首帧恢复与媒体命令幂等.md）
- **媒体命令表达目标态。** `applyMediaAction('play'|'pause'|'toggle'|'stop')` 是唯一入口：play/pause 是目标态（已在目标态 no-op），toggle 才切换，未激活无副作用，stop 关闭播放条。音频元素与当前播放目标由 PlayerBar 持有，切换/关闭后旧 Promise 拒绝不影响新目标；失败重试只属于失败时的元素与 URL。幂等不等于失效：暂停后按 Play 从暂停点恢复，失败回退后再按 Play 是新的真实尝试。
- **关闭确认的“取消”零写，显式按钮才提交。** `CloseAskDialog` 遮罩与全局 Esc 调用 `dismissCloseAsk`，只关确认框，不发 `resolve_close`、不改 `closeToTray`/`closePromptShown`；只有“退出”“最小化到托盘”两个显式按钮调用 `answerCloseAsk` 并提交当前 `remember` 值。设置弹窗的关闭与共享焦点契约仍在；便携恢复使用 store 忙态、App inert 与捕获期键盘阻断，是恢复事务的独立边界。（原 2026-11-04 bug-fix/2026-11-04-关闭取消语义与授权关闭守卫.md；GitHub 授权相关守卫已随功能退役）

## Alternatives considered

- 只把 items 长度加入依赖：长度不变时补页不会触发，否决；用 `IntersectionObserver` 代替补拉状态也无法表达“仍不足一屏”，否决。
- 页脚 sticky 或让容器可收缩：改变“到底”的空间语义，不能修虚拟总高被压缩的问题，否决。
- 社交卡按摘要/封面估算高度：无封面字段的正文图会漏算；line-clamp 也裁不了所有块级媒体，改为固定外框 + 内层测量，否决。
- 保留 CSS 多列再截取窗口：浏览器会重新分列；等高/裁切牺牲自然比例；自研列分配维护面过大，选 lanes。
- 默认 global range 提取器：列间高度差导致屏外挂载与 Tab 进入不可见项；改为逐列相交集，否决。
- 去掉 skip 让插件恢复：显示后恢复的跳变仍在，或需要第二次恢复入口，否决；延迟 show 也不消除机制。
- 关闭遮罩/Esc 提交最小化：把“取消”变成隐藏窗口并记住选择，否决。
- 给媒体只加 `setPlayerPlaying(boolean)`：布尔 set 不能表达 toggle，否决。

## Consequences

- 固定社交外框让短文/空卡有可见空白、标题单行截断，列表可能比自然短卡更长；这是固定节奏换水合稳定的已接受代价。要紧凑短卡需重新选择预测量模型，不能悄悄恢复摘要猜高。
- 逐列窗口仍消费虚拟器全量测量缓存，构造分列索引有随数据量变化的 CPU 成本；收窄的是挂载 DOM，不是整个布局算法与条目数无关。
- 多图集合只缓存当前灯箱会话，关闭即丢弃；反复打开会重新取详情，避免长期保留过期集合。列表更新与晚响应不能重开已关闭会话或覆盖另一条目。
- 历史几何失败（159px/295px、Tab 进入屏外挂载项、192 挂载 vs 17 可见）保留在证据目录；当前实现状态不能写成发布验收通过。
- 浏览器 Edge/CDP 证据不等于 Tauri WebView2 的原生合成、字体与 IPC 时序；窗口恢复的打包实例、全屏与多显示器仍未覆盖。当前缺口见[路线图](../../../../docs/roadmap.md#interface-and-media)。
