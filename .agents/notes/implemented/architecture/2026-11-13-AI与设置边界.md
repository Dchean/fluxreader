# Agent Note: AI 与设置边界

Status: implemented

## Problem

AI 与设置的写入大多是“读—改—整块写回”，而生成、清除、配置测试与资料库恢复又都可能并发。历史缺陷集中在四处：单项清除与在途流式互相复活；AiTab 三个写入口用点击时的旧快照整包覆盖；全局 `translating` 布尔在切换文章后卡死；通用设置 IPC 把敏感键和脚本/样式文本横向暴露。目录与订阅的附带写入也有同类问题：多写不在同一事务，或错误被忽略。

## Decision

- **单项 AI 清除与在途生成互斥。** `clearAiProduct` 在调用后端前检查以文章 ID/产物 kind 为键的 `aiInFlight`，验签或生成在途即拒绝清除；提示等待完成，不承诺不存在的“停止生成”。流式译文每次追加 delta 前确保 raw 标记存在，使未消毒片段走文本渲染；摘要清除只触碰摘要状态，不拆散译文“失败半截 + raw 标记”。清除成功后只有请求代次仍等于发起时值才递增，旧 Done 回读失去写权；若期间已有新请求接管则不误杀。回读不并入 `aiInFlight`（允许 invoke settle 后发起下一笔，逆序由代次处理）。（原 2026-11-01 bug-fix/2026-11-01-清除与在途流式互斥.md）
- **AI 配置在同一模块写链中串行，执行时重读。** AiTab 的 `testAndSave`、`savePrompts`、`selectModel` 全部经 `enqueueAiConfigWrite`；下一笔在前一笔成功或失败落定后才执行，执行时才 `getAiConfig` 并只合并自己的字段，不再用点击时整包快照覆盖。`testAndSave` 收窄为端点四字段，`savePrompts` 只重放两个提示词，`selectModel` 只重放 model。测试捕获点击时的端点四字段与编辑代次，排队、测试返回、配置回读后复核；草稿变化则拒绝陈旧结果进入保存并保留草稿；保存已发出后编辑会提示新草稿未保存，不把成功身份移给新草稿。（原 2026-11-01 bug-fix/2026-11-01-AI配置读改写卡内串行化.md）
- **初始回读资格单调失效。** 初始快照只恢复本挂载仍存活且未被用户意图接管的字段；接管包括敲键、明确测试或保存默认值，不因成功/失败/请求结束而释放，初始读取不能充当隐式回滚。跨挂载时新页面先在写链插入空屏障，等既有写结束再发初始读取；真正的 `getAiConfig` 不放写链，慢读取不阻塞编辑/测试/保存。读取失败、坏 JSON、字段类型错误显示可重试错误，写入口校验新读值后失败则不覆盖；`null` 才表示未配置。
- **资料库恢复复用同一写链。** 恢复在同一 `enqueueAiConfigWrite` 链中等待旧 provider 工作完成，提交成功后推进资料库 epoch；旧表单尚未执行的排队操作可见拒绝，不能把旧凭据重新存入新库。不清空链、不另建 provider 队列。
- **`translating` 终态复位无条件执行。** 五态判定与流式/自动触发的同篇防双发消费按 ID 的 `translatingIds`；全局布尔只作展示提示，终态复位不受 `ownsView` 门控，打开/关闭阅读器时也复位该布尔。A/B 并发时先结算方提前归 false 是可接受失真，旧断言翻转是语义变更，由按 ID 状态与展示态断言钉住。（原 2026-11-01 bug-fix/2026-11-01-translating终态复位与全局单布尔.md）
- **通用设置 IPC 拒绝敏感键。** `read_setting`/`apply_setting` 拒绝 `credentials::SENSITIVE_KEYS`，返回 `protectedSetting` 且不回显存量值；合法业务走专用命令/内核。DB 层仍允许授权内部读取，AI 专用 `get_ai_config` 仍可返回供编辑的明文 key——本修正缩小通用入口，不建立“WebView 完全无法接触凭据”的隔离。DPAPI 只保护落盘数据，不等价于抵抗该用户下已获得专用命令权限的 WebView 代码。（原 2026-10-31 bug-fix/2026-10-31-安全横向面收口.md）
- **正文文本提取跳过 script/style。** `html_to_text` 按解析树跳过 script/style 祖先下的文本，保持 body 与空白口径；摄取、GR 合并及全文提取共用该函数，HTML 渲染净化仍由 `sanitize` 链负责。过滤隐藏子树不等于正文没有提示注入，模型输入仍视为外部内容。
- **退订结转的多写同事务。** 远端快速创建成功、本地源已删除的结转分支，在调用点包外层事务，删除旧意图与写入退订意图同生共死；开事务/入队/提交失败按软失败记录并返回 `Skipped`。事务责任在调用点，不在可被其他事务调用的数据函数内再开事务。GR 游标写失败记录 warn 与 report，保留已合并数据；关闭 `smartDedup` 后清理旧墓碑失败只记 warn，设置保存仍成功，不宣称用户收到同步错误。（原 2026-11-01 bug-fix/2026-11-01-退订结转事务与吞错可见化.md）
- **目录重名分层处理。** OPML 导入查同名目录，命中复用其 ID 且不触碰 layout/collapsed，未命中才创建；手工创建与重命名拒绝同名（trim + 纯空白 validate），返回类型化 `duplicateFolderName`，前端给专属文案。按名查找统一 `ORDER BY id LIMIT 1`，同名存量取最旧，把隐式 rowid 假设变成 SQL 契约。存量重复目录不清理；大小写/内嵌空白变体仍可能视觉同名，属独立后续项。（原 2026-11-01 bug-fix/2026-11-01-目录重名复用与同名拒绝.md）

## Alternatives considered

- 排队到生成结束再清除：会新增等待/取消状态机，且旧回读仍可能复活，否决；只补 raw 标记不能消除后端缓存复活，必须同时有在途闸。
- AI 配置三个入口各自读改写：并发时后完成者覆盖先写者，testAndSave 还会冲掉在途提示词编辑，否决。
- 给 AI 配置接入 feed 级 `aiConfigWrites` 意图队列：该协议面向按键独立字段，`ai_config` 是单 blob，拆键会改变持久化格式，超出范围，否决。
- 互斥锁禁用其他入口：用户无法边测试边编辑提示词，交互退化，否决。
- 用声明集/引用计数替代全局 `translating`：会让“他篇在途”继续拦住新文章自动翻译，且引入模块级簿记，否决；派生 selector 是后续方向。
- 在 DB 层拒绝所有敏感键：会破坏合法同步/AI 消费，否决；只在通用命令边界打码并保留专用入口。
- 把事务下沉到 `enqueue_unsubscribe`：与其他调用方已有外层事务冲突，只在漏掉的调用点补。
- 给 `folders.name` 加 UNIQUE：需先迁移合并存量重复目录及其订阅，范围过大，暂不做。

## Consequences

- 每个译文 delta 多一次标记查找；被拒清除没有后端副作用；已发出的模型请求不能撤回，清除只阻止后续写回。
- 编辑后需重新测试才能保存新端点；已发出的保存不能撤回，落库身份始终是已测试快照。队列是模块级单链，跨挂载存活。
- 全局布尔在 A/B 并发时可能提前归 false，展示提示短暂失真；按 ID 的五态与流式渲染不受影响。
- `html_to_text` 过滤隐藏子树不消除提示注入；正文哈希变化可在重摄取时建立新内容行，未重摄取的历史 `body_text` 仍可能含旧文本。
- 目录重名只在命令层拒绝，`rename` 仍可制造同名；存量重复目录与空白/大小写变体未清理。
- 这些边界由受控 IPC、组件挂载与真实 SQLite 夹具覆盖，不替代真实 AI provider、原生 WebView 与用户库验证；当前缺口见[路线图](../../../../docs/roadmap.md#ai-and-content)。
