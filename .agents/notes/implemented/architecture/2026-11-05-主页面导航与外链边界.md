# Agent Note: 主页面导航与外链边界

Status: implemented

## Problem

Timeline 的社交、通知布局对完成态译文创建 HTML，却没有像正文和 Reader 那样代理链接点击。普通无 target 的译文链接可能直接替换阅读器所在页面。只依赖 opener 插件的初始化脚本不够：固定版本 2.5.4 的脚本只接管 `_blank` 或 Ctrl/Shift 点击，并跳过已阻止默认行为的事件。

后端也没有主页面导航策略。固定 Tauri 2.11.5 的导航链在没有显式拒绝时返回 true；HTML 净化负责标签与媒体域名，不能替代主页面的 origin 约束。CSP 允许 HTTP/HTTPS iframe，不能被概括成“所有内容仅来自本地”。`object-src` 原本继承 default-src，但 `base-uri`、`form-action` 没有相同的 fallback，需要明确配置纵深边界。

## Decision

完成态正文和译文链接统一经 `handleArticleLinkClick` → `openExternalWithFeedback`。代理在事件尚未被处理时从实际点击节点回找当前容器内的 `a[href]`，先阻止默认导航，再只调用一次外开封装；嵌套代理看到 `defaultPrevented` 后退出。URL 必须能解析且协议为 HTTP/HTTPS，拒绝与 opener 失败都返回 false 并走既有可见失败提示。后端 `sanitize` 继续用文章 URL 把相对地址转为绝对地址；未净化的流式译文仍是文本节点。

`navigation::init()` 注册独立 Tauri 插件，`lib.rs` 在创建窗口前装入。主页面仅允许配置对应的应用 origin：Windows 默认 `http://tauri.localhost`，配置 `use_https_scheme` 时为 HTTPS；其他桌面平台是 `tauri://localhost`。开发模式额外允许 `build.devUrl` 的精确 origin，而且配置地址本身必须是 HTTP/HTTPS loopback。协议、主机、有效端口都相同才放行；不接受任意 localhost 端口、主机后缀、带凭据地址或危险 scheme。

导航钩子对其他地址直接返回 false。普通用户外开由前端的统一封装负责，钩子不再启动系统浏览器，避免页面重定向或遗漏代理同时制造第二次外开。

Windows 主 frame 和 iframe 是不同边界。Cargo.lock 固定 Tauri 2.11.5、tauri-runtime-wry 2.11.4、wry 0.55.1：

- Tauri `src/manager/webview.rs` 的导航回调 把导航交给插件链，`src/plugin.rs` 的插件分派 在任一插件返回 false 时拒绝；
- runtime-wry `src/lib.rs` 的导航处理 把该回调交给 wry；
- wry `src/webview2/mod.rs` 注册 `ICoreWebView2::NavigationStarting` 并调用 `SetCancel`，没有把本策略注册为 `FrameNavigationStarting`。因此 Windows 的本策略限制主页面，iframe 加载继续由净化域名单和 frame-src 约束。

CSP 新增 `object-src 'none'; base-uri 'none'; form-action 'none'`。媒体与 frame 的既有来源规则保留；不增加未经播放验证的 iframe sandbox tokens。允许嵌入的播放器仍保留 `allow` 和 `allowfullscreen`。

## Testing

2026-11-05 的历史验证：`tools/component-tests/translation-links.test.mjs` 真实挂载 Timeline 社交、通知布局，覆盖普通/嵌套链接、净化后的相对地址、默认行为阻止、opener 单次调用、失败提示、协议拒绝、流式纯文本以及嵌套委托。定向 3/3 通过，命令与原始输出在 `tmp/convergence-c-translation-links.log`。

Windows 隔离 Rust 环境执行 `cargo test -j1 --lib navigation::tests`（精确 origin/伪域/端口/凭据/协议真值表）、`cargo test -j1 --lib sanitize::tests`（相对链接、媒体属性和危险标签），以及 `cargo test -j1 --test navigation_e2e`（用实际 `TauriPlugin::on_navigation` 回调与 mock runtime 配置验证 HTTP/HTTPS app origin 和 dev origin），分别为 1/1、12/12、2/2，均 exit 0。日志是 `tmp/runtime-closeout/rust-navigation-unit.log`、`rust-sanitize-unit.log`、`rust-navigation-integration.log`。

真实 hook 测试放在 integration target：当前 build.rs 给 integration test 注入 comctl32 v6 manifest；把 mock builder 构造放在 lib unit target 会把 `TaskDialogIndirect` 拉入没有 manifest 的 exe，Windows 在执行测试前返回 `STATUS_ENTRYPOINT_NOT_FOUND`。测试完整迁移而没有删除或 ignore；origin 纯函数仍在 lib unit target。

这些证据覆盖 Windows 编译与 mock hook 分发、净化和浏览器事件接线；没有启动已安装 Tauri 应用，没有声称实际 WebView2 点击、所有第三方播放器或生产账户已实测。

## Alternatives considered

### 只依赖 opener 的全局 click 脚本

可以少写代理代码，并覆盖 `_blank` 与修饰键点击，但它明确不接管普通无 target 点击，不能修复当前译文反例。统一组件委托也能复用既有失败提示。

### 在导航钩子中把所有 HTTP/HTTPS 地址外开

能给遗漏代理提供兜底，但主 frame 重定向同样会触发导航；外开副作用与前端代理可能重复，也没有统一的可见错误通道。钩子只做拒绝，用户点击外开交给既有包装。

### 给所有 iframe 添加 sandbox

能进一步限制嵌入页面权限，但播放器各自依赖的 token 不同，当前没有生产播放矩阵证明兼容。主 frame 的实际缺口由正确的原生事件边界关闭，iframe 继续保持已存在的域名单，不扩大本轮改动。

## Consequences

译文和正文具有同一外开语义，危险或无效地址不再被封装冒充成功；固定版本的导航策略拒绝外域或未配置的本机端口；实际安装应用的 WebView2 事件链仍按下述证据边界单列。显式 CSP 边界阻止对象、基址与表单动作，净化仍是正文内容的第一层边界。

维护成本是 Tauri/Wry 升级时必须重新核对 Windows 导航事件，以及 app/dev origin 配置变化时同步验证。其他平台不在本次生产实测范围；媒体保留的证据是固定 Windows hook 分界、净化测试和未收紧的媒体 CSP，不能替代第三方播放器实机播放矩阵。
