# Agent Note: GR 轻量对账 read 侧改未读差分（xt=read 全集 + 候选存在性校验）

Status: implemented

## Problem

GR 轻量同步的 read 对账此前是「全量拉 read 权威集合 → 逐绑定行 read-wins
落地」。两个问题：

1. **固定成本**：2 万已读库的 read 集合按 n=1000 分页要 ~20 请求/轮（加上
   starred 与主列举，light 轮固定成本 ~26 请求）；单页上限 1000 是历史取值，
   服务端实际允许更大。
2. **挂账的增量形态被证伪**：「read/starred 流 + ot 拉状态增量」曾作为优化
   挂账，但协议事实是 Miniflux 把状态流的 ot 映射为 `AfterPublishedDate`
   （过滤列是发布时间）、FreshRSS 的 ot 不能完整发现只修改 `lastUserModified`
   的读/藏变化、Bazqux 官方文档 Warning 明言勿用 ot——
   不能把 ot 窗口当完整状态变更流（已登记
   `docs/sync-compat-matrix.md` §1，防重复立项）。

需要一个协议支持的等价替代，且必须同时守住三个正确性边界：远端**删除**
的未读条目不得被误标已读；未读集合**不完整**（截断/请求失败）时不得落地
任何差分结果；starred 全量双向对账不受影响。

## Decision

light 轮 read 对账改为**未读差分**（`greader_pull.rs`）：

固定上游事实在 2026-11-05 校准：Miniflux `faecfa2` 为 `published_at > ot`；
FreshRSS `4e8a258` 的 `setMinDate` 在 DAO 展开为 `id >= ot×1000000`，与
`lastModified >= ot` 以 OR 组合，不是旧说明中的 `date >= ot`。
这不改变“完整集合替代状态 ot 增量”的决定，出处见[同步兼容矩阵](../../../../docs/sync-compat-matrix.md)。

1. **拉取**：`fetch_stream_ids(reading-list, xt=read)` 拉当前未读全集
   （ot=0、单页 n=10000、`GREADER_MAX_ID_PAGES=200` 页上限语义不变）。
   完整性守卫是**结构性**的：`fetch_stream_ids` 的 P2-1 纪律保证
   `Ok(ids) ⟺ continuation 耗尽`——页上限命中 / 请求失败 / 损坏 continuation
   一律 Err，调用方整轮跳过 read 差分，不落地任何差分结果；游标语义不变
   （差分是 ot=0 全集操作，不依赖窗口游标；2026-11-05 起集合请求失败也保留
   主窗口游标，为完整集合回补重试保留失败证据）。客户端 `item_ids_excluding`（`greader.rs`）为 xt
   参数的单点入口，`item_ids` 是它的 `xt=None` 薄壳。
2. **差分域**：`maps.mf_id_to_article`（远端 feed 绑定行，与旧 reconcile 的
   域一致）∩ 本地 `is_read = 0` 行；候选 = 该域 − curr_unread。本地已读行
   不进域——旧路径对它们本来就写 0 行（`sync_mark_read_if_unread` 值条件
   幂等），等价。
3. **候选存在性校验（删除/已读不可分的补口）**：「远端新变已读」与「远端
   已删除」在未读集合里同样缺席，凭未读集合不可分。差分仅作用于 curr_unread
   请求覆盖范围内（远端仍跟踪）的已绑定 remote id：候选逐批（100/批）拉
   `stream/items/contents`——逐请求 ID 覆盖校验，重复或无关条目不能凑数；块
   Err 再逐 id 探测，`protocol`（缺条/删除形态）静默跳过，`network`/HTTP
   型失败计入一条聚合诊断（report.errors）并按连续 2 次失败 fail-fast 本
   块剩余兜底（防最坏百次/块串行重试）；未确认候选一律不落地（fail-closed：
   宁漏标一轮、下一轮重差分，绝不把删除误标成已读）。确认集整体经回写边界
   `session.ensure_current` 代际复核后经
   `apply_read_by_policy(GR_READ_DIRECTION, remote_read=true)` 单向落地
   （字段版本守卫 + pending 保护 + 值条件幂等，与旧对账命中侧逐列一致）。
4. **starred 不动**：保持全量集合双向权威对账。starred 不能差分——取消收藏
   是显式动作，双向权威要求「集合未命中 = 可信取消信号」，未读集合与
   starred 集合互不携带对方信息，差分产生不出取消信号。
5. **read 集合退场，unread 增加身份发现**：2026-11-01 当时将未读集合限于
   差分，以避免本卡扩大绑定行为；该限制现由
   [GR 权威集合回补与过期意图恢复](../bug-fix/2026-11-05-GR权威集合回补与过期意图恢复.md)
   部分取代。完整 unread 在差分前有界补缺身份或正文，保留 read-wins 与字段守卫。
   纯窗口测试使用已读且未收藏的条目隔离回补通道，晚到旧未读另有具名回归；
   远端已读且未收藏、又无绑定的旧文章仍需 full 的 ot=0 列举。
   `reconcile_reader_state` 保留 read 侧作为全量语义契约与政策锁定测试锚点
   （生产 light 消费面仅剩 starred）。
6. **单页上限 1000 → 10000**（主列举 + 权威集合列举）：GR 官方 wiki 上限
   10000、Miniflux `MaxEntryIDsLimit=10000`、FreshRSS 无 clamp；页上限 200
   语义保留（上限内单请求更大，页数更少）。

与旧实现的等价性：旧路径实际效果 = 「对每个绑定行，远端已读才写已读」。
差分把「远端已读」判据从「∈ read 集合」换算为「本地未读 ∧ ∉ 完整未读集合
∧ contents 确认仍被跟踪」，三者合取在集合完整时与旧判据逐行等价；等价性由
`tests/unread_diff_e2e.rs` 五用例 + `greader_compat_e2e` 严格夹具 + 既有
政策锁定测试共同锁定。

## Alternatives considered

### ot×状态流增量（原挂账形态）

请求量最小（只拉变更），但被协议证据直接证伪（见 Problem 2），且 mock 若
实现「changed_at 进窗口」只会锁住失真语义。否决，登记防再立。

### 差分不做存在性校验（纯集合减法）

实现最简、零额外请求；但「远端已删除的未读条目不误标」用例必红——删除与
已读在未读集合里同样缺席，纯减法会把删除批量误标成已读，制造虚假的已读
历史。否决。

### 全量枚举 reading-list（不带 xt）判成员资格

一次枚举即可区分「read（在列表）vs deleted（不在）」，且探测批块化后请求
形态更规整；但 reading-list 全集与 read 集合同价（20k 库 ~2 请求/轮起），
等额退回旧成本，优化落空。否决。

### 批块探测失败即整轮跳过差分

比逐 id 兜底简单，但一个已删除 id 会永久毒化其所在 100 条块（该块永远
Err），块内真正已读的 99 条永远无法收敛。逐 id 兜底把毒化半径缩到单个
缺席 id，最坏代价仅出现在「删除 × 本地未读绑定」这一罕见交叠上。否决整轮
跳过。

### Fever 式 unread 双向解释（未命中 = 已读可复活 + 缺席 = 已读）

Fever 侧成立的前提是「按 URL 去重、无跨源副本、集合状态可直接信任」，且
GR 的 read-wins 单向是已显式化的政策（防历史条目成批翻回未读）；双向解释
还会把删除误标问题放大成「删除 = 已读」。维持单向 + 校验，否决。

### 保留 read 集合做双轨对账

风险最低，但 read 集合的全量拉取正是要移除的固定成本，双轨等于不优化；
等价性风险由测试与 CI 承担（本机不可链接 Rust，行为验证由 CI windows
承担）。否决。

## Consequences

**收益**：light 轮固定成本 ~26 → ~7 请求（n=10000 + read 集合 → 未读差分
双刀）；未读差分与 Bazqux 官方推荐的 xt 流同步形态同构，为未来接入铺路；
远端删除不再被误标为已读（旧全量对账对删除行无操作，纯减法方案会引入
回归，本设计一并封死）。

**代价与已知上限**：① 探测请求——稳态两端一致时候选为 0、零额外请求；
多端追赶期候选为「本轮新变已读数」，批块摊薄为 ≤1 请求/百候选，存在已删除
候选时按块内逐 id 探测放大（罕见交叠，可接受）。② read 漂移收敛通道退场：
远端已读且未绑定的条目不再有 light 回补，收敛点后移到 full 同步/窗口
（未绑定旧未读在 2026-11-05 起可经 unread 回补发现，见上面的后续决定）。③ 真实服务端
（Miniflux/FreshRSS xt 行为、10000 上限）未实机验收，行为级验证由 CI 的
mock/严格夹具承担；`xt` 为三家官方参数，风险集中在版本差异而非协议缺口。
④ **语义级截断/空集谎言不可检测**：完整性守卫只保证「分页耗尽」（wire 层），
不保证「集合语义为真」——服务端若返回格式完好但语义不完整的未读集合
（服务端缺陷把未读条目漏出 `xt=read` 流），被漏掉的本地未读行会经「差分 +
contents 存在确认（条目仍存在）」被误标已读；旧 read 全量对账的失败方向是
漏标（无害），未读差分的失败方向是误标——不对称性已登记
`docs/sync-compat-matrix.md` §6-L9，真实服务端实机验收继续挂账。
