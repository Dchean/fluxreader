# Agent Note: GR 未读差分与候选存在性校验

Status: implemented

## Problem

轻量同步每轮枚举全部 read ID，在已读库很大、近期变更很少时形成固定请求成本。但 read/starred 流加 ot 不能替代完整状态集合：Miniflux 的 ot 按发布时间过滤，FreshRSS 的形态也不能证明完整状态变更覆盖，Bazqux 官方文档明确警告这种用法。不能让 mock 用 changed_at 过滤来证明不存在的协议能力。

## Decision

light 的 read 对账采用完整 unread 集合的差分，starred 保持完整集合双向权威。2026-11-05 固定上游校准：Miniflux `faecfa2` 为 published_at > ot；FreshRSS `4e8a258` 的 setMinDate 展开为 id ≥ ot×1000000，并与 lastModified 条件组合。它们都不能被简化成通用状态时间戳，依据见[同步兼容矩阵](../../../../docs/sync-compat-matrix.md)。

1. 以 reading-list、xt=read、ot=0 获取完整 unread ID，单页 n=10000，最多 200 页。只有 continuation 耗尽才返回成功；截断、坏 continuation、请求失败均拒绝该侧差分，不把部分集合当全集。集合失败同时保留相关窗口游标供重试。
2. 差分域为来源已由真实Content证明、绑定与source生命周期仍有效且本地未读的行；候选是该域减去 unread 集合。本地已读不进入这一“未读消失”分支。冷裸ID由Content有限补证，不以正文存在或本机feed信息代替来源证明。
3. 候选缺席可能表示“已读”或“远端删除”，须按 100 条 contents 校验存在性。响应按请求 ID 逐项检查，重复/无关条目不能凑数。块失败后逐 id 兜底：缺条协议形态跳过，网络/HTTP 失败聚合诊断，连续两次失败停止该块剩余探测。未经确认的候选不落地。
4. 只对已确认候选标读，写前复核来源凭据、会话、字段版本和pending。2026-11-09用户已批准双向状态，完整unread集合命中的已证明行另可恢复未读，取代最初GR整体read-wins政策；候选缺席的存在性检查仍保留，本机intent仍优先。
5. starred 不从 unread 推导取消，继续完整双向对账。2026-11-05 的[权威集合回补](2026-11-13-同步写回与状态一致性.md)已让unread承担有界缺身份/正文发现；2026-11-10起由Content复用本轮集合ID执行，已绑定flags唯一归State，不必等正文补齐。旧的远端已读且未收藏、无绑定条目仍依赖full ot=0或窗口发现。

单页从 1000 调至 10000 的依据是官方/固定上游上限，不等于所有部署已测。差分等价依赖“完整 unread 语义正确且 contents 确认仍被跟踪”；分页耗尽只能证明结构完整。服务端若返回格式合法但漏项的 unread 集合，仍可能把实际未读误标已读；旧 read 全量的同类失败方向偏向漏标，两者不对称。

## Alternatives considered

- **ot×状态流增量**：当时固定版本证据不能把 ot 解释为状态变更时间，未采用；不能通过自定义 changed_at mock 消除差异。
- **GR long-poll/ContinueWhatNewStream、Fever last_id_on_sync、订阅 ETag/304**：2026-11-01 的第五轮调研没有得到匹配目标服务端版本的可信能力证据，因此未引入。这是证据不足的决定，不是断言协议或未来版本永远没有；若得到文档、固定源码或真实探针，可重访。
- **直接作集合减法**：无法区别已读与已删除，故加存在性校验。
- **全量 reading-list 判成员**：能够判别删除，但重新承担全库枚举成本；当前采用只查差分候选。
- **一个块失败就整轮跳过**：单个删除 id 会持续阻塞同块其余已读条目；逐 id 兜底缩小失败范围，同时用连续失败上限约束请求放大。
- **套用 Fever 双向 unread 语义**：最初GR read-wins是显式产品政策，不能由另一协议推导，故当时未采用；2026-11-09用户另行批准双向后该方向选择被取代，但删除缺席仍须存在性确认。Fever条目身份同样保留跨源副本，旧“URL去重所以可双向”的解释已不适用。
- **保留 read 全量做双轨**：保留了要移除的固定成本；选择差分并明确语义截断风险，不把测试通过当作服务端正确性证明。

## Consequences

稳态两端一致时候选为零，免去全量 read 的固定成本；多端追赶产生候选请求，删除与网络失败可使逐 id 探测放大。历史“约 26→7 请求”是当时指定库规模与分页形态的示例，不是当前任意轮次的预算或速度承诺。未绑定旧已读的发现范围比全量 read 回补窄，须保持 full 恢复入口。

该存在性HTTP仍持有同一State许可，慢探测会使后续State操作排队；Content分离及持久origin证明只避免新增的重复来源补证，不能宣称任意远端标读都不再请求contents。来源生命周期与token后的发送保护见[运行边界](2026-11-05-同步运行生命周期与诊断.md)。

## Verification

`unread_diff_e2e` 与严格协议夹具覆盖删除不误标、完整集合失败、存在性回退和字段守卫；真实 Miniflux/FreshRSS 部署的 xt/分页语义不能由 mock 代替。当前限制集中在[同步正确性](../../../../docs/roadmap.md#sync-correctness)与[验证边界](../../../../docs/roadmap.md#verification-boundaries)。原请求估算、测试定位及早期取舍见[整理前记录](https://github.com/Dchean/fluxreader/blob/91ece562d79fd909642cd6d570d636e884b7387e/.agents/notes/implemented/architecture/2026-11-01-GR未读差分对账.md)。
