# Agent Note: 查询与分页契约

Status: implemented

## Problem

用极大 limit 假装全库、不稳定集合上的 OFFSET、只按查询参数识别旧请求，曾分别造成旧文章不可达、标读/取消收藏后的跨页漏项和 A→B→A 迟到覆盖。2026-11-09 用户进一步要求阅读中的成员与顺序保持不变：即使未加载尾部已被另一端标读或取消收藏，也应继续可达。仅有 keyset 能避免 OFFSET 位移，却仍会在每次查询的未读/收藏谓词里失去尾部，因此需将成员与属性分开。

## Decision

`QueryScope` 继续派生范围、排序、分区及既有缓存键。`ReadingSession` 拥有一次查询的完整有序轻量 ID、已加载进度、窗口起点、请求代次，以及分区/视图/组或源/筛选/排序/本地日界快照。源索引、读藏、正文和媒体版本属于实体属性，不重新决定当前成员。

进入或显式重选分区、视图、组、源、筛选、排序时，通过 `list_article_member_ids` 捕获完整成员，后端仍按 `(published_at, id)` 同向全序。正文不随全成员回读，也不持有长 SQLite 事务。每页只切既定 ID，再用 `get_article_updates` 读取轻属性，并按成员 ID 恢复顺序；后端属性响应按 ID 排序不能决定显示顺序。后台同步刷新同一会话已加载 ID，不插入新成员、不按变化后的读藏/时间重排。旧缓存只提供返回窗口深度和属性，不替代新的成员查询。

重复点击当前分区、视图或范围仍重新捕获成员，但恢复位置沿当前活锚，不能因为有视图缓存就再次消费上次离开时的旧存档。导航动作在清除会话前判断上下文是否真正改变；同上下文重筛落地只推进 `positionRestoreNonce`，A→B→A 的缓存返回才推进 `switchRestoreNonce`。这保留原先的两通道隔离，防止用户已继续滚动后重复点击当前范围却跳回旧位置。锚被重筛移除时沿用现有不猜位置、回落现状的规则，不新增最近邻算法。

同上下文重筛在等待新成员时，将旧会话标为未就绪，仅保留已加载窗口的ID边界作为定位输入；当前列表不因此继续显示旧筛选集合。新成员顺序与资格仍全部由新查询决定，窗口覆盖旧窗口中仍存在的ID，避免新增头部把页尾活锚挤进未加载区。深搜索窗口平移到其新成员位置再取轻属性，不从0回读到深锚；正文仍按实际挂载水合。连续在途重选继承这一定位输入，旧回应仍按代次拒绝。

跨范围返回的窗口准备与Timeline消费同一份真实存档锚。纯锚模块由components移到`lib/readingPosition`，继续唯一拥有活锚、像素偏移与8键LRU，不新增provider或复制档案。先按缓存进度准备窗口；若存活锚不在该窗口，按它的新成员位置与缓存内相对位置准备有界邻域。缓存首项被删除不等于用户锚消失；真实锚也缺失才沿原null回落，不推测最近邻。测试loader把源码组件与编译store导向同一锚模块实例。

2026-11-09 此策略部分取代原 keyset 续页及后台重筛窗口。旧策略是为消除 OFFSET 漏项并保深页锚，仍适用于后端其他非会话查询；但其每页重新应用筛选不满足新目标。前端续页沿用会话代次和已加载位置，属性刷新另有读取序号；A→B→A 即使参数相同也拒收旧实例。明确 `missing_ids` 保留不可用占位并消费该位置，残缺响应则失败，不能把查询未返回当作删除。搜索命中会话外条目只注入 Reader 消费行，不混入当前成员；同会话的有效 ID 续页可以完成，定位到另一窗口才废弃旧页。

今天的成员查询向后端传 `[since_ms, until_ms)` 毫秒边界。跨零点定时器、恢复焦点或可见性变化刷新属性与当前计数，保持旧会话成员；下一次显式重筛捕获新日界。启动设置与来源/计数元数据并行读取，成员查询必须等启动视图和筛选接受，不能先捕获默认 all 后假装只改本地过滤。日期规范化另见[时间口径](2026-11-13-身份时间与协议边角.md)。

活动导航继续由 `categories/feedIndex` 表达；`sourceIndex` 通过 `list_article_sources` 保存活动与退订来源、冻结分区及真实源名称。退订收藏无需公共假源，也不因活动组缺失被筛掉；Reader、卡片与搜索提示使用完整来源解析。显式缺行的原成员保位不代表数据库里仍有正文。

### 集合与回执

- 2026-11-09 源内身份契约取代跨源 `url_norm` 聚合：同源内容等价组由后端在列表、计数、搜索和状态操作统一裁决；不同源独立。前端移除 `smartDedup` 开关及以它门控精确计数的分支，不保留与后端无效的用户选择。
- 搜索 trigram 只是 ≥3 字符的候选加速，LIKE 才裁决匹配；短词、索引缺失或 MATCH 失败回落 LIKE。它不改变顺序、去重或字段语义。源内等价组的`idx_articles_rss_group`同样是加速提示：索引存在时固定该计划；`prepare`确认索引缺失时，同一语义SQL去掉该`INDEXED BY`后重试，不能因畸形/手工降级库让列表、索引、搜索或计数整体报错。
- “全部已读”使用当前会话捕获的完整 ID（包含未加载尾部），后台新增不悄悄加入本次动作；同源等价别名由后端状态命令闭合。Tauri没有就绪会话时只提示列表尚未就绪，不写入、不乐观标读；新范围查询悬挂或失败不能退到旧动态范围命令。已建立动作的重试继续使用当时捕获的成员，切换范围不扩大其写入集合。mock预览仅执行自己的本地标读。搜索注入不推进分页、不伪造当前分区卡片，非文章定位按统一动作策略仅选择。
- `set_read/set_read_bulk` 返回真实翻转身份，范围入口返回实际影响数。回执是请求时的提交事实，不是当前状态：`applyReadReceipt` 按行×字段写序号识别较新 unread，只更新实际接受的实体和视图缓存 flags，无关行的新操作不使整批回执失效。一个显示组可以返回多个身份回执，因此不按回执条数扣组计数；可见代表的乐观计数与操作后的权威快照负责收敛。
- 全读的IPC输入、pending字段声明和成功投影都以同一捕获成员为基础，不再从动态scope扩张；搜索打开的非成员只有出现在后端真实组回执里才会跟随。未加载成员同样登记字段版本、写序号和目标值；旧尾页不能因没有prev行而绕过写前沿。新鲜属性读取仍可接管本地值，shadow不成为永久权威。

### 读取与计数提交

`counts_snapshot` 在同一数据库锁内返回源计数和范围计数。源计数保留布局无关底座；scopeCounts 带 layout，选择器仅消费当前分区快照，完整来源计数包含退订收藏。空聚合必须 COALESCE 为四个零值，前端默认值不能掩盖 SQL NULL 错误。

本地同步查询有两条明确路径。只有`capture`关闭，或初始化完成且`accepted_job`、folding/applying、普通工作项与待处理意图都为空时，列表、搜索、成员捕获和计数才直接读取已投影的`feeds`与文章行列；这些物理值此时已经由同一逻辑权威物化，属于同一快照的快速路径。任一本地意图、候选接受或物化工作尚未完成时，查询必须回落到`local_sync_article_state`/source视图，保留别名、来源活跃态和迟到意图的即时语义。这个切换覆盖`list_articles`、`article_index`、`list_article_member_ids`、`search_articles`、feed/scope count、条目更新、scoped unread/read-target与mark闭包：筛选、排序定位、去重代表和返回的`is_read/is_starred`都必须取同一逻辑赢家。同源等价组的去重内层EXISTS也必须使用逻辑读藏，否则外层代表进入结果后仍可能按物理状态漏项。不能为了计划形状无条件绕过逻辑视图，也不能在稳定态让每个文章行重复物化整组source窗口。

直接物理路径的可见性片段在进入`WHERE ... AND ...`前必须整体加括号。`starred OR active`是单一布尔原子，不能依赖SQL运算符优先级；否则会解析成`starred OR (active AND filters...)`，让收藏行绕过scope/去重/搜索条件，并给普通行多加约束。列表、索引、搜索、去重和计数继续共用一个带括号常量。

列表、搜索、scope count与`article_index`的计划回归使用生产去重状态，在小型和20k合成规模上要求索引有序、无TEMP B-TREE、稳定态不出现`MATERIALIZE local_sync*`或逐行文章状态视图；同时保留一个待物化工作反例，证明查询确实切回逻辑视图。该快速路径只减少稳定态的重复派生，不改变URL/GUID alias、RSS等价组、代表ID、筛选、排序或计数规则。

reload 与写后对账共用读取序号、写前沿和在途写引用计数。计数只在仍是最新读取、发起后的写前沿未推进且没有未提交意图时落地；读取失败保留同 scope 已确认值。全部写落定后由对账收敛，不能以逐条 ±1 代替折叠组真实计数。

条目快照也记录发起时写前沿与在途行×字段集合。较新本地写保留本地值；读取时已在途的乐观值也受保护，保护本身不推进版本，以便失败还能回滚。若快照值已等于本地值，则按已落定声明推进版本，迟到失败不得推翻已接受事实。未受保护字段照常读取，新鲜读取仍可接受外部变化，本地不是永久权威。

完整成员中未驻留的原读态不能猜。pending声明在首次真实属性到达时取得回滚基线；写失败且属性始终未到时撤销未知目标，让后续真实行决定原值。已有字段链继续组合连续成功/失败及较新unread，真实组回执也经过同一前沿并且不重复扣显示组计数。现存实体/缓存的已知差值可乐观投影，未知原值不参与计数猜测；链分开保存当前可见目标与源计数实际已反映的值，首次出现的pending行不能因显示为true就被当成已经扣过1，再在失败时多补1。即使权威计数暂不可用，失败恢复也不虚增；写后仍以权威快照收敛。

字段版本、写序号和轻值影子按同一生命周期回收：当前完整成员、驻留实体、有界视图缓存、在途字段写与可能携带旧状态的属性读取持有它们。读取从发起到完成/失败/过时退出均有前沿租约；旧组写回执仍在途时保留较新字段接管记录。相关引用全部释放后删除历史，不能为每次全读永久留下全库shadow。回收不清掉仍在途声明，也不修改数据库事实。

app_settings 的读取单飞凭据绑定发起时写序号、应用代次和读取序号，不能把跨提交的旧在途读 join 成新鲜结果。bootstrap 先等待捕获时写前沿；发现旧读则新读，应用回读强制新鲜。完整“确认基线 + 待写意图投影 + 应用屏障”归[内容身份篇的设置协议](2026-10-12-订阅条目与共享内容身份.md#设置快照的独立提交协议)，此处只规定共享读取与旧响应接受条件。

## Alternatives considered

- **保留 keyset 动态续页**：原决定认为完整 ID 需要数据库快照表及额外生命周期，因此选择更轻的 keyset。新要求确认只需当前阅读会话，前端内存完整轻量 ID 即可，不需要持久快照表；其线性内存代价换取尾部可达与顺序不变。
- **OFFSET 客户端补偿**：客户端不知道并发同步移除了多少行，补偿只能猜；集合定位应由 SQL 谓词成立。
- **每个续页推进代际**：会把同一查询中的首页/续页互相作废；代际归查询实例，非每个网络包。
- **日期函数排序**：若表达式与索引不匹配会退回扫描/临时排序；含 localtime 等非确定性修饰的表达式也不能依赖确定性索引。先统一存储口径并保持谓词同构。
- **分页后去重或用显示代表执行 markAll**：前者破坏满页/游标，后者遗漏隐藏副本；显示与操作必须明确各自集合。
- **有缓存即发返回恢复信号**：会把同上下文重筛误作切换返回，消费过期存档；不能以不刷新成员避开问题，故在导航输入处保留“当前位置/返回位置”的区别。
- **无会话时回退动态范围全读**：在新范围成员未返回时可从真实按钮触发，既没有捕获成员又可能写到后台新增；为旧单元夹具保留此路径会违背产品契约，因此移除该前端回退。
- **仅过滤成功投影或忽略迟到尾页**：只修搜索非成员会遗漏尚未驻留成员的声明；直接丢整页会破坏固定成员可达。统一完整成员字段链并消费真实组回执，保留正常分页与失败回滚。
- **返回锚只从缓存首项推断/向store注入可选provider**：首项删除不能代表真实存档消失；provider又增加初始化/卸载协议。将纯状态归lib让两侧直接依赖同一实例，保留原算法与LRU更简单。

## Consequences

契约减少了快照与写回相互覆盖，但保留会话代次、读取序号、写前沿、在途集合和缓存同步成本。完整 ID及全读期间的轻字段状态内存随有效范围总量线性增长，离开且在途/缓存释放后回收；长时间未完成的真实读写仍会延长其前沿寿命。正文仍按视口水合，视图回访缓存仍有既有预算。新入库内容与读藏筛选结果在下次显式重筛出现，这是已确认的阅读保位取舍。同上下文重筛仍可能失去已被筛掉的活锚，当前规则不猜测替代位置；活锚仍存在时必须沿它保位。为覆盖原加载窗口，重筛后轻属性窗口可能随头部新增扩大，深窗口仍保持自己的起点；这个成本不传递到正文或全文加载。失效响应拒绝与字段回滚是不同责任，不能由读取守卫推出连续失败正确，见[乐观写入边界](2026-10-05-乐观写入的版本守卫.md)。
