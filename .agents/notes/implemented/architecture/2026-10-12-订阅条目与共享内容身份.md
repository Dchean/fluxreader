# Agent Note: 订阅条目与共享内容身份

Status: implemented

## Problem

全局 URL→文章映射曾先于远端 entry ID，跨源同 URL 被吞成单行或 CSV 副本，丢失 feed、收藏和远端身份。仅修 URL 规范化不能恢复这些身份；反过来把同 URL 正文直接共用，又会让摘要源覆盖全文源及其 AI 输入。需要条目身份独立、内容等价才共享。

## Decision

2026-10-12 至 10-19 分两阶段落地：先保留全部条目身份与显示集合，再迁移到 contents 单一正文所有者。当前两阶段均已实施；状态不代表当前所有竞争和 UI 路径通过审计。保留技术栈及分批迁移的理由沿用[核心路线](../../../../docs/architecture.md)。

### 2026-11-09的部分后继

[源内等价组与持久状态](../../../../docs/architecture.md)取代下述历史跨源URL显示聚合、read广播、URL即可绑定及回收时删除轻身份的选择；真实GUID/远端ID实体、内容字节复核、SAVEPOINT、版本与异步保护仍沿用。新实现保留独立RSS引用用于组身份，全文提取不改变组；正文过期同时释放RSS与展示引用，留下读藏轻身份。以下历史机制说明保留原由，不能再当当前产品验收标准。

### 2026-11-11正文身份不可变后继

新库不承担旧数据兼容，退役`repair_extracted_body_if_mismatch`及RSS刷新、回填的两处接线。旧逻辑为历史HTML/text错配及“body已修、identity未修”行进行原地迁移或合并；当前内容身份已被L、已封存/发布BodyRef、hold和正文目录共同引用，不能只追articles引用。是否存在本机hold不足以判断这些身份可被改写。

当前正文输入由来源、已清洗HTML与精确纯文本共同确定identity。WebDAV与portable模型接受合法但HTML/text不按本机提取器同源的载荷，仍先核对identity与安全清洗幂等；这一格式没有因退役修复而收紧。普通RSS刷新/回填对已提取readability正文保持identity、HTML、text、revision和flag；RSS刷新更新独立RSS引用，回填可继续补封面/附件等元数据。需要新全文时仍由显式受检提取创建或复用新内容并重指当前条目，保留原SAVEPOINT、token、字节碰撞复核与引用回收约束。

2026-11-10在642E基础正文保留候选的真实SQLite反例：合法readability异text载荷经生产安装、真实收藏hold后，普通RSS刷新使原hold identity查询为空。原始断言及失败日志保留，随后只移除旧修复，不移除/放松模型校验或修改wire身份。退役历史迁移测试时保留逐项原目的与后继覆盖，详见本轮候选交付入口；不把旧版本通过或新回归源码存在作为修复已通过。

### 条目、显示与状态（2026-10-12至11-08）

协议精确 entry ID 优先，URL 兜底只在同 feed、未绑定或同 eid 候选内使用；同源同 URL 不同远端 ID 也各自成行。跨源条目保留 feed/guid/remote_id、读藏、版本、队列和 AI 产物。旧 CSV 缺 feed/正文，不能猜建完整行；未绑定远端源时有限兼容记账，身份恢复须经真实远端重拉和 feeds 阶段。后台 light 只跑状态时不会凭空补出源。

智能去重只聚合查询显示，不再以内容墓碑或全局 URL 丢入库身份。列表、计数、搜索、keyset 与锚定共用当前 scope×视图谓词；markAll 操作范围未读及同组读闭包，不能只操作显示代表。read 本地与远端显式广播，unread/star 只当前条目，同轮 read 优先但历史 read 不永久压过后续 unread，详见[冲突政策](2026-10-07-同步冲突政策单点.md)。回执、计数、写前沿和在途保护见[查询契约](2026-10-05-查询与分页契约.md)。

直连条目没有协议精确 ID 时，持久 guid 依次采用源内真实 guid、规范化 URL、有源日期的 title+date、无 URL/date 的 title+HTML+正文指纹；抓取时刻不参与身份。发布时间与首次见到时间分离，见[发布时间与条目身份](2026-11-13-身份时间与协议边角.md)。这些规则不证明所有输入都可落库：2026-11-06 的协议空链接反例与源 URL 变化重建问题在[同步路线](../../../../docs/roadmap.md#sync-correctness)。

### 内容等价、分叉与生命周期（历史实现及仍有效约束）

v22 追加 contents 与 articles.content_id/ai_epoch，迁移后移除 articles 旧正文列，不维护双真值。contents id 使用 AUTOINCREMENT，避免删除最大行后的 id 重用与 revision 巧合匹配。迁移单事务回填、切换并更新版本，失败整体回滚；既有条目 ID、状态、队列与 AI 保留。

非空内容身份以来源、消毒 HTML、纯文本计算 md5 指纹并附字节长度；md5 只缩小等价候选，不是安全证明。哈希命中必须复核 source/HTML/body 全字节相等；碰撞按既有 base|c<len> 规则加盐，16 次仍冲突则报错，不误并。空正文用 `e|article_id` 私有身份。URL 相同不足以共享，不同来源或字节应分叉。

RSS 刷新保护已有 readability 全文；本机全文提取在新写入边界生成同源HTML/纯文本。当前格式导入的精确bytes不由刷新再次推导，见11-11后继。全文提取取得/创建等价 readability 行后重指当前条目，其他引用继续持有原行。新内容 INSERT、条目插入/重指/回填用可嵌套 SAVEPOINT，任一步失败不留孤儿或半引用。最后引用消失才回收，条目删除通过独立 `trg_articles_recycle_ad` 触发器回收；源/分类级联、账号清理和文章清理均遵守它；当前localSync真实hold也属于回收保护所有者。

提取后当前条目只指向有效全文，旧 RSS 行若失去最后引用会被回收。因此它不是双原文存储：2026-11-06 基线实测重开后 rawContent 与全文相同，“RSS 原文”无法恢复旧源正文。产品选择轻量边界：仅在当前正文缓存确实持有独立 RSS 字节且与全文不同时，提供回切；详情只返回已提取全文时 rawContent 为空，Reader 阅读唯一正文，工具栏与菜单隐藏无数据的切换。工具栏与菜单都经同一公开 selector，只有正文就绪后才提供提取/切换入口；loading 空记录的默认标记不能代表该条目尚未提取。跨缓存淘汰、重开或重启不保证 RSS 来源保留。

### 修复身份（2026-10-12至11-10历史选择）与派生索引

以下两段的旧库惰性修复在11-11被上面的不可变正文决定取代；历史理由保留，派生索引约束仍有效。

受保护提取行的 body 修复必须同时重算 identity。若新 identity 命中等价行，全部引用重指目标、目标 revision+1、原行删除，提取标记取并集不弱化；字节不同走碰撞策略。整组仍同一 SAVEPOINT。

历史“body 已修、identity 未修”的规范未加盐 h| 行通过再次刷新/回填惰性收敛：无目标只改 identity、不推进 revision（正文未变）；有等价目标则合并。私有 e| 和已加盐身份不猜测，未再次触达行仍保持原状；没有隐含的一次性全库修复。

v22 的 articles_fts 曾作派生表，但没有 MATCH 消费者；v29 已删除该表和四个维护触发器，`rebuild_fts` 只为历史迁移保留。搜索权威继续是 LIKE，`articles_trigram_idx` 为 contentless/detail=none 的可重建候选索引，≥3 字符 AND-of-trigrams 仅收缩候选，LIKE 复核保证语义；短词、索引缺失或 MATCH 错误回落 LIKE。条目字段、content_id、共享正文、AI 写和删除的触发器维护每个引用条目的候选行。

v30 为 read 闭包增加 `idx_articles_url_norm_unread ON articles(url_norm) WHERE is_read=0`；rowid 隐含提供 id 次序，不改查询/回执/队列语义。索引缺失回落旧计划，保留旧 is_read 索引供 markAll 使用。数据量与测量前提见[性能记录](../../../../docs/performance.md)，不能把高重复正文、唯一 URL 的合成夹具数字外推为自然语料性能。

### 异步提交和前端失效

内容版本为 `(content_id, revision)`，网络期间不持数据库锁。全文请求在同一数据库锁内取得请求 URL、内容身份/修订与降级判断正文，提交同时复核该 URL 与条目/内容版本，成功回传实际 contentId/contentRevision；AI 提交仍独立复核 ai_epoch/content_id/revision/title，签名记录生成时输入快照而不按提交时新配置重算，未把全文请求 URL 混入 AI token。产物仍属于条目，避免不同标题共用 AI。单条内容替换或清除使迟到提交失败，具体 AI 语义见[AI 完成与缓存](2026-10-08-AI完成信号与缓存提交.md)。

2026-11-06 基线反例曾证明全文 URL 在途变化仍能提交旧页面、正文提交后补封面失败让命令报失败，以及仅有片段的批量 AI 清理不推进 epoch。后继首批/AB 已分别修复：全文 URL 纳入上述提交前提；正文/封面相对地址取最终响应 URL；正文成功后的封面写错只记警告，成功内容仍返回；批量清理将仅有 `ai_segments` 的目标纳入同一事务，先推进 epoch 再删除片段和完整缓存，阻止旧任务复活。2026-11-07 限定自测与独立审计覆盖这些实际触发序列，精确版本证据在当轮交付；这不表示所有异步输入或最终整合/原生门禁已经通过。当前边界继续归[阅读与状态](../../../../docs/roadmap.md#reader-and-state)和[AI 与内容](../../../../docs/roadmap.md#ai-and-content)。

前端实体缓存保存 contentId/revision 与 `feedId|title` 条目锚，快照变化时失效并按需重水合。cleared 可表示“只清 AI、正文仍在”或“正文已失效”，后者才重取；Reader 独立于虚拟化卡片，为未请求及正文空的 cleared 状态发起幂等水合。2026-11-06 基线的新 contentId+snippet 同变反例证明，删实体记录会丢失失效戳并绕过 Reader 重取。修复后 snippet 与内容身份变化沿 cleared 失效，保留旧响应拒收凭据；正文接受结果同时决定 snippet/url 能否落地。全文提取成功也推进失效戳，所有提取入口共用同一落账点，提取前在途的旧详情不能覆盖新正文身份。重试或 LRU 淘汰后的新记录不复用旧请求戳，记录已淘汰时拒绝旧响应重建。订阅保持 useShallow，详见[实体缓存](2026-10-06-正文与-AI-产物的实体缓存.md)。

### 设置快照的独立提交协议

内容身份工作同时暴露 app_settings 全量写入与配置应用的竞争。这部分仍有效，不能以“与正文不相干”删除：

- 写入仍串行，但 2026-11-09 的持续同步接入以**后端事务原子合并本笔已校验 patch**取代“前端确认基线 + patch 整包发送”。此前方案避免偷提交本机较晚意图，却会覆盖回读之后先到达的远端别键更新；`patch_app_settings` 只接受显式字段，返回实际提交后的完整 JSON 作为新确认基线。失败仍只移除此笔意图，UI 投影保留较晚点击。
- 基线未知时，发送前做一次有界校准读取；失败则不发送、不改库、可见报错。空/partial/未知基线下同键连续失败，要把稳定底值传给更晚未落定意图的 prev，不能残留前笔乐观中间值。
- 单飞读取凭据绑定发起时写序号、应用代次和读取序号。跨提交等待者不能把旧读当新读；bootstrap 先等待捕获时前沿，发现过时读取需重读；校准只复用同应用代次，应用回读或标未知会推进代次。不依赖 IPC FIFO，数据库提交与 Promise 回应分开处理。
- `runAppSettingsApplyBoundary` 门控实际写：窗口内新点击仍乐观可见，但请求等应用与真实回读后发送。回读设置新基线，窗口内点击由意图投影保留；失败调用 markAppSettingsUnconfirmed，不假称已恢复。便携导出仅等待发起时已有写前沿，不阻止后来点击；便携恢复的全局 busy 暂停新用户编辑，不能把普通应用窗口的“允许乐观点击”理解为恢复旧资料库时仍可写。
- 这套协议与源/分类 AI 配置的[写入快照对账](2026-11-13-AI与设置边界.md)分别负责自己的状态，不共享可混淆的基线或队列。便携恢复需同时经过两者边界，并等待 AI 服务配置、读藏与播放记录前沿；生命周期见[本地同步与便携恢复界面边界](2026-11-09-本地同步与便携恢复界面边界.md)。

## Alternatives considered

- **扩大 remote_dup_ids 或全局 URL 映射**：能继续 read 广播，却无法表达副本 feed、收藏和列表身份。
- **一次替换表、IPC 和缓存**：难以定位迁移与渲染回归；选分阶段运行中间态，但不把第一阶段当最终内容共享。
- **同 URL 无条件共享可变正文**：摘要、全文、更新版本不同，URL 不能证明内容等价。
- **identity 永远当创建键，仅改 revision**：会保留身份与字节不一致、持续欠共享；选择重算及等价合并。只重算后遇唯一冲突报错会阻塞正常刷新，直接覆目标 body/flag 又无意义且可能弱化保护。
- **全库一次回填旧 identity**：需新迁移、扫描成本与回滚验收；当时选择只对触达行惰性收敛，保留覆盖上限。
- **11-11只在存在hold时跳过旧修复**：不能保护无本机hold但L或已发布目录仍引用的identity；未选。**不可变复制后迁移全部引用**需要改变同步引用与生命周期，当前目标不需要后台重新解释已验证正文；在无旧库兼容前提下直接退役旧迁移路径，保留显式受检提取。
- **只删 FTS 不加候选 / 使用 unicode61 MATCH**：前者在合成大库仍慢，后者改变中文和查询语法；选择 LIKE 权威加候选。detail=full 或正文副本提高体积，自定义 n-gram 需侵入所有写路径，未选。
- **read 闭包 `(url_norm,id)` 部分索引**：计划等价但更大；非部分索引在当时无 ANALYZE 计划下未被选中；强制 INDEXED BY 缺索引会直接报错，均未选。
- **设置发乐观全量、失败回前值、刷新清写队列**：分别会偷提交未确认意图、留下失败中间值或破坏 wire 顺序；保留确认基线、稳定底值、意图投影与持久执行顺序。
- **普通设置先读当前值再拼整包写**：仍存在读写之间的远端更新窗口；持续同步后采用后端事务 patch，原前端确认基线继续承担UI失败恢复而不再承担数据库合并。
- **持久保留 RSS 与全文双来源**：可以跨重开切换，但需要扩展来源引用与回收生命周期；本轮没有此长期要求，选择只对实际持有的数据提供入口。

## Consequences

条目与内容分离保住订阅身份并降低等价正文重复，代价是 JOIN、身份复核、引用回收、迁移和前端失效必须同时正确。共享内容不共享 AI，也不持久保存所有历史正文版本；历史丢失的副本不能凭 CSV 凭空重建。索引是可重建加速，不是内容真值。

11-11后继去掉自动旧库修复及其迁移测试责任；已安装的合法外部text保留其精确字节，不保证与当前本机HTML提取算法输出相同。用户显式重新提取会创建当前版本并按原事务/守卫切换。损坏或旧格式数据库仍由新库格式门拒绝，不以后台惰性改写补救。若未来格式要求统一派生text，须作为明确的新输入/版本契约处理，不能复活原地改identity。
