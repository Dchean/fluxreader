# Agent Note: 三层AI策略与阅读触发

Status: implemented

## Problem

分区阅读模型中，选中、搜索定位、卡片进入虚拟窗口和真正打开Reader是不同动作。把AI绑定到选中态会让快速划过或J/K导航产生费用；只在Reader触发又会使没有Reader的社交/通知自动开关成为空设置。分组必须继承所属实际布局的默认，来源的显式关闭仍要压过上层开启。

本决定部分取代[AI配置继承与派生索引单点](2026-10-08-AI配置继承与派生索引单点.md)的组bool及旧输入兼容决定，保留其写入并发保护理由。用户已明确新模型不兼容旧数据，新增布局上级后“组没有上级”的旧前提不再成立。

## Decision

- `store/aiPolicy.ts`是三层纯解析核心，`selectFeedConfig`负责从实际来源装配输入。顺序为实际内容布局默认→分组mode→来源mode→布局能力。组和源均为`inherit/on/off`；旧bool列仍由后端DTO暂时携带，但不参与有效值或回显。缺mode继承，不把旧bool转换成新授权。来源覆盖了分组布局时，组的inherit仍使用该来源实际布局的默认。退订收藏走`sourceIndex`；已删除分组不伪造，继承实际布局默认；完全未知来源拒绝生成。
- 普通`app_settings`新增五个boolean，缺省均false：`articleAutoSummary`、`articleAutoTranslate`、`socialAutoTranslate`、`notificationAutoSummary`、`notificationAutoTranslate`。同步可携带这些普通行为设置，不能因此携带AI服务端点、密钥、模型提示词或产物。组写入口为`set_folder_ai_modes({id,summary?,translate?})`，每次只发改变字段，仍经既有`aiConfigWrites`队列、意图、确认态和单调读取claim；只替换实体mode适配，没有另建写协议。
- 文章实际挂载、可见、前台且正文已ready后才自动；仅保留activeArticleId不够。社交仅翻译，通知摘要和翻译，画廊/播客两种能力均关闭。手动入口也受实际对象布局能力约束，但不受auto开关约束。自动请求不调用任何标读动作。
- `useAutomaticAi`把所有卡片登记到一个控制器：只有一个列表scroll监听、一个ResizeObserver、一个rAF调度和一个停顿候选timer。卡片必须覆盖`#timelineContentScroll`可见区域的垂直中心，且连续700ms没有列表滚动；700ms是内部控费阈值，不是用户设置。挂载和水合只促使重评，不触发正文抓取，也不直接发收费请求。J/K、搜索定位本身没有特殊收费入口，定位后实际在中心停顿仍可触发。退出中心、切会话/范围、开浮层、blur/hidden、卸载、关有效开关或正文/配置换代同步撤销资格；恢复后重新计时。全体卸载时移除监听、Observer、rAF与timer。
- `startAutomaticAi(id,kind,isCurrent)`在同条目×产物的既有在途表上登记验签→条件生成整链。验签后和`api.aiSummarize/aiTranslate`最后一次await之后、真正invoke之前均复核资格。撤销仅影响尚未发出的意图；现无前端取消IPC，已开始请求继续按原生命周期结束，不承诺撤销费用。
- 保留[AI完成信号与缓存提交](2026-10-08-AI完成信号与缓存提交.md)的旧产物费用保护：已有任何产物（含无签名/过期签名）、partial或已知失败不因打开/停顿而重烧。只有无产物且无失败的新输入可自动尝试；命中或不可验证时保守不生成。内存按条目×产物保存最近一次正文/服务配置身份的尝试，当前运行期同输入不自动重试。手动继续/重新生成仍走后端权威签名和短期分段恢复，不增加持久化自动重试记录。
- 生成输入守卫与显示验签身份分开：请求代次、条目身份、CID/rev、提取身份、已保存AI配置revision保护delta/Done/安全回读；无CID时以实际HTML作见证。普通同CID/rev水合不是换代，摘要流式写入也不是译文输入变化。旧回包不能写到新正文。后端既有签名/epoch/条件提交和HTML消毒保留，前端未消毒增量继续只按文本显示。
- 请求生命周期与费用历史分工：每次run创建独有owner和本次`started`，仅最终invoke资格通过才置started；`automaticAttempts`只防后台重烧，不能作为本次是否发出的依据。尚未发送而被取消的请求完整释放自身生成/原始译文标记；同输入真实失败保留partial草稿和纯文本渲染，只有明确重试或输入失效才结束该草稿。
- 未消毒译文的owner随产物保存在`BodyEntry`或未水合视图行的内存字段，均不进入DB/IPC/备份。安全回读与水合行替换产物时解除草稿owner，即使新旧文本字节相同也不能继续沿用旧raw。`store.ts`原body-cache通知按本次changed id投影raw：缓存有owner时为raw，安全产物无owner时解除。仅明确安全译文接受事件`safeTranslation`才把曾持草稿的视图行一并转交安全值/签名/无owner，避免缓存释放后回退到旧草稿；markLoading里暂时无owner不是安全落账证据。通知不写回body-cache、不改ReadingSession或生成代次，无通知递归；新请求后续delta仍先恢复raw再原子写入自己的owner和草稿。
- 输入失效时先丢弃仍属于自己的未消毒草稿，再释放自己的标记；清理保留新正文的state及水合stamp，不能把loading/cleared改成假ready或废弃新水合。若安全产物或更新请求已接管owner，则不清其内容；旧代次的finally/回读/error也不能清较新请求的raw。摘要路径不清翻译owner。安全回读先写净化HTML，再解除raw，不暴露未消毒文本的一帧。
- 错误中心明确手动重试可针对离屏条目。当前会话无该条目时先getArticle读取当前身份和正文，再经真实sourceIndex解析能力，不将它插回会话、不更换选中。条目已不存在、来源不可解析或布局无能力时不发收费请求并给出反馈。

### 译文归属的写入与转交

| 路径 | 唯一真值与归属 | 通知/后续回退 |
| --- | --- | --- |
| 无记录prepare/delta | 视图行写草稿值+owner，raw为true | 行仅作未水合过渡 |
| 已有记录prepare/delta | BodyEntry写草稿值+owner | changed id通知投影raw，不复制普通缓存值到行 |
| markLoading/正文失效/摘要写 | 不授予安全译文身份，保原draft归属 | 仍广播bodyCacheNonce；不安全转交空loading值 |
| applyBodyRow产物NULL | 采用既有回退值，并从同一回退来源携owner | 未消毒fallback进入缓存仍是raw |
| applyBodyRow产物非NULL/安全回读 | 安全值+签名替换，draft owner解除 | 通知safeTranslation；仅曾持draft的行原子接收安全值+签名+无owner |
| 同输入真实失败 | 当前owner的partial保留 | raw纯文本，用户明确继续/重试 |
| 输入失效/未发送取消 | 仅丢自己仍持有的draft并解除自身标记 | 不改新正文state/stamp，旧gen不动新owner |
| drop/LRU | 缓存不再持有该条目；回退行若存在仍按其值+owner | 安全转交已消除旧行draft；nonce广播保留，LRU插入仍有原通知 |
| 清理/reconcile安全替换 | 产物与签名、owner同笔改变 | 同安全转交通知；摘要字段变化不夺取翻译owner |

## Alternatives considered

- 每卡独立scroll监听与停顿timer：未采用；虚拟窗口内有许多卡片时会同时读取布局并保留多笔候选。共享控制器一次只选择视觉中心的一个对象。
- 以activeArticleId、虚拟卡挂载或水合完成直接触发：未采用；这些事件不能证明用户实际阅读，快速导航会产生费用。
- 因签名过期自动重新生成：未采用；用户可能仅修改模型或返回旧文章，沿用既有费用保护，提供明确手动重新生成/继续。
- 仅靠请求代次丢弃迟到结果：不足；正文或配置改变不一定产生新请求，所以另核生成输入身份。直接复用显示状态mutation也不足；一种产物的开始会使另一种产物的验签误判过期。
- 用历史自动attempt判本次是否已发送，或只删除generating不处理raw：独审AI-A2/AI-A1已分别证明会造成未收费的取消请求永远generating、新净化译文字面显示。改为本次started与草稿owner；不靠文本相等判断所有权，相同HTML也可能已被安全水合重新接受。
- 取消已发送请求并宣称退款：无对应IPC和费用保证，不作该承诺。

## Consequences

控制费用与阅读资格有唯一入口，组/源显式on/off可覆盖布局默认；能力限制始终后置。设置页新增五个布局默认开关，组控件改三态，按组自身及所有成员实际布局的能力决定是否显示，组继承统一标“继承布局”，不伪造不同布局成员共用的开/关值；来源弹窗继承标签随目标分组及实际布局变化。社交没有摘要开关，画廊/播客没有AI开关。

自动尝试记账仅在当前运行期，不持久化失败或触发历史；应用重启后无产物、无持久片段的失败可能成为新的自动尝试。这一边界不等于后台无限重试。正文/配置更新时已经发出的旧请求仍可能由服务计费，前端只能阻止旧结果污染新输入，后端条件提交负责缓存一致性。
