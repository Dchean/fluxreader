# Agent Note: AI 完成信号与缓存提交

Status: implemented

## Problem

2026-11-09 补充：流完成、后端签名/epoch提交与HTML分段净化契约继续有效。前端生成链现在同时核对请求代次和正文/已保存服务配置身份；普通同CID/rev水合、另一种产物的流式写入不算输入换代。每笔请求的started及未消毒草稿owner与历史自动attempt分离；安全产物替换解除旧raw，失效清理只丢自己的草稿且保留新正文水合stamp。自动触发资格与重烧保护见[三层AI策略与阅读触发](2026-11-09-三层AI策略与阅读触发.md)，旧产物、partial与失败仍由明确手动动作恢复。本篇有关Gist/旧配置应用消费方的历史描述随配置同步退役工作另行承接。

最初把 HTTP 干净 EOF 当成模型完成，截断、过滤、坏帧、取消及缓存写失败都可能变成 Done。之后又发现“完整”不足以证明可复用：换模型、提示词、标题或正文后，非空旧产物仍短路请求；长文翻译失败只能整篇重来，清除与迟到写入互相竞争。本篇整合 2026-10-08 的完成语义及 2026-10-15 的签名、分段和状态消费决定，保留实际兼容例外。

## Decision

### 流完成与字节预算

`ai.rs` 的解析器以 `finish_reason:"stop"` 加正常收尾判定完成，HTTP EOF 本身不是完成信号。

| 输入 | 处理 |
| --- | --- |
| stop 后 `[DONE]` | 立即完成并释放响应，不消费同 chunk 尾随字节 |
| stop 后干净 EOF | 兼容完成，无须强制 DONE |
| DONE 先到、无 finish 的 EOF、tool_calls/未知 finish | aiIncomplete |
| length / content_filter | aiTruncated / aiFiltered |
| 重复或冲突 finish、stop 后增量、坏 JSON/UTF-8 | aiStream |
| error:null、usage 空 choices、注释与心跳 | 不改变完成语义 |
| 非 null error | 显式流错误 |
| sink 返回 false | completed=false，停止读流 |

流首 BOM 可跨 chunk，仅在流首剥除。多条 data 以 LF 拼为一个事件，只有去 EOL 后长度为零的行派发；空白行是未知字段，不能用 trim 判空。2026-11-07 补齐 LF、CR、CRLF：CR 立即结束行，紧邻 LF 即使跨 chunk 也只算同一个结束符；行预算仍计入实际 CRLF 两字节。值剥一个前导空格，无冒号 data 视为空值。EOF 仍派发单行尾事件是有意兼容偏离，不能由此称完全符合 WHATWG SSE；2026-11-06 的 CR-only 历史失败保留为修复依据。

完整行和未结束残行各限 8 MiB，事件 data（含 join LF）限 8 MiB，累计输出限 256 KiB。完整行在 drain/复制前检查，避免“超长残行 + newline”绕过。摘要/翻译请求 token 上限分别为 1024/4096；调整 token 不能修复完成判定，也不能替代本地缓冲预算。模型列表及配置/Gist 成功正文复用 16 MiB 收体上限（Content-Length 预检及累计流量两条防线）；AI/Gist 错误详情只保留 8 KiB 前缀并标明截断，不能为显示一条错误先 collect 全文。正常配置 16 MiB 边界仍接受，这些是本地资源预算而非远端服务上下文保证。

命令层取消不写缓存、不发 Done；产物提交失败必须 Err。完整缓存命中可零网络回送 delta+Done。单段空文本保留历史“无缓存但 Done”语义；多段空片段、解析后零有效节点或整篇消毒后为空则 aiIncomplete。不得把 Done 简化为任何路径都已持久化非空内容。

### 输入身份与提交条件

后端在同一短锁中读取 AI 配置与提示词快照；网络在锁外。签名以带标签和长度前缀的字段计算 SHA-256：产物种类、模型、有效 base_url、有效 system 提示词、标题、content_id/revision、输入正文哈希和分段策略版本。API key 不进入签名、DTO 或日志。签名记录生成时的输入，提交时不按新配置重算。

命中要求产物非空且签名相等，由 `ai_cache_check` 在动作时刻裁决；前端不重写提示词回退、preset 或哈希算法。旧 NULL 签名不回填为“当前有效”，内容保留并按当前状态规则标过期。产物与签名同条 UPDATE，条件复核 `ai_epoch/content_id/revision/title`，失配报 aiStale，无 Done。

每个条目×产物的前端“验签 → 条件生成”整链登记在途 Promise，自动与手动入口复用。生成请求的 delta、Done 和安全详情回读核对请求代次；清理在途表按 Promise 身份，不能由旧 finally 删除新请求。翻译回读缺行丢弃未消毒文本，摘要回读缺行保留已渲染文本。生成真值是 per-id 集合；全局 translating 的终态处理遵循[翻译全局状态复位](../bug-fix/2026-11-01-translating终态复位与全局单布尔.md)，不能从请求代次推导“旧请求不得复位任何全局兼容布尔”。

### 长文分段与恢复

当前策略为 `v3-list-boundaries-8192`，取代 v2-html-blocks-8192（更早为 v1-flat）。分段器解析 HTML，按序列化字节分组；超长元素递归拆子节点并重包标签，文本不切断 UTF-8 或实体。非规范 HTML 会先经解析器规范化，不能承诺逐字原样；锁定 scraper 的属性表为 HashMap，开标签完整属性 token 在保留 serializer 转义后排序，避免同一输入不同次 parse 的属性顺序改变实际发送片段。标签自身超预算、注释/DOCTYPE 或超过拆分深度的节点按原子保留，因而 8192 字节不是所有输入的硬上限，也不是模型绝不截断的保证。

片段以 `(article_id, product, signature, segment_index)` 持久化，同序号 UPSERT，失败重试只补缺失段。全部完成后拼接并消毒，再经带条件的整篇提交；成功后的旧签名片段清理为 best-effort，失败不能把已提交成功倒挂成 Err。条目删除级联回收片段，清除删除相应产物的全部签名片段。策略/预算/边界变化必须更换策略版本，防止新策略复用旧序列。

分段保留配对标签，不等于保持所有 HTML 语义。2026-11-06 的 echo 服务与浏览器 AX 实测表明，v2 一份连续有序列表被拆成多个 ol 后编号从 1/2/3 变成 1/1/1。v3 在源 DOM 分段时留下边界双方共同源 NodeId 路径，最终只重合被证实属于同一源节点的克隆壳，同 li 跨段重合为同一项目，原本独立的相邻 ol 不合并。计划每次从同源正文确定重建，不进入数据库 schema。模型仍收到自包含 HTML，不依赖它回传内部标记或额外收费调用。

片段净化后按源片段的列表树校验项目数/层级，并恢复 start/reversed/type/li[value]；写入、整篇再净化、get_article 读回都沿同一白名单。列表项目内部的段落、强调等普通排版允许改变；必要的边界壳或列表树失配返回 aiStructure，不发 Done、不存失败片段，先前有效 partial 留存可继续。此校验拒绝结构损坏，不保证模型翻译文字正确。policy 进共享签名，旧 v2 片段只计 discarded，不与 v3 混用；旧摘要签名也保守失效，产物保留显示、动作时验签，不能自行触发额外模型费用。

摘要输入超过 64 KiB 时 aiTooLong，零请求、不截断；这是本地预算，不保证适配任意模型上下文。翻译续译只流式显示本次新段，旧段不重放，Done 后回读整篇。校验响应附带 total/completed/discarded；有可续段就说明继续位置，全部段已在则说明直接提交，不能共用“整篇重新翻译”文案。

### 显示、清除与边界

`selectAiProductState` 统一生成中、完整、已过期、部分完成、失败及无状态；优先级为 generating → 经验证 complete → stale → partial → failed。原始流式半截不进入 HTML 渲染。Reader 与卡片消费同一选择器，重试/继续用同一生成命令，清除成功才清前端并切回原文，失败保留内容并报错。

单条 `ai_clear_cache` 在事务内清产物/签名、删除该产物全部片段并推进条目级 `ai_epoch`；片段写入也核对 expected_epoch。共享 epoch 会使同条目另一产物的在途提交一并失效，这是已接受的保守代价。2026-11-06 证实“只有片段、没有整篇产物”的年龄清理曾漏推进 epoch，旧 token 可写回；本轮在同一清理事务内让 EXISTS ai_segments 的适龄条目也推进 epoch，再删除片段，迟到片段与整篇都受同一屏障。清理回执按实际受影响文章数计，年轻兄弟条目与没有缓存的老条目不因本修复推进。

`aiStatusById` 由动作校验、生成计划和显示时惰性校验填充，避免每张卡片挂载都扫描整篇 HTML。2026-11-06旧complete留存/迟到partial反例保留；前端本轮给status.input绑定正文CID/rev、snippet/URL/anchor及旧后端/提取HTML兼容见证、已保存AI配置revision和显式产物mutation。check/hint/refresh落地均核输入与latest read serial，terminal强制新读而不复用早读；同输入的动作决策不因显示读接管而被取消。生成代次、输入身份和只读校验序号分工各自闭合。

`api.saveAiConfig`、配置应用和AI批清成功点经唯一store callback推进配置/缓存revision，失败不推进。Reader与虚拟窗口内已水合卡片的ensure仅做只读验证；只有片段也能显示partial并继续/清除，不额外调用收费模型。校验失败保留旧显示，不自动重烧token；旧产物不会仅因打开文章就自动重生成。2026-11-07 收口：前端链路与后端AB分别由独立审计关闭（`tmp/repair-2026-11-06/audit-frontend/player-ai/report.md`、`tmp/repair-2026-11-06/audit-backend/data-ab/report.md`）；本行原“仍待验”仅描述记录时点，两者范围不同、结论不互替的分工表述保留。

## Alternatives considered

- **EOF 即完成 / 强制必须 DONE**：前者把中断当成功，后者拒绝 stop 后直接关流的兼容端点；采用 stop 且正常收尾。DONE 没有 finish 也不够。
- **逐行 JSON、静默坏行、trim 判空或值保留 EOL**：会丢多 data 语义、吞坏内容或重复计算 LF；按事件处理并严格报错。
- **DONE 后继续等 EOF 并拒绝尾随**：keep-alive 会挂到超时；立即停止消费已满足不拼接尾随内容。
- **每行剥 BOM、按 provider 猜宽松模式**：BOM 只属于流首，URL 不能可靠识别实现；只为明确的兼容形态设统一规则。
- **调大 max_tokens/取消预算、增加不完整事件类型**：前者不修正确性并扩大失控成本，后者重复既有 invoke rejection 的失败通道。
- **前端算签名或 DTO 携带当前期望签名**：需要复制后端输入解析，且返回后配置仍可改变；动作时刻后端裁决更集中。
- **所有命中都调用生成命令 / 提交时重算签名**：前者会反复清空并重放已有内容，后者可能给旧输入产物记上新配置身份，均未选。
- **按字节硬切或只按顶层 block 切**：前者破坏标签/实体，后者处理不了超长单节点；递归重包只是选定策略，不证明列表、表格等全部语义等价。
- **合并所有相邻 ol / 只补 start 属性**：前者误合原文有意分开的列表，后者不能处理同 li 跨段；只沿源 DOM 已知共同边界重合，并保留列表编号属性。
- **要求模型严格复刻整棵 HTML 树**：正常翻译可能调整段落与强调，没必要因此失败；只约束列表项目/层级和重组所需壳，属性语义由可信源恢复。
- **分段摘要再合并**：引入二次调用、去重与矛盾合并口径，个人客户端当前选择明确拒绝超预算输入。
- **新建进度事件/IPC / 回放旧片段 delta**：已有校验命令能承载计划，旧段回放会重复打字机内容；复用响应和最终回读。
- **每张卡片立即验签 / 仅缺签名判过期**：前者形成滚动 IPC 成本，后者识别不了有签名但已失效的产物；采用惰性校验，并承认其失效窗口需补齐。
- **清除只清前端或只删当刻片段**：重启或在途迟到写会复活；清除代次是必要条件，批量片段-only遗漏本次以同事务 epoch 推进修复。

## Consequences

严格完成条件避免把多种失败写成完整缓存，分段降低重复生成成本，但增加请求次数、延迟和状态维护面。产物持久化、前端校验缓存、内容身份与清除代次是不同层，单层通过不能推导全链路可用。已确认剩余问题统一在[AI 与内容路线](../../../../docs/roadmap.md#ai-and-content)。
