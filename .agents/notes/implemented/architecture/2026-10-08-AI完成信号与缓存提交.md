# Agent Note: AI 完成信号与缓存提交

Status: implemented

## Problem

最初把 HTTP 干净 EOF 当成模型完成，截断、过滤、坏帧、取消及缓存写失败都可能变成 Done。之后又发现“完整”不足以证明可复用：换模型、提示词、标题或正文后，非空旧产物仍短路请求；长文翻译失败只能整篇重来，清除与迟到写入互相竞争。本篇整合 2026-10-08 的完成语义及 2026-10-15 的签名、分段和状态消费决定，保留实际兼容例外。

## Decision

### 流完成与字节预算

`ai.rs` 的解析器以 `finish_reason:"stop"` 加正常收尾判定完成，HTTP EOF 本身不是完成信号。

| 输入 | 处理 |
| --- | --- |
| stop 后 `[DONE]` | 立即完成并释放响应，不消费同 chunk 尾随字节 |
| stop 后干净 EOF | 兼容完成，无须强制 DONE |
| DONE 先到、无 finish 的 EOF、tool_calls/未知 finish | aiIncomplete |
| length / content_filter | aiTruncated / aiFiltered |
| 重复或冲突 finish、stop 后增量、坏 JSON/UTF-8 | aiStream |
| error:null、usage 空 choices、注释与心跳 | 不改变完成语义 |
| 非 null error | 显式流错误 |
| sink 返回 false | completed=false，停止读流 |

流首 BOM 可跨 chunk，仅在流首剥除。多条 data 以 LF 拼为一个事件，只有去 EOL 后长度为零的行派发；空白行是未知字段，不能用 trim 判空。LF/CRLF 支持，值剥一个前导空格，无冒号 data 视为空值。EOF 仍派发单行尾事件是有意兼容偏离，不能由此称完全符合 WHATWG SSE：2026-11-06 实测标准允许的 CR-only 行结束符失败，见[AI 与内容路线](../../../../docs/roadmap.md#ai-and-content)。

完整行和未结束残行各限 8 MiB，事件 data（含 join LF）限 8 MiB，累计输出限 256 KiB。完整行在 drain/复制前检查，避免“超长残行 + newline”绕过。摘要/翻译请求 token 上限分别为 1024/4096；调整 token 不能修复完成判定，也不能替代本地缓冲预算。上述流预算不覆盖所有 HTTP 错误正文读取，后者仍有已确认的无界读取缺口。

命令层取消不写缓存、不发 Done；产物提交失败必须 Err。完整缓存命中可零网络回送 delta+Done。单段空文本保留历史“无缓存但 Done”语义；多段空片段、解析后零有效节点或整篇消毒后为空则 aiIncomplete。不得把 Done 简化为任何路径都已持久化非空内容。

### 输入身份与提交条件

后端在同一短锁中读取 AI 配置与提示词快照；网络在锁外。签名以带标签和长度前缀的字段计算 SHA-256：产物种类、模型、有效 base_url、有效 system 提示词、标题、content_id/revision、输入正文哈希和分段策略版本。API key 不进入签名、DTO 或日志。签名记录生成时的输入，提交时不按新配置重算。

命中要求产物非空且签名相等，由 `ai_cache_check` 在动作时刻裁决；前端不重写提示词回退、preset 或哈希算法。旧 NULL 签名不回填为“当前有效”，内容保留并按当前状态规则标过期。产物与签名同条 UPDATE，条件复核 `ai_epoch/content_id/revision/title`，失配报 aiStale，无 Done。

每个条目×产物的前端“验签 → 条件生成”整链登记在途 Promise，自动与手动入口复用。生成请求的 delta、Done 和安全详情回读核对请求代次；清理在途表按 Promise 身份，不能由旧 finally 删除新请求。翻译回读缺行丢弃未消毒文本，摘要回读缺行保留已渲染文本。生成真值是 per-id 集合；全局 translating 的终态处理遵循[翻译全局状态复位](../bug-fix/2026-11-01-translating终态复位与全局单布尔.md)，不能从请求代次推导“旧请求不得复位任何全局兼容布尔”。

### 长文分段与恢复

当前策略为 `v2-html-blocks-8192`，取代 v1-flat。分段器解析 HTML，按序列化字节分组；超长元素递归拆子节点并重包标签，文本不切断 UTF-8 或实体。非规范 HTML 会先经解析器规范化，不能承诺逐字原样。标签自身超预算、注释/DOCTYPE 或超过拆分深度的节点按原子保留，因而 8192 字节不是所有输入的硬上限，也不是模型绝不截断的保证。

片段以 `(article_id, product, signature, segment_index)` 持久化，同序号 UPSERT，失败重试只补缺失段。全部完成后拼接并消毒，再经带条件的整篇提交；成功后的旧签名片段清理为 best-effort，失败不能把已提交成功倒挂成 Err。条目删除级联回收片段，清除删除相应产物的全部签名片段。策略/预算/边界变化必须更换策略版本，防止新策略复用旧序列。

分段保留配对标签，不等于保持所有 HTML 语义。2026-11-06 的 echo 服务与浏览器 AX 实测表明，一份连续有序列表被拆成多个 ol 后编号从 1/2/3 变成 1/1/1；后续方案需同时覆盖片段消毒、拼接消毒和读取消毒，尚未实施。

摘要输入超过 64 KiB 时 aiTooLong，零请求、不截断；这是本地预算，不保证适配任意模型上下文。翻译续译只流式显示本次新段，旧段不重放，Done 后回读整篇。校验响应附带 total/completed/discarded；有可续段就说明继续位置，全部段已在则说明直接提交，不能共用“整篇重新翻译”文案。

### 显示、清除与边界

`selectAiProductState` 统一生成中、完整、已过期、部分完成、失败及无状态；优先级为 generating → 经验证 complete → stale → partial → failed。原始流式半截不进入 HTML 渲染。Reader 与卡片消费同一选择器，重试/继续用同一生成命令，清除成功才清前端并切回原文，失败保留内容并报错。

单条 `ai_clear_cache` 在事务内清产物/签名、删除该产物全部片段并推进条目级 `ai_epoch`；片段写入也核对 expected_epoch。共享 epoch 会使同条目另一产物的在途提交一并失效，这是已接受的保守代价。全局按年龄清理不能被视为等价保证：2026-11-06 证实“只有片段、没有整篇产物”的条目清理未推进 epoch，旧 token 可写回。

`aiStatusById` 由动作校验、生成计划和显示时惰性校验填充，避免每张卡片挂载都扫描整篇 HTML。校验失败保留旧显示，不自动重烧 token；旧产物不会仅因打开文章就自动重生成。不过缓存并未完全绑定输入/清除代次：实测内容变化后旧 complete 留存、清除后迟到校验恢复 partial。生成请求代次不能替代校验请求代次，这些是待修缺陷而非已接受保证。

## Alternatives considered

- **EOF 即完成 / 强制必须 DONE**：前者把中断当成功，后者拒绝 stop 后直接关流的兼容端点；采用 stop 且正常收尾。DONE 没有 finish 也不够。
- **逐行 JSON、静默坏行、trim 判空或值保留 EOL**：会丢多 data 语义、吞坏内容或重复计算 LF；按事件处理并严格报错。
- **DONE 后继续等 EOF 并拒绝尾随**：keep-alive 会挂到超时；立即停止消费已满足不拼接尾随内容。
- **每行剥 BOM、按 provider 猜宽松模式**：BOM 只属于流首，URL 不能可靠识别实现；只为明确的兼容形态设统一规则。
- **调大 max_tokens/取消预算、增加不完整事件类型**：前者不修正确性并扩大失控成本，后者重复既有 invoke rejection 的失败通道。
- **前端算签名或 DTO 携带当前期望签名**：需要复制后端输入解析，且返回后配置仍可改变；动作时刻后端裁决更集中。
- **所有命中都调用生成命令 / 提交时重算签名**：前者会反复清空并重放已有内容，后者可能给旧输入产物记上新配置身份，均未选。
- **按字节硬切或只按顶层 block 切**：前者破坏标签/实体，后者处理不了超长单节点；递归重包只是选定策略，不证明列表、表格等全部语义等价。
- **分段摘要再合并**：引入二次调用、去重与矛盾合并口径，个人客户端当前选择明确拒绝超预算输入。
- **新建进度事件/IPC / 回放旧片段 delta**：已有校验命令能承载计划，旧段回放会重复打字机内容；复用响应和最终回读。
- **每张卡片立即验签 / 仅缺签名判过期**：前者形成滚动 IPC 成本，后者识别不了有签名但已失效的产物；采用惰性校验，并承认其失效窗口需补齐。
- **清除只清前端或只删当刻片段**：重启或在途迟到写会复活；清除代次是必要条件，批量清理的遗漏仍需修复。

## Consequences

严格完成条件避免把多种失败写成完整缓存，分段降低重复生成成本，但增加请求次数、延迟和状态维护面。产物持久化、前端校验缓存、内容身份与清除代次是不同层，单层通过不能推导全链路可用。已确认剩余问题统一在[AI 与内容路线](../../../../docs/roadmap.md#ai-and-content)。

## Verification

历史验证包括真实 loopback SSE、keep-alive、跨 chunk、BOM、多 data、预算边界，DB 触发器失败与真实 Channel、签名变化和分段恢复；这些提供对应输入的证据，不证明任意 provider 或 HTML。2026-11-06 基线 `91ece562` 的 CR-only、批量清除、校验迟到和有序列表反例限定了原先过宽的结论。完整阶段理由、早期标签及用例定位见[整理前记录](https://github.com/Dchean/fluxreader/blob/91ece562d79fd909642cd6d570d636e884b7387e/.agents/notes/implemented/architecture/2026-10-08-AI完成信号与缓存提交.md)。
