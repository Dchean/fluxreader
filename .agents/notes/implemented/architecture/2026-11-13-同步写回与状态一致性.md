# Agent Note: 同步写回与状态一致性

Status: implemented

## Problem

RSS 服务双向同步里，“本地已保存”“远端已接受”“远端已确认”是三件事，却很容易被压成一件：把 HTTP 200 当成功、把集合缺字段当空集、把换号当暂停、把广播副本的主目标确认当全组确认。结果不是多一次重试，而是本地意图被静默删除、旧账号的墓碑压制新账号、或游标越过未知窗口。本篇合并 2026-09-18 至 2026-11-05 的写回接线、事务、失败关闭、ACK 验证与过期恢复决定，给出仍约束当前代码的同一组边界。

## Decision

- **本地先提交，远端后确认。** 本地变更、墓碑与类型化订阅 outbox 在同一事务写入；生产命令不等待网络成功。墓碑表示“本地有意不存在”，outbox 表示“远端仍需完成动作”，二者不能互当确认。退订响应被接受也不直接清墓碑，pull 以完整远端列表确认 URL 不存在后才回收。（原 2026-09-18 bug-fix/2026-09-18-双向同步的写入接线与墓碑.md）
- **状态、字段版本与队列同事务，操作身份不可复用。** 读/藏值、对应字段版本和队项在同一事务完成；批量全有全无。`sync_queue.id` 使用 AUTOINCREMENT 风格的持久身份，用户删旧插新后旧推送确认不能误删新意图。是否配置凭据不决定是否保存本地意图；无身份项按队列生命周期分类，过期保留而非物理删除。（原 2026-09-18 bug-fix/2026-09-18-状态写入事务化与对账守卫.md；后继写预留见[多连接 SQLite 写预留](2026-11-09-多连接SQLite写预留与原子设置.md)）
- **pull 在任何 HTTP 前捕获 read/star 版本。** 合并逐字段要求版本仍匹配且该字段无 pending；读与收藏互不连坐。HTTP 期间新出现的既有行也过守卫；重建匹配映射不重定义旧快照，缺失基线保守补 0，不能拿网络之后的版本当请求之前的版本。
- **集合缺失不等于空集。** GReader 的 `subscriptions`/`itemRefs`/`items`（及 `tag/list.tags`）与 Fever 的 `feeds`/`groups`/`feeds_groups` 按 action 必填；缺失、null、非法 ID/continuation、未完成分页都是 protocol 错误并保留游标；显式 `[]` 才是权威空集。条目级状态字段是 Missing/false/true 三态：Missing 只允许回填内容，不改本地读藏。绑定不完整时 Content 与 State 共用的准入在首个条目/权威 HTTP 前阻断，不推游标。（原 2026-10-19 bug-fix/2026-10-19-同步集合失败关闭.md）
- **写成功只进入“待读回确认”，不直接出队。** GReader `stream/items/contents` 与 Fever `items&with_ids` 必须覆盖全部请求 ID；重复/无关条目不能凑数。只有目标存在且状态等于 desired 才 `done` 并出队；空/短/缺字段/非法 body 一律 `retry_wait/verification`。当前读回端点没有“目标已删除”的权威信号，未知不能升级为终态 `target_missing`；同一 states 轮只发送一次已尝试项。（原 2026-11-03 bug-fix/2026-11-03-状态写回ACK验证与条目三态.md）
- **源内等价组逐成员结算。** 2026-11-09 取消跨源读广播后，每个真实成员有自己的队项与精确远端目标，逐目标读回确认；一个成员缺失/未知/不一致只保留它自己的意图，其他成员 ACK 不替它结算。历史“主目标确认即出队”只适用于已不存在的广播副本。（同源 2026-11-03 后继）
- **权威集合按字段独立失败。** GR 完整 unread/starred 集合、Fever unread/saved 对：成功侧照常对账，失败侧单独记错；失败不走空集删除。GR 读对账使用完整 unread 差分，不下载历史 read 全集；已有未读消失候选仍经 contents 确认目标存在。Fever 要求 unread/saved 成对成功，失败时不改已绑定 flags，正文页也不能代替 State。
- **GR 回补与来源证明。** 每次 pull 每集合最多 2000 个唯一 ID 回补缺身份/正文，100/请求、批内并发至多 3；按数值 ID 与账号代际持久轮转，只有整批请求与合并成功才保存进度。空正文/缺 feed 占预算防头部饥饿。可推送身份要求精确 `remote_id` + 真实 Content 响应的 `remote_origin_feed_id` + 当前有效来源；裸 ID 不算。冷绑定另有来源补证预算，已证明绑定的状态变化不新增 origin 请求。（原 2026-10-31 bug-fix/2026-10-31-GR回补与拉取侧身份与性能修复.md、2026-11-05 bug-fix/2026-11-05-GR权威集合回补与过期意图恢复.md）
- **过期不等于删除，恢复只认当前目标。** 无身份项超过 30 天转 `expired_unconfirmed`，队项与本地读藏保留；显式恢复在同一 DB 锁内复核 `account_generation`，按文章当前 read/star 重建，来源已证明的绑定项转 pending，缺文章仍过期；每次新建操作 ID，重复点击为 no-op。断开/换号放弃旧状态队列，本地直连读藏保留但不会自动迁入新账号。（原 2026-11-05 后继；生命周期见[同步队列生命周期](2026-11-03-同步队列生命周期与本地意图.md)）
- **断开身份见证与订阅 outbox 生命周期。** `commit_disconnect` 把断开账号指纹明文写入受保护设置；断开后连接不同账号才清 feed 墓碑，重连同身份保留。分类墓碑按 key 隔离，不顺手统一清理。换号/换用户名重连在同一事务内删除旧账号 outbox 行；同身份重连保留；断开本身不清账。跨账号入队屏障与执行代际守卫是另外两层，不能互相替代。（原 2026-11-01 bug-fix/2026-11-01-断开重连墓碑身份见证.md、2026-11-02 bug-fix/2026-11-02-订阅outbox生命周期终点.md）
- **事件按真实变化产生。** 同值 UPDATE、处理行数、守卫通过都不等于数据变化；绑定、条件状态写或正文变更成功后才置位，且早于后续可失败读取。Fever 页回滚还原页内标记；GR 已提交变化不能因后续失败丢信号。（原 2026-09-18 状态事务篇）

## Alternatives considered

- 远端成功后再允许本地删除：离线用户无法操作，且下一轮 pull 会重建已删源，否决。
- 只按 payload/action/时间确认：read→unread→read 目标相同，时钟精度不是操作身份；按操作 ID 才能区分，否决。
- 缺字段当空集只记日志：日志无法撤销已执行的删除/清状态，协议字段缺失必须与显式空集分开，否决。
- 相信 200/OK 只在 UI 提示“可能未生效”：不能阻止出队删除最后的本地意图，确认必须发生在出队之前，否决。
- 换号保留旧 outbox 等“回原账号恢复”：对永不回来的账号只是永久表污染；同身份重连已覆盖可恢复场景，否决。
- 断开即清账：会把网络排障升级成写回意图全丢，超出范围，否决。

## Consequences

- 本地成功不等于远端完成；网络长期不可用时意图与墓碑保留是恢复条件，也是持续占库空间的代价。
- 回补需要多轮，真实空正文仍可能持续回访；已读未收藏旧文仍需 full 同步；远端已删除的历史正文无法补造。
- 读回多一次只读请求；读回端点不可用时队项停在 `retry_wait`，需要服务端/网络恢复后再次同步；协议无法证明目标已删除时不会自动进入永久终态。
- 绑定不完整时条目/状态同步暂时停顿，以短暂延迟换“不把游标推过未知窗口”。
- 本篇的协议结构覆盖使用 HTTP 夹具与受控本地库，不代替真实 Miniflux/FreshRSS 部署与原生链验证；当前缺口见[路线图](../../../../docs/roadmap.md#sync-correctness)。
