# Agent Note: AI 配置继承与派生索引单点

Status: implemented

## Problem

审计 F13（OPT-011）指出同一族缺口：**AI 自动开关在「分类默认 / 源覆盖 / 运行消费」三段之间没有一条真值链，开关看起来切换了但不真正生效，且输入范围前后端不一致。**

1. **分类开关是死设置。** `folders.auto_summary/auto_translate` 在设置页可切换、能落库，但运行时没有任何消费者——`selectFeedConfig` 只读源自己的 bool。打开分类开关后，其下订阅源的自动摘要/翻译一行都不会变。
2. **源只有二元 bool，表达不了「继承 / 显式关闭」。** 用户无法在「分类开」的前提下对个别源明确关闭（也不存在继承语义）；升级三态时若直接把旧 `false` 当「未设置」，原本关闭的源会在分类开启后开始消耗付费 AI。
3. **切换不生效（旧索引）。** `toggleFeedSummary/Translate`、`toggleCatSummary/Translate` 只 `set({ categories })`，不重建 `feedIndex`——`selectFeedConfig` 读的是 `feedIndex` 里的旧 feed/cat 对象，消费者当帧看到的仍是旧配置；设置页归设置页、Reader/卡片归 Reader/卡片。
4. **Reader 自动请求不订阅有效配置。** 自动请求 effect 只随「文章 id / 水合完成」重跑；期间有效开关被关闭，尚未发起的请求不会被阻止。
5. **refreshInterval 双口径。** 前端校验/滑杆是 5–120，Rust scheduler 读 5–720（`as_i64`），且前端 `inRange` 接受小数——小数能写进 `app_settings`，Rust 读不到整数就静默回默认 30，UI 与运行值分叉。
6. **配置快照不带三态。** `config_sync` 的 `FeedSpec` 只有旧 bool：上传丢失三态信息，导入忽略 mode（未来 OPT-010 的镜像应用会以本卡契约为基础）。

## Decision

**一、三态真值 + 唯一 resolver（前端）。**

- `FeedAiMode = 'inherit' | 'on' | 'off'`；`FeedItem` 增 `summaryMode / translateMode`（真值），旧 `autoSummary / autoTranslate` 降级为**兼容输入**（仅缺 mode 的旧行/旧 mock/schema1 快照按 bool 映射显式 on/off，`normalizeFeedAiMode` 单点归一，绝不悄悄回 `inherit`）。
- `resolveFeedAiMode(mode, categoryDefault) = mode==='on' || (mode==='inherit' && categoryDefault)`：显式关闭压过分类开启，**不以 OR 合并**。
- 运行时唯一 resolver 是 `selectFeedConfig`（store/selectors.ts）：返回有效布尔 + 模式原值；Reader/Timeline/卡片/设置页全部经它消费，任何组件不得直读源上旧 bool。

**二、Rust：v21 三态列 + 兼容写入口（mode 真值，bool 镜像不分叉）。**

- 追加迁移 v21：`feeds.summary_mode / translate_mode TEXT NOT NULL DEFAULT 'inherit'`（SQL CHECK 只允 inherit/on/off）；旧行由原 bool 回填 on/off——升级后每行语义与升级前逐字一致，不增加意外 AI 调用；新行缺省 inherit。**不改 v20 的 read/star 版本列与任何同步字段。**
- 旧 bool 兼容列保留，镜像是 mode 的**纯函数**（仅显式 on 镜像 1；inherit 镜像 0——降级读旧库的旧客户端绝不会因继承态而突然烧 AI），任何写入后两列不可能分叉。
- 合并规则单点在 `db::update_feed_full`：显式 mode 优先；只给旧 bool 时映射显式 on/off；两者皆缺该字段不动；非法 mode 串 `FeedAiMode::parse` 拒绝（不悄悄回默认）。
- 入口：`insert_feed_origin_modes`（add_feed/配置导入）、`set_feed_ai_modes`（新 IPC `set_feed_ai_modes` 与 update_feed 的可选 mode 参数）、`set_feed_ai_flags` 旧入口继续存在但**写显式 on/off 到三态列**；`FeedRow` 序列化携带两个 mode 字段（fixture 契约同步）。

**三、前端原子索引更新 + 单字段 patch + per-键串行；失败恢复/快照对账移交新协议。**

- `applyFeedAiModePatch / applyCategoryAiFlagPatch`（internals.ts）经 `reconcileCategories` 在**同一 setState** 更新 categories 与 feedIndex——消费者当帧看到同一配置；四个源/分类 AI 写入口（`toggleFeedSummary/Translate`、`toggleCatSummary/Translate`）统一经 `store/aiConfigWrites::issueAiWrite` 这一份实现，不搞第二份。
- **单字段 patch**（独立 review 修复）：写入只携带被改字段——分类走 `set_folder_ai_flags` 的 Option 参数（缺省字段 `COALESCE` 不动），源走 `set_feed_ai_modes` 的单字段参数。旧整对写要求调用方快照「另一字段的现值」随行（toggleCatSummary 快照 translate、反向亦然），A(true,false) 迟到于 B(true,true) 时会把 B 的新写入用旧值回退；单字段 patch 后两字段独立落库，乱序到达也不互相覆盖。IPC 旧 full 调用（两字段都给）语义不变；`db::set_folder_ai_flags` 整对入口保留给配置导入/旧 caller。
- **per-键 wire 队列**：同键请求严格串行（后一笔等前一笔落定才发出），不同键（同一分类/源的 summary 与 translate）各自独立、互不阻塞——同字段快速连点也不会成功乱序到达；乐观更新仍在调用点同步落地，UI 不受队列延迟影响。队列现由 `aiConfigWrites` 协议持有。
- **失败恢复与异步配置读取的新鲜度契约**：由《AI配置写入与快照对账》接管（待写意图 / 确认态 / 读取凭据三态分离；失败恢复到最近可确认值；读取快照接受时保留未落定意图、过时读取不得回退期间成功写入）。此前 R2「确认基线链」与 R3「接受点重定基线」是该协议的雏形，已被取代——相关反例（连续失败、pending→bootstrap→reject、旧读取晚到覆盖成功写入、刷新期间新点击被快照吞掉）全部收敛进协议回归。
- **实际写入口全部接入协议（R5）**：四个快捷开关之外，`editFeed` 含 AI 更改时是一笔**多键操作**（`issueAiMultiWrite`：只登记被改 AI 字段、完整 `update_feed` 只发一次、不拆事务/不丢标题分类布局/不回显未改变字段），请求排在涉及键队列尾之后（同域有序）；配置应用/上传经 `runConfigApplyBarrier / awaitAiWriteFrontier` 与协议对账（组件经 `store.ts` 公开面消费，见该篇）。新建（addFeed）/删除入口不写既有 AI 键（新建源 id 在写后由后端分配、删除只移除实体），无需进入写序——删除后的旧回包由接受点脱链与实体缺失 no-op 兜底。

**四、Reader 自动请求订阅有效配置；取消政策如实。**

- effect 依赖加入 `config.autoSummary / config.autoTranslate`：切换继承/显式/分类默认立即重评——关闭阻止尚未发起的自动请求；开启时为当前打开文章触发一次；已有生成态（`summarizingIds / translatingIds / translating`）时防重复发起。
- **已在途的请求不取消**：内容已出网，不声称可撤销（三态控件 tooltip 明示「关闭只阻止尚未发起的自动请求，已发送的请求不会撤销」）。

**五、分类默认保持 bool，源三态独立摘要/翻译。**

分类是默认源、无上级，bool 足够（默认 false）；摘要与翻译各自独立三态。

**六、config payload 兼容（不做镜像应用，留给 OPT-010）。**

- `FeedSpec` 增可选 `summary_mode / translate_mode`（serde default）：导出携带三态 + 旧 bool（旧客户端兼容输入）；导入 mode 优先、非法拒绝整包回滚，缺 mode 按旧 bool 映射显式 on/off；变化判定含 mode（只改 mode 也计 updated，重复应用幂等）。schema 版本与镜像/稳定 ID 契约留给 OPT-010。

**七、refreshInterval 统一 5–720 整数（双侧同口径，含配置导入）。**

- 前端 `settingsValidation` 用 `inIntRange`（区间 + `Number.isInteger`），GeneralTab 滑杆 max 120→720；Rust `read_refresh_interval` 单点：JSON 整数与整数值小数（300.0）等价接受，非整数（30.5）与越界拒绝回落默认——「客户端收下小数、Rust 静默回默认」的分叉不再可能。
- **配置导入同口径（独立 review 修复）**：`config_sync::merge_app_settings` 先经 `validated_remote_refresh_interval` 校验远端 `app_settings.refreshInterval`——存在时必须是 5–720 整数（30.0 数值等价，**归一为整数写回**）；30.5 / 4 / 721 / 字符串 / null 一律 `validate` Err，由 `apply_payload` 的事务整体回滚：本地 settings 与 feeds 逐字原样，绝不静默把非法值写进本地（修前 30.5 原样落库会造成 DB=30.5 / UI 保留旧值 / Rust 回默认的三方分叉，且不能把正确性托付给 UI 忽略）。远端缺该键走既有「白名单键远端缺失 → 本地删除」语义，不在此校验范围。

## Alternatives considered

- **nullable override（NULL=继承）+ 分类 bool 计算。** 否决：NULL 与「未设置」的语义混入列可空性，显式 off 与缺失难区分、CHECK 也表达不了；独立 TEXT 三态列直白且能锁值。
- **分类也升三态。** 否决：分类是默认源、没有上级，「继承」在分类上无意义；多一个恒不使用状态只会扩大解析面。
- **把解析结果物化到 FeedItem.autoSummary（行上直接存有效值）。** 否决：分类开关一变就得重写所有继承源的行——又造出一个可漂移真值源；resolver 留在 selector 才能保证「一处解析、全处一致」。
- **Reader 关闭时主动取消在途请求（Abort/版本号丢弃响应）。** 否决：请求已发送、内容已出网，取消只是本地丢弃，「可撤销」是虚假承诺；明确政策是不取消、不补发、不重复。
- **失败只 toast 不回滚（现状）或无条件回滚。** 否决两者：前者让卡片与库不一致；后者在连点/竞态时会踩掉更晚的成功写入——采用 per-键序号的条件回滚。
- **失败回滚到「本笔乐观前值」（R1 形态）。** 否决：该值可能是另一笔未落定的乐观值——连续失败会停在从未持久化的中间态（false/off→on→off 两笔均失败停在 on）；正确做法由《AI配置写入与快照对账》承担：失败恢复到最近可确认值（连续失败不留在中间乐观值）。
- **接受点清空 per-键队列，或让旧失败静默跳过/无条件恢复。** 否决：清空队列会让同键旧请求与新点击并行、乱序到达（wire 顺序破坏）；静默跳过丢失失败语义；无条件恢复会覆盖更新意图——正解是队列原样保留 + 待写意图/确认态/读取凭据分离（见《AI配置写入与快照对账》）。
- **编辑直连 update_feed、配置应用直连 apply、上传直连取快照（R5 前形态）。** 否决：全部成功也可能出错——A(off) 已提交未回包、B(on) 已排队时，编辑 C(off) 直连先发并成功，随后旧排队 B 才发出把后端覆盖成 on（用户最后意图丢失）；A(on) 迟到成功回包也会把编辑并回读后的 UI 改回 on。正解：编辑作为一笔多键操作进同一 per-键队列（请求只发一次），配置应用走受控写屏障、上传先等发起时写前沿（见《AI配置写入与快照对账》）。
- **v21 把旧 bool=false 回填 inherit。** 否决：分类默认开时，原本关闭的源升级后会开始自动生成（付费 AI 意外调用），违背「迁移不改变既有语义」。
- **只放宽前端到 720、Rust 不动。** 否决：小数会在 UI 看似生效而 Rust 回默认——统一区间的同时必须统一整数口径，否则「一致」不成立。
- **config 快照 schema 直接升 2。** 否决：可选字段向后兼容，老客户端忽略新字段即可；版本演进与镜像契约属于 OPT-010，本卡只提供 mode 序列化契约。

## Consequences

- 分类开关不再是死设置：`inherit` 源当帧跟随分类默认；显式 on/off 永远压过分类（可关闭）。
- 切换源/分类 AI 值后 categories 与 feedIndex 同帧一致，Reader/卡片/设置页看到同一配置；并发写不互相踩、连续失败不留在中间乐观值、旧读取不回退成功写入、刷新期间的新意图不被快照吞掉——协议细节见《AI配置写入与快照对账》。
- 升级安全：旧行显式 on/off、新源缺省 inherit（分类默认 false）、bool 镜像对 inherit 保守为 0——任何路径都不会把原关闭的源推向付费 AI。
- 配置快照往返携带三态；旧 schema1 快照导入仍可合并，非法 mode 与非法 refreshInterval（含 30.5）整包失败不留半套，合法小数（30.0）归一为整数。
- 分类/源 AI 写入只带被改字段且 per-键串行：两字段并发乱序不互相覆盖，同字段快速连点按点击顺序到达；失败恢复与读取快照对账由《AI配置写入与快照对账》协议统一收口（恢复到最近可确认值；快照接受保留未落定意图；刷新不清空队列，窗口内新点击照常排在在途请求之后）。
- 代价一：feeds 表多两列 + 旧 bool 列继续维护（镜像写），由单一纯函数规则保证不分叉。
- 代价二：连点同键写时，旧失败不回滚但会给出「较新的修改已生效」提示——有意为之（最终以更晚写入为准）；协议状态（确认态/队列）按会话存活、意图随落定出列——用于读取-写入新鲜度比较，空闲期检测到外部替换的自愈见《AI配置写入与快照对账》。
- 代价三：`insert_feed/update_feed` 旧 bool 入口语义固定为「显式」（不引入 inherit）；新 UI 新增路径必须显式传 mode 才能得到继承默认。
- 后续：OPT-010 的镜像/稳定 ID 契约以本卡 mode 序列化与 resolver 为准；`FeedRow` 契约由 `row_fixture_e2e` + `ui-contracts.mjs` 双向锁定，改字段须同步 fixture 与 `lib/api.ts` 镜像。
