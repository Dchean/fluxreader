# Agent Note: 同步运行生命周期与诊断

Status: implemented

## Problem

PULL_LOCK/PUSH_LOCK 只保护各自阶段。auto、focus 与前端分次调用 feeds/states 会交错，旧轮的无 ID `sync-idle` 能提前熄灭仍运行的同步灯。ClientBuildFailure::Failed 又被改写为 notConnected；当队列为空时，没有 last_error 承接真实认证或网络错误。后台 report.errors 只进调试日志，发布构建没有可持续诊断记录，退出也只有封面补全消费停止信号。

## Decision

`sync/runtime.rs` 按数据库连接维护整轮闸门。所有生产 phase、即时状态推送、订阅 outbox、auto/focus 进入同一个运行协调器；同一轮内部通过 task-local 重入，保留现有局部锁与账号代际屏障。`sync_run` 一次 IPC 执行 feeds→states，保留每个阶段的报告及失败 stage/code/message。旧 sync_phase 可继续单阶段调用，但每次调用仍受相同闸门约束。前端抓取/reload 保持在前端活动内，不跨 IPC 保持后端互斥锁。

整轮第一次读取的账号 generation 固定于 task-local；进入后续阶段和重新认证前检查这一值，账号变更立即结束旧轮。客户端仍经既有会话缓存取得，不把一份客户端引用强行贯穿所有阶段；整轮固定的是身份代际和活动所有权。

活动事件携带唯一 id、单调 sequence、来源、stage 和明确结果。前端用活动表收敛，不让一个结束事件清除其他活动；已结束轮次的迟到开始/阶段事件被拒绝。手动链关联前端 owner，后端结束不能提前结束后续抓取/reload。后台 partial/error 即使没有队项也会进入错误中心并提供重试；只有明确 NotConfigured 可静默。

运行协调器使用受管理后台任务：调用方取消等待不丢弃已经开始的轮次，panic 由 Drop 发布失败并释放闸门。退出先关闭准入和取消在途异步链，等待最多三秒；SQLite 同步短事务不会被协程取消切断，已发出的远端请求无法撤回，未确认意图仍留待重试。调度循环在启动等待和 tick 等待期间也消费停止信号；不增加电源事件或改变 v34 抓取 CAS/footprint。

RSS 批次 worker 在等待并发许可和执行抓取两处消费同一停止信号，停止后的批次返回 `syncCancelled`。这是退出准入接线：仍由原 single-flight 任务收集 worker 结果并释放批次，不改变普通调用方取消时继续完成抓取的语义。

发布诊断采用独立的结构化写入器：只记录时间、活动 ID、枚举来源、结果、错误分类，不接受原始错误、URL、用户名、凭据、请求头或正文。每文件最多 256 KiB，最多三份轮转。与完整日志加正则脱敏相比，受控字段无法保留详细远端错误正文，但提供可关联的失败/恢复/取消记录，避免未知格式绕过脱敏。普通详细错误仍在本机界面按现有错误中心处理。

报告内 partial 与单次手动 IPC 内的阶段失败同样产生受控错误分类；队列/订阅通知读取失败进入现有可重试错误事件，事件发射失败记录 `event_failed`。订阅通知的同值缓存仅在发射成功后推进，失败载荷仍可在下一次通知重发。

GReader 的真实 401 为兼容既有 IPC 保持 `code=network`，认证原因来自 `AppError` 内部结构化标记。阶段错误汇入 `SyncRunError` 时一并保留该标记，使用 `serde(skip)` 隔离于 IPC 三字段之外；发布诊断据此写 `auth`，不从 code 或错误正文猜测认证失败。

## Alternatives considered

- 跨 feeds/states IPC 保存锁租约：能保留旧前端调用形态，但页面消失、IPC 失败与超时会制造悬挂租约或提前释放，无法说明整轮终态。采用单次 sync_run，保留旧入口兼容。
- 只把 bool 改计数：可以改善灯色，却仍无法拒绝旧事件或关联失败和具体轮次，后端阶段依然交错。使用活动 ID 和 sequence。
- 发布启用全部 log 再正则脱敏：诊断更详细，但 reqwest/插件错误可包含任意正文和含凭据 URL，正则无法给出稳定边界。仅写受控字段。
- 把真实 401 的 IPC code 改成 auth：会改变既有错误契约，也无法解决以后再次包装时丢元数据的问题。保留现有 code，阶段结果内部传递结构化认证标记。
- 退出硬停所有任务：实现简单，但无法明确活动结束或限制收尾等待。关闭准入、取消异步链与有限 drain 使恢复边界可测试。

## Consequences

同步轮次排队会增加后发操作等待，但避免全链互相消费游标与错误。调用方取消不等于停止服务端已发请求；退出取消也不能撤销远端已接受的操作，后续 ACK 验证和持久意图负责恢复。诊断目录不可写时无法落盘，应用不为日志失败中止启动。真实 Tauri 退出窗口效果、真实部署认证响应与跨机器日志权限仍须单独验收，loopback/协调器测试不能替代。

## Verification

2026-11-05 在隔离 Windows Rust/MSVC 环境使用临时库和 loopback，验证整轮串行/重入、取消等待、panic、停止与有限 drain、空队列失败、手动阶段报告及跨阶段换代。真实 ClientLogin 401 经手动整轮曾丢认证标记，独立反例和正式红/绿回归推动保留内部 auth 元数据，同时 IPC 仍为 stage/code/message 三字段；原始证据在 tmp/runtime-closeout/ 与 tmp/runtime-closeout-audit/。

诊断器只能记录上游交付的事实。2026-11-06 `91ece562` 仍确认认证重试丢已提交变化、outbox SQL 确认失败和完成时间 SQL 失败未充分进入报告，见[同步正确性](../../../../docs/roadmap.md#sync-correctness)。因此活动表/日志存在不等于错误覆盖完整。真实 Tauri 退出、真实部署认证、发布目录不可写和事件传输故障仍需各自验证；旧 Note 格式计数和整轮门禁状态不在此重复维护。
