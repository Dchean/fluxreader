# Agent Note: 全布局键盘焦点与响应式阅读列

Status: implemented

## Problem

键盘、焦点与可访问性此前按布局和组件各自修补，留下以下真实断点：

- J/K 在文章布局只更新 `activeArticleId`，Timeline 只同步 roving `focusIndex`，DOM 焦点仍停在上一条；社交/播客/通知在二列布局没有统一选中视觉，按 J 后 store 已换条、屏幕上看不出选中谁；画廊被显式排除在 J/K 之外。
- 收藏/筛选让当前持焦卡卸载时，React 把焦点甩到 `BODY`。用户失去键盘位置，且没有播报条目为何消失、焦点去了哪里。
- 文章三栏使用固定 `260px + 用户列宽 + 1fr`。在 980×640 且用户列宽为 560px 时，列表占 560px，阅读器只剩约 160px。
- 设置页的 `≤700px` / `≤560px` 媒体查询低于 Tauri 主窗 `minWidth: 980`，实际不可达；同时设置开关、range、文本框与自定义 combobox 在 Chromium AX 树中缺少稳定名称，combobox 常以“当前选项值”冒充名称。
- 侧栏源行用 `div role="button"` 包住刷新/编辑两个真实 button；动作区只在 hover 时可见。DOM 与 AX 都形成 button 嵌套，Tab 无法稳定从源行到达动作，键盘用户看不见也无法操作。
- 源行改成平级真实 button 后，主选择按钮只覆盖内容区；行容器的左侧与上下 padding 不再是点击热区，鼠标点在行内边距不会选中源，较旧的全行热区出现回归。
- 播放器激活时，App 的全局 Space 只检查 `defaultPrevented`。聚焦搜索、刷新、编辑等原生控件按 Space 会同时触发控件自身与播放器切换，出现一次按键双重动作。

## Decision

### J/K：五种布局统一由“选中”驱动焦点

`App.tsx` 仍只负责用 `jkLayoutAllowed` / `jkNextIndex` 计算并调用 `selectArticle`；DOM 侧由 Timeline 单点消费 `activeArticleId`：

1. 选中 id 变化后，按当前可见集合求下标；
2. `focusCardAt(index)` 调对应虚拟化实例的 `scrollToIndex(index, { align: 'auto' })`；
3. 目标卡挂载后按文章身份再次核对，再执行 DOM `focus()`，并在随后约 120ms 内做有界 `nearest` 可见性复核，吸收虚拟测量晚一帧造成的回退；每次请求拥有自己的帧与定时器，新请求、卸载、菜单打开或焦点进入浮层时取消旧任务，执行时还要复核所有权；
4. 五种卡片统一写 `aria-current="true"` 与 `.active-selected`，画廊的焦点元素是图片/无图占位，选中类落在外层卡。

J/K 覆盖文章、社交、画廊、播客、通知。选择全布局而不是保留“画廊不支持”，是因为同一时间流导航在同一窗口里突然失效没有可解释性；画廊已有 lanes 虚拟化与可聚焦卡，继续排除只会制造第二套产品规则。快捷键页同步改为“全部内容布局”。

2026-11-09 按分区阅读契约将选择和打开副作用分开：文章 J/K 实际呈现正文，按打开设置标读并水合；其余分区只选中/聚焦，不借隐藏 Reader 请求全文或自动 AI。Reader 仅文章分区挂载。画廊真正打开大图、播客真正开始播放与文章共用 `markEntryOpened`，均服从 `markReadOnOpen`；显式标读不受自动设置禁止。社交/通知的中心停顿自动 AI 由后续独立触发策略负责，不能从选择动作暗中发起。

搜索的 `anchorToArticle` 收尾同样调用 `selectArticle`，不再复制“标读 + 全文”的第二套实现。独审发现画廊搜索定位虽未打开图片/Reader却被旧收尾标读；统一动作入口使文章搜索继续打开正文，其余分区搜索只选择定位，读藏回滚与设置政策由同一实现承担。

选中后的入窗和聚焦只由 `focusCardAt` 发起，发起前与延迟回调均核对浮层/阅读上下文。删除旧的第二条 `activeArticleId → rowVirtualizer.scrollToIndex` effect：它在画廊选中并打开灯箱时仍滚动错误的单列虚拟器，绕过浮层所有权。此收口保留 J/K 入窗，并让打开/关闭灯箱保持滚动位置与原卡焦点。

右键菜单的打开状态也进入统一快捷键让路集合。菜单自身仍截停单键事件，但 App 不再以事件必须发自菜单 DOM 作为唯一前提；焦点意外离开时，背后文章也不会被 J/K/S/M 改变。菜单关闭或卸载同时释放该状态。

### 移除后的焦点迁移

Timeline 在滚动容器上以 `focusin` 捕获当前持焦卡，记录 `{ id, index }`。当 `items` 变化且该 id 消失时：

- 只有焦点确实丢到 `BODY` / `documentElement` / 已断开节点时才迁移；用户把焦点放在筛选控件或侧栏时不抢焦点。
- 优先落到新集合的同一线性下标；若原卡在末尾，则夹取到新集合最后一条。
- 画廊同样按线性顺序迁移，不按 lane 做空间猜测；焦点目标可能是另一列。
- 无可迁移条目时焦点落到列表滚动容器，并播报“列表已为空”。

同一 effect 还比较持焦卡的 `isStarred`：收藏状态变化、或取消收藏导致条目被筛掉，都写入 Timeline 的 `role="status" aria-live="polite"` 区域。迁移文案点名被移除条目与新焦点条目。

### 980 视口的三栏列宽

三栏改为：

```css
grid-template-columns: 260px
  clamp(280px, min(var(--list-width, 380px), 37vw), 420px)
  minmax(0, 1fr);
```

- 用户偏好仍是下界内的可选宽度；窄窗再按 37vw 收缩，宽窗最多 420px。
- 980px 时列表约 362.6px、阅读器约 357.4px；1280px 时列表封顶 420px、阅读器 600px；1536px 时阅读器 856px。三档均无横向溢出。
- 拖动夹取上限同步改为 420px；旧持久化的 560px 值在显示时被 CSS 夹取，但这次不改设置校验或数据库。
- resize handle 复用同一 `clamp()` 表达式，避免分隔条与真实列边界错位。

### 设置断点与可访问名

- 设置页断点改为 `≤1100px`（侧栏 190px）与 `≤1000px`（弹窗 94vw、侧栏 170px），980 最小窗宽下真实可达。
- `SettingCard` 用生成 id 把标题暴露为内部控件的稳定名称；`Switch` 与 `FluxDropdown` 通过 context 取得标题，控件显式 `ariaLabel` 优先。range、原生 text/password、textarea 与弹窗内下拉补显式名称。
- 订阅管理中的布局/AI 三态下拉以“分类名/源名 + 作用”命名，不再用“文章/开启/关闭/继承组”等当前值。
- 侧栏搜索改为真实 `button`；分类标题改为真实 `button`。当前视图/布局用 `aria-pressed`，当前源与分类用 `aria-current`，设置导航当前页用 `aria-current="page"`。
- 2026-11-07共享FluxDropdown补独立listbox/option ID，combobox关联controls和active-descendant；键盘活动项与已选项分开，portal不改变关联，Esc/Tab/焦点离开收起并清关联。组件覆盖真实键盘路径，Edge AX和读屏实听的结论仍分别受证据约束。
- 窄窗Reader byline允许整组换行，时间与阅读时长保持词组不拆，作者/标签可按可用宽度折行；阅读列宽公式不改。

### 侧栏源行：平级选择/动作按钮

源行外层恢复为普通容器，只承载 `data-ctx`、`data-id`、`data-cat` 与布局类。主选择区是真实 `button.feed-leaf-select`，内部保留源名、favicon、失败标记与计数；刷新和编辑是它的同级真实按钮。DOM/Tab 顺序因此固定为“选择 → 刷新 → 编辑”，没有 button 嵌套。

动作区继续在 hover 时淡入，但新增 `.feed-leaf-item:focus-within`；键盘路径明确关闭 `visibility` 过渡，避免焦点进入主按钮的同一帧动作区仍是 `hidden`，导致 Tab 跳过。动作按钮仍保留 `stopPropagation()`、context menu 数据属性与原有尺寸/间距。

行容器补回非语义鼠标选择处理：事件 target 若位于子 `button` 或菜单项内则直接返回，其余 padding/空白区域调用 `selectFeed(f.id)`。容器不添加 `role="button"` 或 `tabIndex`，键盘入口仍只有主选择按钮；刷新/编辑继续 `stopPropagation()`，因此不会与行级选择形成双重动作。

### 播放器 Space：原生交互控件优先

`shortcutYield.isInteractiveSpaceTarget` 统一定义 Space 让路清单：真实 `button`、`a[href]`、`input/select/textarea`、可编辑节点、带 controls 的媒体、菜单项及其它常见 ARIA 交互角色。文章/播客的卡片焦点节点及画廊的图片/无图占位使用 `role="button"`，社交/通知卡容器保留 `role="article"`；它们共享 roving 焦点与键盘行为，并不统一容器角色。清单刻意**不包含** `[role="button"]`，让这些卡片焦点上的 Space 在播放器激活时仍交给全局播放切换；卡内真实按钮会先命中原生控件清单并让路。

App 的 Space 分支同时检查 `defaultPrevented` 与该清单。Timeline 的卡片处理器在播放器激活时直接返回、不 `preventDefault()`，让同一次 Space 冒泡到 App 切换播放；播放器未激活时，卡片原有的 Enter/Space 选中/灯箱/播放语义不变。

## Alternatives considered

### Why not 继续在二列布局禁用 J/K？

禁用可以避免“不可见选中”，但会让同一快捷键随布局改变语义，且用户已经能看到画廊卡与动作按钮。统一的选中/焦点路径比维护一份按布局例外表更可验证；代价是 GalleryCard 也必须维护选中类与 `aria-current`。

### Why not 只监听 `activeArticleId` 来迁移焦点？

“选中”与“持焦”不是同一状态：用户可以只 Tab/方向键移动焦点而不打开条目；筛选或后台刷新也可能移除一张仅持焦、未选中的卡。只读 `activeArticleId` 无法知道被移除的是哪张卡、原下标在哪。因此另记 `focusin` 身份，并在确认焦点丢失后迁移。

### Why not 用固定延时或持续轮询等待虚拟化挂载？

固定延时只会在慢机器上变成新的 flaky；持续轮询会让已卸载卡长期占用定时器。实现采用“每帧尝试、最多 4 次挂载重试 + 5 次最近可见性复核”的有界路径，并取消被菜单/浮层接管的旧请求。只增加等待时长无法关闭已签发回调抢焦的窗口。

### Why not 让列表固定占 40vw？

40vw 会在 1536px 下允许 614px，仍可能压过用户实际需要的阅读宽度；而 37vw + 420px 上限同时满足窄窗保底和宽窗上限。另一个候选是缩窄 260px 侧栏，但那会牺牲导航标签与订阅树，超出本卡阅读列的问题域。

### Why not 用容器查询替代视口断点？

设置弹窗宽度由视口和自身 `max-width` 共同决定，容器查询理论上更精确；当前组件树没有统一的查询容器，且 WebView2/Chromium 现有验证链路就是视口媒体查询。把不可达断点平移到可达区间是最小、可回归的修法。

### Why not 保留 `div role="button"` 并把动作按钮移出视觉层？

把动作按钮做成浮层或 sibling portal 可以绕开 DOM 嵌套，但仍会留下一个“整行都是 button、动作区却在别处”的伪控件；Tab 顺序、命中区与右键菜单归属都会变成第二套规则。更直接的结构是让选择与动作各自是同一层级的真实按钮，布局仍由同一个 flex 行承担。

### Why not 用覆盖整行的透明 button 恢复鼠标热区？

透明覆盖层会与刷新/编辑的真实点击层抢命中顺序，并迫使动作区额外提升 `z-index`；在窄侧栏里还会让可点击区域与视觉边界依赖覆盖尺寸。保留普通行容器并在事件 target 上排除子按钮，既恢复 padding 热区，也不引入第二套键盘语义或新的层叠规则。

### Why not 只依赖 `defaultPrevented` 处理播放器 Space？

原生 button 在 Space 上的 click 合成并不保证先调用 `preventDefault()`，搜索/刷新/编辑都会因此同时触发控件动作与播放器切换。`defaultPrevented` 只能兜住应用自己写了处理器并显式拦截的控件，不能替代“原生交互控件优先”的目标判定。

## Consequences

- 五布局 J/K 选择后的焦点路径共用 Timeline 实现；`aria-current` 与 `.active-selected` 可用真实 DOM/AX 断言锁定。
- 焦点迁移是“保持键盘位置”，不是“自动打开下一条”：阅读器中的文章不会因后台筛选而自行切换。
- 列表宽度上限从持久化层的 560px 视觉收紧到 420px；设置仍可保留旧值，但拖动新值不会超过 420px。这是有意的视图层兼容取舍。
- live region 只在可迁移/收藏状态变化时写入；普通后台刷新不播报，避免噪音。
- 设置卡片标题成为表单名称来源，后续新增卡片控件默认继承标题；若一张卡需要多个独立控件，调用点必须显式区分名称。
- 2026-11-06 基线在合法 rAF 顺序下复现菜单打开后旧 Timeline 回调夺焦，K 改变背后选中/标读，同基线组件 CI 也失败。首批补上取消、身份与菜单状态守卫且独立复审通过。画廊混合比例的超量挂载与 Tab 到不可见卡另由[逐列窗口记录](2026-11-13-界面布局与启动时序.md)维护；本批候选Tab先用几何可见项，不再把mounted当visible，真实浏览器仍待验。combobox关系候选已补，不能由菜单修复或组件通过推导交互全部完成。
- 源行动作区现在始终占位；hover 与 focus-within 只改变可见性，不改变行宽。代价是动作按钮在视觉上仍随 hover 出现，但键盘用户能在焦点进入源行后立即看到并 Tab 到达它们。
- 源行鼠标热区覆盖整行 padding，但行容器仍是非语义元素；读屏与 Tab 只看到主选择、刷新、编辑三个平级按钮，不会多出一个“整行按钮”。
- Space 的优先级变为“原生控件 > 播放器 > 卡片自身”；这是有意的全局快捷键语义。若未来新增自定义交互控件，必须把角色加入 `isInteractiveSpaceTarget` 清单，否则会被播放器吞掉。

## Verification

2026-11-04 的 jsdom 与 Edge/CDP 在 1536×900、1280×800、980×640 覆盖 J/K、源行 padding/Tab/Space、AX 名称和响应式列宽；980 档列表约 362.59px、Reader 357.41px 是当时量测。没有 NVDA 或 Tauri WebView2 实机读屏验证。2026-11-06 `91ece562` 的上述竞争和 combobox 关联反例限制了旧结论，见[界面与媒体路线](../../../../docs/roadmap.md#interface-and-media)。名称存在不证明活动选项可感知，终态焦点正确也不证明中途没有夺焦。

历史实现与测试定位见[整理前记录](https://github.com/Dchean/fluxreader/blob/91ece562d79fd909642cd6d570d636e884b7387e/.agents/notes/implemented/architecture/2026-11-04-全布局键盘焦点与响应式阅读列.md)。本篇记录决定，不单独维护当前门禁计数。
