# Agent Note: 配置快照镜像应用

Status: implemented

## Problem

保守合并保留本地独有对象，无法按远端快照收敛删除；直接覆盖又会级联删除文章与状态，且用户确认期间本地配置、文章和 pending 意图可能变化。配置同步还必须与 RSS 账号退订分开，不能把“镜像本机”变成“退订服务端”。

## Decision

应用采用 plan → 用户确认 → apply。merge 为默认，mirror 单独确认；切换模式使旧预览失效。plan 对数据库只读，但有删除项时会生成自动快照文件；取消不改数据库，文件按保留策略保存，不能简称为全部零写入。

预览列出 feed/folder 的新增、更新、删除、文章影响数、设置键变动、连接建议与 warnings；文章按被删源计一次，目录仅归组。apply 在同一事务重算计划，核对 payload 的 snapshotHash 与本地 currentVersion，失配返回 stalePreview，要求重新预览，不能按新计划直接删。镜像缺签名拒绝；库级 apply_payload 保留 merge 兼容入口。

本地签名覆盖全部分类/源配置、白名单 settings 投影，以及被删源的文章数、读藏聚合和 pending 写回。无关源的新文章不参与，降低后台抓取造成的无谓失效；被删源的 AI/正文变化不单独入签名，故 apply 必须在锁内、删除事务前新建并校验完整快照，失败 backupRequired 阻止删除，不复用预览路径。详见[数据库快照](2026-11-05-数据库快照与恢复边界.md)。

schema2 分类采用 sync_id：身份优先，名称兜底仅双方其一缺身份，且只填本地空身份。同名且双方身份不同视为不同对象并预警；新目录 INSERT 时一次采用远端身份，无身份才随机。不能先随机创建再用“只填空”更新，否则远端身份永远落不进去。远端身份已被其他本地对象占用时不共享，降级随机/保留空身份并警告。schema1 无身份按名称/源 URL 兼容合并。

2026-11-06 起，新导出的源增加可选 `folder_sync_id`，引用同一快照内分类的稳定身份；字段存在时必须精确命中，未知或空身份整包拒绝，不能悄悄按名称换归属。保持 schema2，旧 serde 消费者忽略未知字段，但旧版不能因此正确恢复重名分类。旧文件缺字段时按原始名称精确引用，保留首尾空白；同名多槽选择快照首槽并在预览警告，旧文件未保存的信息无法推断。新格式因此补足源到分类的身份引用，既有分类匹配/身份占用纪律仍有效，不重命名或合并存量分类。

镜像只改本机：不创建 unsubscribe outbox，既有 pending 一个字节不动并告警；匹配源先移动，再删多余源，最后删空目录。文章级联按最后引用回收 contents，不直接删除共享正文。删除源留 feed 墓碑防同账号 pull 复活；分类不写名称墓碑，后续可按服务端 label 导入。mirror 对源未知/空分类引用整体拒绝，不创建 merge 的“导入”兜底目录。

显式配置恢复实际新增本机源时，在 apply 同一事务内仅解除该 URL 的当前及 legacy feed 墓碑，与 OPML 重加共用原语。未新增的源、其它 URL 和账号状态不因此变化。恢复不产生远端订阅/退订；此前另一次显式删除产生的 pending unsubscribe 继续保留，预览提醒它之后可能执行，因此本机恢复不承诺重新绑定远端必成。mirror 删除本身不造退订意图，其后恢复解除墓碑后允许正常订阅拉取重绑。

settings 只传白名单客户端配置和分类/源 AI 开关；AI 服务模型/密钥与活动账号凭据不在覆盖范围。2026-11-07 更正：“只传白名单”是记录时点的过时口径——实际协议保留未知字段，仅对已知消费字段严格校验、本机专属键忽略（独立审计见 `tmp/repair-2026-11-06/audit-backend/report.md` 第60–64行与第84行；后端首审的数据首批章节已限定通过，首审整体因 RB-S1 不通过，与本范围区分），不据此扩大为敏感账号键被同步的已证缺陷。连接信息只落带 serial 的待确认建议，见[账号边界](2026-10-08-账号会话与配置应用边界.md)。前端应用需同时经过 app_settings 与 AI 配置的写屏障，真实回读才确认新基线，不能把 reload Promise 返回当已完成。

导入准备阶段验证实际消费字段：订阅源只接受完整 HTTP(S) URL、分类/源布局只能是已支持值（inherit 仅源可用），app_settings 对象内校验既有字段类型、枚举与界限，非法整体拒绝且无业务写入。本机专属键仍忽略；旧非对象 app_settings 的无操作兼容仍保留，不能把它当删除全部设置的指令。OPML 在递归树解析前限制 XML 嵌套预算，随后整包验证 URL 再进入导入事务。

## Alternatives considered

- **下载即应用**：缺少删除后果和竞争复核点，不能满足显式镜像确认。
- **只有 payload hash 或信任前端 plan items**：前者不包含本地变化，后者把过期/可篡改清单当事实；后端重算并比对双签名。
- **签名包含全库所有文章**：无关抓取也使确认窗口失效；限定删除后果，执行前新快照覆盖后来 AI/正文。
- **镜像同时远端退订或清 pending**：都改变此前用户意图及远端资产，不属于本机镜像范围。
- **分类也用全局名称墓碑**：会把“快照未包含”变成未来所有账号的永久抑制；保留分类重新导入语义。
- **仅事务回滚，不建快照 / 复用预览文件**：事务不能恢复已提交的误删，旧文件又缺预览后的更新；apply 新建恢复点承担相应 IO。
- **严格只按身份匹配 / 双方有不同身份也按同名合并**：前者破坏 schema1 兼容，后者猜测两个对象相同；只对缺身份做名称兜底。
- **身份占用时强行复用**：会持续污染匹配；当前唯一性优先于畸形混合快照的重复应用收敛，预览必须反复显式提示新增/删除。
- **统一 trim 分类名 / 仍只按名称关联**：前者会合并原本不同的名称，后者丢失同名不同身份的归属；保留原名并增加可选身份引用。
- **本机恢复顺带取消远端退订**：把两个独立用户意图合并且无法撤回已发 HTTP，超出配置恢复的本机范围；保留原退订并在预览说明。

## Consequences

用户可检查后果，过期签名阻止按未确认计划删除。代价是源编辑会使预览失效、预览和执行均有快照 IO、既有 pending 继续存在。混合快照若同身份被无身份槽位按名称占用且又被另一槽位声明，当前会反复新增/删建空分类；这是已登记的异常输入取舍，不应静默合并身份。

删除集合的部分 IN 参数尚未分块，超过 SQLite 变量上限会显式失败，不应以“个人使用不可达”删除这条边界。下载预览中的网络/解析/校验共同显示下载失败；应用错误单独显示应用失败，这是现有可观察阶段划分。

2026-11-06 对 `91ece562` 的实测否定了原“畸形输入全拒绝”表述，并确认空白分类名、同名引用和恢复墓碑缺口。该历史反例仍成立；本次实现按上述字段校验、身份引用与仅本机恢复规则补齐，不推导为所有畸形输入已覆盖。
