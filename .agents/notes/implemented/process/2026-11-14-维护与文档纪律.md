# Agent Note: 维护与文档纪律

Status: implemented

## Problem

项目文档反复与代码脱节：2026-11-14 的审计里 20 条被纠正的结论中过半是注释/文档失实（索引说法、行号指向、注释把死代码写成生产语义）。同时缺少三件基础设施：文档与代码冲突时没有处置口径；改动影响哪些契约与文档靠记忆；文档没有路由，查一件事要么通读 `docs/` 要么读错篇目。

## Decision

- 规则正文落 [docs/maintenance.md](../../../../docs/maintenance.md)，契约单点落 [docs/contracts.md](../../../../docs/contracts.md)，[docs/README.md](../../../../docs/README.md) 升级为"任务 → 必读"路由 + 索引（含代码锚点、触发更新、最近核对）。
- `AGENTS.md` 只留七条摘要与跳转，避免每轮会话加载全部规则，也不复述上位总则。
- 文档纪律：不写行号（用文件 + 符号名或显式锚）；能由类型或测试表达的不重复写进文档；一篇一主题。
- 冲突处置：以代码为准，但先登记差异并告知用户，确认后再同批改文档；必要时补防复发断言。
- 新增 `npm run docs:check`（`tools/docs-check.mjs`）：索引覆盖、相对链接、锚点、`docs/` 内行号禁令，本地与 CI 都跑。
- 审计结论摘要入 [docs/audits.md](../../../../docs/audits.md)（基线 SHA + 计数 + 证据位置 + 复跑命令），原始输出留 `tmp/`。

## Alternatives considered

1. **全部写进 AGENTS.md**：只有一个入口，但每轮会话都加载全部规则、与 `~/.dsh/AGENTS.md` 的证据/审计总则大面积重复——否，改为摘要 + 跳转。
2. **只写 `docs/`，不动 AGENTS.md**：上下文最省，但新会话不知道有这套规则——否。
3. **只做约定、不做校验**：零门禁成本；但本次审计证明靠人眼守不住文档一致性（行号与索引会悄悄漂移）——否，故选脚本门禁。
4. **文档内保留 `path:line`**：更精确；但行号随改动必漂，且本次已发现多处指向错位置——否，改为符号名 + 锚。

## Consequences

- 改契约或模块时，要按索引表的"触发更新"列对账，并在同一批更新文档与索引；做不到就登记到 roadmap，不许口头欠账。
- `docs:check` 只守结构，不判内容对错；内容与代码是否一致仍靠审计与评审，不能拿绿灯当正确性证明。
- 新增或改名文档必须登记索引，否则门禁红；这是有意的摩擦。
- 门禁清单多一项（frontend job），`docs/development.md` 与 `AGENTS.md` 的对应表已同步。
- 该决定与 2026-09-16 的测试门禁纪律、2026-11-13 的零消费清理同属"每项检查必须有承担者"的延伸。
