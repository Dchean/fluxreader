# Agent Note: 修复波次的分批、证伪审计与证据门槛

Status: implemented

## Problem

跨同步、数据、界面与运行时的修复共享文件和验证资源。一次性全修会混淆写入归属与证据版本，历史绿灯又容易被误作当前全功能证明。早期主控/编码工具限定和逐轮任务卡也不适合作为永久执行指令。

## Decision

- **按关键接口、写入边界与可验证结果分批。** 一个写域一个负责人；依赖未稳定的下游不占共享资源等待；强耦合修复由同一实现者完成调查、修改、验证和记录。并行只用于独立写域，真实 UI/端到端与共享构建按当前项目规范预留。
- **实施与独立审计分开。** 审计者未参与实现，核对真实输入、当前差异和原始证据，不能只采信实现者 PASS、Note 状态或 CI 绿。修复复用适合的原负责人；补查范围由证据缺口和变化决定，不为重复全套仪式增加成本。角色、确认、冻结及升级诊断服从当前 AGENTS 与 [roadmap](../../../../docs/roadmap.md)，不由旧 Note 覆盖。
- **测试对应所声称的层次。** 类型/格式、状态、挂载、真实布局、生产数据库/网络与真实部署各有边界：Node 24 结果不冒充 Node 22；jsdom 不冒充布局引擎；mock 不冒充真实服务器；同提交旧二进制复跑不冒充新编译。CI 必须实际执行适用门禁；失败与未验证分别保留，不能靠降阈值或多 sleep 掩盖。
- **每次修复携带最小有判别力的反例与正常对照。** README 文案契约检查应验证“同步什么/留在本机什么”的语义，不锁旧完整句；Rust payload 行为测试仍负责实际上传面。基础门禁可执行不等于业务缺陷已修。
- **证据与文档分工。** 长期理由在归属 Note，事实在 docs，当前缺口在 roadmap，轮次状态只在本入口或当次交付；不复制完整日志或新建台账。历史审计与任务卡从固定 Git 提交恢复；清理前先承接独特约束，不按年龄或篇幅归档。
- **归档封印只追加，不改历史。** 旧归档与 manifest 条目冻结；新解释写活跃篇。唯一历史头块例外是 2026-11-02 的五调色盘档案：规范头块把 `Status: implemented` 紧邻 `Archived: 2026-11-02`，正文从 Problem 起未改，该 Status 是归档头契约而非当时实施声明。首次封印前后 SHA256 分别为 `a91838aae6eba88d03d1ae75a5c591eead58eed98402180e32bbab6deca5f266` 与 `91f4458be322dcc6fa007f3b78bc0f3de642ff87b0d1e6e3ac8d9a86aba17257`，证据在 `tmp/docs-convergence/archive-evidence.json`。之后的旧正文与 seal 不再改。

## Alternatives considered

- 一张总卡修全部域：协调少，但共享写入和证据版本难区分，选按职责分批。
- 实现者同时完成最终证伪：上下文可能只支持自己的假设，保留未参与实现的审计角色。
- CI 绿或 CLI 退出 0 直接验收：只能说明实际执行的断言，不能证明全部用户操作或外部版本。
- 为恢复绿灯改回 README 旧句、跳过归档失败或重算旧 seal：掩盖契约/历史问题，改为语义检查并保留原始失败。
- 固化旧工具、模型和每轮重开规则：与实际能力及任务大小脱节，改由当前协作规范安排；历史选择仍可追查。

## Consequences

写入与证据能够对应，必要回归留在既有工具链；代价是共享面必须串行，真实环境仍需要独立验证。良好流程不能保证零缺陷，文档整理也不修复代码。

早期轮次的路线理由与授权边界已由本篇、[测试门禁与断言纪律](../testing/2026-09-16-测试门禁与断言纪律.md)及对应领域 Note 承接；原时点授权、未采方案和过程保留在固定历史快照与归档分支，不复制到当前执行规则。

## Verification

当前版本、发布状态与仍开放的产品/验证缺口只由 [roadmap](../../../../docs/roadmap.md) 维护；门禁命令、环境与常见故障见 [development](../../../../docs/development.md)；每个结论以其固定 SHA 的 CI 或对应 Note 的验证边界为准。本篇不记录轮次计数、逐项通过清单或临时命令；需要复核历史批次时，用 Git 历史与当轮交付记录定位，不用本篇冒充当前全量证据。
