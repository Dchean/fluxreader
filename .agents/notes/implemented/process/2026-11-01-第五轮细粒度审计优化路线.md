## Problem

用户要求：同步优化不得再出现「减少抖动时间」式表面方案，只接受有实际参照证据的机制；审计拆分为更细粒度的多任务并派发全新子代理；优化持续至 2026-11-02 08:00（最晚 08:30 收敛），每轮完成打小 tag 发布。第五轮基线 dev @ c04a471（v0.18.4 已发布）。

## Alternatives considered

- **`ot×状态流` 增量（原挂账形态）**：被协议证据直接证伪——Miniflux 把 read/starred 流的 ot 映射为 `AfterPublishedDate`（handler.go:1063-1096），FreshRSS 的 ot 匹配 `date≥ot OR lastModified≥ot` 而状态变更只动 `lastUserModified`（EntryDAO.php:550-557），Bazqux 官方 Warning 明言勿用。挂账以此形态正式关闭，改采未读差分。
- **GR long-poll / ContinueWhatNewStream、Fever `last_id_on_sync`、订阅清单 304/ETag**：全部查无权威出处或服务端无实现（四路审计代理实测抓取官方文档与两服务端源码 rg 无命中），不采纳、登记防再立。
- **`item_contents` 块 100→1000**：稳态增量窗常不足 100 条，放大块抬高单请求失败重拉成本，与既有失败粒度设计冲突，维持 100。
- **五调色盘全量 WCAG 收敛**：本轮审计以实测探针（`tmp/probe-contrast.mjs`，算法经 W4 数字交叉验证）复认 9/10 调色盘 tertiary 不达标，但维持 [rejected Note](../../rejected/feature/2026-11-01-五调色盘WCAG全量批量收敛.md) 的「待用户决策」状态，不未经决策翻案；仅在交付说明中提请用户拍板。
- **401 回落串匹配改结构化错误标记**：影响有界（最坏 10 分钟 TTL 自愈且有单测锁文案），重构横切 error 类型面，本轮不做。
- **Bazqux 主列举立即切换**：非当前目标后端，仅登记 matrix §5，与未读差分改造同构、未来一次落地。

## Consequences

- 收益：GR 轻量同步固定成本从 ~26 请求/轮降至 ~7（n 提升 + read 差分双刀）；中文输入 Esc 不再丢词/误关；阅读器加载失败有现场重试入口；启动少一个串行 IPC 往返并消除理论永挂首屏；README 与事实恢复一致。
- 代价：未读差分改变 read 对账实现形态，语义等价性靠差分用例 + 完整性守卫 + mock e2e + CI 保证，真实服务端实机验收继续挂账（与既有口径一致）；前端卡一次性改六个交互面，复核审计工作量前置。
- 边界：Fever 侧无增量空间为协议下界（本轮登记后不再投入）；五调色盘 WCAG 与 401 结构化重构留待用户决策/后续轮次；「证据不足以采纳」清单（COALESCE 空串语义、greader 条数守卫对抗面等理论项）不进路线。
