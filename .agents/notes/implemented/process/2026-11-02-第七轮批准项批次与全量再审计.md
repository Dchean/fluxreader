第七轮两卡并行（写集互不重叠），完成后接三轮跨版本全量再审计：

1. **Rust 合并卡**：a) 订阅 outbox 生命周期终点——`abandon_stale_outbox(conn, current_key)` 在 `commit_account_settings` 同事务内覆盖 identity_changed 与 old_was_empty 两分支（断开保留、身份切换清账），显式放弃「换号→回原账号恢复 pending 意图」语义；就地更新 outbox.rs 头注与 2026-10-14 执行器 Note；b) 401 回落结构化——`AppError` 增加认证失败结构化标记替换 `is_auth_failure_message` 串匹配（Display 文案不变，仅增判据）；c) 图片代理响应体经 read_body_capped 流式收体（settings.rs 封面图 `resp.bytes()` 旁路闭合）。
2. **CSS 卡**：五调色盘 × 深浅色 WCAG 全量收敛——tertiary-on-card 九盘不达标项、浅色 bg-base 残留、accent-light 作文字色 28 处、hover 瞬态底色残留，目标全部 ≥4.5:1；以既有探针（tmp/probe-contrast.mjs，算法经 W4 数字交叉验证）复测全部达标；rejected Note 移入 archived/ 并新建 implemented Note 记实际取值与验证数字。

全量再审计（三代理全新、互不重叠，均明确「不得引用 CI 绿作为证据」）：
- Rust 跨版本审计：未读差分、会话缓存、事务补口、规范化绑定、outbox 生命周期、401 结构化——逐项以代码与测试自证，含故障注入点审查。
- 前端跨版本审计：IME、Reader 三态、ContextMenu、bootstrap 并行/落库门、autoFocus、假空态、对比度——跑门禁自证 + DOM/CDP 探针验证真实行为。
- 一致性与发布审计：三版本 tag/Release/资产/附注正文、Note 与代码双向一致、roadmap 事实核对。

发现的问题回原写集修复后复审，全绿后按发布序列打 `v0.18.7`。

## Alternatives considered

- **四项拆四卡并行**：401 重构与 outbox/图片代理同为 Rust，此前两轮并行 Rust 卡各有一次编译级返工（E0364/E0369 与死锁），合并为单卡把编译风险收敛到一个 CI 周期；CSS 卡独立无 Rust 依赖。
- **401 结构化用独立错误码枚举**：横切全部错误构造点，改动面大于 bool 标记且 Display 文案需保持不变；取最小标记方案。
- **本轮顺带图片代理之外的第四旁路（封面图下载）**：已并入图片代理同一行登记，不重复开工。

## Consequences

- 收益：全部待决策项收口；跨版本调整获得一轮「不信门禁」的独立取证复核，追溯链完整到 Note/提交/Release。
- 代价：Rust 合并卡改动面较大（三域），CI 返工风险仍存，审计成本前置；WCAG 调色板取值变化影响全部主题的观感连续性（以探针数字与构建验证）。
- 边界：GR/Fever 真实服务端实机验收继续挂账；Bazqux 接入形态维持前瞻登记。
