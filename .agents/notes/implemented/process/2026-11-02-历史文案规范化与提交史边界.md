# Agent Note: 历史文案规范化与提交史边界

Status: implemented

## Problem

旧提交与Release文案混有内部进度、回归数字及过时模板。用户希望阅读发布说明即可知道变化，但改写提交历史会使既有tag、资产和SHA引用失效。

## Decision

2026-11-02选择编辑历史Release web正文并重写README，保留历史提交及tag附注。新说明以用户可感知变化组织，不放提交数、模型/代理过程、门禁数量和TASK/REQ编号；未来tag附注直接采用这一文案口径。

历史web正文与旧tag允许不同，新发布仍按[附注来源单点](2026-09-29-发布说明取自-tag-附注.md)。当时对v0.8.0–v0.18.7共28版的web正文作过整理，此数字只描述那次工作，不是本次重新检查外部Release的结论。旧提交信息例外保留，不假装历史已满足新约定。

操作格式只在 [docs/release.md](../../../../docs/release.md) 维护，README面向用户介绍范围，协议差异指向兼容矩阵。文案不得把仅夹具验证的能力说成所有部署已验收，或把研发计划写成已交付功能。

## Alternatives considered

- filter-repo/rebase统一全部提交：破坏SHA溯源与tag，未采用。
- 重打历史tag使附注等于新web正文：会触发重构建并可能覆盖资产，未采用。
- 旧web正文完全不动：不能满足用户明确的文案整理目标，因此选择编辑web而保留tag历史。

## Consequences

用户说明更直接，同时保留原始历史证据。早期版本正文由提交范围重构，精度受历史提交质量限制，不能补造未记录收益或门禁。

历史web/tag分叉在这里集中声明；最终用户正文不再携带曾被否决的内部溯源注。以后若要改变历史哈希、资产或说明来源，需重新评估追溯与构建后果。原决定和当次统计见[固定原文](https://github.com/Dchean/fluxreader/blob/91ece562d79fd909642cd6d570d636e884b7387e/.agents/notes/implemented/process/2026-11-02-历史文案规范化与提交史边界.md)；2026-11-06整理未执行外部Release写操作。
