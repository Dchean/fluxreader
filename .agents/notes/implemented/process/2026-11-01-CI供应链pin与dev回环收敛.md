# Agent Note: CI 供应链 pin 与 dev 回环收敛

Status: implemented

## Problem

可移动的action tag、超出checkout所需的token权限及向局域网开放的开发服务器扩大了工程风险。对个人Windows客户端，缩小默认暴露面比建立复杂供应链服务更合适。

## Decision

工作流 action 使用完整 commit SHA 并保留版本注释；CI、Release 预检使用 `contents: read`，发布所需 `contents: write` 只授予 Windows 构建发布 job。2026-11-06 将 Release 的历史 Actions 轮询改为同提交可复用 CI 后，不再需要 Actions API 读取权限。Vite 开发服务绑定 localhost，生产构建读取 frontendDist，不依赖开发 server 配置。

SHA只固定所引用action代码，不等于所有下载工具或依赖不可变。dtolnay/rust-toolchain固定action提交但仍请求stable，rustc与rustup bootstrap仍可变化；当前接受新lint导致无项目改动也变红的代价。目标更强可复现构建时才评估明确工具链版本。

## Alternatives considered

- 继续固定版本tag：tag可移动，不满足不可变action引用的目标。
- 保持host:true依靠每台电脑防火墙：把默认边界交给外部机器配置，未选。
- 同批固定全部工具链并安装自动升级平台：超出本次防护范围；保留手动SHA更新，是否引入保活按实际维护成本决定。

## Consequences

减少可移动tag和默认局域网入口风险，但不保证供应链零风险。升级action需核对SHA；定向cargo update也可能重解析其他锁文件项，必须看完整diff，不能以命令里只写一个包推断无连带变更。

localhost可能绑定IPv6，依赖Chromium/WebView2的本地解析行为；Node/Vite升级后应验证开发窗口实际加载。生产网络策略由独立正文/导航边界管理，不以开发server绑定代替。

具体未处理告警及签名边界集中在[维护缺口](../../../../docs/roadmap.md#maintenance)。发布适配沿用原 action SHA、Node 22 和 Windows Rust/Edge 门禁，不通过升级工具或降低阈值隐藏现有失败。当前验证结果集中在[验收入口](2026-11-03-修复波次的分批、证伪审计与证据门槛.md)，历史落地依据见[固定原文](https://github.com/Dchean/fluxreader/blob/91ece562d79fd909642cd6d570d636e884b7387e/.agents/notes/implemented/process/2026-11-01-CI供应链pin与dev回环收敛.md)。
