# Agent Note: CI 供应链 pin 与 dev 回环收敛

Status: implemented

## Problem

2026-11-01 审计确认三类工程面缺口：CI workflow 的 action 全部浮 tag（release job 持 `contents: write`，action 被投毒即随 tag 触发）；vite dev server `host: true` 实际绑定 0.0.0.0 向局域网暴露 dev server 与 HMR；ci.yml 无 `permissions:` 收口。

## Decision

三个 action 文件内 10 处 `uses:` 全部 pin 到 commit SHA（行尾保留 `# v4` 式版本注释）；vite dev server 收敛 `host: 'localhost'`（WebView2 对 localhost 的双栈解析回退由浏览器承担，release 构建走 `frontendDist` 不读 server 配置、零影响）；ci.yml 顶层 `permissions: contents: read`（GITHUB_TOKEN 仅被 checkout 消费）。

## Alternatives considered

- **pin tag 而非 SHA**：tag 可被上游移动，防投毒目标要求不可变引用，tag 不满足；SHA + 注释保留可读性。
- **继续 `host: true` 并靠防火墙**：把安全责任外包给每台开发机的网络配置，默认暴露面不可接受；`localhost` 的代价是 Node 单栈绑定（本机实测 `::1`），依赖 Chromium 系内核对 localhost 的双栈回退——dev 窗口空白的失败症状需在升级 Node/Vite 时复测。
- **dtolnay/rust-toolchain pin 具体版本**：当前 pin stable 分支快照（该 action 纯输入驱动、不解析 ref，已核对其 action.yml），rustc 仍随 stable 频道浮动——新 rustc 的新 lint 可让 `-D warnings` 在无仓库改动时变红，rustup bootstrap 也不在 pin 覆盖内。可复现构建需 pin `1.xx` 或引入 rust-toolchain.toml，当前选择接受浮动并在此声明取舍。

## Consequences

- 收益：action 投毒路径被 SHA 不可变性切断；dev server 不再向局域网暴露；CI token 最小权限。
- 代价：升级 action 需手动换 SHA（候选保活：dependabot github-actions 通道）；rustc 浮动可能带来无改动的 CI 红；定向 `cargo update -p` 的重解析会静默挪动范围要求依赖（本次 windows-sys/getrandom 降级副作用已手工还原），后续任何定向升级必须逐行 diff 复核。
