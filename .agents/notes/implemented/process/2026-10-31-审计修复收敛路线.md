# Agent Note: 审计修复收敛路线（门禁先行）

Status: implemented

> 后续轮次：2026-11-01 全量双轮审计的修复路线与派发纪律见 [审计修复路线与子代理派发纪律](2026-11-01-审计修复路线与子代理派发纪律.md)。

## Problem

2026-10-31 的两轮证伪审计（4 个专项 + 13 个专项，全部新开代理、真实证据判定）确认了四类测试替身语义失真：`mock_greader` 的 `ot` 过滤列（`src-tauri/tests/mock_greader.rs:1316`）与真实 Miniflux 的 `published_at >` 不一致；Fever 星标 mock 为绝对赋值而真实 Miniflux 是取反切换（`fever_compat_e2e.rs:656`）；`quick_add` mock 默认幂等而真实服务端会拒绝重复 URL（`mock_greader.rs:116`）；compat 套件的 `/stream/items/ids` 无窗口语义（`greader_compat_e2e.rs:517`）。叠加确认的 5 项高危缺陷（Miniflux 星标翻转、quick_add 跨重启卡死、空 link 跨源塌缩、GR 身份桥接缺口、smartDedup 计数 155s/次）与一批 P2，用户指令明确：先修门禁、再动源码、稳定收敛、防无限修复。前一轮收敛路线见 [核心一致性重构路线](../../implemented/architecture/2026-10-05-核心一致性重构路线.md)，其"政策单点 + 事务守卫"底座保留，本篇只规划本轮缺陷收敛，不推翻该路线。

## Decision

收敛按三阶段执行完毕（2026-10-31 当日完成），三条结构纪律全程有效，固定范围防扩散：

1. **阶段 A（门禁对齐）**：只改 `src-tauri/tests/**` 与 AGENTS.md 门禁表，不改产品源码。四类替身语义已修正为真实服务端语义；受影响旧用例按真实语义重写且 CI 绿；AGENTS.md 门禁表与实机能力一致（cargo test/clippy/check 由 CI 承担）。落地与契约见 [测试替身对齐真实服务端语义](../../implemented/testing/2026-10-31-测试替身对齐真实服务端语义.md)。
2. **阶段 B（源码修复，红门禁与修复原子提交）**：B1 Fever 推送语义与 B2 拉取侧（GR 回补、预过滤、url_norm 空串、F1 计数计划断言，落地见 [GR 回补与拉取侧身份/性能修复](../../implemented/bug-fix/2026-10-31-GR回补与拉取侧身份与性能修复.md)）；B3 前端（计数窗口 + 标题截断 + 画廊占位，落地见 [B3 计数落地写结算判据与窄列/画廊视觉修复](../../implemented/bug-fix/2026-10-31-计数落地写结算判据与窄列视觉修复.md)）；B4 安全横向（`get_setting` 敏感键过滤、AI body_text 剔除 script/style，落地见 [安全横向面收口](../../implemented/bug-fix/2026-10-31-安全横向面收口.md)）。每项同批交付 implemented Note 与受影响文档同步（sync-compat-matrix、performance.md、roadmap.md）。
3. **阶段 C（收敛审计）**：两个全新审计代理对固定清单逐项证伪复核——同步域 10 项 9 证实 1 幅度注记、前端/安全/门禁文档全部证实，无推翻性发现；CI run 41212205100（HEAD f4368d0）双 job 全绿。清单外新发现只登记 `docs/roadmap.md` 不修。

派发纪律执行情况：门禁代理复用承接 B1（已持有 Fever 夹具上下文），B2/B3/B4 与阶段 C 审计按上下文评估分别新开；全程未催促，仅按完成通知推进。

## Alternatives considered

- **直接修源码、门禁后补**：见效最快，但这正是本轮审计暴露的失败模式——门禁继续锁定错误语义，修复无法被证伪，必然反复回归。否。
- **全部缺陷交一个代理大爆炸式修完**：无并行收益，上下文必膨胀，写冲突面最大。否。
- **红门禁先推送 dev、源码后补**：dev CI 长期红违背稳定收敛；改为红门禁与对应修复同批原子落地。否。
- **只修 P1、P2 留待下轮**：计数窗口与标题截断是已实测复现的用户可见缺陷，留着必然再开一轮；纳入 B3。P3 与美观批次（对比度、aria、焦点陷阱、ErrorBoundary）本轮不做。

## Consequences

**收益**：门禁从「锁定 mock 世界」转为「锁定真实服务端语义」，四类替身失真清零并经全新审计代理双源核对；5 项高危（Miniflux 星标翻转、quick_add 跨重启卡死、空 link 跨源塌缩、GR 身份桥接缺口、F1 计数慢路径）与 P2 批次修复且经独立证伪复核（含计数判据的独立变异验证与视觉修复的实拍指标）；文档体系与代码同批同步。

**代价与已兑现的风险**：全程约 28 个提交、CI 多轮往返（本机无 MSVC 链接器，Rust 验证只能走 CI；门禁语义修正确实牵出连锁红夹具，B2 经 4 轮迭代转绿）；并行代理同树提交发生一次卷入——a26e8b4 提交信息为 B1 夹具修复，实际卷入 B4 的 5 个文件（B4 代码唯一落点，内容正确但归属失真，历史不可逆，登记为流程遗留）。

**验收结果**：阶段 A「CI 绿 + 审计双源核对替身语义 + 门禁表与实机一致」、阶段 B「固定清单逐项源码 + Note + 配对门禁 + CI + 文档同步」、阶段 C「全新审计无推翻性发现 + roadmap.md 登记不做项 + 本篇转 implemented」三条全部满足。

**登记的残留**（详见 docs/roadmap.md 收敛轮小节）：Fever 星标探测→mark 的 TOCTOU（协议无条件写，客户端不可消除）；Fever 空正文条目每轮 with_ids 重拉一次；迁移 v31 无专属单测；F1 绝对耗时跨 SQLite 构建不可比；P3/美观批次、RustSec 升级、同步端到端性能基线、架构环与 god-module 重构均未纳入本轮。
