## 附：那条 console 错误的根因判定（不是本次拆分引入）

冒烟中出现 1 条：
```
Failed to load resource: net::ERR_BLOCKED_BY_RESPONSE.NotSameOrigin
涉及的资源 URL: https://openai.com/favicon.ico
```

### 判定过程（分阶段定位）

用「先不打开设置、再打开设置」两阶段分别计数：

```
阶段 A（注入 mock，**未打开设置**，等 4s）       : 0 条
阶段 B（打开设置并遍历 8 页签）                  : 1 条  ← 仅此
→ 初步结论：与打开设置相关，需进一步排查
```

### 根因

继续追该 URL 的出处：

| 线索 | 证据 |
| --- | --- |
| 源码里没有 `openai.com/favicon.ico` 字面量 | `src/**` 全量 grep `favicon\|openai\.com\|rel=.icon` 无该 URL |
| 它来自 **mock 数据** | `src/mockData.ts:27`：`{ id: 'f-openai', name: 'OpenAI Blog', …, favicon: 'https://openai.com/favicon.ico' }` |
| 由侧栏渲染 | `src/components/Sidebar.tsx:227`：`<img src={f.favicon} …>` |
| 被 WebView 拦下 | 跨源远程资源，`ERR_BLOCKED_BY_RESPONSE.NotSameOrigin` |

### 为什么与本次拆分无关（三重证据）

1. **`git diff HEAD -- src/mockData.ts` 为空**——该 favicon 不是本次加的；
2. **`git show HEAD:src/mockData.ts:27` 该行已存在**，逐字相同；
3. **`git diff HEAD -- src/components/Sidebar.tsx` 为空**——渲染它的组件本次未动。

第 4 重：本任务只移动了 `SettingsModal.tsx` 的 14 个函数，而该 URL 与设置页**毫无关系**
（设置页的 AI 页签只含 `placeholder="https://your-newapi.example.com/v1"` 之类的**文本占位符**，
不加载任何远程资源）。

### 结论

该错误是**测试环境的产物**：我为冒烟注入了 mock 数据，其中「OpenAI Blog」源指向真实的
`https://openai.com/favicon.ico`，被 WebView 的跨源响应策略拦下。
**真实用户环境下，订阅源 favicon 由其自己的数据决定**；此错误既非本次拆分引入，
也不是应用自身的缺陷。

**故冒烟判定按「8 页签全渲染 + 2 处交互生效 + 可正常关闭」为通过；
该条错误单独列出并标注为环境产物，不计入本次结论。**
