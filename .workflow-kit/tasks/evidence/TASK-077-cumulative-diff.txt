A. P2-10 (second half): full-text extraction degradation is no longer silent
   DEC-req104-p2-10b-fulltext-degraded-20260920
================================================================================
Files: src-tauri/src/commands/settings.rs, src-tauri/src/extraction.rs,
       src/lib/api.ts, src/store/slices/reader.ts, tools/frontend-regression.mjs

BEFORE: `extract_fulltext` returned a bare String. "Extraction succeeded" and "we gave up and
kept the original" were INDISTINGUISHABLE in the return value, so the frontend guessed by
comparing strings - reader.ts did exactly `full === cur2.content` - which misfires whenever the
text legitimately matches, and was silent either way. There was also a second, separate silent
path: when extraction yielded NOTHING, the old guard was `extracted_text_len > 0 && ...`, so an
empty result simply fell through and was stored as if it were a successful extraction.

AFTER:
  1. `ExtractOutcome { html, degraded, reason }` is returned instead (commands/settings.rs).
  2. The decision was extracted into a pure function so both degradation shapes are directly
     unit-testable: `extraction::degradation_reason(original_html, extracted_html)
     -> Option<&'static str>`; the command only acts on it (store vs. report degraded).
  3. Two degradation shapes are now distinguished with accurate reasons:
       - empty extraction (page had no usable body: not HTML, script-only, unparseable), and
       - extraction significantly shorter than the original (< 80%), i.e. the original was
         probably already the full text.
  4. Frontend: `api.ts` gained `ExtractFulltextResult`; `store/slices/reader.ts` now reads the
     `degraded` flag directly on BOTH paths (automatic on-open fulltext, and the manual refresh
     button), replacing the string comparison and the extra `fulltextExtracted` special-case
     that existed only to work around it. On degradation both paths now toast
     "未采用全文提取：<reason>" and keep state unchanged (no flag, no fulltext view).
  Success-path behaviour is unchanged: on success the content is stored, the extracted flag is
  set, and the fulltext view opens.

B. P2-11: AI input validation and config observability
   DEC-req104-p2-11-ai-validation-20260920
================================================================================
Files: src-tauri/src/commands/ai.rs, src-tauri/src/ai.rs

  B1. `ai_summarize` had NO empty-body guard, while `ai_translate` did
      (`if html.trim().is_empty() { return Err(...) }`). An empty body therefore still fired a
      real model request (wasting tokens, and with an empty response nothing was cached), and
      the user just saw "no summary appeared". Now it returns
      "文章无正文可摘要", symmetric with translate's "文章无正文可翻译".
  B2. `ai.rs::AiConfig::from_json` silently fell back to `deepseek-chat` and
      `https://api.deepseek.com` when the `preset` was unknown. A user who picked a
      non-existent preset had their request sent to a PROVIDER THEY DID NOT CHOOSE, with no
      signal at all. Now only two shapes are legal:
        - preset matches `PRESETS` -> that preset's default model/base_url, or
        - custom (explicit non-empty `model` AND `baseUrl`) -> used as given.
      Anything else returns an `aiNotConfigured` error naming the unrecognised preset.
      NOTE the custom path must keep working: the pre-existing unit test
      `config_from_json_full` sends `preset:"custom"` with explicit model+baseUrl.
