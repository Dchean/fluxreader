================================================================================
WHY THIS TASK EXISTS
================================================================================
My own TASK-081 commit (d46eff2) grew src-tauri/src/db/articles.rs from 751 to 930 lines by
adding P3 unit tests, which breached REQ-105 acceptance ① ("拆分后无超过 800 行的生产单体").
The owner instructed: "评估是否有拆分必要，如果没有的话可以不用管" — i.e. assess whether a
split is actually warranted rather than assume the line-count rule must be satisfied by code.

================================================================================
DELIVERABLE 1 — ASSESSMENT: the file does NOT need splitting
================================================================================
Measured by splitting each revision at the #[cfg(test)] boundary:

  revision                              total   production   in-file tests
  TASK-064      (6e36fdb)                 791      716            75
  after TASK-081(d46eff2)                 998      751           247
  current       (TASK-082)                994      747           247

Production code has ALWAYS been under 800; only the total crossed the line, because unit tests
live in the same file (Rust convention — they need access to module-private items).

Four reasons the split is not warranted (all evidenced):
 1. Single cohesive domain: everything operates on the `articles` table and its immediately
    adjacent binding/dedup/state columns, sharing `ARTICLE_COLS`, `article_row`, `article_where`.
    Splitting would trade cohesion for jump cost and force many cross-module exposures.
 2. No natural seam: TASK-079 could split `ingestion/` because its four parts (HTTP conditional
    GET / parsing / staged refresh / favicon) share no internal state. `articles.rs` is the read
    and write halves of ONE table — it has no such structure.
 3. The BRIEF already ruled on this exact class of file: non_goals says verbatim
    "不拆分 Overlays/Timeline/db/sync_map.rs/base.css 与协议客户端（评估结论：内聚良好，拆了只加跳转成本）".
    `articles.rs` is the same judgement.
 4. Cost/benefit: ~747 production lines of pure movement, cutting 15 `pub fn` (measured: exactly
    15 in the production section) plus their call sites, plus an independent review round — for
    a smaller file and no real maintainability gain.

Recorded in `.workflow-kit/docs/AUDIT-20260919-v2.md` §「一之附二」, including a
recommendation that REQ-105 ① be measured on the PRODUCTION segment (or exclude in-file
#[cfg(test)]), otherwise any task that adds unit tests to an existing file "violates" it.
