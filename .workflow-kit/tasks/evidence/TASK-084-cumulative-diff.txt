TASK-084 change set — AUDIT P3[F4]: markEntriesReadBulk 逐条 IPC → 一次批量命令 (REQ-104)

================================================================================
WHAT CHANGED
================================================================================
Before: `reader.ts` did `Promise.allSettled(unread.map((id) => api.setRead(Number(id), true)))`
— one `invoke('set_read')` PER id. "Mark all read" or scroll-marking with several hundred ids
meant several hundred IPC round-trips.

Now:
  · Rust  `commands/articles.rs`: new `set_read_bulk(ids, read)` command. It takes the DB lock
    ONCE, loops the ids through the EXISTING `record_read_state(conn, id, read)`, then calls
    `schedule_state_push` once outside the lock. Empty `ids` returns Ok immediately.
    Registered in `lib.rs`.
  · Front `src/lib/api.ts`: new `setReadBulk(ids, read)`.
  · Front `src/store/slices/reader.ts`: `markEntriesReadBulk` now makes ONE call and reports a
    single failure toast via `.catch(...)` (so no unhandled rejection).

Because the bulk command reuses `record_read_state`, the semantics are by construction identical
to the per-item path: local `is_read` write, `sync_queue` enqueue (action `read`/`unread`), and
"enqueue even when no backend is configured, push段 silently skips" (A-5).

================================================================================
EVIDENCE — the two claims that matter
================================================================================
Claim A ("semantically equivalent to the per-item path"):
  Rust test `set_read_bulk_is_equivalent_to_per_item_read_state` seeds TWO databases identically,
  runs the per-item path on one and the bulk path on the other, and compares
    · count of locally-read articles, and
    · the full `sync_queue` item set (action + article_id, ordered)
  They must match exactly. A second test covers the `read=false` direction.
Claim B ("one IPC, not N"):
  The harness already records every invoke in `invokeCalls`. The assertions now require
  `invokeCalls.filter(c => c.cmd === 'set_read_bulk').length === 1`, `... 'set_read').length === 0`,
  and that the bulk payload contains exactly the unread ids.

assertions FAIL (the two `(f)` ones and the `(L1)` one); restored → 314/314.
