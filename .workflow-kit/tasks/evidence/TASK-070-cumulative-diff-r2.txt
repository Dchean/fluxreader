(bullet 3) still claimed that locally failed direct fetches "另行回退后端拉取 (source='miniflux')".

(db/feeds.rs:16), inside FEED_COLS (:21), as a read (:34), as a write (db/feeds.rs:125 in

matched neither URL nor remote_id AND the remote feed is already bound", which is unrelated to
fetch failure. The real mechanism is exponential backoff retry.
  Fix: sync/mod.rs header rewritten to state that origin='remote' feeds are covered implicitly by
  the reading-list (GReader) / unread+saved (Fever) pulls, that no fallback-on-failure path exists,
  and that fetch_failed only drives backoff (pointing at set_feed_fetch_state / feeds_due_for_refresh).
