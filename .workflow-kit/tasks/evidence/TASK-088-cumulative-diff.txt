================================================================================
THE CHANGE
================================================================================
`src-tauri/tests/refresh_dedup_e2e.rs`'s mock HTTP server thread had TWO exits that killed the
WHOLE server thread rather than just one connection:

  (a) `let mut stream = stream.unwrap();` — panics the thread if a connection errors;
  (b) `if n == 0 { return; }` — a NORMAL client disconnect (the response carries
      `Connection: close`) returned out of the entire `for stream in listener.incoming()` accept
      loop instead of just ending that connection.

Either one makes every SUBSEQUENT request in the same test unable to connect, and the symptom
masquerades as a "fetch failure" rather than a test-infrastructure fault — which is exactly why
this is worth fixing.

Now: a bad connection is skipped (`let Ok(mut stream) = stream else { continue }`), a read-side
disconnect only `break`s the current connection, and a write failure is ignored for that
connection only.
