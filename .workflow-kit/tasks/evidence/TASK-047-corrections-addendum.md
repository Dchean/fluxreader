## 瑕疵 1：日志第 18 行的括注自相矛盾

`TASK-047-verify-log.txt` 第 18 行写：

```
Tab 走满一圈：停靠点 32 个（主视图 32 + 回绕锚点 1）
```

**自相矛盾**：32 若已含回绕锚点，则主视图应为 31；若主视图确为 32，则总数应为 33。
**真实口径**：走一圈会额外访问一次「首个停靠点」作为**回绕确认**（我在代码里 push 了这条并标 `wrapsToFirst`），
故原始计数 = 主视图 + 1；**严格的主视图停靠点为 31**。

**为何不影响结论**：消融对照的不变式是「**主视图停靠点在两态下相同、差异全在浮层内**」——
该不变式由审查者独立复现（31 = 31），与括注口径无关。

## 教训

1. **计数口径必须在生成时就写清楚**：瑕疵 1 的根源是我在脚本里把「回绕确认」这条也
   `push` 进了 `stops`，输出时却按「主视图 + 回绕锚点」分段括注，两者对不上。
   正确做法是**在生成侧就分开计数**（主视图 / 回绕各一个变量），而不是事后在文字里解释。
2. **同一量在多处复述时需同源**：瑕疵 2 是同一个数值被手写进两处、
   各自在不同时点测量。应由脚本一次算出、两处引用同一变量。
3. 这三处都属「结论对、表述不严」——独立审查者把它们与「影响验收项的错误」区分开，
   判为**非阻断**，处理得恰当；但**记录在案**，避免下一个人按字面采信。
