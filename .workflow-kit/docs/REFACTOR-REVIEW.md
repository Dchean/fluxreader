## 1. 总体建议

**M2 结构性重构中最有价值的部分已经完成并合入，剩余队列应先做功能与兼容，结构整理择机而非齐头并进。**

依据：

- 本项目 M2 处置方案（ISSUE-008）认定的首要结构问题是 **SQL 边界失守**（commands.rs 13 处、sync.rs 17 处直接 SQL）。该问题**已解决并合并**（TASK-017、TASK-022）。本轮实测：`commands.rs` 与 `sync.rs` 直接 SQL 均为 **0**，132 处 SQL 全部集中在 `db.rs`。
- 剩余 `ready` 任务分两类：
  - **功能/兼容**：`TASK-028`、`TASK-029`（FreshRSS 两组合实测 0/3 失败，ISSUE-017/018，P1）、`TASK-027`（OPT-004 敏感凭据排除加固，DEC-009 已确认需求）。
  - **纯结构整理**：`TASK-023`（db.rs 模块化）、`TASK-024`（sync.rs 分层）、`TASK-025`（commands.rs 命令组拆分）、`TASK-026`（store.ts 拆 slice）。
- 结构整理的价值是**可读性/可导航性/变更风险下降**，不是缺陷修复；其收益取决于后续变更频率，属"渐进重构"而非"必须重写"。

**因此：不预设全做 4 个结构任务；允许保持现状。** 若要做，按收益排序、单项试点，不做"一次性拆完整个仓库"。

判断范围：本结论覆盖 `src/` 与 `src-tauri/src/` 的模块结构与既有问题清单；**不含**运行时行为验证（未运行）、真实服务兼容实测（未闭环）、性能与覆盖率评测（无目标）。

## 3. 最重要的发现（证据 → 影响 → 建议 → 不确定性）

### F1. FreshRSS 兼容缺口（ISSUE-017 / ISSUE-018，P1）— 最高价值、优先修

- **证据**：`docs/ISSUES.md` 真实服务实测（2026-09-13）：Miniflux × GReader/Fever 均通过；**FreshRSS × Google Reader 0/3**（`greader.rs` 用 `resp.json()` 解析 ClientLogin，FreshRSS 返回经典文本）、**FreshRSS × Fever 0/3**（`fever.rs` 硬编码 `{base}/fever/?api`，FreshRSS 实际在 `{base}/api/fever.php`，404）。
- **影响**：`REQ-SYNC-001` 明确要求"面向 FreshRSS / Miniflux"。当前两种协议对 FreshRSS 均不可用 → 已确认需求的部分组合不可用。
- **最小有效改法**：`TASK-028`（登录解析 JSON→文本双格式回退）、`TASK-029`（`.php` 端点按 `{base}?api` 直用）。均为**局部**修复，不动架构。
- **验证**：修复后用测试账号复测 FreshRSS 两组合；修复前失败、修复后通过的对照。
- **不确定性**：真实服务复测依赖测试凭据（不写入仓库）；FreshRSS 版本范围仍属 `Q-COMPAT-001` 未决。

### F2. SQL 边界（ISSUE-008）主体已解决 — 结论：无需再重构，只需同步文档

- **证据**：本轮测量 `commands.rs`=0、`sync.rs`=0、`db.rs`=132 处 SQL 模式。
- **影响**：M2 认定的首要结构风险已消除；"所有 SQL 集中 db.rs" 现在基本成立。
- **建议**：`docs/ISSUES.md` ISSUE-008 行与 `docs/ARCHITECTURE.md`（仍写"sync.rs 仍有 17 处"）与本实测不符，属**文档漂移**，应同步（是否需要新授权待定）。
- **不确定性**：仅静态模式计数，未验证 SQL 语义等价（由 TASK-022 的 105 项测试与哈希审查背书）。

### F3. 职责聚合（ISSUE-009）— 何时值得动，取决于后续变更频率

- **证据**：`src/store.ts` 1493 行 / 22+ 职责（M2 认定为 ISSUE-009 最典型）；`db.rs` 3516 行；`commands.rs` 1254 行；`sync.rs` 1201 行。
- **影响**：单文件越大，一次变更的回归面越大、评审越难；但**文件长本身不是重写理由**。
- **建议**：若要动，**优先级 store.ts 拆 slice（TASK-026）> db.rs 模块化（TASK-023）> sync.rs 分层（TASK-024）≈ commands.rs 命令组拆分（TASK-025）**。理由：TASK-026 对应最集中的职责聚合；TASK-024/025 对应的文件在 SQL 收敛后已降到 ~1200 行、耦合显著下降，边际收益最低。
- **不确定性**：收益无法用现有测量量化；只有"改起来是否更省事"的真实体验才能证明。

### F4. 保护网缺口 — 动大结构前应先补保护

- **证据**：现有保护为 105 项 Rust 测试 + 8 项前端逻辑检查；`ISSUE-003`（无安装/启动、无真实桌面 UI E2E）、`ISSUE-007`（真实服务兼容未闭环）、`ISSUE-006`（9 项未运行：7 真实服务 + 2 本地 fixture）。
- **影响**：结构重构的安全网对"同步链路的真实协议兼容"**无覆盖**；纯移动式重构靠测试网兜底，但功能修复只有真实服务复测才能证明。
- **建议**：**先补关键行为保护**（尤其 FreshRSS 兼容回归，可复用现有 live test 骨架），再考虑铺开结构重构。
- **不确定性**：真实桌面 E2E 需要驱动能力，成本未评估。

## 4. 保留范围 / 非目标 / 收益 / 成本 / 验证

**必须保留（任何方案不得触碰）**：核心 4 项 + OPT-001～010；OPT-004 仅订阅源+客户端设置、排除凭据；`src/`、`src-tauri/`、`tools/` 结构；现有同步/协议/安全/凭据边界。

**非目标（本次）**：不重写架构、不换技术栈（不引入 ORM、不替换 Zustand）、不做数据库迁移、不做 UI 改版、不升级依赖、不改门禁。

**预期收益**：
- 功能任务（F1/F2-修/TASK-027）：用户可见——FreshRSS 可用、凭据边界达标。
- 结构任务（F3）：可维护性——单文件变小、职责分离、变更回归面下降；**不产生用户可见变化**。

**成本与风险**：
- 结构任务为纯移动/重组，风险中等（105 测试网 + 公开函数集合对照）；主要风险是"移动中改行为"（TASK-022 已吸收 `db.rs` 覆盖事故教训，要求 Edit 追加式）。
- 功能任务风险中等，但需真实服务复测，且受 `Q-COMPAT-001` 未决影响。

**验证方式**：功能任务——修复前后对照 + 真实服务复测；结构任务——`cargo test` 全量、`clippy -D warnings`、`fmt --check`、`grep` 结构断言、公开函数集合对照；回归后旧行为不变。
