# 按使用方式选技术

用户先说明业务需求，Agent 再根据现有项目、目标设备和维护成本推荐技术。不要求零基础用户先选择框架或数据库。

| 主要使用方式 | 优先核对 |
| --- | --- |
| 本地小工具或脚本 | 现有运行环境、输入输出、文件保护、是否需要图形界面 |
| 浏览器应用 | 使用设备、是否多人、数据保存位置、离线需求、部署方式 |
| 桌面或移动应用 | 目标系统、安装和更新、平台权限、已有成熟壳或模板 |
| 接口服务 | 实际调用方、认证、数据和运行位置、已有服务能否复用 |
| 旧项目重构 | 已有技术栈、行为基线、维护痛点、兼容和回滚边界 |

先找可复用组件或类似项目，比较维护性、可靠性、资源性能和迁移风险，不以少花实现工作量降低质量。没有服务端需求不预建服务端，没有数据关系需求不预设复杂数据库。测试覆盖关键行为，覆盖率百分比不是跨项目统一门槛。

只有影响费用、体验、兼容性或长期维护负担的选择才需要用户决定；普通实现细节由 Agent 在已确认范围内处理。职责映射见 [ROLE_COLLABORATION](ROLE_COLLABORATION.md)。
