# 有限重试与中断接续

run 在宿主会话内推进一个任务。任务、运行记录和检查点保存在项目中；宿主关闭后没有常驻服务代替它工作，重新接手的 Agent 先用 start/next 检查现场。

## 已落实的上限

- 默认最多修复 3 轮，任务墙钟预算 90 分钟，原始时钟跨会话保留。
- CLI 单次调用默认最多 600 秒，实际使用它与任务剩余时间的较小值；验证命令默认最多 300 秒。
- 同一阶段的连续网络失败默认最多自动重试 2 次，退避 5、15 秒。失败数从原始 RUN 中计算，等待时间从原失败结束时间计算，重开会话不清零。该阶段真实成功后，后来的新故障才构成新一轮连续失败。
- 两次相同测试/审查失败且候选没有变化时，run 返回 replan，停止原样重复修复。主 Agent 先分析日志、记录不同方案，再在剩余修复预算内 begin；不要机械重复 run。
- 同一项目只允许一个活动运行。超时、取消和活动进程需要先检查，不自动当成网络失败重放。

上限可在确认范围内配置，但不能靠新建任务、清空记录、切换模型或修改认证绕过。时间和修复额度追加继续使用有真实决定依据的 extend；受限付费调用的费用检查每次重试仍执行。

## 哪些可以自动重试

任务定义中的 retry_safe 默认为 false。只有主 Agent 已检查该任务及其门禁可以重复执行，才设为 true：例如本地源码修改、模拟数据和可重复的只读检查。该标记被纳入冻结定义，不能失败后临时打开它给自己放行。

支付、通知发送、上传提交、生产迁移、真实数据写入或效果未知的命令不能直接标为可重复。高风险任务不自动重试。

工具仅把明确的连接重置、DNS 临时故障、连接超时、部分暂时性 HTTP 错误等识别为 network。认证、权限、证书、配额、计费、缺失依赖以及结构化输出损坏交给主 Agent 处理，不盲目重试。

每次重试前核对：原进程已退出、没有其他活动 RUN、任务定义未变、当前文件与失败后保存的完整现场一致、退避后仍有预算。等待期间又发生修改时停止自动重放。失败日志保留，网络重试不冒充代码修复轮。

实现阶段网络失败后重试同一任务并先读已有代码；验证阶段继续验证；审查阶段候选未变时继续审查。不能把已经实现的部分当作不存在，重复追加接口或重复执行外部副作用。

## 需要主 Agent 接手的情况

自动次数用完、失败无法明确归类、缺少现场快照、用户改过文件、费用用量未知或任务不适合重复时，保存卡片并返回明确动作。主 Agent 可以继续独立的本地任务；解决根因后，依据已有授权检查并继续原任务。不要循环调用同一个失败命令来“碰碰运气”。

控制器锁或 RUN 遗留时，先核对进程和文件，再用 recover 保存接手依据。recover 的 source 是检查事实，不要求每次都向用户重新索取已有授权。仍存活的进程不会被自动接管；强制关闭或效果不明的运行也不会自动假定可以重放。

网络自动重试不等于失败操作具有事务性，也不等于后台永久在线。新环境和真实 CLI 仍需做一张小任务的实机验收。
