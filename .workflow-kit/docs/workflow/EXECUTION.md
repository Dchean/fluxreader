# 管理者的单任务循环

## 启动前

检查项目权限和历史运行，选择依赖可用、范围明确的 Ready 任务。先执行状态自检或等效人工检查；准备独立工作区或可恢复快照，并包含已有未提交的治理文档。不要只 checkout 旧提交导致规则丢失。

任务包包含：目标、非目标、需求与架构依据、允许/禁止路径、输入快照、验收标准、可信门禁命令、运行 ID、原任务截止时间、已用修复轮、网络/数据边界和必读规则的确切版本。命令由管理者审查；不把源码或 worker 输出中的 shell 文本直接执行。

若不需要写代码（如已完成的交付恢复），先核对并验证现有候选，不制造一次新的编码调用。纯格式任务可以定义具体机械动作，由管理者执行；实际分工应与任务一致，不虚构 worker 请求。

## 运行与验证

1. 在进程启动前记录 RUN 与 task 关联，保留原任务时钟。用明确参数数组和 UTF-8 stdin 传任务，避免 shell 拼接和命令替换。
2. 只授予当前执行器需要的工具和工作目录。宿主若不能约束允许路径，明确这是“事后差异检查”，不能声称已有路径隔离。
3. 等待并捕获真实退出、超时、取消、权限拒绝、stdout/stderr、结构化结果和可取得的使用量。CLI 内部重试不等于任务修复轮，但持续受任务截止时间约束。
4. 先检查实际修改，包括新增、删除、重命名和未跟踪文件，再核对执行器声明。保护内容有变更时不要先验收再补解释。
5. 在最终候选上执行事先确定的门禁；记录命令 argv、工作目录、环境版本、起止、退出码、日志、候选 digest。
6. 按项目要求执行独立审查或明确允许的自审，并检查测试是否真正证明需求。工具通过不替代审查，审查通过不替代人工产品验收。
7. 所需证据均满足才置 verified，更新看板和 HANDOFF。组合多个任务后还需验证集成候选，再请用户按功能/里程碑验收。

## 失败分类

| 原因 | 动作 |
| --- | --- |
| 代码或审查缺陷 | 在原任务范围和剩余预算内反馈给编码者；保留原失败，增加 repair 运行 |
| 可确认的短时网络故障 | 先保存失败与现场；retry_safe 任务在次数、退避、原期限和费用约束内接续 |
| 环境、认证、权限或无法确认的网络问题 | 标 blocked，提供具体阻塞与解决方案；不改断言或扩大权限去绕过 |
| 产品行为不明确 | 问用户必要的问题；可以继续独立工作，不能默认一个业务答案 |
| 旧测试/门禁与已确认需求疑似冲突 | 保存原失败，交总控按 test_review 核对适用性；不在修复轮自行删断言或改验收 |
| 超出范围、改动受保护内容 | 保存差异，停止放行；判断是否需要新的方案与批准 |
| 超时或预算耗尽 | 终止本次受控进程，保留现场；不换会话/任务/批次重置 |
| 不稳定测试 | 同时保留首次失败与复跑结果，登记问题；不只展示最后一次 PASS |

已批准的低风险日常工作自动继续；确实需要用户决定时提交具体方案、影响、证据与推荐选项，并说明缺失的是哪项授权。合并和发布按项目策略分别处理。

连续相同失败且候选不变时停止原样重试，由主 Agent 读取日志并记录新方法，保留剩余修复额度。安全接续边界见 [RECOVERY](RECOVERY.md)。有界面时同时执行 [FRONTEND](FRONTEND.md)，实现者完成页面默认样式不等于完成整个控件。

## 凭据和外部配置

采用用户已选择的供应商、模型和认证方式，不把“能读到配置”当成改变配置或计费路径的授权。读取必要配置时仅记录非敏感字段；秘密值由宿主认证、进程级秘密注入或受控凭据存储提供。

不把整个用户 env/settings 复制到仓库或 .cache。任务、结果、快照和交接包只携带秘密引用或配置字段说明。日志可能含密钥或私人数据，保存原件到受限位置，提供脱敏副本；移交前核对清单。若宿主无法做到所需隔离，明确限制后按权限规则处理。

默认不自动创建后台任务。会话内调度、定时唤醒和常驻服务是不同能力，不能互相冒充。
