# 新项目起步

先按 [INTAKE](INTAKE.md) 确认角色、目标项目目录、基本产品范围与权限。

1. 用最少文档明确目标用户、核心场景、首个里程碑、非目标与验收要求。未知业务规则问用户；不要用技术模板补造需求。
2. 完成必要的流程草图、技术约束与目标架构。没有旧系统就明确当前架构“不适用”，不虚构考古或已有基线。
   有界面时先验证关键技术限制，再按 [FRONTEND](FRONTEND.md) 用沿用组件和模拟数据制作可点击预览；用户确认后才接入真实功能。
3. 把最小可运行纵向功能拆成首批任务：运行环境与骨架、一个端到端核心路径、对应测试和构建。技术栈确定后再选择实际工具与目录。
4. 依赖安装、代码和 CI 修改在相应范围已获批准后执行。锁定依赖与可重复构建方式，不从模板携带别的项目版本。
5. 首个小任务走完编码、真实工具检查、审查和基础验收，再扩大自动推进范围。第一次测试是从无到有建立基线，不写“原有测试已通过”。

不要为了满足通用目录图创建无用途的空模块或四套空测试。项目可以是服务端、桌面、移动端、脚本库或 Web；目录随架构确定，测试层次随风险选择。测试设计不能省略，只是允许明确的不适用。

后续按 [LIFECYCLE](LIFECYCLE.md) 交付，并持续维护需求到验收的映射。
