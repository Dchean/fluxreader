# 宿主 Agent 包办与审查

Agent 包办表示不调用额外编码 CLI，不表示只能使用同一个上下文。主 Agent 可以管理和实现，再由宿主中未参与实现的新 Agent 上下文审查；使用同一个模型也可以。

## 具备独立上下文时

1. 用户确认执行和审查安排；coder/reviewer 都可使用 current_agent，review_mode=independent_required。
2. 主 Agent 固定任务、实现并运行真实验证。
3. 用 review-packet --task 取得当前需求、候选、原始验证和审查要求。
4. 使用宿主实际支持的子 Agent 或新会话，把该包交给审查者。提供必要源码与证据，不复制作者会话、内部推理或“已经没问题”的结论。
5. 审查者按 REVIEW 返回报告；总控用实际审查上下文标识记录 review --mode independent。记录工具被调用的上下文不等于审查工作的来源，不能随便编一个新 ID。
6. 未通过时回到原任务修复、验证并再次审查。审查可串行完成，不要求另开长期进程或换模型。

显式 role=reviewer、task_id 和 candidate_digest 的输入包指定本次审查身份；不是恢复旧工作流的 Worker 角色。不得在审查时修改业务文件给自己放行。

## 只有一个上下文时

只有用户已选择 self_review_allowed，且任务不是高风险，才可采用自审。先暂停实现，从原需求重新检查完整差异，找可能推翻结论的输入、边界、异常与恢复场景；真实测试和 UI 实看仍按任务执行。

报告必须覆盖需求、回归、异常路径、可维护性和性能，给出实际 evidence_files、简短可核对的 analysis 和当前 verification_run。没有适用性依据不能标 NOT_APPLICABLE，没有检查完不能 PASS。测试应能发现目标缺陷，而不只是运行成功或断言实现当前输出。

自审始终不是独立审查。没有新上下文时如实展示限制和证据；高风险或已选 independent_required 的任务保持待审/阻塞，不能偷偷退化。无需让用户逐行看代码，但不能把自审承诺成没有遗漏。

## 用户可见进度

按 [PRESENTATION](../PRESENTATION.md) 展示阶段和任务。宿主有原生面板就调用实际工具，否则直接在对话显示 progress 结果；任务文件只负责保存事实。

没有文件/终端能力时只能提供建议，实际验证为 NOT_RUN；不能声称项目已经运行。质量目标优先于节省 Agent 工作量，仍保留防空转和费用边界。
