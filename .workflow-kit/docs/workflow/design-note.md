# Agent Note: 可移植的项目工作流程

Status: implemented

## Problem

项目管理方法如果绑定一个产品、一个模型的历史会话或一个执行器，就难以在新项目和已有项目间复用。只写提示词又不能发现任务状态矛盾、历史运行遗漏及无证据的完成声明。

## Decision

交付一个自包含的 Skill 包，同时提供不依赖 Skill 注册的 START 入口。主 Agent 分轮询问业务目标，先寻找类似项目或成熟组件，再确认产品、执行方式和授权。以兼容的 schema_version=1 维护真实任务和运行记录，将职责映射到 manager/coder/reviewer 三个执行单元。

标准库工具增加受控的前台执行、真实命令日志、候选校验和检查点恢复；主 Agent 负责业务判断和跨任务协调。每次调用前记录 RUN，失败后保存原结果，按实际文件接续。任务卡和看板从唯一任务 JSON 生成；网络中断不重置任务身份、时钟或修复预算。

参考方案记录来源、维护情况、许可证、适配与限制。直接复用依赖或代码时固定版本；仅参考设计不引入运行依赖。新接入通过 bootstrap 在独立目录保存本包记录，规则入口位于原 AGENTS/CLAUDE 顶部，原文与旧任务保留。经典 init/adopt 仍兼容，但不能把外来状态当成已接入，也不能通过再次初始化重置预算。

保留单 agent、管理 agent 配合编码 CLI、自定义执行工具三种方式。逻辑角色与物理进程分开：同一上下文的自审必须如实记录，不能伪称独立审查。新项目与重构项目共享交付循环，但采用不同的起步路线。

这是包本身的设计记录，不授予使用它的新项目任何权限。目标项目复用该项目实际确认的需求与授权。个人模式默认少量业务文档；Memory、Lessons、接口说明等扩展模板按需建立，不重复维护相同事实。

PROJECT_STATE、任务卡和看板由已有 JSON 与检查点生成。后续任务通过明确依赖延续之前的候选，同时继承其快照范围和必需回归命令；旧 PASS 保留为历史证据，最新任务负责当前组合版本，验收包括尚未接受的延续链。这样允许多个功能逐步修改同一源码，又能发现后来的未验证修改。

任务保留首次开始时间与原截止时间。断线后的孤立锁可以单独恢复；恢复先辨认活动进程，失效的预算不能遮住恢复入口。需要更多时间时，extend 追加有真实决定依据的期限与修复额度，不清空原记录。续批通过既有明确策略或新决定执行；受美元额度限制的批次需要明确续批决定，不能靠自动换批清零费用。

执行协议、Python 子进程文本输入输出统一使用 UTF-8，避免 Windows 本地编码破坏中文任务 JSON。原有实进程测试发现该问题，新增中文管道、恢复、共享源码延续和续批回归覆盖这些边界。仅完成已建任务不等于整个产品完成；最终验收必须明确确认完整需求范围。

保留三个执行单元，明确补足 UI/UX、前端、后端、QA 和视觉验收职责。新界面或改版先核对关键技术限制，再用可沿用的组件、统一主题和模拟数据制作可点击预览；用户实际接受该预览后才能开始正式实现。既有界面的局部维护沿用原设计，不强制重做全套预览。下拉展开、浮层、焦点、禁用和错误状态成为任务的明确检查项，而非只要求页面配色一致。

UI 任务冻结约定引用及检查状态，审查要求截图、交互报告和覆盖状态，并保存证据摘要。已确认的约定不能由正式实现静默改写；用户对未接受预览的意见经 feedback 回到原任务修复，预算与历史保留。工具能发现缺少或改变的证据，不能替人判断审美，也不把模拟数据预览称为后端完成。

retry_safe 在准备任务时冻结。只有可安全重复、风险非 high、已明确归类为短时网络故障的任务才自动接续；每次核对原进程、完整失败现场、定义与剩余预算。默认同一阶段最多两次自动重试，按原失败时间退避 5、15 秒，阶段成功前不因换会话清零。CLI 单次默认上限 600 秒，仍受任务总期限约束；费用检查每次执行。相同测试/审查失败且候选连续未变时回到主 Agent 重新分析，保留剩余修复额度。

已有项目先区分价值评估、已确定改造和普通小修。显式使用本包时，短评估也先核对真实接入，业务代码可保持未授权；只有用户明确仅参考方法时才不接管，并标明未接入。评估允许保持现状、补保护或证据不足的结论。实际重构建立行为基线和真正的源码恢复点，再做最小试点。snapshot 只核对哈希，不承担源码备份；原测试失败作为基线事实，不触发未经授权的自动修复。

这个分支由主 Agent 的业务与证据判断驱动，沿用现有 adopt、授权、任务、验证和恢复机制，不新增自动架构评分器或另一套状态机。只有评估目标变成了经授权的实现目标，才更新对应决定、策略和阶段；不能通过再次 onboard 清空旧记录。

用户在带旧 Agent 资料的仓库中试用后，暴露出入口缺少物理确认的问题：外来 PROJECT 同样可能是 schema_version=1，却使用 phase/execution_policy 而非 stage/policy；旧 CLAUDE 文档还可能把总控固定成 Worker。bootstrap 现在验证工作流身份、配套工具和顶部入口，给出明确的 connected 回执；不能凭同名文件或口头承诺接管。

新布局在 .workflow-kit/ 保存记录和工具，根入口为 WORKFLOW-KIT.md，产品命令仍在真实项目根运行。路径映射只用于本包记录，不改变产品快照或原任务目录的含义。旧业务资料采用引用；有旧流程时，legacy_review 明确已读来源、保留约束、旧任务处置及角色/流程冲突，不能静默沿用旧队列或旧授权。

绑定校验覆盖受管理文件和入口摘要，文本只容忍 LF/CRLF 的等价换行变化，原业务快照仍按原字节核对。接入失败回滚本次写入；已绑定时再次 bootstrap 只检查，不重置记录。工具版本不配套或旧版本缺标识时要求明确迁移，不盲目新建相同工作绕过预算。

## Alternatives considered

- **不做，继续手工复用既有提示词**：最强论据是没有新工具需要维护，熟悉项目的人可以灵活裁剪。未选为交付方式，因为需要反复清除产品事实和授权，容易把历史通过状态带到新项目。
- **只交付 AGENTS.md**：最强论据是简单、可直接读取且无需安装。单文件适合承载入口约定，但不适合混入多种执行器的参数、项目模板和运行证据格式；保留它作为生成项目的入口。
- **只交付某一平台的 Skill**：最强论据是发现和调用方便。增加通用 START 提示词和可复制的流程文档，避免把注册机制变成使用前提。
- **立即实现常驻多 agent 控制器**：最强论据是可管理跨会话队列与集中调度。保留主 Agent 协调及前台执行，因为当前需求优先是可复制、易启动和可恢复；退出宿主后不承诺继续工作。
- **引入 LangGraph 作为必需依赖**：它提供成熟的持久执行和状态基础设施，适合长期运行的服务。借鉴检查点与副作用恢复原则；此启动包先采用标准库和项目文件，降低初次安装负担。
- **只增加提示词和角色数量**：宿主 Agent 可以灵活完成工作，但不能因此证明状态、配置、执行器和真实测试已经连通。保留职责提示词，同时由脚本承担可机械验证的记录和执行。
- **初始化全部业务、Memory 和 Lessons 文档**：内容目录清楚，适合较长期项目；个人项目会重复记录进度与决策，所以默认保留最小文档，完整模板只在需要时生成。
- **永久冻结所有已验证任务的文件**：校验简单，但第二个功能修改同一文件就被拦住。采用带回归检查的候选延续；代价是必须串行准备依赖任务，不能随意分叉或丢弃前序验证。
- **断线就重新计时或重新建任务**：恢复快，却掩盖已用预算与失败。保留原时钟，显式追加授权额度；需要用户决定的额外时间仍须等待决定。

- **恢复七个固定执行进程和长角色提示词**：专门上下文有利于复杂界面的设计与检查；个人项目先明确专业职责、共享 UI 约定与验收证据，复杂时再增加专门上下文，避免多份状态和固定调度成本。
- **所有失败都无限重试**：短时故障恢复率可能更高，但权限、付费调用和不确定副作用会被重复触发。只对明示可重复的任务做有限退避，其余交回主 Agent 判断。
- **完整后端完成后再审 UI，或先做一次性静态稿**：前者先固定业务能力，后者起稿快；本包先验证关键可行性，再制作可沿用的交互前端，降低视觉返工，也避免做出无法落地的交互。

- **只把启动句改成“帮我重构”**：使用成本低，适合目标明确的熟练用户；对尚不确定是否要改的个人项目容易预设结论，因此补齐先评估分支和不改的出口。
- **新增一套重构评分/审批引擎**：统一分数和强制状态有利于大规模管理，但文件长度或测试数量不能决定真实改造收益；当前由主 Agent 解释证据并复用已有机制，避免新增维护面。

- **仅加强启动提示词或在旧规则末尾补一句**：修改少，但长旧文档容易先决定角色，文件名相同也不证明协议兼容；采用实际 bootstrap 回执与顶部入口，减少静默未接入。
- **把旧任务和规则整体覆盖/迁移到新格式**：目录可统一，但未知授权、预算和历史链接难以可靠自动转换；默认隔离保存新流程，旧内容不动，语义冲突由总控明确处理。

## Consequences

新项目和渐进重构共享同一小型标准库工具；用户回答业务问题，Agent 维护技术记录。初始化保留未批准状态，已有文件冲突先说明，不覆盖用户内容。重要决定复用已有 ADR/Notes；任务卡承担进度，设计记录承担理由。

持续执行仍依赖宿主会话。单写入者和串行依赖减少并发恢复成本，也限制了大型团队吞吐。继承的回归检查会增加验证量；旧业务规则有意改变时需要明确记录需求变更，不能让实现者删检查放行。若未来需要多写入者、跨会话常驻执行或复杂需求迁移，再单独评估事务存储和调度服务，不提前引入。

视觉流程增加一次用户确认和必要的截图/交互证据，适用于有界面项目，不强加给脚本或纯后端。有限自动恢复减少短时中断的人工接续，但遇到未知消费、变化的现场和非重复操作时仍会暂停；没有以便利为理由放宽原权限和费用约束。复杂项目需要更强隔离、平台控制器或更多专门上下文时再重新评估。

评估会增加前期调查成本，因此目标明确的小改动不重复做全项目评估。保持现状同样是有效交付；是否建议重构依赖实际业务计划、观察范围和验证质量，程序不能代替这一判断。评估记录、进度和技术取舍各自沿用已有归属，不扩展成新的报告平台。

隔离布局增加一个状态根，换取不破坏旧流程的接入；回执提供实际路径，避免用户手工记忆。保留原文不等于继续旧角色或队列；接入也不授权业务修改。文件校验不能证明宿主自动加载规则或模型绝对服从，WorkBuddy 等宿主仍需用明确的首条指令/固定项目指令调用入口，必要时在接入后新开会话。

## Verification

在包根目录运行 `python -B -m unittest discover -s project-workflow/tests -q`；Windows 实际子进程覆盖 UTF-8、失败修复、超时与模拟断网，状态测试覆盖初始化、保护既有项目、候选失效、任务延续、孤立锁和追加预算。可执行示例使用明确标记的确定性执行器，不冒充模型调用或真人验收。包检查核对分发文件哈希、JSON 和文档链接。

新增的实进程回归覆盖自动网络接续、持续故障上限、跨调用计数、stdout/JSON 故障、认证停止、无进展重规划、费用重查和 CLI 调用超时。UI 流程回归覆盖预览确认门槛、原任务反馈、控件状态覆盖和证据失效；这些合成图像/报告仅测试协议，不冒充实际视觉验收。

重构价值判断由主 Agent 完成，不把文档检查当成真实项目已评估。接入回归使用带旧 phase/execution_policy 和 Worker 指令的合成仓库，检查旧内容保留、独立任务执行、复制后 CLI、规则核对、入口篡改、换行转换和失败回滚。真实 FluxReader 仓库只读复现了旧 start 的 policy 字段错误，不宣称重现了已删除的 WorkBuddy 会话。

文本约定不是权限沙箱；本地校验也不能证明测试真实有效或批准真实存在，必须审阅原始证据。CLI 参数与能力会变化，应根据目标机器帮助及官方文档核对，不能静默去除限制来运行。复制模板不等于项目已具备自动化测试或已完成架构设计。
