## 三、架构与技术路线评估

**拆分成效**：commands.rs 1254→7 文件（最大 329）；sync.rs 1201→8 文件（最大 303）；store.ts 1493→9 slice（最大 378）；SettingsModal 1512→13 tab（最大 302）。除 ingestion.rs（766，唯一未拆旧单体）外无 700+ 行生产单体。Overlays 765/Timeline 751 内聚不拆。

**结构性发现（值得做）**：
1. **pull 游标失败仍推进**（最有价值单点）：greader_pull.rs:77-90 分块失败 continue、:116-119 set_last_sync_ts 无条件执行 → 失败块条目本轮丢失只能等全量。「偶发漏文章」类问题的结构性温床。改法：report.errors 含 pull 失败不推进游标
2. app_settings JSON blob 逐字段解析重复 6+ 处（lib.rs:38-96、commands/mod.rs:18、scheduler.rs:62,201-222）→ 类型化助手收口
3. 行类型契约无自动防漂移（lib/api.ts:38-144 手写镜像）→ 轻量 serde fixture 往返断言，不引 codegen
4. 仓库根目录垃圾文件（run*.log、teeth.log、`''' + $db + '''` 等）+ .gitignore 补全

**不建议动**：merge_remote_status 一带同步合并语义（pending 保护/read-anywhere-wins/跨源副本记账，有书面不变式）；Overlays/Timeline/sync_map/base.css；协议客户端；状态库/DB 访问层路线级更换。

**技术路线结论**：Tauri 2.11.5 + React 19.2.8 + Zustand 5 + rusqlite 0.32 bundled(FTS5) 对个人 Windows 桌面 RSS 阅读器是合适组合，依赖新近无冗余，**无更换必要**。唯一非常规是前端自研零依赖测试 harness——合理取舍非技术债；DOM 组件测试缺口存在（Timeline 虚拟化/Reader innerHTML/弹层未测）但边际价值低，需 DOM 验证时走 CDP e2e 路径。发布构建无日志（tauri-plugin-log 仅 debug）——个人应用可接受，记录备查。

**模块边界**：后端依赖单向干净（commands→sync/db/ingestion→db，无循环，HTTP 全在锁外）；前端 slice 键集两两不相交由 tsc 兜底，跨 slice 收口 internals 仅 7 处且只写自己的键。
