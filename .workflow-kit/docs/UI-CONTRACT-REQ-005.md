# UI 契约：REQ-005 交互动画打磨（TASK-042）

## 范围与冻结项

- 沿用现有 UI 与既有动效词汇表；不引入新依赖、新动画库或新的设计系统。
- 只改「出现 / 消失 / 展开 / 切换」的过渡与时长曲线，**不改布局结构、信息层级、配色与行为**。
- 必须复用既有 token 与曲线：`--transition-fast: 0.15s cubic-bezier(0.16, 1, 0.3, 1)`（src/styles/tokens.css:12），
  0.2s 同曲线见 base.css:2215 / 2227 / 2991。不得逐元素发明新时长或新缓动。
- **必须遵守既有性能取舍**：不要给 2col/3col 布局切换加 `grid-template-columns` 过渡
  （base.css:225-228 明确记录了这是有意的决定）。该场景的正确做法是让**内容**淡入。

## 必须覆盖的状态（ui_checks）

1. 列表与视图切换：切换布局 / 筛选 / 订阅时内容淡入（当前 `.list-entering` 是声明了却从未被应用的死代码，见 base.css:893）
2. 下拉菜单与右键菜单：打开时的入场（当前挂载即带 `open` 类，from 态永不渲染）
3. 阅读器：视图切换与文章之间的切换
4. 播放：底部播放条与全屏播放器的出现 / 消失（当前是 `display` 硬切）
5. 折叠与展开：侧栏订阅树、设置页分组、通知/译文/AI 区块
6. 覆盖层：弹窗卡片入场、灯箱图片、设置页分区切换、加载更多状态
7. 无障碍：`prefers-reduced-motion: reduce` 时必须关闭或显著削弱上述过渡

## 验收要点（逐条可核）

- 每个改动点都能在代码中定位到具体选择器与时长，且时长/曲线取自既有词汇表
- 修复「声明了却没生效」的死代码：`.list-entering` 必须真的被应用到元素上
- 下拉菜单入场必须是「先挂载、再在下一帧置 `open` 类」（rAF 或等价手段），而不是初始即带 `open`
- 以 `display` 切换的区块（AI / 译文 / 通知）改为可过渡的可见性方案，且不得破坏原有的隐藏语义（不可见时仍不可聚焦、不可被读屏读到）
- 新增 `prefers-reduced-motion` 保护，覆盖本次新增或修改的全部过渡
- 不改行为与布局；lint 0/0、build 通过、前端回归 26/26 全绿

## 需要提交的证据（放在 .workflow-kit/tasks/evidence/ 下）

- 截图 PNG：主视图与设置页（证明静态结果未被破坏）
- 交互报告 MD：逐条列出「选择器 → 原状态 → 改后时长/曲线 → 触发场景」，并显式说明**静帧无法证明动态效果**
- 诚实声明：报告必须区分「代码路径核对」与「实机操作观察」两类结论，不得用截图冒充动态证据

## 限制与不适用

- 不新增动画库；不做视差或纯装饰性动画
- 不改 REQ-008 的静态控件外观（属 TASK-041）
- 桌面单平台，无移动端手感目标
