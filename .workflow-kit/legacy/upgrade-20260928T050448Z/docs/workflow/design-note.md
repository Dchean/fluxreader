# Agent Note: 可移植的项目工作流程

Status: implemented

## Problem

项目管理方法如果绑定一个产品、一个模型的历史会话或一个执行器，就难以在新项目和已有项目间复用。只写提示词又不能发现任务状态矛盾、历史运行遗漏及无证据的完成声明。

## Decision

交付一个自包含的 Skill 包，同时提供不依赖 Skill 注册的 START 入口。已有项目先问重构意向，再结合实际分析以问题给用户选择路线；主 Agent 负责证据与建议，用户决定改进范围。新项目分轮明确业务目标，寻找类似项目或成熟组件，确认产品、执行方式和授权。以兼容的 schema_version=1 维护真实记录，将职责映射到 manager/coder/reviewer 三个执行单元。

目标是在必要复杂度内优选可维护、稳定和性能，工作量多少不作为降低质量的依据。先规划完整目标，再以小步验证控制风险；避免没有需求或可验证收益的层次、依赖和服务。质量目标用维护/可靠性验收及代表负载下的测量表达，不承诺所有维度同时理论最优。运行额度防止失控，不作为把项目缩成最低可运行版本的理由。

问答采用“提问＋补充”，每轮最多三个必要问题。执行方式显式选择 Agent 全部处理或 Agent + CLI，既有回答按适用范围复用。intake 把分轮答案存入原 BRIEF；建议与真实确认分开，确认带回答、来源和主题数值摘要。数值变化使旧确认失效；onboard 校验必答项，防止默认值代替同意。无界面和无外部服务不追问无关细节。新模块只审计问答完整性，不建立另一套任务状态机，也不认证会话身份。

requirements 统一收集主目标、已知 Bug、新功能和其他要求，区分本轮纳入与暂缓；没有补充也记录真实回答。quality 明确维护、稳定和性能安排。任务引用需求 ID，进度展示未拆分项，项目级验收检查已确认范围的任务覆盖。BRIEF 必须与其用户决定快照一致，防止后续直接删减要求而丢失目标。

标准库工具增加受控的前台执行、真实命令日志、候选校验和检查点恢复；主 Agent 负责业务判断和跨任务协调。每次调用前记录 RUN，失败后保存原结果，按实际文件接续。任务卡和看板从唯一任务 JSON 生成；网络中断不重置任务身份、时钟或修复预算。

参考方案记录来源、维护情况、许可证、适配与限制。直接复用依赖或代码时固定版本；仅参考设计不引入运行依赖。新接入通过 bootstrap 在独立目录保存本包记录，规则入口位于原 AGENTS/CLAUDE 顶部，原文与旧任务保留。经典 init/adopt 仍兼容，但不能把外来状态当成已接入，也不能通过再次初始化重置预算。

保留单 agent、管理 agent 配合编码 CLI、自定义执行工具三种方式。逻辑角色与物理进程分开：同一上下文的自审必须如实记录，不能伪称独立审查。新项目与重构项目共享交付循环，但采用不同的起步路线。

Agent 包办与审查独立性正交：宿主可用未参与实现的新 Agent 上下文审查，同一模型即可，不要求 CLI。review-packet 提供当前需求、候选和原始验证，省去作者检查点，不复制作者会话。高风险或策略要求独立时不能自审。通过报告包含需求、回归、异常路径、维护性与性能五项依据，quality_digest 绑定报告、候选和证据；已核验源文件从其原候选清单取摘要，允许后续合法任务修改同一源码而保留历史审查。

同一次审查摘要计算只读取同一份证据一次，复用已算摘要，不引入跨调用缓存或跳过后续变更检查。合成重复引用探针验证验证记录读取从三次降为一次、摘要保持相同；这只说明证据读取去重，不作为产品性能基准。

这是包本身的设计记录，不授予使用它的新项目任何权限。目标项目复用该项目实际确认的需求与授权。个人模式默认少量业务文档；Memory、Lessons、接口说明等扩展模板按需建立，不重复维护相同事实。

PROJECT_STATE、任务卡和看板由已有 JSON 与检查点生成。后续任务通过明确依赖延续之前的候选，继承其快照范围和仍有效的必需回归命令；旧 PASS 保留为历史证据，最新任务负责当前组合版本，验收包括尚未接受的延续链。这样允许多个功能逐步修改同一源码，又能发现后来的未验证修改。

可读文件不保证用户能在 Agent 里看见。progress 与 start/next 提供 presentation，PROJECT_STATE 使用同一投影；包括阶段目标、问答进度、任务、阻塞和剩余需求，不维护第二套状态或假百分比。宿主有真实任务面板时同步其接口，否则直接在对话显示。阶段变化、结果、阻塞与恢复必须更新，不能只落盘。原生 UI 是否出现仍取决于宿主实际能力和调用。

已有项目在实施前用任务 test_review 对照当前需求审查旧测试、门禁及相关夹具/配置，分组记录保留、适配、替换、退役和补充。纯文档与基线采集可先进行。原基线附件纳入快照并保护，计划随任务定义冻结；任务卡直接生成摘要，不新增独立测试管理系统。

结构重构不让业务测试自动失效。行为不变的测试入口、内部接口或 mock 适配由 Agent 在既有范围处理；业务契约变化/删除引用覆盖本任务或需求的真实用户决定。默认继承前序门禁，只有准确标明 from_task/from_gate 的适配、替换或退役才停止继承该项；适配/替换需要当前必需验证作为承接，其他保护和原始结果保留。程序校验映射、决定与冻结记录，实际等价性和覆盖质量仍由审查负责。

任务保留首次开始时间与原截止时间。断线后的孤立锁可以单独恢复；恢复先辨认活动进程，失效的预算不能遮住恢复入口。需要更多时间时，extend 追加有真实决定依据的期限与修复额度，不清空原记录。续批通过既有明确策略或新决定执行；受美元额度限制的批次需要明确续批决定，不能靠自动换批清零费用。

执行协议、Python 子进程文本输入输出统一使用 UTF-8，避免 Windows 本地编码破坏中文任务 JSON。原有实进程测试发现该问题，新增中文管道、恢复、共享源码延续和续批回归覆盖这些边界。仅完成已建任务不等于整个产品完成；最终验收必须明确确认完整需求范围。

保留三个执行单元，明确补足 UI/UX、前端、后端、QA 和视觉验收职责。新界面或改版先核对关键技术限制，再用可沿用的组件、统一主题和模拟数据制作可点击预览；用户实际接受该预览后才能开始正式实现。既有界面的局部维护沿用原设计，不强制重做全套预览。下拉展开、浮层、焦点、禁用和错误状态成为任务的明确检查项，而非只要求页面配色一致。

UI 任务冻结约定引用及检查状态，审查要求截图、交互报告和覆盖状态，并保存证据摘要。已确认的约定不能由正式实现静默改写；用户对未接受预览的意见经 feedback 回到原任务修复，预算与历史保留。工具能发现缺少或改变的证据，不能替人判断审美，也不把模拟数据预览称为后端完成。

retry_safe 在准备任务时冻结。只有可安全重复、风险非 high、已明确归类为短时网络故障的任务才自动接续；每次核对原进程、完整失败现场、定义与剩余预算。默认同一阶段最多两次自动重试，按原失败时间退避 5、15 秒，阶段成功前不因换会话清零。CLI 单次默认上限 600 秒，仍受任务总期限约束；费用检查每次执行。相同测试/审查失败且候选连续未变时回到主 Agent 重新分析，保留剩余修复额度。

已有项目先区分价值评估、已确定改造和普通小修。显式使用本包时，短评估也先核对真实接入，业务代码可保持未授权；只有用户明确仅参考方法时才不接管，并标明未接入。评估允许保持现状、补保护或证据不足的结论。实际重构建立行为基线和真正的源码恢复点，再做最小试点。snapshot 只核对哈希，不承担源码备份；原测试失败作为基线事实，不触发未经授权的自动修复。

这个分支由用户意向、主 Agent 的证据建议和用户的路线选择驱动，复用接入、授权、任务、验证和恢复机制，不新增架构评分器。只有评估目标变成了经确认的实现目标，才追加带已确认快照的决定并更新策略/阶段；不能直接翻转代码权限，也不能再次 onboard 清空旧记录。

外来 PROJECT 同样可能是 schema_version=1，却使用 phase/execution_policy 而非 stage/policy；旧 CLAUDE 文档还可能把总控固定成 Worker。bootstrap 验证工作流身份、配套工具和顶部入口，给出 connected 回执；不能凭同名文件或口头承诺接管。

新布局在 .workflow-kit/ 保存记录和工具，根入口为 WORKFLOW-KIT.md，产品命令仍在真实项目根运行。路径映射只用于本包记录，不改变产品快照或原任务目录的含义。旧业务资料采用引用；有旧流程时，legacy_review 明确已读来源、保留约束、旧任务处置及角色/流程冲突，不能静默沿用旧队列或旧授权。

绑定校验覆盖受管理文件和入口摘要，文本只容忍 LF/CRLF 的等价换行变化，原业务快照仍按原字节核对。接入失败回滚本次写入；已绑定时再次 bootstrap 只检查，不重置记录。工具版本不配套或旧版本缺标识时要求明确迁移，不盲目新建相同工作绕过预算。

分发文件清单明确列出维护文档，历史报告和本机设置留在活动包之外。包检查同时核对生成模板中的本机绝对路径，ZIP 只从清单生成。该设计记录会复制为目标项目的流程设计说明，因此只保留通用约束和可复用理由，不写其他项目的名称、路径、成绩或会话授权。

恢复通道与失败类别对称。实战中 scope、protocol、action_required、evidence 四类阻塞没有命令出口，几乎每张任务卡都要靠手改 JSON 解围。现在 unblock 记录处置来源与核对说明后把任务放回 ready 或 verifying，cancel 记录作废；任务身份、时钟、修复额度和运行历史不变。解锁后的 begin 沿用本任务先前的范围基线（中间没有其他任务运行时），因此 changed_files 是本任务累计改动，修复轮不再只报最新增量。

校验的作用域是本次变更，不是全局。finish 只比对本任务基线以来的产品文件：工具改写的记录（任务条目按冻结定义哈希、卡片、决定、状态页、日志、笔记）、.gitignore 命中路径和常见构建目录都不计入；protocol 报错直接列出漏报（含删除）和多报的文件。check 的错误以任务 ID 归属，变更命令只被全局错误和本任务新引入的错误阻止；这是 extend 原有的“只拒绝新错误”模式，现在统一到所有变更命令。验证与审查是只读门禁，时钟过期后仍可运行，只有 begin 需要先 extend；默认墙钟 180 分钟。

审查证据的引用面封闭。evidence_files 只能是候选快照内文件（按候选清单取哈希）或 .workflow-kit/tasks/runs、.workflow-kit/tasks/evidence 附件；引用会被工具改写的记录会让审查在保存后立即自我失效，因此直接拒绝并说明原因。工具语义变更导致派生摘要过期时，recompute 用当前函数重算并在 run.recomputed 留痕，禁止手写摘要。

笔记是接手的第一入口。notes/JOURNAL.md 只追加：onboard、research、prepare、检查点、阻塞、解锁、验收、续批、追加预算和 Agent 用 note 写的上下文、决定、待办、教训。notes/RESUME.md 由记录、检查点和日志生成，给接手的 Agent 一页当前状态、未完成的判断、最近事件和继续用的命令；入口块和 WORKFLOW-KIT.md 都指向它。这两份文件是视图，不是第二套状态。

绑定只管理会破坏协议的文件：引擎脚本、契约、提示词、模板和入口块本身。说明文档可以批注，AGENTS/CLAUDE 入口块前后允许其他内容；rebind 在审计后重新核验并记录历史，--upgrade-tools 用调用包的引擎覆盖项目内副本，实现不重初始化的升级。生成项目在记录目录写入 .gitattributes 禁止换行转换，避免证据摘要在新克隆后漂移。prepare 一次返回全部问题并给出字段形态，决定 scope 为字符串时按单元素列表处理，已知会失败的门禁参数形态在准备阶段拒绝。

展示与上下文按宿主能力和项目规模适配。presentation 同时给出 native_.workflow-kit/tasks/native_plan（面板同步）、compact（日常十行）、markdown（关键节点）和 needs_user（所有等用户决定的事），宿主选最高一档，不猜工具名。resume 一条命令输出接手页：进度、Agent 留下的判断与待办、下一条可运行命令和本步该读的文档；start/next 附 read_next，任务包与审查包只带本任务相关的需求。大项目推荐一个会话一张任务卡，用 checkpoint/note 落盘后由新会话 resume。changed_files 可写 auto 由工具按 diff 填入；宽快照在 verify 后得到收窄建议；同类可避免失败第二次出现自动写入教训。

时钟按活动时间计。墙钟把断网、等待用户和 Agent 分析时间都算进任务额度，实战中一个区间追加了六次预算。默认 clock=active 只累计实现/修复/探测运行的时长，额度为基础分钟加各次 extend；wall 保留为旧策略。ui_checks 允许带 id 的对象，审查按 id 匹配，避免措辞微调导致失败；documentation/baseline 任务的审查只强制需求与回归两项。各级 .gitignore（含否定和目录规则）参与改动比对。acceptance.require_committed_evidence 为可选严格门禁：验收记录必须已入库，accept 放行一次并返回待提交清单。

升级是可重复的原地操作。绑定记录 kit_release，与调用包不同时提示；rebind --upgrade-tools 用新版包的渲染结果整体替换引擎、契约、提示词、流程文档、模板和入口块，被覆盖的批注文档先备份到 legacy/upgrade-<时间>/，任务、运行、证据、决定、笔记和 POLICY 不动，每次留 rebind_history；存在活动运行或控制器锁时拒绝。这样多轮优化可以逐次落到同一个项目，不需要重新接入。

## Alternatives considered

- **不做，继续手工复用既有提示词**：最强论据是没有新工具需要维护，熟悉项目的人可以灵活裁剪。未选为交付方式，因为需要反复清除产品事实和授权，容易把历史通过状态带到新项目。
- **只交付 AGENTS.md**：最强论据是简单、可直接读取且无需安装。单文件适合承载入口约定，但不适合混入多种执行器的参数、项目模板和运行证据格式；保留它作为生成项目的入口。
- **只交付某一平台的 Skill**：最强论据是发现和调用方便。增加通用 START 提示词和可复制的流程文档，避免把注册机制变成使用前提。
- **立即实现常驻多 agent 控制器**：最强论据是可管理跨会话队列与集中调度。保留主 Agent 协调及前台执行，因为当前需求优先是可复制、易启动和可恢复；退出宿主后不承诺继续工作。
- **引入 LangGraph 作为必需依赖**：它提供成熟的持久执行和状态基础设施，适合长期运行的服务。借鉴检查点与副作用恢复原则；此启动包先采用标准库和项目文件，降低初次安装负担。
- **只增加提示词和角色数量**：宿主 Agent 可以灵活完成工作，但不能因此证明状态、配置、执行器和真实测试已经连通。保留职责提示词，同时由脚本承担可机械验证的记录和执行。
- **初始化全部业务、Memory 和 Lessons 文档**：内容目录清楚，适合较长期项目；个人项目会重复记录进度与决策，所以默认保留最小文档，完整模板只在需要时生成。
- **永久冻结所有已验证任务的文件**：校验简单，但第二个功能修改同一文件就被拦住。采用带回归检查的候选延续；代价是必须串行准备依赖任务，不能随意分叉或丢弃前序验证。
- **让所有旧门禁永久继承**：可以防止后继任务遗漏回归，但需求变化后会继续运行已经过时的断言，诱发反复修复。默认继承有效检查，允许带适用性依据和需求决定的精确替换/退役。
- **只要选择重构就重新写测试**：容易适配新实现，却会丢失旧业务约束并增加维护工作。先按当前需求判断，只适配实现依赖、补必要覆盖；改变业务保护需要对应的已确认需求。
- **断线就重新计时或重新建任务**：恢复快，却掩盖已用预算与失败。保留原时钟，显式追加授权额度；需要用户决定的额外时间仍须等待决定。

- **恢复七个固定执行进程和长角色提示词**：专门上下文有利于复杂界面的设计与检查；个人项目先明确专业职责、共享 UI 约定与验收证据，复杂时再增加专门上下文，避免多份状态和固定调度成本。
- **所有失败都无限重试**：短时故障恢复率可能更高，但权限、付费调用和不确定副作用会被重复触发。只对明示可重复的任务做有限退避，其余交回主 Agent 判断。
- **完整后端完成后再审 UI，或先做一次性静态稿**：前者先固定业务能力，后者起稿快；本包先验证关键可行性，再制作可沿用的交互前端，降低视觉返工，也避免做出无法落地的交互。

- **只把启动句改成“帮我重构”**：使用成本低，适合目标明确的熟练用户；对尚不确定是否要改的个人项目容易预设结论，因此补齐先评估分支和不改的出口。
- **新增一套重构评分/审批引擎**：统一分数和强制状态有利于大规模管理，但文件长度或测试数量不能决定真实改造收益；当前由主 Agent 解释证据并复用已有机制，避免新增维护面。

- **仅加强启动提示词或在旧规则末尾补一句**：修改少，但长旧文档容易先决定角色，文件名相同也不证明协议兼容；采用实际 bootstrap 回执与顶部入口，减少静默未接入。
- **把旧任务和规则整体覆盖/迁移到新格式**：目录可统一，但未知授权、预算和历史链接难以可靠自动转换；默认隔离保存新流程，旧内容不动，语义冲突由总控明确处理。

- **只要求 Agent 多问几句**：维护成本低，但无法区分默认配置和已确认答案。复用 BRIEF 增加轻量审计与确认摘要，既能恢复分轮问答，又不要求用户操作 JSON。
- **把所有配置变成固定问卷**：选项覆盖全面，但无界面、本地工具也会承担无关问题。只审计影响范围、体验、费用和权限的主题，已明确或有依据不适用的内容不重复问。
- **继续打包整个工作目录**：操作简单，但历史个案和本机设置容易进入其他项目。保留开发备份，使用清单生成可复用 ZIP；代价是新增分发文件需要同步清单规则。

- **只生成 Markdown 任务文件**：便携、可恢复，但用户不一定看到。保留文件事实，增加对话投影和宿主原生面板的能力适配，不再维护独立 Web 看板或第二套完成状态。
- **把 Agent 包办等同于自审**：调度简单，但浪费宿主已有独立上下文能力。执行载体与审查模式分开，优先使用实际可用的独立审查；缺少能力时如实记录。
- **仅要求自审给出 PASS/FAIL**：输出短，却不能看出哪些方面未查。用五项证据覆盖和摘要绑定降低空报告风险，保持真正的上下文独立性、测试质量和语义判断由宿主及审查负责。

- **让 scope/protocol 阻塞继续依赖人工改 JSON**：不增加命令，但每次处置都不可审计，也让零基础用户无法自行推进。采用带来源和说明的 unblock/cancel，处置进入任务记录和日志。
- **finish 继续比对全仓 inventory**：实现简单，却把记账动作、构建产物和别人的改动算到当前任务头上。改为只比对本任务基线以来的产品文件，并按任务分区校验错误；代价是需要维护忽略规则和归属规则。
- **审查证据允许引用任意路径**：灵活，但摘要稳定性要求引用面有界；开放引用导致审查自锁和追溯失效。封闭到候选文件与 runs/evidence 附件，需要引用其他源文件时先加进 snapshot_paths。
- **把所有复制的说明文档纳入绑定哈希**：任何批注都触发 needs_repair，且没有修复命令。改为只管理引擎、契约、提示词、模板和入口块，并提供 rebind。
- **用独立的 Note 技能或第二套状态文件做笔记**：格式更丰富，但会出现第二份事实。采用只追加的日志和自动生成的接手页，事实仍在任务 JSON。

- **为每个宿主写专门的面板适配器**：显示效果最好，但工具名和接口随版本变化，包内无法验证。改为输出宿主中立的 native_.workflow-kit/tasks/native_plan 与两档文本，由宿主 Agent 按实际能力调用。
- **让 Agent 每轮都读完整看板和全部文档**：信息最全，但长项目里上下文迅速耗尽，正是实战中出错的主因。改为 compact 默认、read_next 指路、任务包裁剪、一会话一卡加 resume 接手。

## Consequences

新项目和渐进重构共享同一小型标准库工具；用户回答业务问题，Agent 维护技术记录。初始化保留未批准状态，已有文件冲突先说明，不覆盖用户内容。重要决定复用已有 ADR/Notes；任务卡承担进度，设计记录承担理由。

持续执行仍依赖宿主会话。单写入者和串行依赖减少并发恢复成本，也限制了大型团队吞吐。继承的回归检查会增加验证量；适用性记录允许按真实需求调整旧门禁，代价是实施前多一份简短映射与审查，不能让实现者删检查放行。它不会自动识别所有测试语义或决定哪些断言过时。若未来需要多写入者、跨会话常驻执行或复杂需求迁移，再单独评估事务存储和调度服务。

视觉流程增加一次用户确认和必要的截图/交互证据，适用于有界面项目，不强加给脚本或纯后端。有限自动恢复减少短时中断的人工接续，但遇到未知消费、变化的现场和非重复操作时仍会暂停；没有以便利为理由放宽原权限和费用约束。复杂项目需要更强隔离、平台控制器或更多专门上下文时再重新评估。

评估会增加前期调查成本，因此目标明确的小改动不重复做全项目评估。保持现状同样是有效交付；建议依赖业务计划、观察范围和验证质量，路线由用户选择。确认记录有少量维护成本，但可发现漏问和过期答案；程序不能证明真实回答存在，原始会话仍须核对。评估、进度和技术取舍沿用已有归属，不扩展成报告平台。

隔离布局增加一个状态根，换取不破坏旧流程的接入；回执提供实际路径，避免用户手工记忆。保留原文不等于继续旧角色或队列；接入也不授权业务修改。文件校验不能证明宿主自动加载规则或模型绝对服从，WorkBuddy 等宿主仍需用明确的首条指令/固定项目指令调用入口，必要时在接入后新开会话。

阶段投影使用户不必查 JSON，但仍需要 Agent 调用实际展示工具或发送对话内容。质量证据会增加记录和验证量，这是所选质量目标的必要成本；字段本身不能消除自审盲点，也不能证明未测量的性能提升。完整范围持续可见，预算与复用策略用于稳定执行而非省略需求。

## Verification

在包根目录运行 `python -B -m unittest discover -s project-workflow/tests -q`；test_recovery 用实战反馈中的场景覆盖阻塞出口、累计 diff、按任务分区的校验、封闭的审查证据、笔记与接手页、rebind 与升级。Windows 实际子进程覆盖 UTF-8、失败修复、超时与模拟断网，状态测试覆盖初始化、保护既有项目、候选失效、任务延续、孤立锁和追加预算。可执行示例使用明确标记的确定性执行器，不冒充模型调用或真人验收。包检查核对分发文件哈希、JSON 和文档链接。

新增的实进程回归覆盖自动网络接续、持续故障上限、跨调用计数、stdout/JSON 故障、认证停止、无进展重规划、费用重查和 CLI 调用超时。UI 流程回归覆盖预览确认门槛、原任务反馈、控件状态覆盖和证据失效；这些合成图像/报告仅测试协议，不冒充实际视觉验收。

接入回归使用带旧 phase/execution_policy 和 Worker 指令的合成仓库，检查旧内容保留、独立任务执行、复制后 CLI、规则核对、入口篡改、换行转换和失败回滚。问答回归覆盖意向先于分析、推荐未获确认、明确执行选择、分轮恢复、摘要失效、条件性问题和评估不授权代码。测试夹具不代替真实项目评估或用户决定。

测试适用性回归以真实本地断言验证需求变化后的门禁替换、未涉及回归继续执行和原始 RUN 保留，同时覆盖缺失审查、无对应需求决定、无有效替代门禁、行为不变的技术适配与冻结后篡改。

展示/质量回归覆盖问答阶段无任务时的阶段目标、真实检查点、未拆分需求阻止全项目完成、需求快照防静默删改、Agent 载体下独立审查协议、空自审和无证据报告拒绝、高风险禁止自审及审查报告变更失效。合成上下文标识只验证协议，不冒充宿主端到端独立审查或原生面板验收。

文本约定不是权限沙箱；本地校验也不能证明测试真实有效或批准真实存在，必须审阅原始证据。CLI 参数与能力会变化，应根据目标机器帮助及官方文档核对，不能静默去除限制来运行。复制模板不等于项目已具备自动化测试或已完成架构设计。
