# UI 契约：REQ-047 关闭态浮层不可聚焦（inert）

冻结于实现之前（2026-09-17）。实现期**不得修改本文件**；如确需变更，走 owner 决定并重新冻结。

## 0. 契约目的

修复复核报告 B-3：**浮层关闭后，其内部控件仍留在 Tab 序列中**——用户按 Tab 会进入一个
看不见的对话框，焦点环落在不可见处，键盘用户彻底失去方向感。

## 1. 根因与受影响面（实测）

`src/components/primitives.tsx:298-318` 的 `ModalOverlay` **无条件渲染** `children`，
只用类名切换开合：

```tsx
<div className={`modal-overlay ${open ? 'open' : ''}`} onClick={...}>
```

而 `src/styles/base.css:1962` 的 `.modal-overlay` 关闭态只有
`opacity: 0; pointer-events: none;`——**不改可聚焦性**，也不从无障碍树移除。
于是关闭时内部控件依旧可被 Tab 命中（TASK-043 的复核实测：关闭态设置弹窗内
仍有约 20 个可 Tab 控件，`inert=false`、`aria-hidden=null`）。

**受影响的常驻浮层**（`git`/源码实测）：

| 浮层 | 位置 | 开合方式 |
| --- | --- | --- |
| `ModalOverlay` 本体 | `primitives.tsx:298` | `open` prop 切类名 |
| 其 7 处调用 | 命令面板（`Overlays.tsx:29`）、托盘询问（`:335`）、添加源（`:393`）、编辑源（`:535`）、重命名分类（`:670`）、另一询问（`:726`）、设置（`SettingsModal.tsx:79`） | 同上 |
| 灯箱 | `Overlays.tsx:314` | `lightboxUrl` 切类名 |

**不受影响的**（已条件渲染，无需改动，列为非目标）：

- `ConfirmDialog`：`primitives.tsx:279` 有 `if (!open) return null;`
- `ContextMenu`：`ContextMenu.tsx:77` 有 `if (!menu) return null;`

## 2. 必须达成的结果

1. **关闭态整棵子树不可聚焦**：未打开的浮层（含 7 处调用与灯箱）必须带
   `inert`，使用户无法用 Tab 或脚本聚焦其内部任何控件，且其内容不出现在无障碍树中。
2. **打开态完全不受影响**：打开时内部控件可正常 Tab 进入，
   `:focus-visible` 焦点环按既有 accent 语言显示（不新增颜色或令牌）。
3. **关闭后焦点不停留在 inert 子树内**：若关闭时焦点正在浮层内，
   焦点应离开该子树（回到触发元素或 `body`），不得停留在不可交互的节点上。
4. **Tab 序列与 TASK-043 一致**：默认全关状态下，主视图的 Tab 停靠点
   仍为 TASK-043 记录的 16 个（不因本次改动增减可见控件、不新增停靠点）。

## 3. 实现约束

1. **只加 `inert`，不加焦点陷阱**：本次**不**实现「打开时把焦点困在浮层内」
   （focus trap）。那会改变既有交互习惯，超出本次范围。
2. **不改视觉**：不得改动任何浮层的 `opacity` / `transform` / 过渡 / 层级；
   `inert` 不产生视觉变化。
3. **不改开合与关闭语义**：`open` 的判定条件、`onClose` 的触发、
   `App.tsx:199-211` 的 Esc 逐层关闭链一律不变。
4. **不改鼠标行为**：点击遮罩关闭、点击内容不冒泡等既有行为不变。
5. **不改浮层内部**：表单逻辑、校验、提交、文案、控件顺序一律不变。
6. **复用既有焦点语言**：不新增颜色、令牌或 CSS 变量。

## 4. 验收标准（= 任务卡 ui_checks，逐字对应）

1. 默认（全部浮层关闭）状态下，Tab 遍历不得停留在任何不可见控件上
2. 设置弹窗打开时，其内部控件可正常 Tab 进入并可见焦点环
3. 设置弹窗关闭后，焦点若原在弹窗内应回到触发元素或 body，且弹窗内控件不再可 Tab
4. 命令面板（搜索）打开/关闭时同上：关闭后其控件不可 Tab
5. 灯箱打开时 Esc 可关闭，关闭后其控件不可 Tab
6. 右键菜单关闭后其菜单项不可 Tab
7. 小弹窗（新建分类 / 添加源 / 编辑源 / 重命名分类 / 确认对话框）关闭后其控件不可 Tab
8. Tab 顺序仍为：窗口控件 → 侧栏搜索 → 视图 → 布局 → 工具栏 → 内容区，不因本次改动新增停靠点

> 第 6、7 条中，`ContextMenu` 与 `ConfirmDialog` 已条件渲染，预期**本来就通过**；
> 仍需实测并留证，以证明本次改动未把它们改成常驻渲染。

## 5. 证据规则

- 必须提供**实机证据**（真实 WebView2，经 CDP 驱动，不得注入系统级键鼠、不得抢占用户焦点）：
  - 关闭态：Tab 遍历的停靠点清单（证明不含浮层内控件），并给出浮层节点的 `inert` 状态
  - 打开态：浮层内控件可 Tab 进入且 `:focus-visible=true` 的截图
  - 关闭后：`document.activeElement` 不在 inert 子树内
- 不得用「脚本直接读属性」代替实机 Tab 遍历（属性存在 ≠ 行为生效）。
- 证据图必须**逐张可区分**且**内容真实**（不得同图复用、不得拍到别的内容）。
- 报告中必须写明**未覆盖项**，不得冒充通过。
- 行数以可信口径给出（LF 字节数 / `splitlines()` / `ReadAllLines()`）；
  **不得**用 PowerShell `Measure-Object -Line`（本项目已记录它会少算）。
- 文本文件必须为 **LF** 行尾（仓库 `.gitattributes` 为 `* text=auto eol=lf`）；
  写文件时须显式指定行尾，避免文本模式在 Windows 上静默写成 CRLF。
