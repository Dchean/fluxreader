# UI 契约：TASK-059（Endpoint 只填域名）

目标设备：Windows 桌面端（Tauri）。UI 模式：existing（沿用现有布局与交互习惯，**不改版**）。
范围：**设置 → 同步 → 「后端 Endpoint」卡片及其连接提示**。其余区块与控件不得改动。

## 背景（需求已纠正）

owner 明确：**不管 FreshRSS 还是 Miniflux，用户只需要填写域名**，
不需要知道或填写 `/api/greader.php` 这类 API 后缀。

TASK-057 曾按其时（被作者误读的）需求，把界面文案改成「教用户填完整路径」。
本任务实现自动适配后，**那些文案会反向误导用户**，必须一并更正。

## 需要核对的状态

### A. 文案：只填域名（核心）

1. **desc 文案**须说明**只填域名**即可，不再要求 `/api/greader.php` 之类的后缀；
   若仍需提示协议差异，只能表述为「两种后端都支持，填域名即可」这类**不需要用户做额外动作**的信息。
2. **placeholder** 给出**纯域名**示例（如 `https://demo.freshrss.org`），
   不得再出现 `/api/greader.php` 后缀示例。
3. **不得回归**：界面任何位置都**不应**再出现「需填 /api/greader.php」这类指引。

### B. 行为：填域名即可连

4. **纯域名 + 正确凭据 ⇒ 连接成功**（FreshRSS 与 Miniflux 两种后端都要成立）。
5. **已填完整路径的旧用法仍然可用**，且**不得把解析结果回显**成后缀——
   输入框显示的始终是**用户填写的原始值**（避免让用户以为必须填后缀）。
6. **凭据错时报凭据错**：路径正确但凭据被拒（401/403/400）时，
   提示须指向**凭据**问题，**不得**说成「找不到 API / 地址不对」。
7. **地址确实不可达或找不到 API 时**，提示如实说明该原因。

### C. 视觉与主题

8. **深色主题**：改后的文案完整可读，不截断、不溢出。
9. **浅色主题**：同上。
10. **既有控件行为不变**：`测试连接` / `保存并同步` 的禁用态与加载态（`testing`/`saving`）不受影响；
    协议下拉（`FluxDropdown`）不受影响。

## 明确不改

- **不改认证流程**与 ClientLogin 的双格式（JSON / 文本）解析；
- **不改同步协议语义**（推送顺序、对账口径、入队条件）；
- 不改 TASK-058 的同步失败可见性实现；
- 不改本卡片之外的任何设置区块或侧栏控件。
