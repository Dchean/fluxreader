# UI 契约：REQ-004（播客页 toast 位置）+ REQ-008（控件一致性）

目标设备：Windows 桌面端（Tauri）。UI 模式：existing（沿用现有布局与交互习惯，不改版）。

## 需要核对的状态

### A. Toast 层位置（REQ-004）
1. **仅迷你播放条可见**：toast 固定在右下，位置在播放条上方（当前 `body.has-player` → bottom 96px），不遮挡播放条控件。
2. **全屏播放器展开**（`playerExpanded`，覆盖层 z-index 260）：迷你播放条隐藏，toast 应回到右下贴底（bottom 24px），不得悬浮在半空遮挡播放器中部；且始终浮于播放器覆盖层之上、操作按钮可点击（toast 层 z-index 高于 260，低于二次确认弹窗 3000）。
3. **无播放时**：toast 右下贴底（原行为不回退）。
4. 切换展开/收起播放器的过渡中，toast 位置变化平滑（既有 0.25s 过渡保留）。

### B. 设置页控件一致性（REQ-008）
5. **同步协议选择**：设置 → 同步 → 协议，由原生 `<select>` 改为全应用统一的 `FluxDropdown`；展开/收起、选中高亮、深色主题外观与其他下拉一致。
6. **展开方向**：接近视口底部时应向上弹出（FluxDropdown 既有能力），不出现被裁切。
7. **键盘/焦点**：Esc 关闭、点击外部关闭、焦点样式与既有下拉一致。
8. **错误/空态**：选项列表为空时不崩溃（保持当前值显示）。

## 验证方式
- 代码层面：`npm run lint`（0 警告）+ `npm run test:frontend`（既有断言不回归）
- 人工核对：`npm run tauri dev` 后按 A1–A4、B5–B8 逐条观察（含深浅主题各一次）
- 复查：独立上下文审查核对 diff 与上述状态的可实现性
