# UI 契约：TASK-092（封面图片位统一代理与失败回退，REQ-106 ③）

目标设备：Windows 桌面端（Tauri WebView2）。UI 模式：existing（沿用现有卡片、播放条、灯箱的布局与样式，**不改版**）。
范围：**内容图片的取图方式与失败表现**——文章卡封面、播客卡封面、迷你播放条封面、全屏播放器封面、灯箱大图。
其余区块（文案、图标、间距、交互）不得改动。

## 需要核对的状态

### A. 取图路径（核心）

1. 五处图片位在**渲染前**按既有策略判定是否需要代理（沿用 `lib/imageProxy.ts` 的判定，不新造第二套规则）；
   需要代理的域名走 `api.fetchImage`，成功时渲染为 `data:` URL。
2. **不扩面**：不需要代理的域名保持直连（不为每个封面付一次 IPC/字节拷贝）。
3. 画廊卡片既有行为**逐字保留**（它已经是代理路径的参考实现）。
4. 代理拿不到时不得阻塞渲染：卡片先出占位，拿到后替换；不出现整块布局跳变（封面容器尺寸/圆角/`aspect` 与现在一致）。

### B. 失败回退（核心）

5. 图片加载失败（代理失败或直连失败）时显示**占位**：不留空白、不显示浏览器破图图标、不撑破卡片。
6. 占位与既有视觉语言一致（复用现有卡片背景/图标体系，不新造控件）；深色与浅色主题下都可读。
7. 失败后**不重复请求**同一图片（同一次会话内）。

### C. 失效封面可被纠正（与 TASK-091 的后端命令对接）

8. 失败时上报后端（`report_broken_cover(article_id, url)`），使该行重新进入封面补全队列；
   上报**幂等**：同一条目同一 URL 只上报一次，避免反复 IPC。
9. 上报对象是**文章条目的封面**：播放条/灯箱展示的是同一 `cover` 字段，须共用同一处理，不重复上报。

### D. 边界

10. 无 `cover`（null/空串）的条目：不渲染 `<img>`、不代理、不上报（既有空态不变）。
11. 代理返回的字节不是图片（例如登录页 HTML）时，同样走占位 + 上报，不注入 DOM。
12. 灯箱打开时图片失败：显示占位而不是空白，关闭/Esc 行为不变。

## 明确不改

- 不改布局、字体、间距、颜色、动画；不改卡片结构与既有类名（仅加必要的回退类）。
- 不改后端补全口径（`source='direct'` 与「只填空」语义保持不变）。
- 不把「代理域名白名单」写死在组件里：判定仍在 `lib/imageProxy.ts` 一处。
- 不改设置页、侧栏、播放以外的任何控件。
