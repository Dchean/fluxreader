# UI 契约：TASK-115 返回位置统一规则

- 依据：AUDIT-20261005-core-consistency.md 第三阶段 + 探查事实（2026-10-06 dev）
- 原则：离开时的阅读位置可恢复；无法可靠恢复时明确归零，不猜。

## 全场景规则表（X3 的文档化载体）

| 场景 | 行为 | 机制 |
| --- | --- | --- |
| 后台刷新（feeds-updated/手动同步/单源刷新） | 原位保持 | TASK-111 顶条锚 + positionRestoreNonce（既有，不动） |
| 切布局/视图/范围后**切回** | 恢复到离开时顶条条目 | 本卡：per filterKey 锚存档 + 恢复 |
| 切排序（重拉） | **不恢复**（新语境，列表已重排重拉） | 裁定：filterKey 变化即新语境，存档随之失效 |
| 首次进入某 filterKey | 顶部（现状） | 无存档 → 归零回落 |
| 锚 id 不在恢复列表中 | 归零回落 | 不猜位置 |
| 阅读器关闭（Esc） | 滚动不动 + **焦点归还原选中卡** | 本卡：关闭信号 + moveCardFocus 原位 |
| 阅读器关闭但列表已切换 | 焦点归还回落（不聚焦） | 同上回落规则 |
| 画廊布局（非虚拟化） | 全部回落现状 | 与 TASK-111 同口径 |

## 实现约束

- 锚存档容量有上限（复用 TASK-111 预算纪律），LRU 或按 filterKey 覆盖。
- 切换返回恢复**先于/独立于**后台刷新保位：恢复动作不置 positionRestoreNonce，两者不得叠加滚动。
- 恢复使用 scrollToIndex(align:'start') + 既有程序性滚动抑制。


## 实施记录（TASK-115，2026-10-06，主控落账）

1. **同上下文重复导航不算「切换返回」**：nav 三路径带 `contextChanged` 段变化守卫，缓存命中但不 bump 恢复信号（selectLayout 的范围重置也算上下文变化）。
2. **cache-miss 切回 = 归零回落**：恢复仅在缓存命中（entries 同步恢复）路径触发；LRU 淘汰/切排序清缓存后的重拉路径不恢复（恢复列表尚未就位，不猜）。
3. **切排序裁定精确化**：契约「存档随之失效」仅指**新语境**——旧键存档保留（t115-x1c 断言回原上下文仍可恢复）；若切回原排序后未再滚动即离开，随后缓存命中切回会恢复排序前的锚（真实历史阅读位）而非严格「离开时顶条」。
4. **恢复成功后活锚重锚到落点**（rearmTopAnchor 绕过节流）：保证随后再离开时存档的是恢复后位置。
5. **X2 落地形态**：关闭信号 = `readerCloseNonce`（store 不透明计数器）；原选中卡由 Timeline 在 activeArticleId 跟随 effect 用 ref 记账（关闭 commit 保留关闭前值）——store 不反向依赖 components 层。
6. **UI 取证**：真浏览器交互实证（tasks/evidence/TASK-115-ui/）：切换返回 scrollTop 317.69→318 恢复；Esc 关闭后 activeElement=原选中卡（data-card-index=1）。
