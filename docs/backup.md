# 便携备份、同步与本机恢复

订阅、读藏与正文保存在当前 Windows 用户的本机 SQLite。换机使用设置 → 关于 → **便携备份与换机**；纯本地多设备持续同步使用设置 → 同步 → **本地资料库 · WebDAV**。OPML 仅用于订阅列表交换。

本页描述当前隔离组合已经接入的前后端职责；完整组合门禁、当前真实WebDAV、原生文件选择器、跨机和规模验证仍未闭合，具体状态见[验收入口](../.agents/notes/implemented/process/2026-11-03-修复波次的分批、证伪审计与证据门槛.md#2026-11-09-已确认重构路线与退出条件)，不能据操作说明判断已经发布。

## 当前数据空间

2026-11-09 重构使用独立 `fluxreader-v2.db` 数据空间，格式由 application_id `1179796018`、schema version `1` 和当前必需的图片来源、远端来源证明、资料库控制、分类归属、对象引用及本机正文保留时间结构共同识别。原 `fluxreader.db` 及其 `-wal`/`-shm` 原样保留，不自动迁移、不删除。首次发现旧库时，新版进入新空间并显示一次提示，说明旧文件保留位置。

新格式只初始化当前结构；缺少必需结构的本轮早期试验格式也不自动升级。误把旧格式文件放到新空间时，打开入口先只读检查并明确拒绝，拒绝发生在 WAL、凭据或 schema 写入之前。旧数据与旧备份不属于兼容范围。

## 便携备份（.flxb v4）

从任意 RSS/WebDAV/纯本地模式导出，包含订阅、分类、普通设置、读藏状态及可用的未读/收藏正文，也保留已退订来源的收藏。AI 服务配置、凭据、生成产物与分段缓存、机器身份与发送队列不进入便携文件。缺少的正文单独计数，不伪造完整正文。文件未做口令加密，属于用户私有资料。

v4按头、分类、源、文章及唯一内容记录逐块编码，验证每块与完整容器摘要。RSS来源收藏不套用WebDAV的本地源过滤；同一内容被多条文章或primary/RSS引用时只写一份。缺少已经引用的正文块是损坏，不能当作声明缺正文后继续成功。旧配置快照和旧便携v3明确拒绝，不自动迁移；备份保存正文及媒体引用，不承诺永久镜像所有图片/音频二进制。

1. 选择“导出 .flxb 文件”，在 Windows 原生对话框指定新文件。已有文件不会被覆盖；导出结果显示文件路径与收藏、缺正文数量。
2. 在另一台电脑选择“选择备份并预览”。预览验证完整文件及正文引用，不修改资料库；取消选择或预览不恢复数据。
3. 核对订阅、分类、文章、收藏、可用正文与缺正文数量后，明确点击“确认替换并恢复”。恢复会替换当前资料库，断开 RSS 与 WebDAV；AI 服务和全部凭据须重新输入。本机开机启动/关闭提示选择保留，非敏感 `syncMode` 偏好可恢复。
4. 恢复前文件再次校验，必须与已审阅预览的摘要相同。后端在同一Windows句柄上拒绝其他写入/删除共享，校验与解析同一输入；校验、文件变化或事务失败时，原资料库保持可读；失败后需要重新预览。

恢复期间界面处于明确忙态，既有设置、AI 配置、读藏、封面上报和播放记录写入先结清，图片请求暂停且旧灯箱请求失效，新的用户编辑暂时不可用。提交在一个事务内完成，分类/源/文章新ID高于旧库持久高水位（包含已删除行），本机同步身份重新生成；失败同时回滚数据与序列。前端清除旧选择、阅读位置、正文/AI/播放缓存，回读设置、RSS/WebDAV 状态和新数据。

“资料库恢复已完成，但界面刷新失败”表示数据事务已提交。此时只使用“重试界面刷新”，不会再次替换资料库。普通 WebDAV 后台数据刷新仍保留当前阅读成员和位置，不调用恢复专用的重建入口。

## WebDAV 持续同步

仅纯本地模式可以连接 WebDAV；RSS 同步服务与 WebDAV 不能同时成为读藏状态权威。同步订阅/分类、普通设置（含 AI 行为开关）、独立读藏状态及未读/收藏正文，AI 配置、AI 产物和凭据留在本机。可选实时或 1–1440 分钟定时同步，并可手动“现在同步”。

“已配置连接”只说明已保存连接；“状态同步确认”“正文同步确认”分别显示后端的确认时间。本机待补正文数不是上传进度，待处理状态/待确认批次与下一重试时间分别显示。状态轮次完成不代表正文已全部到达。错误不会擦除当前可读资料，断开也保留本地数据。

远端物理删除当前关闭，已知覆盖和替换对象读回仍不能证明未知离线设备没有保护义务；远端空间治理与容量验收继续保留为缺口。正文保留后端已静态接入：普通已读未收藏可按本机保留期维护，未读/收藏、队项与实际hold继续保护；设置默认0永久，当前候选已提供永久/限定1–3650天控件，沿原子patch保存并保恢复代次守卫。SQLite故障快照保本机年龄，便携格式不传年龄，恢复按本机时间重新开始。控件专项已限定通过，真实Edge键盘/980与组合调度/native验收尚未完成。

旧 Gist、GitHub 同步授权与手动配置快照前后端已退役。GitHub Releases 更新检查仍保留。

## 本机故障快照（高级）

设置 → 关于 → **本机故障恢复（高级）** 中保留“创建数据库备份”。它生成当前数据库的完整 SQLite 快照，包含正文、同步队列、AI 缓存和 DPAPI 密文凭据，只适合当前 Windows 用户的本机故障恢复，不作为换机入口。

快照使用 `VACUUM INTO` 读取 WAL 中已提交数据，生成自包含文件，校验后交付。位置为 `%APPDATA%\com.fluxreader.app\backups\`；手动快照不自动清理。历史迁移/配置镜像文件按其原规则保留，新数据空间不再执行旧升级和镜像配置流程。决定与历史证据见[数据库快照决定](../.agents/notes/implemented/architecture/2026-11-05-数据库快照与恢复边界.md)。

本机快照的恢复仍在应用外进行：完全退出 FluxReader 和托盘，保留当前现场后将选定自包含快照复制为 `fluxreader-v2.db`，并移除同目录当前 `fluxreader-v2.db-wal` / `fluxreader-v2.db-shm` 旁文件，再启动验证。跨 Windows 用户/机器不能复用 DPAPI 凭据；便携换机请使用上面的 `.flxb` 流程。

不能分别复制运行中的主库/WAL/SHM 来冒充一致快照，也不能以文件哈希或 `quick_check` 代替恢复后的功能验证。真实原生选择器、跨机器与断电恢复需各自环境证据；当前交付的具体检查状态集中在当次验收入口。


## 历史配置快照与凭据边界

40389fa 基础批的手动配置快照已提升为 schema3，分组摘要/翻译三态必须显式保存；schema1/2 拒绝、旧 bool 与三态独立往返及身份匹配的理由保留在[配置快照决定](../.agents/notes/implemented/architecture/2026-10-15-配置快照镜像应用.md)。当前组合退役该手动入口与后端，换机改用上述便携 v4 流程，不能据此把 schema3 修复抹去或把旧快照当作当前便携格式。

**历史早库反例与当时防御（旧版本记录）**：2026-11-06 用生产首迁移 SQL 构造schema v1并放入合成敏感键时，原实现升级后的主库已加密，但升级前快照仍保留明文。后继修复按settings实际存在性先迁移凭据，已通过限定独审；合成v1/v2快照保持原schema且凭据为当前Windows用户可解密的密文，旧快照复制后再次打开升级也有验证。

上述旧版本前置凭据迁移不是全键事务：后续键写入失败时，先前已加密的键可能保留，schema不推进且不产生新快照；修复故障后可重试。历史已生成快照不会被自动改写。当前可追溯 Git 最早版本已有四个迁移，仍未证实真实发布v1用户库自然含该敏感键，不能据合成反例声称发生用户凭据泄露，也不能把当前库加密外推到全部历史快照。原失败与后继验证见[验收入口](../.agents/notes/implemented/process/2026-11-03-修复波次的分批、证伪审计与证据门槛.md#本轮修复的限定验收2026-11-07)。

新基线不再调用上述历史迁移；当前敏感设置仍由专门凭据入口加密写入，普通配置导出不能包含密钥。历史记录仅解释旧快照风险，不能作为当前格式升级承诺。
