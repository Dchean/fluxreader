# 数据库备份与恢复边界

订阅、文章正文、读藏状态和设置保存在本机 SQLite。OPML 与配置同步只覆盖部分订阅/设置，不能替代完整数据库备份。

配置快照恢复的是本机配置：实际新增恢复源时，同事务解除其 URL 的删除墓碑；不生成远端订阅或退订，也不取消此前明确入队的远端退订，预览会提示其之后仍可能执行。分类身份与旧同名文件的兼容规则见[同步兼容矩阵](sync-compat-matrix.md#鉴权分类与订阅写回)。下述数据库快照则还包含文章、状态与待发送队列，两类恢复不能互相替代。

## 自动与手动快照

| 触发 | 行为与失败处理 |
| --- | --- |
| schema 升级 | `db::open` 对实际含settings的待升级旧库先迁移明文凭据，成功后再尝试快照。凭据迁移失败会停止本次打开，不生成新快照或推进schema；快照创建本身失败仍记录错误并在启动后警告，不阻止schema迁移。迁移失败文案给出已有快照文件名 |
| 配置镜像删除 | 预览生成提示快照；确认 apply 时在 DB 锁内、删除事务前重新生成并验证，包含预览后提交的新数据。此时失败会阻止删除，不能复用旧预览文件冒充本次快照 |
| 设置→关于→数据备份 | “创建数据库备份”生成完整快照，显示路径、schema 与大小，可在文件夹中显示 |

快照使用 `VACUUM INTO`，包含 WAL 中已提交但未 checkpoint 的数据，形成可独立读取的数据库，不直接分别复制运行中的主库/WAL/SHM。位置为 `%APPDATA%\com.fluxreader.app\backups\`，自动文件名含类型、from/to schema 和 UTC 时间。

迁移和镜像两类自动快照各保留最近 10 份；手动备份不参与清理。排序使用合法生成名中的 UTC、数值序号、PID，不按 schema 版本排序。本次快照即使遇时钟回拨也保留；只有完整合法日期/字段且为普通文件的自动快照参与清理，未知命名、`.partial`、目录和符号链接不删。

## 内容与凭据边界

完整快照包括源/分类、文章/正文、读藏状态、同步队列、设置和 AI 缓存。正常当前库的凭据以 DPAPI 密文保存；密文不是跨 Windows 用户或机器的可移植凭据。快照文件沿用应用数据目录默认 ACL，不另做整库加密。

**历史早库反例与防御**：2026-11-06 用生产首迁移 SQL 构造schema v1并放入合成敏感键时，原实现升级后的主库已加密，但升级前快照仍保留明文。后继修复按settings实际存在性先迁移凭据，已通过限定独审；合成v1/v2快照保持原schema且凭据为当前Windows用户可解密的密文，旧快照复制后再次打开升级也有验证。

该前置凭据迁移不是全键事务：后续键写入失败时，先前已加密的键可能保留，schema不推进且不产生新快照；修复故障后可重试。历史已生成快照不会被自动改写。当前可追溯 Git 最早版本已有四个迁移，仍未证实真实发布v1用户库自然含该敏感键，不能据合成反例声称发生用户凭据泄露，也不能把当前库加密外推到全部历史快照。原失败与后继验证见[验收入口](../.agents/notes/implemented/process/2026-11-03-修复波次的分批、证伪审计与证据门槛.md#本轮修复的限定验收2026-11-07)。

请将备份作为私有数据保管，勿上传到公共位置。具体生命周期选择与历史来源见[数据库快照决定](../.agents/notes/implemented/architecture/2026-11-05-数据库快照与恢复边界.md)。

## 应用外手动恢复

应用没有覆盖式 restore 或提交后的自动撤销。恢复前完全退出 FluxReader，包括托盘，并保留当前现场：

1. 确认 FluxReader 及托盘已退出。
2. 备份 `%APPDATA%\com.fluxreader.app\` 内当前数据库现场，再把选定自包含快照复制为 `fluxreader.db`。
3. 删除同目录残留的 `fluxreader.db-wal` 与 `fluxreader.db-shm`（若存在），防止旧 WAL 覆盖恢复文件。
4. 重新启动，检查订阅、文章和同步设置；来自其它用户/机器的密文无法解密时重新输入同步与 AI 凭据。

运行中分别复制三个数据库文件、或只验证文件哈希，不能证明一致快照或恢复后的逻辑正确性。原生跨用户恢复、真实断电和全部历史迁移尚未完成本轮验收。
