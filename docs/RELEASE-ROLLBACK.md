# 合并、发布与回滚

TASK-002 已完成构建和测试，当前准备管理 agent / Claude Code 交接。没有执行提交、合并、打标签、发布、安装应用或数据恢复。

## 用户控制点

用户按功能/里程碑验收并确认合并；发布单独确认。总控应先准备完整候选版本与证据，再提交具体批准事项，不能让用户批准一个尚不存在的产物。

当前 release.yml 会在 v* 标签或手动触发时运行，且 releaseDraft=false。因此自动执行器在未获发布授权前不得通过推送发布标签或触发工作流间接发布。

低风险基础验收由管理 agent 执行，不逐项请求用户确认；合并与发布仍需要用户。工作分支提交/推送按用户对目标仓库的既有授权执行，授权不明确时先确认，不推主分支或发布标签绕过控制。

## 合并前证据

- 本次候选提交或完整工作区快照，以及包含的需求/任务。
- 实际差异、范围检查、适用测试与独立审查。
- 完整功能/里程碑组合验证及用户可理解的验收记录；功能范围以 FEATURES 已确认保留的核心和全部 OPT 项（OPT-004 使用限定后的同步数据范围）为准，不能只验核心后默许其他保留能力丢失。
- 已知问题、未运行检查及对验收结论的影响。
- 具体合并对象和回滚方式。

尚未核实 GitHub 分支保护、仓库环境审批和工作流权限设置。本地文档约定不是平台强制限制，后续单独配置和验证。

## 发布前证据

对实际准备发布的同一提交/产物验证构建、安装启动与规定回归，记录版本、产物哈希、环境、发布说明和已知问题。检查或批准后又修改代码，必须重新验证相应候选版本。

不能把“某次 CI 成功”替代为“这次发布候选已通过全部要求”。发布说明应来自实际变更，不沿用当前工作流中固定的一版说明。

## 回滚范围

| 对象 | 需要说明的恢复方式 |
| --- | --- |
| 未合并代码 | 独立补丁/分支或明确差异，使失败任务不会覆盖其他工作 |
| 已合并代码 | 经过审查的撤回变更；不自动重写共享历史 |
| 桌面安装包 | 保留已验证的上一版本产物及其说明 |
| 本地数据库和配置 | 在涉及变更的任务中说明可恢复范围、备份与兼容策略 |
| 远端同步状态 | 说明哪些写入无法用回退本地程序撤销，以及测试/恢复方案 |

首轮无需兼容旧数据，来源为 PRODUCT DEC-004；这不代表任何用户数据已获删除许可。未来版本的数据库与远端写入仍需按实际任务设计恢复策略。

当前只记录回滚要求，不执行备份、数据迁移或删除。
