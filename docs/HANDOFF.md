## 如何开始

1. 在具备文件读写、终端执行、进程等待/取消能力的管理 agent 中打开项目根目录。同一台电脑可直接使用 E:/tik/fluxreader。
2. 将 [MANAGER-RESUME](prompts/MANAGER-RESUME.md) 的正文作为新会话首条指令；原 MANAGER-START 已改为指向恢复入口。管理 agent 负责项目管理、调度、审查和基础验收，Claude Code 负责产品/测试/CI 代码。
3. 接手方核对任务、源码与未提交文件、全部运行证据、CLI 版本、认证方式和预算，从实际停止位置继续。当前先准备 BATCH-001 审查收尾，不再领取已经实现的首批任务。已确定的功能范围不重复问用户。
4. 完成最多 3 个任务后交付批次报告；合并和发布仍按现有用户决定分别确认。不要自动重开批次绕过上限。

宿主可能仍要求对项目 Note、git 或构建命令给予系统权限。初次可配置限于本项目/既定命令的权限；这与日常业务审批不同，不能通过全局权限绕过来消除提示。

## 风险与审批

低风险任务由管理 agent 判断、拆分并推进：已明确需求下的局部实现/修复、纯格式整理、补充有效测试、按锁文件准备依赖、增加既定 CI 检查且不降低门禁或扩大权限。

以下情况提交具体方案后询问用户：

- 新增/删除功能、改变已确认业务规则，或有无法从需求中解决的产品歧义。
- 大范围架构替换、数据库结构/迁移、外部协议或公共契约的破坏性调整。
- 操作真实用户数据、真实服务账号，改变凭据存储/认证/安全权限边界。
- 降低/删除既定门禁，修改授权或预算，启用广泛权限绕过。
- 引入未批准的新依赖/大版本升级、新外部目的地或基础设施。
- 合并、发布、推送发布标签，以及超过批准预算。

已经明确的需求不重复询问；例如 OPT-004 的保留和同步范围已确定。但具体实现若涉及上述高风险边界，仍需对那一部分提出方案。不能拆成多个“小任务”规避审批。

普通技术选择、低风险方案和 Note 由管理 agent 审查；这是用户将日常项目管理交给 agent 的授权范围。高风险 Note 仍由用户决定。此处是对技能中通用“人点头”规则的具体委托范围，技能原文保留。

## 每个任务的执行循环

1. 管理 agent 检查需求、依赖、风险、预算、范围、验收标准和验证计划，满足条件后将任务置为 ready。
2. 固定输入提交/文件哈希、允许路径、受保护文件、验证命令和必要 Note。低风险 Note 可由管理 agent 审查；纯格式与明确的无行为清理按技能适用范围处理。
3. 在受控工作区装配任务包，按 CLAUDE-WORKER 调用 CLI。Prompt 通过 stdin/结构化参数传入，不拼接成可执行 shell 文本。
4. 收集退出码、原始输出、结构化结果、权限拒绝和实际差异。Claude 的报告只是待核对的声明。
5. 先检查范围与受保护文件，再执行可信验证计划。不要直接执行 Claude 临时建议的未知 shell 命令。
6. 管理 agent 独立运行适用的格式/静态/类型/单元/集成/回归/构建检查，并审查实际代码和测试是否证明需求。界面行为改变时必须取得相应的真实界面证据。
7. 失败时区分代码、环境、需求和权限问题；可修的代码问题在范围内反馈给 Claude，最多 3 轮。环境问题不靠改断言修复。
8. 通过后将任务置为 verified，更新看板和批次报告，再挑选下一项。verified 不等于已合并或发布。

每项验证绑定实际候选代码哈希。验证后发生相关修改必须重跑；未经变化的独立部分可按已记录的哈希复用证据，不能复用“Claude 说通过”。

用户已确认：每任务最多 3 轮修复、90 分钟；每批最多 3 个任务，不设置费用上限。

首次实现不计入“修复轮”，因此最多为首次调用加 3 次修复调用。任务截止时间从首次启动计算，包含本次执行、验证与审查；移交或重启不能清零。超时停止本任务进程，保留现场和报告。批次满额后等待用户追加，不改批次 ID 继续跑。

不设置费用上限不代表允许购买服务、切换计费账户或扩大工具权限。CLI 费用字段是估算值，报告时注明。

## 基础验收与回归

- 每项验收标准都要有证据，不以编译通过代替业务行为验证。
- Bug 任务关联复现条件和有效测试，优先证明修复前失败、修复后通过；已有有效测试可复用，不机械新增重复测试。
- 无法复现或暂不能自动化的部分如实记录。需求变更后可调整测试，但不悄悄移除仍有效的行为保护。
- 模块评价分别记录结构问题与验证程度；高耦合/缺测试不会自动触发重写。
- 缺少所需证据的任务不能标为通过。未运行、跳过、不适用、失败分别记录。

## 输出与恢复

每次输出任务 ID、输入版本、实际修改文件、验证报告、审查结论、未解决项和下一步。原始 CLI 输出与工具日志保存在运行目录，摘要入 tasks/runs；历史报告不回写成新结果。

管理状态/授权、验证计划和批准记录由管理 agent 持有，不能让 Claude 修改后作为自己的通过依据。工作区隔离不等于安全沙箱，工具白名单也不等于逐文件权限强制；还需宿主权限约束和管理 agent 的实际差异检查。

当前没有常驻调度程序，也没有创建后台自动任务。管理 agent 所在环境退出后，下一次依据记录恢复，不能声称它仍在后台持续工作。
