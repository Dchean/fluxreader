# 维护与文档纪律

本页是项目的维护规则落点。**上位规则不在此复述**：证据分级与独立审计见上位规则第六节（分层验证、独立审计与交付判定），记录与技能见第九节（项目经验自治）；本页只写本项目怎么落地。

## 1. 证据标准

一条结论要能复现，至少给齐五样，缺任一样只算线索：

| 项 | 要求 |
| --- | --- |
| 基线 | 完整或短 SHA（`git rev-parse --short HEAD`）+ 工作树是否干净 |
| 方法 | 具体命令，或"静态审读：读 X 文件的 Y 函数" |
| 输入 | 语料/夹具/请求形态；静态结论要写触发前提 |
| 结果 | 原始输出或 path:line 快照；行号只在快照里有效 |
| 性质 | 运行验证 / 静态推导 / 未验证，三者必须标一个 |

- 静态结论不得写成"已确认行为"；未跑过的路径写"未验证"。
- 证据只对当时的源码与输入成立；源码变了要重评，不能沿用旧结论。
- 本机结果只代表本机；跨环境结论以固定 SHA 的 CI 为准（见 [开发与门禁](development.md)）。

## 2. 审计与证伪

- 上位规则见第六节（分层验证、独立审计与交付判定），此处只写落点：审计者只交报告与摘要、**不写文件**；实现者负责登记 [审计记录](audits.md) 与保留 `tmp/` 证据。实现者的自检不能冒充审计。
- **新发现必须再证伪一次**：由另一个独立上下文复核，先假设它错，找不到反证才算成立。
- 被推翻的结论要留档（写进当轮审计报告的"纠正"节），否则下一轮会被重新提出。
- 由实现者把结论摘要写入 [审计记录](audits.md)（含基线、范围、计数、结论、证据位置、复跑命令）；原始输出留 `tmp/`，不进仓库。
- 审计报告是一次性材料，放 `tmp/` 或存档分支，**不进 `docs/` 索引**。
- 三层任务中明确指定的非审计登记者及其与正文写者的分工见 [AGENTS.md](../AGENTS.md#三层编排)。

## 3. 变更流程

1. **定位**：先在 [契约单点](contracts.md) 查这次改动触及哪些契约，再看 [文档索引](README.md) 的路由表挑要读的篇目。
2. **改**：按契约单点的"唯一出处"改；跨层改动先改上游单点，再改消费方。
3. **影响面**：按契约表的"改它要同步什么"逐项核对，含测试与文档。
4. **证据**：跑 [开发与门禁](development.md) 里适用的检查；证据按第 1 节给齐五样。
5. **同一批更文档**：这里的"同一批"= **同一个提交**（不是同一个任务、同一个 PR 或同一天）。代码、测试、契约表、文档、索引在同一次提交内完成；做不到就当场登记到 [roadmap](roadmap.md) 的「文档待办」，不许口头欠账。

提交信息引用条目或契约名，例如 `fix(sync): 删除 min(1) 恢复 refreshInterval 语义（契约：同步节奏）`。

## 4. 文档与代码冲突

以代码为准，但**不是**发现冲突就改文档：

1. **先分类**：①代码改动使文档过时 → 直接同批更新，不请批；②无法判断哪边对（可能是文档错，也可能是代码错）→ 登记"文档说 X、代码做 Y"的位置与证据，报告给用户；③错字、格式、失效链接 → 直接修。
2. **确认**：只有第②类需要用户决定改代码还是改文档；未确认前不得单方面改写文档，避免把真 bug 洗成"文档笔误"。
3. **同批改**：确认后同一次提交里改文档 + 改索引；若可测，补一条防复发断言（优先让测试或类型表达，其次才是文档）。
4. **留痕**：重要冲突写进当轮审计记录或 [roadmap](roadmap.md) 的文档待办。

## 5. 文档写作纪律

- **只写稳定事实与边界**：契约、责任归属、失败语义、验证边界。实现细节、调用顺序、临时取舍不进 `docs/`，进 `.agents/notes/`。
- **能由类型/测试表达的，不写文档**：字段集合用 row fixture 锚定、门禁命令用 `package.json` 锚定、状态机用测试锚定。文档重复一遍就是第二个真值。
- **不写行号**：引用代码写"文件路径 + 符号名"，跳转写文件链接或显式 `<a id>` 锚。行号只允许出现在一次性审计报告里。
- **一篇一主题**，标题稳定；被取代时标 `Superseded by …` 并保留原文，不改写历史理由。
- **不写教程式说明**与设计意图；读者是要改代码的人。

## 6. 索引与阅读路由

- [文档索引](README.md) 是唯一入口：先看"任务 → 必读"，只读那 1–3 篇；**不要通读 `docs/`**。
- 索引表的"触发更新"列就是文档的归属规则：改到对应的契约/模块时，该篇必须同批更新。
- 新增文档必须同时登记索引，否则 `npm run docs:check` 会失败。

## 7. 生命周期

- 索引表的"最近核对"= 日期 + 基线短 SHA，**只在该篇正文被实际核对或改动时填写**；不要按轮次批量回填，没核过的保持"未标"。查不到就是"未核对"，不能当现状。
- 被取代的文档标 Superseded 并指向后继；归档走 `.agents/notes/archived/` 的既有约定。
- 一次性材料（审计报告、探针、日志）不进 `docs/`。

## 8. 门禁

`npm run docs:check`（脚本 `tools/docs-check.mjs`）检查五件事，本地与 CI 都跑：

1. 每个 `docs/*.md` 都登记在索引里；
2. `docs/roadmap.md` 含「文档待办」节（文档缺口的登记处，缺了门禁直接失败）；
3. 文档内的相对链接都能解析；
4. `#锚` 在目标文档里存在（显式 `<a id>` 或标题锚）；
5. `docs/` 内不出现 `path:line` 形式的行号引用。

它只查结构，不判内容对错——内容与代码是否一致靠第 4 节的流程与审计。

## 9. 清理批次

清理不是攒到审计再做；**任务包含清理时**，按下面的批次动作执行（不清理的任务不必强行做一批）。

- **范围四类**：死代码（零引用且零导出）、无用测试（零断言或断言无判别力）、过度设计（不可达防御、为将来预留的开关/兼容层）、耦合修正（见第 10 节）。
- **准入证据**：全仓 grep（含字符串拼接与动态 key）、编译通过、受影响门禁绿、可回滚点（提交或快照）。缺一样不许删。
- **规模**：一批一个模块、一次提交；超过一个模块或涉及共享契约时拆批。清理与功能不混提交。
- **不做**：为变绿删测试或放宽断言；删 ``最终审计报告` §7 的"判定勿动"项或 [roadmap](roadmap.md)「继续保留的边界」里列的东西；在没有消费者证据时删跨层契约。
- **产出**：清理清单写进当轮交付；发现文档没覆盖的事实，走第 11 节的文档缺口流程。

## 10. 耦合判据

不追求"到处解耦"。耦合本身不是问题，**错误的耦合边界**才是。

保持耦合（不拆）的信号，命中任一条就默认不拆：

- 同一事务/同一生命周期：拆开就要跨边界补偿事务，比如写事务与捕获触发器、外键与删除顺序。
- 同一变更频率：总是一起改的东西，分开就会同步两次。
- 同一性能关键路径：虚拟化、批量写、锁序、分块收体——拆一层就多一次分配或加锁。
- 同一信任边界：凭据、sanitize、账号代际这类，拆开容易出现绕过路径。

拆分的门槛（要同时满足才动手）：

1. 有跨发布节奏或跨信任边界的实际需求；
2. 有第二个消费者，或能显著改善可测性；
3. 迁移成本低于未来重复维护成本；
4. 拆分后不引入双份真值（双份真值应当**合并**，不是解耦）。

不为"将来可能"加抽象；单一消费者不建抽象，除非它本身就是跨层契约（见 [契约单点](contracts.md)）。

## 11. 覆盖矩阵与文档缺口回收

**覆盖的定义**：域 × 深度（结构级 / 关键段 / 逐行）× 基线 SHA × 证据位置。矩阵维护在 [审计记录](audits.md)。

- 任何"全量""全覆盖"结论必须附矩阵；矩阵里没审的格子要显式写"未覆盖"，**不许留白**——留白会被下一轮当成审过。
- 每轮只补"覆盖最浅且最久未碰"的域，避免重复审计同一块。

**文档缺口回收**（任何一次调整、修复或审计都适用）：

1. 发现 `docs/`、`AGENTS.md`、`.agents/notes/` 活跃篇或代码注释里的契约引用**缺失、失实或过期**时，在当次交付里指出：位置、代码事实、差异。
2. **询问是否更新文档**，不静默补写——静默补写会把真 bug 洗成"文档笔误"。边界：用户已授权的文档重写批内，按第 4 节的分类，①③类可直接改；②类仍须单列上报，授权不覆盖它。
3. 确认后同批更新文档与索引（含索引表的"最近核对"）。
4. 暂不更新的，登记到 [当前缺口](roadmap.md) 的「文档待办」，并写明**下次触碰该模块时必须处理**；没有过期作废，挂着就是未完成。
5. **"重要"的判据**：涉及用户可见行为、数据正确性、对外契约或安全边界的差异算重要，必须走第 2 步；纯措辞、链接、排版直接修。

## 12. 视觉回归分层与禁令

视觉回归按成本分三层，能下层解决就不上上层；各层测试目录、运行方式与覆盖范围见 [开发与门禁](development.md) 的测试分层。

- **L1 几何（已实现）**：`npm run test:ui-layout`，真实 Edge + CDP，已在本地门禁与 CI。
- **L2 令牌与计算样式（无独立门禁）**：只有零星 `getComputedStyle` 读取（布局门禁的溢出/最大高度指标），没有主题令牌矩阵断言。
- **L3 组件截图（未实现）**：没有截图基线。

- **禁止全站像素对比**：5 调色盘 × 明暗共 10 套主题，全量截图必然假红，假红多了门禁就没人看。
- 若引入 L3 比对，先有基线方案；回退同样属门禁变更（依据 + 用户确认 + 独立审计），不自动执行。
- 前端断言的偏好顺序：行为/渲染断言 > 组件级快照 > 源码字符串 `includes`。用最后一种要在断言旁写明为什么无法用前两种——它是重构误报的最大来源。
