# 关键流程：首轮静态追踪

对应源码基准见 BASELINE。下列路径依据源码入口与调用关系整理；未启动应用或通过真实桌面操作验证。箭头不代表每个边界均已测试通过。

| 流程 | 代码路径 | 下一阶段需要验证 |
| --- | --- | --- |
| 启动与载入 | lib.rs 打开 SQLite/构建 AppState/启动 scheduler → 前端 bootstrapFromBackend → API 读取分类、源、文章、设置等 → store/组件 | 全新安装、空数据、错误提示、后台刷新与初始加载的关系；浏览器回退不能代替此验证 |
| 五布局阅读 | 分类/源绑定布局 → selectors 派生可见文章 → Timeline 渲染对应布局 → selectArticle / ensureArticleContent → Reader | 五布局的选择、筛选、正文水合和阅读状态；切换后是否显示旧请求结果 |
| 连接与同步 | SettingsModal → sync_test / sync_save → sync_phase 或 sync_now → sync::Backend → Google Reader/Fever → SQLite → 前端刷新 | 首次/增量、失败重试、分页、状态冲突、协议切换；认证语义按服务端核实 |
| 已读/收藏 | 前端操作 → set_read / set_starred 等 IPC → 数据库与同步队列 → 后续同步推送/对账 | 离线修改、远端冲突、未读筛选中保留行为、重复请求及部分失败 |
| AI 摘要/翻译 | 前端触发 → ai_summarize / ai_translate → 配置与缓存读取 → ai::stream_chat → Channel → store/Reader → 结果持久化 | 未配置、缓存命中、分片、断流、取消、切文章、错误提示、译文清洗与显示 |
| 配置导入（OPT-004） | config_sync_download → config_sync_apply → apply_payload | 保留；目标仅同步订阅源与客户端设置，地址、模型等非敏感配置可同步，敏感凭据排除；需核对现有 payload 与目标字段范围的差异 |

## 产品待澄清与测试发现分开

- 现有行为已观察但尚未获得需求认可：记录在问题/行为清单，不自动写成永久验收要求。
- 明确违背用户要求：登记缺陷并提出修复任务。
- 协议不提供某项能力：记录能力限制与用户可理解的交互，不靠 mock 伪造所有协议功能相同。
- 所有 OPT 项纳入保留与验收范围，OPT-004 按订阅源与客户端设置的限定范围验证。功能保留决定不替代进入编码或测试阶段的授权。

下一步无需先重新设计整套 UX。先按风险为核心链路和已确认保留能力补足可复现的验收场景，再按每次变更更新受影响流程。
