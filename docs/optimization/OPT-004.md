## 根因与固定参照

客户端POST不带Authorization且T=登录Auth；FreshRSS指定实现依靠Authorization设用户上下文，edit-tag等修改端点检查独立action token（普通用户也容许空T/x，不能表述所有POST都必须token）。Miniflux POST T用登录Auth，但/token端点可返回该token。不能仅按URL后缀猜服务端。

## 必须达成的接口行为

1. 所有API请求一致携带 Authorization: GoogleLogin auth=<auth>，ClientLogin仍表单认证。
2. 写操作的T与auth职责分开，从已认证/token读取并安全缓存action token；同一客户端多次POST不应反复获取token。Miniflux返回auth本身、FreshRSS返回不同字符串，两种都可。明确空token/401/网络失败错误，不吞认证错误或改猜URL。既有GReaderClient::new直接构造路径仍可被现有测试使用，不能改public签名破坏所有调用者。
3. token GET存在与否按实际契约处理：已支持的两服务端有/token，若兼容无/token端点只能对明确404限定回退，不对401/403/5xx回退。说明选择。
4. 分类规范化优先category.label；没有label的folder tag从user/.../label/后缀解析；subscription category缺type但id为label前缀应识别为分类。普通state tag不能创建目录，保留中文名称与斜杠等真实标签含义。
5. POST form编码继续用reqwest.form，不拼未转义表单；不会把密码/token写入错误正文或日志。
