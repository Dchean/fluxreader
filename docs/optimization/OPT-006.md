# OPT-006：账号生命周期与配置导入隔离

Status: verified-local
覆盖：F05/F06。前置：OPT-001/004/005完成，OPT014凭据Result接口稳定。

## 目标

切换/断开后旧HTTP响应不得复活旧内容或修改新账号队列；配置导入不得把新地址/用户名与旧密码拼接。本地读写不被长HTTP锁冻结；不是单纯禁用设置按钮。

## 设计边界

使用每个数据库的持久化sync_generation与SyncSession（捕获generation+Backend）建立同步会话边界：在同一个短DB临界区读账号配置与generation；HTTP外执行；每次落库/确认队列/写游标、推后续块之前在同DB锁内校验generation仍匹配。不得仅检查一次函数入口，不得全局跨所有DB互斥错误影响两个客户端测试。

账号更改/断开通过唯一后端操作服务：验证新凭据后，在一个事务中清旧remote数据、清旧账号绑定/队列/游标/endpoint cache、写新配置并递增generation。需先重新校验开始验证时捕获的generation，防两个保存并发覆盖。失败保持旧完整状态；PUSH_LOCK不变成全局DB锁。

相同账号只刷新密码/endpoint等的边界必须明确：不以密码更改就无提示删除所有远端文章；身份定义以协议+规范化服务器根+用户名为准，token更新可换generation但保留同账号数据。协议切换的remote id可能不同，需显式解绑/重拉，不把旧ID给新协议。

配置导入只存非敏感待确认连接建议（pending_connection_config），不改活动凭据/绑定；UI显示待确认地址/协议/用户名，保存时仍经过同一账号生命周期。现有get_setting通用IPC不能绕过活动凭据更改：敏感活动连接键写入必须走专用保存入口或有一致generation规则。不要仅修config_sync而留下任意set_setting旁路。

## 必测交错

1. 本地mock以屏障暂停A的tags/subscriptions/items响应，断开后释放：无A内容/绑定复活，无旧游标写回。
2. A改B（同remote ID数值），释放A旧响应：B数据/队列不变；旧push确认不能删B项。
3. 同时保存两组凭据，迟到验证不能覆盖较新保存；密码更新不清同账号阅读数据。
4. A已连接时导入B配置，fake B服务不能收到A密码；激活B需明确保存流程，pending建议不改变当前sync_status。
5. 失败/取消/超时下无永久busy/锁泄漏，UI saving覆盖真正链路，返回明确错误不假成功。
6. 用户本地直连源保留、既有删除墓碑归属不污染新账号。

## 精确边界补充（在 OPT014 事务内核上扩展）

- 复用已建立的 commit_account_settings / commit_disconnect 与 purge_remote_data_in，不回退到分步提交。generation 与配置变化在同一事务提交；必须可用于多个测试数据库，不用全局原子计数替代每库身份。
- read_credentials 已是 AppResult<Option<...>>，严格保留Err/未配置差异。SyncSession 捕获的 generation 不包含或日志输出密码。
- 守卫清单必须逐项：build_client端点缓存写回；push plan构建、失败标记、prune确认；订阅pull的建分类/绑定/删除；GR/Fever正文merge与状态对账；两类游标推进；sync_local_feeds和直接edit/unsubscribe（避免换号后用旧remote_id向新client发送）。
- 已发给旧账号的请求不能被事后撤回，不宣称取消可回滚服务端；变更后阻止后续请求及本地回写。每个新批次发送前检查代际，HTTP不跨DB锁。
- 同账号密码更新不清内容，仍更新generation使旧请求失效。protocol变化属于远端ID命名空间变化，原行为保守解绑/重拉。
- 配置导入pending建议的激活入口必须显示明确的需要重新输入凭据信息，不能只是落库一个从不消费的新字段。通用set_setting对活动credential键（protocol/endpoint/username/password/游标generation）禁止绕过专用命令，内部db::set_setting仍可被受控事务使用。
- 所有变更以已有服务端用户范围为界：先离线读状态入队的本地意图在首次连接保留，真正换账号的旧远端队列按原清理边界，不误删纯本地源。

## 与最新 Fever 页恢复接口衔接

当前已实现 FeverHistoryState（内部 setting fever_history_state），不是旧临时 fever_history_cursor；账号换号/断开与代际更新时，同事务使该历史状态回 Unknown/移除，并重置 sync_last_entry_id/sync_last_sync。保留密码更新的同账号历史进度，但旧请求仍失效。Pending捕获的页游标只对原session有效。不能只重置GR时间戳而让新账号继承A的Complete或旧页游标。通用setting写旁路也覆盖此内部进度键。
