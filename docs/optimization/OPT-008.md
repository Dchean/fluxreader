## 现状收口（2026-10-19，OPT-008C）

以下为当前实现口径，覆盖本卡早期按字面写下的 FTS/版本边界（历史章节保持原样，不重写）：

- **迁移边界**：当前迁移末版是 **v30**；v22 建 `contents` 并在同一迁移内回填 `content_id`、删除旧正文列，v29 删除 `articles_fts`，v30 追加读闭包索引。「当前 v21」类表述只适用于 2026-10-12 的第二阶段计划现场，不是现状。
- **搜索权威 = LIKE**：生产搜索入口是 `db::search_articles` 的 LIKE 条件（中文分词原因，见 `db/articles.rs` 决策注释）。`articles_trigram_idx` 是 FTS5 trigram、contentless 的**可重建候选索引**——只收缩候选集合，等值验证仍由 LIKE 完成；索引缺失/损坏时回落纯 LIKE，不改变结果集。
- **验收口径**：父卡早期把「FTS 可搜」写作字面验收项；按 OPT-017B 结论，验收以「共享正文变更后每个引用条目可搜、旧词消失、派生索引可从 articles×contents 无损重建」为准，不再要求存在 `articles_fts`。
