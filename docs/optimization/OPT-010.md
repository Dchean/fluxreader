# OPT-010：配置快照合并与镜像应用

Status: review
覆盖F18；前置OPT006/009。

## 明确产品范围

现有Gist/WebDAV是手动配置快照传输。保留安全“合并”默认，同时提供明确“镜像应用”（以远端快照为准删除本地缺失订阅/分类）的预览与单独确认；这不是宣称已有自动双向CRDT同步。UI不能把合并写成覆盖。

镜像只影响本机订阅/客户端设置，不能因为导入快照就把真实RSS账号的所有订阅退订；若要推远端应由OPT009的显式操作范围另行确认，默认不推。删除会级联本地文章与状态，确认必须展示数量/关键对象且能取消。切换连接信息遵守OPT006 pending建议，不改变活动凭据。

## 应用契约

Rust plan_config_apply(payload, mode) 返回结构化 additions/updates/removals（feed/folder/affectedArticleCount）和当前配置版本签名；实际 apply 必须复核签名/快照hash，避免用户确认后并发变更被悄悄删掉。失效预览要求重新确认，不能重新计算并直接删。整个应用事务全有全无。

快照schema版本追加，旧schema1无稳定ID的URL/名称按现有保守匹配；跨重命名身份变化不能猜“相同名字就同对象”，明确冲突预览。用户需要的AI开关继承模式在OPT011同步兼容。非敏感连接建议白名单，所有敏感值/AI服务配置不导出。未知结构/枚举/URL/范围错误不把半套应用到本地。

## 反例和验收

1. 合并保留本地独有feed，镜像预览列出removal但取消无写入；确认后只删除列出对象。
2. 预览后用户新加/改feed→签名不符Err，任何删除/更新都回滚；失败注入中途也回滚。
3. 镜像后再次应用幂等；folders无成员与源移动先后关系不误cascade要保留的文章。
4. config含密码/API key/AI服务字段不出网，pending connection不替换active；Gist/WebDAV请求只配置文件，不发RSS退订。
5. 旧快照读取仍可合并，新模式明确版本；用户UI显示当前模式和删除后果。

### 当前事实（主控读码确认）

- `src-tauri/src/config_sync.rs` 约 823 行，`SCHEMA_VERSION = 1`，`SyncPayload{schema,folders,feeds,app_settings,connection?}`；`apply_payload` 为单一合并实现，`ApplyOutcome` 只有 updated 类计数，无 additions/updates/removals 结构化预览，无快照签名/CAS，无事务全有全无语义。
- 前端 `src/components/settings/ConfigSyncSection.tsx`（269 行）只有「下载并应用」直接动作，无预览、无 `mode`、无删除数量/关键对象展示；`src/lib/api.ts` 无 `config_sync_plan/apply` IPC。
- 因此本卡新增两段式 IPC：`config_sync_plan(payload, mode) -> {mode, snapshotHash, additions[], updates[], removals[], affectedArticleCount, currentVersion}`；`config_sync_apply(payload, mode, expectedSnapshotHash, expectedVersion)` 在单事务内复核签名与版本后执行，全部成功或全部回滚。
