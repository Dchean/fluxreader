# OPT-009B2：补齐订阅 outbox 生产者与分类收敛边界

## 目标

在 OPT-009 B1/B1-R2/B1-R3 当时未提交实现上，补齐后端订阅写回的生产者、分类操作与账号边界。该子卡处理独立复审确认的 5 项 P2：成功移动后的代际切换结转、退订仍为 best-effort、分类改名/删除未接 outbox、分类墓碑读取 fail-open、OPML 标题未进入订阅目标。完成后，删除/改名/移动/OPML 导入均不得只依赖一次性远端请求或未确认的本地状态。

## 必须交付

1. **在途移动与代际变化**：旧账号请求已成功、同 URL 后继移动已排队、数据库 generation 随后变化时，仍按旧请求的 account key 与远端已接受目标安全重定该账号的后继意图；不得因当前 generation 不同而让后续请求移除错误分类，也不得影响别的账号队列。覆盖响应屏障、后继移动、切换 generation、放行、回原账号重试的完整时序。
2. **持久退订**：普通源删除在墓碑、本地删除及 typed unsubscribe 入队之间具备单一事务边界；失败/离线/重启后可重试，旧账号远端 id 不得发给新账号。分类级联删除须在级联前保存成员 URL/远端目标，并对每个实际远端成员建立独立可恢复退订意图。保留墓碑“不因 2xx 清除”的既有判据。
3. **分类改名与删除**：按当前确认弹窗契约保留“删除分类会同时移除其下订阅和本地条目”的行为。非空分类改名应对每个订阅以严格 GReader wire 表达目标 label 添加与旧 label 移除，保留其它标签；删除分类应对成员逐源持久退订。分类本地变更、成员 outbox 与墓碑必须原子提交；部分失败/重启后可收敛。不得以未验证的 `rename-tag`/`disable-tag` 名称推断服务端支持；空分类若协议没有可验证的远端表达，明确记录为本地/远端不支持，不伪造成功。
4. **分类墓碑失败关闭及账号隔离**：读取墓碑失败不得按空集合继续 pull、创建旧分类或提交依赖该映射的 feed 状态；需记录同步错误并跳过受影响的导入/删除阶段。审查现有墓碑在账号切换时是否跨账号误抑制同名分类；若确认会串账号，采用带 account key 的持久表示并提供旧数据兼容/迁移测试，不得以静默丢弃历史墓碑换取隔离。
5. **OPML 标题**：导入的非空标题必须进入 typed subscribe 的 `desired_title`，并在 quick_add 后用真实 `t=` wire 写回；分类目标、标题、URL 和本地导入在同一事务语义下保持一致。已有空标题/重复 URL/已有 feed 的行为须有回归，不得双投 legacy add_feed。

## R2 复审返工要求

R1 的 CodeBuddy 新会话审计认为原 P2 已关闭、无新增 P1/P2；但主控与独立 Codex reviewer 对照当前源码发现以下未关闭问题。不得因 R1 的门禁通过或初审结论而略过：

1. **全局分类墓碑被单账号提前回收（P2）**：空 `account_key` 明确定义为对所有账号生效（纯本地操作或迁移时无账号），但 `prune_folder_tombstones` 将其作为任何单个当前账号的活动墓碑，并在该账号远端不含 label 时删除。账号 A 的一次 pull 因而能让账号 B 之后导入并复活同名分类。保持声明的全局语义：单账号 pull 不得回收全局墓碑；若采用不同寿命/所有权模型，必须先说明如何证明所有适用账号均已观察且不得静默削弱当前契约。增加生产 pull 跨 A/B 的回归，并就地更新墓碑 Note，记录保留/回收边界与代价。
2. **未知 id 退订在列表读取失败时错误确认（P2）**：`exec_unsubscribe_item` 对空 `remote_id` 执行 `quick_add` 后，若读取订阅列表失败，目前只记日志，仍退订 quick_add 返回的单个 id 并 `Confirmed`。若某协议实现对重复 URL 非幂等且列表暂时不可用，可能只删除新建 id、漏删原 id，随后丢弃唯一持久意图。当前 pinned 上游未证明所有 GReader 服务端重复 quick_add 都幂等；严格 mock 只能证明自身模型。修复时不得把未验证的服务端假设当契约：只有在重复目标已被安全发现/收敛后才能确认；列表或解析失败必须保留可恢复意图，避免每次重试都无界地产生新订阅。明确持久状态推进、重启恢复与账号隔离；用 loopback 故障注入验证列表失败、重复 id、重试后所有同 URL 远端项移除且 outbox 不提前出队。若无法对任意服务端保证，需缩窄能力声明并保持未解决意图可见，不伪称可靠收敛。
3. **移动完成后删除再重加的移除基准（P3，先证明时序）**：独立审计提出与 R1 屏障覆盖不同的时序——移动已确认出队后，用户删除并快速重加同 URL；若 unsubscribe 尚未完成便被新 subscribe 意图替换，可能丢失远端当前分类 `prev_folder`，新挂载只 `a=` 而残留旧 label。先构造真实生产命令/响应屏障反例，区分 unsubscribe 已确认后与仍 pending/在途两种路径；确认可触发时持久结转旧分类并在远端最终态验证 `a=`/`r=` 与其它分类保留，否则将基于源码和协议证据的“不触发”理由写入结果。
4. **mock 幂等化后测试计数语义失真（P3）**：`quickadd_count` 统计远端创建而非请求；mock 现会让重复 quickadd 返回既有 id，所以“只创建一次”断言不再能发现重复请求。核查所有相关既有断言，将其改为 request-level 计数（如 `quickadd_requests`），并保留创建数断言去区分网络请求与远端重复创建。

R2 必须遵守本文原有写集、Note、行为反例先红后绿及 Rust 门禁要求；任何新增的持久状态/格式变化必须迁移兼容并写入决定笔记。R2 结束保持 `rework`，等待新的独立只读 CodeBuddy 审计和 Codex 子代理 review；不得提前推进 B3 或更新父卡为完成。
