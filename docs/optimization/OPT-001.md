## 目标与根因

sync_queue.id 为普通 INTEGER PRIMARY KEY。enqueue_sync 删除旧同类/相反项再插入，可能复用最大 ROWID；旧 push plan 在网络后按 id prune，误删新的用户意图。PUSH_LOCK 不保护本地入队。不能改为联网期间锁住整个 DB。

## 决定和接口

追加 v18 迁移，将 sync_queue 重建为 id INTEGER PRIMARY KEY AUTOINCREMENT，保持所有现存列、FK、id、payload、created_at、attempts/last_error 和两个索引。已发布 v1–v17 的 SQL 不修改。应用写入继续使用自动生成 id，不重置 sqlite_sequence。原 public enqueue_sync / take_sync_queue / prune_sync 形状保持不变；唯一的新保证是已提交操作身份在删除和进程重启后不复用。账号隔离是 OPT-006，不声称本卡解决所有并发问题。
