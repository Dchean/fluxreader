# OPT-021：空集计数的启动失败

Status: verified-ci
审计覆盖：P0（空集聚合 NULL）
前置：v0.18.1 实机复现（2026-10-20）
通用约束与验收流程：[路线](README.md)

## 交付目标

`counts_snapshot` / `scope_counts` 在合法空集合上必须稳定返回零值计数，不得因为
SQLite 聚合函数返回 `NULL` 而导致启动装载失败。

## 已核实事实

- `src-tauri/src/db/articles.rs` 的 smartDedup `scope_counts` 使用
  `SUM(NOT EXISTS (...))` 计算 `total`。
- `counts_from_row` 对 `total` 直接按 `i64` 读取；空结果集时
  `SUM(NOT EXISTS (...))` 返回 `NULL`，触发
  `Invalid column type Null at index: 1`。
- 启动路径在 `src/store/slices/bootstrap.ts` 通过
  `api.countsSnapshot(layout)` 调用该查询；断开后端或当前布局没有文章时可
  进入该合法空集状态。
- 当前安装库已出现 `articles=0`、`smartDedup=true` 的实际触发条件。

## 非目标

- 不重做 smartDedup、布局解析或 effective_layout。
- 不修改数据库 schema、迁移或同步协议。
- 不处理“同步中不退出”的 UI 问题（由 OPT-022 承接）。
- 不用前端默认值掩盖后端返回的非法 null；后端契约必须自身返回零值。

## 实施要求

1. 修复必须保证所有 smartDedup 计数聚合字段在空集上返回 `0`，至少覆盖
   `total`；应优先在 SQL 端使用 `COALESCE(..., 0)` 固化契约。
2. 保留非空集合、布局过滤、开关关闭路径的既有计数语义。
3. 增加可判别反例：修复前应失败，修复后通过，且失败信息必须来自真实查询/读取，
   不能只断言源码包含字符串。
4. 覆盖至少以下场景：
   - 空数据库且 `smartDedup=true`；
   - 有源但当前 layout 没有文章；
   - `smartDedup=false` 的空集；
   - 有文章时计数与列表集合仍然一致；
   - `counts_snapshot` 返回的 `all.total` 不为 null。
5. 同步更新相关 Note 的事实与边界；不要改历史决定的反面。
