# OPT-002：正文安全边界与解析健壮性

Status: review
审计覆盖：F07、F20；前置：无。遵守 [路线](README.md)。

## 目标

保留合法 RSS 富媒体，补全和存量正文不能绕过清洗；残缺/多字节 iframe 不 panic。不是移除所有 HTML 或只在 UI 隐藏报错。

- src-tauri/src/sanitize.rs
- src-tauri/src/db/sync_map.rs（backfill_article_content）
- src-tauri/src/db/articles.rs（详情/with_content 列表可渲染字段统一净化，不改查询分页/状态政策）
- src-tauri/src/sync/entries.rs（补全错误至少记入 report，不扩展游标协议；OPT-007 完整处理）
- src-tauri/tests/content_safety_e2e.rs（新建）
- .agents/notes/proposed/architecture/2026-10-08-可渲染正文安全边界.md 转至 implemented/architecture 同名文件，改为现在时与 Consequences，更新反向注释。
- tmp/optimization-20261008/OPT-002/RESULT.md 等临时自测材料

## 契约和实现步骤

1. 先写直接调用生产 sanitize() 的用例：<iframe、<iframe中>、普通中文正文、合法 youtube iframe、白名单外 iframe、大小写/属性空白等。不得复制 sanitizer 到测试当被测对象。
2. 先写实际 db API 回归：空正文补入 script/onerror/任意 iframe 被净化；相对 URL 按 article.url 重写；非空旧正文不被回填覆盖。
3. 旧库可含已经污染的正文/译文，get_article/get_articles 及 with_content=true 列表返回前保证可渲染字段安全；只元数据的列表不执行正文清洗。测试直接插入原始 HTML 再读，断言危险节点不存在而合法内容存在。
4. 修复 iframe 判定使用安全字符访问或现有 DOM 解析器，不能让所有 iframe 丢失。复用现有 ammonia/scraper，不新增依赖。
5. backfill_article_content 自身承担清洗，URL 基址从对应文章取得；错误正常向上传递。同步调用点不得 let _ 吞掉错误。
6. 格式门禁和相关测试：完整 Rust 由 Windows CI；可提取原表达式/真实 SQL 做独立补充 probe，必须准确说明执行边界。若可以本地跑完整测试也需保留明确实际命令，不虚构成功。

## 反例断言

~~~text
input = '<iframe src="https://evil.invalid/embed"></iframe><img src="/x.png" onerror="x()"><p>保留</p>'
backfill_article_content(article_with_empty_body, input)
row = get_article(id)
assert row.content_html 不含 <iframe / onerror
assert row.content_html 含 https://合法基址/x.png 与“保留”
~~~
