# OPT-020：错误重试的失败上下文快照

Status: verified-ci
审计覆盖：P1-C1
前置：v0.18.0 发布后只读审计（2026-10-19）
通用约束与验收流程：[路线](README.md)

## 交付目标

错误中心/toast 的“重试”必须重放失败时的操作上下文，而不是读取用户当前视图。
视图、文章、分页范围或表单在失败后发生变化时，旧重试不得作用于新上下文。

本卡只收口重试快照语义，不顺带扩展错误中心 UI 或修改同步逻辑。

## 已核实事实

- `AppErrorEntry.action.run()` 当前允许闭包直接 `get()` 当前 store。
- `markCurrentViewAllRead` 失败动作调用自身并重新读取当前 view/layout；同 key
  `mark:all-read` 会把不同视图的失败合并。
- reader 全文/翻译存在由当前活动文章派生的重试闭包；load-more 重试重新读取当前
  分页范围；`SyncTab` save-and-sync 重试读取当前 React 表单状态。
- 同文件的 feed/AI 多数重试已经捕获实体 id，属于需要保留的正确模式。

## 非目标

- 不改错误中心 20 条上限、TTL、去重展示、toast 生命周期或后端错误分类。
- 不重做 `markCurrentViewAllRead` 的业务算法、读藏冲突保护或同步协议。
- 不为所有动作引入持久化序列化；快照只需覆盖本进程内错误中心的存续期。
- 不修改 Rust 侧、真实账号或服务端。

## 实施要求

1. **动作对象不可变**：写入错误中心/toast 的 `run` 必须闭包捕获失败时实体 id、
   范围、视图、布局、游标或表单草稿；`run` 内不得通过“当前 active id/view”
   重新推导目标。
2. **失败不丢入口**：保留 `retryError` 现有“先消费再执行、同步抛错恢复”语义；
   重试再次失败时仍应产生可重试入口。
3. **同 key 不跨上下文合并**：同一操作但不同视图/范围/文章不得被合并到可互相
   替换的错误项。实体 id 已足够的沿用现有 key；范围类操作需带稳定上下文标识。
4. **目标已消失时失败关闭**：文章被删除、表单目标失效或旧范围不可用时，不得
   自动作用于当前替代对象；需显式提示或安全 no-op。
   - `load-more` 的范围/游标/首页代际/后端重载漂移属于终态：旧入口消费后只给普通
     提示，不重新登记 retry action；仅“上下文仍匹配但请求在途”可同 key 保留。
5. **至少覆盖审计点名链**：mark-all-read、reader fulltext、reader translation、
   load-more、save-and-sync。其余带重试动作逐一核对；已捕获 id 且无当前状态
   重推导的保持不动。
   - Reader translation 的全局 `translating / isShowingTranslatedProse` 只能由当前
     文章的 current 请求修改；A/B 并发时 A 的迟到完成或失败不得关闭 B 的展示态。
6. **真实组件边界**：`SyncTab` 如无现成挂载夹具，可用最小真实 React 挂载验证
   表单快照；若环境不适合，必须说明缺口，不能用源码 contains 冒称行为通过。

## 必测反例

- 视图 A 的 mark-all-read 失败 → 切到视图 B → 点重试：后端只收到 A 的
  feed/folder/view/layout/since 参数；B 的条目不被标记。
- 文章 A 全文提取失败 → 切到文章 B → 点重试：只请求 A，不请求 B。
- 文章 A 翻译失败 → 切到文章 B → 点重试：只请求 A，不请求 B。
- 范围 A 的 load-more 失败 → 切到范围 B/重载首屏 → 点旧重试：不得把 A 的续页
  拼到 B；旧上下文不可用时应安全放弃。
- save-and-sync 用表单 A 失败 → 编辑为表单 B → 点重试：调用参数仍是 A。
- mark-all-read 首次已提交但响应丢失 → 切 B → 重试返回 `affected=0`：A 缓存收敛为
  已读且重新做计数对账。
- Reader 翻译 A/B 并发：A 的迟到流错误/reject/done 不得关闭 B 的全局生成态或译文
  展示，B 成功后仍显示译文。
- 重试再次失败仍保留新入口；成功路径仍按 key 消费旧入口。
