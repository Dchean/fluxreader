# OPT-019：同步集合失败关闭与首次绑定守卫

Status: verified-local
审计覆盖：P1-A1、P1-A2、P1-A3
前置：v0.18.0 发布后只读审计（2026-10-19）
通用约束与验收流程：[路线](README.md)

## 交付目标

关闭两个会造成静默数据损失的同步路径：

1. GReader/Fever 的权威集合响应缺字段时，不得被 serde 默认成空集合继续对账、
   推进游标或写完成态。
2. 当前数据库没有任何远端 feed 绑定时，条目 pull 不得消费历史窗口、推进游标或
   写 Fever history complete。

修复必须基于当前源码与确定性夹具，不以审计报告或文档代替行为证据。

## 已核实事实

- GReader `SubscriptionListResponse.subscriptions`、`ItemIdsResponse.item_refs`、
  `ItemContentsResponse.items` 当前都带 `#[serde(default)]`。
- Fever 信封的 `groups`、`feeds_groups`、`feeds` 当前都带 `#[serde(default)]`；
  已有 `items`、`unread_item_ids`、`saved_item_ids` 的 `Option` + 调用点失败关闭范例。
- `sync_light` 只跑 `states_phase(full=false)`；feed 绑定来自 `feeds_phase`。
- `sync_match_maps` 在无远端绑定时返回空映射而不是错误；GReader 随后仍可能推进
  `last_sync_ts`，Fever 随后仍可能推进页游标或完成历史态。
- 外部协议实现核对：Miniflux 的 `subscriptionsResponse`、
  `streamIDResponse`、`streamContentItemsResponse` 均固定输出对应 JSON 字段；
  FreshRSS 的 GReader/Fever 实现也显式输出 `subscriptions`、`itemRefs`、`items`
  与 Fever 的 `feeds`/`groups`/`feeds_groups`。因此“字段缺失 = 协议错误”与
  两个受支持实现一致；显式空数组/空字符串仍必须合法。

## 非目标

- 不处理 P2 的 item `is_read`/`is_saved` 缺省 false、分类集合缺省空或
  `feed_ids` 缺省空，除非同一测试夹具必须最小扩展。
- 不改协议端点、认证方式、队列语义、同步频率或 UI 设计。
- 不以“再跑一次就恢复”替代失败关闭；也不把真实空订阅当作网络错误。
- 不访问真实账号、用户数据库或真实服务端写接口。

## 实施要求

1. **缺字段失败关闭**：GReader 的 `subscriptions`、`itemRefs`、`items` 缺失必须
   在反序列化或紧邻调用边界显式报协议错误；Fever 必须按 action 契约校验当前
   action 所需的字段，不能让认证/`mark` 等不含集合字段的合法响应被误伤。
2. **空集合语义不变**：显式 `[]`、空的 `unread_item_ids`/`saved_item_ids` 仍是
   权威空集，必须保持现有成功路径与对账语义。
3. **失败不落库**：缺 `subscriptions`/`feeds`/`groups`/`feeds_groups` 时，已有
   `origin='remote'` 源与文章不得被删除；缺 `itemRefs`/`items` 时，已有读藏状态
   不得被清空，游标/完成时间不得推进。
4. **首次绑定守卫**：pull 入口取得匹配映射后，若没有任何远端 feed 绑定，则不请求
   条目/权威状态、不消费历史、不推进 GReader `last_sync_ts`、不推进 Fever
   `last_sync_entry_id` 或写 history complete。只有至少一个远端 feed 可绑定时才
   进入正常 pull。
5. **最小错误可见性**：允许保留空订阅为正常成功；若实现选择记录“尚无绑定，
   本轮跳过”的诊断，不得把它伪装成已同步完成，也不得产生无限写事件。
6. **测试锁定分层**：先写会失败的确定性反例，再修复。禁止仅用
   “struct 没有 default” 或源码 contains 代替 HTTP→生产 pull→DB 断言。

## 必测反例

- GReader `subscription/list` 返回 HTTP 200 `{}`：报告有协议错误，既有远端源/
  文章保持，订阅删除对账不执行。
- GReader `stream/items/ids` 返回 200 缺 `itemRefs`：`last_sync_ts` 不推进，
  star 对账不清空收藏。
- GReader `stream/items/contents` 返回 200 缺 `items`：游标不推进，既有状态保留。
- Fever `feeds`/`groups` action 响应分别缺其所需集合或 `feeds_groups`：本地远端源
  不被清空；显式三空数组合法。
- 空映射 light sync（GReader 与 Fever 各一）：没有条目/权威状态请求，游标与
  Fever history state 原样保留；预置文章仍存在。
- 至少一个绑定的正常同步仍有绿测，防守卫把正常增量同步整体阻断。
