## 当前隔离 SQLite 基线（OPT-017A，2026-10-09）

- 50k × 8KiB 的两类搜索仅 DB 调用即超过 1 秒，构成受测路径需要优化的证据，不等于已测完整 UI 搜索或真实用户库。feed_counts 另列慢路径，原来的搜索端到端阈值不适用于它。

- 50k × 8KiB 的 1000 条批量标读中位数 A/B/C 分别为 2799.102 / 1516.664 / 1765.648ms；旧审查稿“标读未超过 1 秒”一语错误，已在修订交付中更正。

## 读闭包查询规划与批量标读成本（OPT-017G，2026-10-16）

构建：`a309219` + 本卡未提交改动（仅 `src-tauri/src/db/{articles,migrations}.rs` 与本文件等文档；工作区完整 diff 与其哈希见 tmp/optimization-20261008/OPT-017G/evidence/build-workspace-final.diff 与 RESULT.md；测量运行于 rustfmt 格式化前的同一语义版本）。语料：逐字节复制自 OPT-017B 的 20k×8KiB 与 50k×8KiB 库（未覆盖旧样本），首次打开执行 v29→v30 升级；driver、JSON 与工作副本全部在 tmp/optimization-20261008/OPT-017G/（与 017A/017B 样本分开）。

**问题（同构建复现与定位）**：OPT-008B R1 读闭包（`read_targets_with_state`）逐条执行 `url_norm = ?2 AND is_read = 0 ORDER BY id`，被规划为 `SEARCH articles USING INDEX idx_articles_unread (is_read=?)`——**扫描全部未读行**并逐行回表取 `url_norm` 过滤（EXPLAIN 原文落盘 `probe_pre_*.json`）。per-item 拆分（50k×8KiB，SQL 级合计）：闭包查询 ≈24–60 ms/条（快/慢档漂移见下），url_norm 主键读 ≈0.014ms/条、回读 ≈0.008ms/条、生产 `set_read`+`enqueue_sync`（无闭包）≈0.087ms/条——闭包占 set_read_bulk 单条成本 99% 以上，复现 017B 范围外发现。

**处置（v30，仅追加迁移）**：新增部分索引 `idx_articles_url_norm_unread ON articles(url_norm) WHERE is_read = 0`（`url_norm` 等值前缀 + `id`=rowid 隐式覆盖 + 免排序）。读闭包查询文本、写路径与语义**零改动**；`idx_articles_unread` 保留（mark_all_read 的 UPDATE 计划消费）。同构建 A/B/D 三臂轮内交错、顺序旋转（A=迁移后主库、B=同副本 DROP INDEX、D=未改动副本对照文件/缓存状态）：

| 20k × 8KiB | 32.96 ms | 2469.26 ms | 237.75 ms | 24981.10 ms | 105× | 0.238 ms |
| 50k × 8KiB | 43.06 ms | 6629.78 ms | 736.20 ms | 65772.05 ms | 89× | 0.736 ms |

- 计划对照：A/D `SEARCH articles USING COVERING INDEX idx_articles_url_norm_unread (url_norm=?)`（无 TEMP B-TREE）；B 回落 `SEARCH articles USING INDEX idx_articles_unread (is_read=?)`。
- 索引体积（dbstat）：20k 0.545MB、50k 1.53MB（对照全量 `idx_articles_url_norm` 0.99/2.50MB）；升级建索引 0.17s（20k）/1.09s（50k，open 计时含迁移）。
- 写入成本：读/取消读翻转与插入探针在新旧索引间无法与测量噪声区分（A/B/D 交叉不一致，|差|≤0.2ms/次），远小于闭包消除的 25–66ms/条。
- 回落与等值：删索引后计划回落、闭包结果集与回执行/逐行状态/计数逐字等值（`opt017g_read_closure_tests`）；迁移在含数据 v29 旧库上幂等（`opt017g_migration_tests`）。

测量边界与未测项：

- 合成语料 `url_norm` 每篇唯一（闭包命中恒 0 行）：上表只测**查询固定成本**的消除；闭包多行传播的写入放大由小夹具等值回归覆盖、未在大库测；自然语料未测。

## 封面补全请求预算与生命周期（OPT-017D，2026-10-16）

**变更**：候选集合从「`source='direct'` 的无封面文章」扩展为**全来源**的「无封面 + 有原文 URL」（服务端正文无图文章此前永久无任何封面——正文首图兜底只在正文有图时成立；两处封面写入都不会把本地封面清成空：回填路径 `COALESCE(旧值, 新值)` 严格只填空、内容刷新 `COALESCE(新值, 旧值)` 只在远端给出非空新图时覆盖，R1-P2-1 修正）。本节记录其**请求预算与生命周期语义**；这是预算规格，不是性能基准数字。

**每轮预算（`src-tauri/src/scheduler.rs` 常量）**：

| 项 | 值 | 约束的东西 |
| --- | --- | --- |
| 每轮批次 | 20 个 URL | 单轮最多发起 20 次文章页请求（同 URL 的多个条目共享一次请求） |
| 并发上限 | 2 | 与 feed 抓取（默认 4）错峰，避免抢带宽 |
| 单请求超时 | 30s（`COVER_BACKFILL_REQUEST_TIMEOUT`） | 慢页面不拖住整轮 |
| 单轮候选扫描 | 4 页 × 20 条 | 每轮的 SQL 与候选评估成本上限；扫描游标跨轮推进（仅进程内）（R1-P2-2：按已扫描行前移、扫到底回绕，保证有限轮数内全覆盖） |
| 循环间隔 | 60s | 补全速率上限 ≈ 20 URL/分钟 |
| 负缓存上限 | 1024（`COVER_BACKFILL_ATTEMPT_CACHE_MAX`） | 进程内「已尝试 URL」内存有界；逐出最旧 |

**失败与恢复语义**：一次尝试**完整结束后**（成功 / 页面无 og:image / 抓取失败）URL 才记入负缓存——本进程内不重试；容量满后按插入序逐出，被逐出的 URL 只有在再经历 ≥1024 条其它尝试后才可能重试，每轮请求量仍受上表约束（不存在对单个 URL 的无界重试）。**候选查询失败**记录 `warn` 并提前结束本轮扫描（不记任何「已处理」，下轮重试）；**写库失败**记录 `error` 且不记负缓存（下轮重试）；抓取失败/无 og:image 记录 `debug`（含 URL 与原因）。DB 故障不得压成空集合或 0 后把任务标记为已处理。

**生命周期**：应用退出（`RunEvent::Exit`）触发终止信号；补全循环在等待与请求两处消费——不再发起新请求、在途请求被取消，单轮返回前等待全部子任务结束，不残留任务。终止中断的尝试不记负缓存。

**未测边界（验收缺口，不以此节关闭）**：真实库的补全请求总量与全量补完耗时未实测（本卡的证据是本地 mock 服务器下的确定性夹具与红绿/变异日志，见 `tmp/optimization-20261008/OPT-017D/evidence/`）；**隐私边界**：扩面后客户端会直接请求服务端收录文章的第三方源站页面（抓 og:image），客户端 IP 对更多第三方站点可见，这是候选扩展的已知代价；**扫描游标**（`CoverBackfillState::scan_offset`）按已扫描行推进、扫到底回绕，只在进程内保存；静态候选集下可继续覆盖，不能把动态数据变化概括为固定轮数保证；「服务端文章本地补上的封面不参与失效清理（404 时显示占位、进程内不重试）」是保留的保守边界；`first_image`/og:image 的质量启发式仍缺（见 [roadmap.md](roadmap.md)）。

**受测条件的边界（引用这些数字时必须一并带上）**：

- 延迟类数字（切换 59–78ms、搜索 ~510–556ms）含 IPC 与渲染，且切换延迟的旧判据（「存在任意卡片」）在旧卡未换掉时即成立——**数字主要反映 50ms 轮询粒度，不是真实的界面就绪时间**；新版电池改用双判据（见下）。

- 测量环境**无真实同步后端**，同步耗时未测。
- JS 堆与进程 RSS 是不同量纲，不可互相换算。

## SQLite 单连接：维持不变

审计原话是「单连接是否改读写分离应根据锁等待和查询耗时决定」。历史 v0.17.0 夹具下所测查询低于 70ms，没有锁等待证据；该数字不能外推到当前大正文语料。OPT-017A 已显示搜索和计数查询耗时显著上升，但未测并发锁等待。当前先定位查询/索引与内容存储的确定性成本，**暂不以这些数据直接引入读写分离**；若优化后仍出现实际锁竞争，再评估连接方案。`sync_queue_stats` 的 IPC 往返只能作代理指标，不能冒充 DB 锁计时。

## 测量方法纪律

这些是纠正过程中得到的教训，重新测量或阅读历史数据时都适用。

**切换延迟用双判据。** `firstResultMs`（卡片 id 集合发生变化）与 `stableMs`（连续 3 帧 rAF 无 DOM 变更）。只看「是否存在卡片」会把旧卡当成结果；只看一帧会把动画中间态当成稳定态。超时只写 `timedOut`，不给毫秒值——编一个数比留空更糟。

**搜索必须断言结果归属。** 搜索段的 `ownership.tokenAbsentBeforeTyping` 与 `negativeProbe` 用于证明：输入前结果里不含该词、输入后结果确实在 `[role=group][aria-label=文章]` 内。没有归属断言，搜索计时可能测的是背景文本里恰好出现的同一个词。

**条件要分段记录。** `conditions` 是起点条件，`conditionsBySection` 是每段自己的条件；结论行只引用本段那份。锁等待段会自己触发一次同步，借用起点条件会与 JSON 自相矛盾。

**JS 堆与进程 RSS 分列，不可互相换算。** 进程 RSS 须按本次应用父子进程/命令行身份过滤；同名 WebView2 可能来自其他应用，不能按进程名求和。

**崩溃布局的堆值写 null 并附 `heapInvalidReason`**，不填数字。

**中断则增量作废，不输出假值。** 电池可被打断（用户操作、应用退出），此时该段的数字无效。

## 历史测量工具的数据安全纪律

本节的 `--seed`、`--restore` 与 `--no-sync-probe` 是存档分支 `archive/tooling-and-reports` 的测量工具参数，不是 FluxReader 产品命令，也不是当前备份/恢复入口。复用旧工具前须核对其版本与当前 schema；产品快照及退出应用后的恢复步骤以 [backup.md](backup.md) 为准。

**历史测量电池不是全只读。** `lockWaitProxy` 段曾通过命令面板触发一次真实联网刷新，`--no-sync-probe` 用于跳过该段。该工具可能写本机库、触发已连接账户的同步；旧按钮文案和点击路径不能直接假定适用当前版本。

**旧 `--seed` / `--restore` 使用文件副本与 SHA256 清单。** 它曾备份 `.db` / `-wal` / `-shm` 并在还原后逐字节复核；哈希只能证明拷贝一致，不能证明运行中分别复制的三文件来自同一数据库时点。不能用这条历史工具约定代替当前 `VACUUM INTO` 自包含快照。

**旧工具还原前也必须完全退出应用。** 运行中的 SQLite 连接持有文件句柄，覆盖可能失效或被后续 WAL 写入破坏；哈希通过不等于恢复后的逻辑状态已验收。

**失败处置一律「先退应用再还原」**，`skipped` / `timedOut` / `invalid` 按原样记录，不手填数字。
