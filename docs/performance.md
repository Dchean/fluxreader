# 性能基线与测量方法

性能结论必须附日期、构建、语料与测量范围。本页保留仍适用的判定线、方法纪律、当前基线与资源预算；构建或输入变化后旧数字不能直接比较，历史任务卡只用于定位固定材料。

## 判定线（触发优化才动手）

| 指标 | 阈值 |
| --- | --- |
| 内存随文章数 | 超线性增长 |
| 滚动帧间隔 p95 | > 50ms |
| 视图切换 / 搜索端到端 | > 1000ms |
| 长会话 | 首末内存增量显著为正且 DOM 节点同向增长（缓存无界） |
| 两档规模之间 | 指标超线性恶化 |

## 当前本地同步基线（2026-11-12，组合候选实测）

**构建与前提。** 数字来自 debug 构建的 `cargo test`（opt-level=0、无内联、无优化）与隔离 Windows Rust 窗口的合成语料；发布给用户的是 release 构建，同一路径通常快一个数量级，不能用这些耗时推算用户换机恢复或首同步体验。

**范围裁定（2026-11-13）。** 本版 v0.19.0 的规模验证标准正式定为 10k distinct 4KiB 全流程（4KiB 正文、全部相位、全部断言、2 秒门槛不变，仍为 ignored 容量测试）；50k distinct-body 记为本版**开放边界**，不写成通过或已验证（`r9-i1-50k-03/04` 证据保留）。依据：用户口径“以实际使用为参考，不需要考虑太多极端情况”；50k 在 debug 构建下整库应用约 2 小时量级，且 state-only 50k 主测已通过；连续两轮向用户确认范围未得到回复，按已给出的推荐继续。该裁定不改变任何测试强度。

**10k distinct-body exact（最终源码，审计修复后）。** 4KiB 不同正文、全部相位与 2 秒前台断言自然 exit 0：墙钟 1,442,330 ms；initialize 24,653 ms、state_seal 4,812 ms（11,915,932 B/64 对象）、state_ack 46 ms、seal 22,954 ms（88,032,541 B/144 对象）、ack 5,167 ms、delta 4,405 ms（3 对象/155,724 B）、portable_export 30,568 ms（96,021,252 B）、portable_preview 10,486 ms、preflight 46,242 ms、state_first_apply 1,254,000 ms（其中 retention 排空 306,998 ms）、state_metadata_apply 69,320 ms；9 个源前台阶段单次最大 358,782 µs，全部低于 2 秒。

**50k 状态 exact（小 delta，非整库 apply）。** 同一源码上自然 exit 0：墙钟 65,019 ms（测试自身 63.47 s）、initialize 27,912 ms、seal 15,004 ms、click 14,347 µs、delta 1,619 ms、preflight 3,139 ms、`fast_apply_us=3,184,493`、`idle_us=1,530`。

**50k distinct-body（开放边界）。** r9-i1-50k-04 完成 initialize 137,950 ms、state_seal 22,927 ms、state_ack 44 ms、seal 101,420 ms、ack 35,957 ms、delta 21,228 ms、export 141,445 ms（480,327,791 B）、preview 48,989 ms、preflight 245,234 ms，但 accept 后的整库 apply drain（物化 + retention）在 60 分钟硬上限内未完成，因此 **50k distinct-body 容量未验证**。

**WAL 时间序列（r9-i1-10k-02 采样，约 0.3 s 间隔，共 4,825 个样本）。** 窗口边界按 `logs/r9-i1-10k-02.dbsize.jsonl` 逐点确定：portable 文件首次出现于 18:49:44.362Z（大小 0），首次达到最终大小 96,021,252 B 于 18:50:13.832Z；最后一次可读样本在 19:12:29.803Z，下一 0.3 s 样本（19:12:30.126Z）已因测试清理而为空。导出期间文件大小采样恒为 0，完成瞬间才以最终大小可见，故窗口由文件出现/达到最终大小界定。

| 时点 | 源库 `.db` | `−wal` | 导出文件 | 采样点数 |
| --- | ---: | ---: | ---: | ---: |
| 导出开始前（18:48:25.780–18:49:44.030Z，最后样本 18:49:44.030Z） | 264,298,496 | 93,610,552 | 不存在 | 242（其中 231 个已见 `.db`） |
| 导出期间（18:49:44.362–18:50:13.506Z） | 264,298,496（91 点恒定） | 93,610,552（91 点恒定、未增长） | 0（91 点均为 0） | 91 |
| 导出完成至测试清理前（18:50:13.832–19:12:29.803Z） | 264,298,496（4,102 点恒定） | 93,610,552（4,102 点恒定） | 96,021,252 | 4,102 |

结论：导出期间 WAL 不随导出时长增长；**“回落为 0”发生在连接正常关闭时，而不是导出结束**。跨运行核对用 r9-i1-50k-02 的 2,973 个采样：`−wal` 为 465,823,712 B 的 686 个样本持续到 11:44:39.44Z 进程退出，紧接着的采样变为 0，之后 2,287 个样本保持 0；被外部终止的运行保留 WAL 文件、不归零。10k-02 第三段之后还有 390 个样本，因测试清理文件已不可见，不参与上述三个窗口。

**内存。** 进程内存按采样阶段区分：r9-i1-50k-03 的 2.36 GiB 单进程峰值出现在启动后约 13.5 秒的编译期（样本 27/2084，known_pids 含 cargo/rustc），不是 apply；测试进程 apply 期的实测峰值是 r9-i1-50k-04 的 401,154,048 B（样本 2296/3955）。两者不构成“apply 占 2.36 GiB”的结论，差异不作归因。

**已知规模瓶颈（既有缺陷，本轮未修）。** 整库 state 应用到新库会为每条被应用的 read/star 字段生成一个 `retention/` 工作键：10k 库约 20,001 个，debug 构建下实测排空 306,998 ms（约 15.3 ms/键）；50k 约 100,002 个，r9-i1-50k-04 在 60 分钟硬上限内未完成，故 50k distinct-body 未验证。只影响“一次性整库应用”的耗时，不影响便携导出、前台延迟或正确性。`retention_work` 按 `feed_url+guid` 找物理文章的查询分支没有 `articles(guid)` 索引，按 feed 扫描；retention 也只在整库 state 应用时成批产生，日常增量 state 只覆盖变化条目。修复需 schema 索引与迁移并补旧库兼容验证；后续方向（不承诺）是该索引或把 retention 按 key 查询批量化。

**方法与边界。** 整库 state 应用阶段走 `merge_apply` 测试入口（不是生产恢复），其无前台写者的原因与生产同步 receive 入口相同：候选折叠期间逻辑修订必须稳定，持续写只会可重试失败、停写后收敛；生产便携恢复 `backup::restore` 另有独占锁/`capture=0` 语义。源半程保留 20 写/秒负载。不外推自然语料、真实 WebDAV、IPC/渲染、前台等待 SLO 或真实存储介质 I/O 损坏。

## 查询与搜索预算

- 列表、搜索、成员捕获和计数在完全投影态直接读取物理 `feeds`/文章状态；存在普通工作、候选接受、folding/applying 或待处理意图时回落到本地同步逻辑视图。两条路径的可见性、去重、排序与计数必须同值；计划回归要求稳定态无 TEMP B-TREE、无 `MATERIALIZE local_sync*`，并用一个待物化反例证明确实切回逻辑视图。
- 搜索的 trigram 索引只是 ≥3 字符的候选加速，LIKE 才裁决匹配；短词、索引缺失或 MATCH 失败回落 LIKE，不改变顺序、去重或字段语义。索引体积与写入成本不可外推到自然语料。
- 读闭包查询使用 `articles(url_norm) WHERE is_read=0` 的部分索引；批量标读不得逐条扫描全部未读行。
- 计数由后端非线性聚合，前端不能按字段或副本数线性推算；读取失败保留最后已知值，写后以权威快照收敛。
- 以下历史只作为方向性结论保留（同构建前后对照、合成语料、db 层中位）：trigram 候选把 50k×8KiB 唯一词搜索从数百毫秒级压到毫秒级；部分索引把 1000 条批量标读的逐条闭包成本从约 25–66 ms/条降到约 0.2–0.7 ms/条。绝对数字不可跨构建比较，端到端（IPC/渲染）未测。

## 封面补全请求预算与生命周期

**每轮预算（`src-tauri/src/scheduler.rs` 常量）：**

| 项 | 值 | 约束的东西 |
| --- | --- | --- |
| 每轮批次 | 20 个 URL | 单轮最多发起 20 次文章页请求（同 URL 的多个条目共享一次请求） |
| 并发上限 | 2 | 与 feed 抓取（默认 4）错峰 |
| 单请求超时 | 30s | 慢页面不拖住整轮 |
| 单轮候选扫描 | 4 页 × 20 条 | 每轮的 SQL 与候选评估成本上限；游标只在进程内保存，动态集合不保证固定轮数全覆盖 |
| 循环间隔 | 60s | 补全速率上限约 20 URL/分钟 |
| 结果缓存上限 | 1024 | 成功与失败共用条目上限，按插入序逐出；是条目数，不是字节硬界 |
| 失败/无图缓存 | 10 分钟 | 实际尝试完成后计时，命中不续期 |
| 文章页正文 | 16 MiB | Content-Length 预检与累计流式收体，超量不采用前缀中的 og:image |

- 候选是全来源的“无封面 + 有原文 URL”；回填只填空（`COALESCE(旧值, 新值)`），内容刷新只在远端给出非空新图时覆盖。
- 正文首图、OG 和 RSS 媒体按显式尺寸及角色跳过小图、头像、emoji；无尺寸正常图保留，不另发尺寸探测。
- 本机封面按 article ID 与当前图片 URL 精确 CAS 清除，并撤销共享成功缓存、设短期失败屏障；旧图迟到不能清新图。
- 应用退出触发终止信号：不再发起新请求、取消在途请求，单轮返回前等待子任务结束；中断的尝试不记负缓存。
- 客户端会直接请求服务端收录文章的第三方源站页面，暴露客户端 IP，这是候选扩面的既有隐私取舍；真实库请求总量、补完耗时与图床解码未测。

## 画廊布局预算

画廊使用 `@tanstack/react-virtual` 的 lanes 模型，按视口 4/3/2 列、14px 间距与图片自然比例渲染。挂载量由列数、可见高度与 overscan 决定，不是全量挂载：参考视口 768、卡高 ≥150 时，测试口径按 48 项作为检查界，但 48 不是任何视口的绝对上限。虚拟化不能测量未挂载内容，列归属依赖已测高度；自然图片分批到达时，几何发布与滚动补偿必须先于测量更新，避免可见锚漂移。

- 当前门禁在真实 headless Edge 中跑两视口、图片两波异步到达，要求指定可见锚漂移 ≤3px；历史失败（159px、295px）保留在 commit 与 CI，不用后续本地结果覆盖。
- 5000 条合成数据、程序化滚动的 rAF 间隔约 16.8–16.9ms；这是回调时间戳间隔，不是硬件 FPS、INP 或真实库持续性能。
- 真实 WebView2 滚动 p95、解码与自然语料仍未测；相关缺口见 [roadmap](roadmap.md#interface-and-media)。

## 图片代理编码资源预算

代理四个 active、32 个 queued 不同 key；单图 25 MiB，后端整条 Referer 链总寿命 30s。前端 ready（含在用及退休版本）与 active 每个 25 MiB 预留合计 ≤128 MiB；无人使用 ready 子集 ≤64 MiB 且 ≤256 条；服务持有代理 lease ≤256，失败/上报元数据分别 ≤1024 条，普通失败 30s/明确对象失效 10min 冷却。普通直链不占代理 entry/lease 或字节预算，本地失败状态仅随消费者保存。

解码失败在真实 DOM 移除 Blob src 后归还该消费者的票，健康共享消费者继续保护同一版本；失败占位不阻止原有 LRU 和新请求回收无人使用 bytes。只有无人用的 Blob 能淘汰，超额代理消费者由容量释放自动唤醒，保持真实可见图最终可加载。预算是资源规格，不能冒充 WebView/native/GPU 进程内存硬界。

## 测量方法纪律

- **切换延迟用双判据。** 记录 `firstResultMs`（卡片 ID 集合变化）与 `stableMs`（连续 3 帧 rAF 无 DOM 变更）；只看“存在卡片”会把旧卡当结果，超时只写 `timedOut`，不给毫秒值。
- **搜索必须断言结果归属。** 输入前结果不含该词、输入后结果确实在文章区域内；否则计时可能测到背景文本。
- **条件分段记录。** 起点条件与每段条件分开，结论只引用本段条件；锁等待段自己触发同步，不借用起点条件。
- **JS 堆与进程 RSS 分列，不可换算。** 进程 RSS 按应用父子进程/命令行过滤；同名 WebView2 可能来自其他应用。
- **崩溃布局的堆值写 null 并附原因**，不填数字；中断则本段作废，不输出假值。
- **证据对应固定 SHA 与输入**：本地未提交改动或不同构建的数字不能与 CI 结果混用；旧任务卡的测量工具在存档分支，复用前核对 schema 与读写边界。
